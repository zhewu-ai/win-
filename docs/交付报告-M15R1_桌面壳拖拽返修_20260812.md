## 一、结论

桌面壳拖拽上传返修完成。采用 QA 建议的**方案 A**：在 Tauri 壳的两个窗口（主窗口 `main`、悬浮窗 `floating_*`）上禁用 Tauri 内部拖放处理，让系统文件拖入直接落到前端 HTML5 drop 逻辑，复用现有 `onParseFile`（AI 导入）与 `imageUploadRef.uploadFiles`（便签图片），**零前端改动**。

- Mac 壳实机：用户在 `tauri dev` 壳窗口实测拖拽上传成功 ✓
- Web 浏览器回归：dev + 生产全绿 ✓

- Windows 壳：本机无 Windows 实机，待 Windows 实机补测（见 §五）

## 二、根因

Tauri v2 默认启用内部 drag drop handler，系统文件拖入会被 WebView 层拦截，前端 HTML5 `dragenter/dragover/drop` 不触发（Windows WebView2 尤甚）。此前 Web 验证通过是因为普通浏览器不受该拦截影响；桌面壳才是验收缺口。

## 三、修复（1 个文件）

`src-tauri/src/lib.rs`：

| 窗口 | 位置 | 改动 |
|---|---|---|
| 主窗口 `main` | `setup()` 中 `WebviewWindowBuilder` | 加 `.disable_drag_drop_handler()` |
| 悬浮窗 `floating_*` | `open_floating_note()` 中 `WebviewWindowBuilder` | 加 `.disable_drag_drop_handler()` |

依据：Tauri 2.11.5 crate 源码该 API 注释原文 —— *"Disables the drag and drop handler. This is required to use HTML5 drag and drop APIs on the frontend on Windows."*。禁用后文件拖入由 WebView 原生处理并触发前端 DOM drop，主窗口/悬浮窗均覆盖（便签图片拖拽可能发生在悬浮窗）。

未改：前端 drop/paste 逻辑、数据模型、解析流程、窗口事件处理（`disable_drag_drop_handler` 只影响文件拖放，不影响窗口拖动/缩放/置顶/悬浮窗）。
