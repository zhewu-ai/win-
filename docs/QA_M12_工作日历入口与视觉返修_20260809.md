# QA M12：工作日历入口与视觉返修要求

日期：2026-08-09

## 一、结论

M12 工作日历的底层方向基本正确：已经有结构化事件模型、日历页、月/周/今日列表、事件关联便签、管理员灰度。

但当前交付在**产品入口和视觉体验**上不通过。问题不是“功能没做”，而是“做法破坏了原有界面节奏”：日历入口被放成普通导航链接，首页顶部又新增一条日历条，导致主界面更挤、更碎，也不符合 PinNote 作为轻量便签工具的气质。

本轮返修目标：

- 不新增复杂功能。
- 不继续扩 AI 导入。
- 不继续改造原有首页结构。
- 把日历入口收敛为左侧侧边栏顶部的卡片入口。
- 修复左侧便签列表预览里内部链接仍显示代码的问题。
- 明确视觉验收标准：功能通过但界面丑、不协调、不想用，不能算通过。

## 二、问题复盘

### 2.1 当前日历入口位置不合理

当前实现：

- `Sidebar.tsx` 在搜索框下方、便签列表上方放了一个普通“日历”链接。
- 视觉上像一个额外导航项，夹在搜索和便签卡片之间。
- 它不是一个“工作空间入口”，也没有承载今日信息。

问题：

- 打断左侧栏原有层级。
- 搜索框、日历链接、便签列表三者挤在一起。
- 入口视觉形态和便签卡片体系不统一。
- 用户无法从入口直接感知“今天有什么工作”。

### 2.2 首页顶部今日条不合理

当前实现：

- 在首页全局顶部加了 `TodayStrip`。
- 位置在 `OfflineBar` 下、主布局上方。

问题：

- 改造了原有首页结构。
- 压缩了便签列表和编辑区域的垂直空间。
- 让顶部栏变得更复杂、更拥挤。
- 视觉上像硬塞了一个新功能条，而不是自然融入产品。

结论：

首页顶部今日条需要删除。今日信息应该沉到左侧“日历卡片”里，点击卡片后进入完整日历空间。

### 2.3 左侧便签列表预览仍显示链接代码

当前正文编辑区和待办编辑区已经能显示链接/便签芯片，但左侧便签列表仍直接使用原始文本：

- 自动标题从 `note.content` 第一行取值。
- 摘要从 `note.content` 或 `checklistItems.text` 取值。
- 遇到 `[[note:id|title]]` 时仍显示内部语法代码。

问题：

- 用户在正文里看到的是正常链接/芯片。
- 但左侧标题/摘要看到的是 `[[note:...]]` 代码。
- 同一个内容在不同区域显示不一致，破坏“链接不露代码”的产品承诺。

## 三、返修范围

### 3.1 必须做

1. 删除首页顶部 `TodayStrip`。
2. 左侧侧边栏顶部新增“日历卡片”入口，仅管理员可见。
3. 日历卡片显示今日预览信息。
4. 点击日历卡片进入 `/calendar`。
5. 普通用户不显示日历卡片，直接访问 `/calendar` 仍无权限。
6. 左侧便签列表标题和摘要不再显示 `[[note:id|title]]` 代码，只显示 `title`。
7. 更新交付报告，明确本次返修的视觉调整和验收截图/验证结果。

### 3.2 不做

1. 不做 AI 排期导入。
2. 不做拖拽日历事件。
3. 不做提醒通知。
4. 不做复杂项目管理。
5. 不恢复极小模式/悬浮窗。
6. 不把日历做进 Tiptap 编辑器。
7. 不新增首页顶部、编辑器顶部或工具栏里的日历入口。

## 四、日历卡片入口设计要求

### 4.1 位置

日历卡片放在左侧侧边栏顶部，建议位置：

- 搜索框下方。
- 便签列表上方。
- 管理员账号置顶卡片或管理员相关区域上方/附近，作为“工作空间入口”。

如果当前侧边栏没有明确的管理员置顶卡片，则按以下层级：

1. 搜索/刷新/折叠工具行。
2. 日历卡片。
3. 便签列表。
4. 底部新建/账号区。

不要把日历做成普通一行链接。

### 4.2 视觉形态

日历入口必须是卡片，不是导航文本。

要求：

- 形状和现有便签卡片体系统一。
- 圆角、边框、阴影、hover 状态与 `NoteList` 卡片气质一致。
- 尺寸克制，不要做大 banner。
- 不使用大面积高饱和颜色。
- 不使用营销式 hero、渐变大块、夸张装饰。
- 在亮色/暗色主题下都要协调。

建议结构：

```text
┌────────────────────────────┐
│ 工作日历              今天 │
│ 8月9日 · 今日未完成 3 项    │
│ 09:30 角色绑定初版          │
│ 全天  排期整理              │
└────────────────────────────┘
```

如果今天没有事件：

```text
┌────────────────────────────┐
│ 工作日历              今天 │
│ 今天暂无事件                │
│ + 添加今日事件              │
└────────────────────────────┘
```

### 4.3 信息密度

日历卡片只做预览，不做完整操作台。

显示内容：

- 标题：工作日历。
- 日期：今天日期。
- 今日未完成数量。
- 最多 2 条今日事件。
- 无事件时显示“今天暂无事件”。

可选：

- 一个很轻的“+”或“添加”入口。

不显示：

- 月视图。
- 周视图。
- 复杂按钮组。
- 三个以上事件。
- 大段说明文字。

### 4.4 点击行为

主点击：

- 点击卡片主体进入 `/calendar`。

事件点击：

- 如果实现成本低，可以点击事件进入对应事件编辑或关联便签。
- 如果会让卡片交互变复杂，本轮先统一点击卡片进入 `/calendar`。

新增入口：

- 如果卡片上有“+ 添加今日事件”，点击进入 `/calendar?date=YYYY-MM-DD&new=1`。
- 但不能让按钮挤压卡片主体。

## 五、首页布局返修

必须删除首页顶部 `TodayStrip`。

删除后要求：

- 首页顶部不再出现日历条。
- 原有 `OfflineBar`、侧边栏、编辑器布局不被日历功能改变。
- 管理员和普通用户的主界面结构保持一致，区别只在管理员左侧多一张日历卡片。

验收重点：

- 管理员首页不应比普通用户首页多一个全局顶部条。
- 双栏和单栏模式下，编辑器高度不应被日历条挤压。
- 320px 窄窗口下，不出现额外顶部拥挤。

## 六、左侧链接预览修复

### 6.1 目标

左侧便签列表里的标题和摘要，遇到内部便签链接语法时，不再显示代码。

示例：

原始存储：

```text
今天跟进 [[note:abc123|客户反馈]]，下午整理。
```

左侧预览应显示：

```text
今天跟进 客户反馈，下午整理。
```

不能显示：

```text
今天跟进 [[note:abc123|客户反馈]]，下午整理。
```

### 6.2 覆盖范围

必须覆盖：

- 普通便签自动标题。
- 普通便签摘要行。
- 待办清单摘要行。
- 小标题行摘要。
- 搜索高亮时也不能破坏替换后的显示文本。

### 6.3 建议实现

新增或复用一个纯文本展示函数，例如：

```ts
displayPlainText(text: string): string
```

行为：

- `[[note:id|title]]` 显示为 `title`。
- 外部 URL 保持原 URL 文本，不需要在卡片里变成可点击链接。
- 残缺或非法内链语法保持原样，避免误删用户文本。
- 支持 M11.1.2 的 escape 标题：`A\]B` 显示为 `A]B`。

位置建议：

- 可放在 `src/lib/link-parser.ts`，复用现有解析逻辑。
- `NoteList.tsx` 的 `getAutoTitle()` 和 `getSummaryLines()` 调用该函数。

注意：

- 左侧卡片只做“可读预览”，不要求芯片化，不要求可点击。
- 不要把 Tiptap/React 节点引入 NoteList 预览。这里只需要纯文本。

## 七、日历完整页保留但不扩

`/calendar` 日历空间可以保留现有月视图、周视图、今日列表、事件编辑弹窗。

但需要注意：

- 日历页内部可以有自己的顶部操作栏。
- 这个操作栏只存在于 `/calendar` 页面内部。
- 不要把日历页的控件搬到首页。

日历页视觉要求：

- 安静、工作流导向。
- 信息清晰，不拥挤。
- 月/周/今日切换明确。
- 320px 下优先可读，不强行塞满。

## 八、权限要求

保持 M12 管理员灰度：

- 管理员显示日历卡片。
- 普通用户不显示日历卡片。
- 普通用户不显示首页今日条，因为今日条应被删除。
- 普通用户直接访问 `/calendar` 不展示日历功能。
- 普通用户访问 `/api/calendar-events` 返回 403。
- 未登录访问 API 返回 401。

## 九、视觉验收标准

本轮必须把“美观和协调”作为验收条件，不允许只说功能可用。

### 9.1 左侧栏

通过标准：

- 日历入口是一张卡片，不是一行普通链接。
- 卡片和便签卡片视觉统一。
- 搜索框、日历卡片、便签列表之间留白自然。
- 左侧栏没有明显拥挤感。
- 320px 下卡片内容不重叠、不横向溢出。

不通过示例：

- 日历入口像一个临时按钮或普通菜单项。
- 日历入口夹在搜索和便签列表之间显得突兀。
- 卡片文字过多，像小型仪表盘。
- 卡片颜色过重，抢过便签列表。

### 9.2 首页

通过标准：

- 首页顶部没有日历条。
- 原有便签列表和编辑器布局不被日历功能改变。
- 管理员只是左侧多一张日历卡片。
- 普通用户界面完全不受日历影响。

不通过示例：

- 顶部仍有 `TodayStrip`。
- 编辑器区域被日历条挤矮。
- 顶部工具栏变复杂。

### 9.3 链接预览

通过标准：

- 左侧便签标题不显示 `[[note:...]]`。
- 左侧摘要不显示 `[[note:...]]`。
- 待办摘要不显示 `[[note:...]]`。
- 搜索高亮仍可用。

不通过示例：

- 正文不露代码，但左侧卡片露代码。
- 只有普通便签修了，待办摘要没修。
- 标题含 `]` 的内部链接预览异常。

## 十、功能验收标准

### 10.1 管理员

1. 登录管理员账户。
2. 左侧顶部看到日历卡片。
3. 卡片显示今天日期、今日未完成数量、最多 2 条事件。
4. 点击卡片进入 `/calendar`。
5. `/calendar` 月/周/今日视图仍可用。
6. 新建事件、编辑事件、删除事件仍可用。
7. 事件关联便签仍可用。
8. 首页顶部没有日历条。

### 10.2 普通用户

1. 登录普通用户账户。
2. 左侧不显示日历卡片。
3. 首页顶部没有日历条。
4. 直接访问 `/calendar` 不展示日历。
5. 直接请求 `/api/calendar-events` 返回 403。

### 10.3 链接预览

准备数据：

```text
外链：https://example.com
内链：[[note:abc123|客户反馈]]
转义标题：[[note:def456|A\]B]]
```

验收：

- 左侧标题/摘要显示 `客户反馈`，不显示 `[[note:abc123|客户反馈]]`。
- 转义标题显示 `A]B`。
- 外链可以保留 URL 文本。
- 正文编辑器和待办编辑器原有链接能力不回退。

## 十一、构建与部署验收

本地：

- `npm run build -- --webpack` 通过。
- `npx tsc --noEmit` 通过，若 `.next/types` 干扰，先 build 或清 `.next`。

生产：

- 如只改前端和纯函数，不需要 DB 迁移。
- 如未改 schema，不需要 `prisma db push`。
- 部署后健康检查：
  - `/login` 200。
  - 未登录 `/` 307。
  - `/api/auth/me` 未登录 401。
  - 管理员首页显示日历卡片。
  - 普通用户首页不显示日历卡片。

## 十二、交付报告要求

技术部交付时必须包含：

1. 返修结论：M12 从“顶部今日条 + 普通入口”改为“侧边栏日历卡片入口”。
2. 删除 `TodayStrip` 首页挂载的说明。
3. 日历卡片截图或 DOM 验证说明。
4. 普通用户不可见验证。
5. 左侧链接预览修复验证。
6. 320px 窄窗口验证。
7. 构建结果。
8. 未做项说明：AI 导入不做、悬浮窗不做、首页顶部条不保留。

## 十三、给技术部的重点提醒

本次不是单纯补功能，而是补产品体验。

用户是视觉设计/三维设计背景，对界面协调度非常敏感。功能“能用”但界面显得临时、拥挤、丑，不能算完成。

后续所有产品功能，尤其是会进入主界面的功能，都必须同时满足：

- 功能成立。
- 信息层级清楚。
- 不破坏现有布局。
- 视觉形态和已有组件统一。
- 320px 窄窗口不挤、不乱、不重叠。

如果需求没有明确说要改首页结构，不要主动加顶部条、全局栏或大面积新模块。新功能优先用“入口卡片 + 独立空间”的方式承载。
