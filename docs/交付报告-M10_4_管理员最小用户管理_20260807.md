# PinNote M10.4 管理员最小用户管理：交付报告

日期：2026-08-07

## 1. 结论摘要

本轮完成 M10.4 四件事：

1. **管理员用户列表**：`GET /api/admin/users` + `/admin/users` 页面（仅 admin 可见），账号菜单左下角新增「管理用户」入口（仅 admin 显示）。列表含昵称/文字头像、用户名、角色、状态、已用/额度、创建时间，绝不下发 `passwordHash`。
2. **禁用 / 启用用户**：禁用后无法登录（403 `ACCOUNT_DISABLED` + 友好文案）、旧会话访问业务 API 一律 403；启用后恢复。管理员不能禁用自己（400 `CANNOT_DISABLE_SELF`）。
3. **调整存储额度**：1 MB – 500 MB 正整数；不能为 0；不能低于当前已用空间；非法值返回明确错误码。
4. **管理员重置密码**：bcrypt 重新哈希，最少 8 位，不下发明文；重置后旧密码立即失效。

配套：`User` 表新增 `role` / `status` 字段、`requireAdmin()` / `requireUser()`、业务 API 统一改为按请求实时校验账号状态（禁用即时生效）。生产已部署并回归通过，数据零变化（User 1 / Note 26 / Attachment 1）。

未做（SPEC 明确排除）：用户注册、邮箱找回、内容审核、删除用户。

## 3. schema 变更说明

```prisma
model User {
  id                String   @id @default(cuid())
  username          String   @unique
  passwordHash      String
  displayName       String?
  avatarColor       String?
  storageQuotaBytes Int      @default(10485760)
  storageUsedBytes  Int      @default(0)
  role              String   @default("user")    // 新增："admin" | "user"
  status            String   @default("active")  // 新增："active" | "disabled"
  // …（createdAt / updatedAt / notes / attachments 不变）
}
```

- 两列均有默认值，`db push` 后历史 `admin` 行自动获得 `role=user, status=active`，需手动将其 `role` 提升为 `admin`（生产已执行）。
- `role` / `status` 均为字符串枚举语义，未引入 Prisma enum，保持与 `storage*` 字段一致的最小侵入。

## 4. 鉴权设计（关键决策）

M10.4 要求「禁用即时生效」（SPEC §2.3）：仅凭 session 里的历史数据无法感知禁用，因此业务 API 从「读 session → 放行」改为 `authOrResponse()`，**每次请求实时查一次 `User.status`**：

```
getSession() → getActiveSessionUser()（findUnique 只取 id/status）
  → status !== "active" 抛 HttpError(403, "ACCOUNT_DISABLED")
  → authOrResponse() 返回 { userId } 或 NextResponse
  → 路由 if (session instanceof NextResponse) return session;
```

- `getSession()` 现仅限登录/登出/me 等认证路由使用（已 grep 确认业务路由不再直接 import）。
- 管理路由用 `requireAdmin()`（含禁用拦截），失败经 `toErrorResponse()` 映射为对应 status 的 `{ ok:false, error }`。
- 每请求多一次 `findUnique`（SQLite 本地命中，开销可忽略），换回禁用即时生效的语义。

## 15. 回退方案

若出现登录异常、用户数据不可见等异常：

```bash
# 1) 停服务
export XDG_RUNTIME_DIR="/run/user/$(id -u)"
systemctl --user stop sticky-notes.service

# 2) 恢复 M10.4 前数据库备份
cp /home/ubuntu/backups/prod_M10_4_<ts>.db \
   /home/ubuntu/projects/sticky-notes/data/prod.db

# 3) 校验
sqlite3 /home/ubuntu/projects/sticky-notes/data/prod.db "PRAGMA integrity_check;"

# 4) 回退代码（git checkout 上轮 commit 后 rsync src/ --delete + prisma/schema.prisma）
# 5) 重新 build + 重启服务
npm run build
systemctl --user restart sticky-notes.service

# 6) 复查：admin 可登录 / Note 26 / Attachment 1 / 旧图片可打开
```

回退后 role/status 两列随 schema 回退被 `db push` 移除，业务 API 回退为 session 放行（禁用保护随代码一并回退），历史便签/附件不受影响。
