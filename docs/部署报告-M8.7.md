## 关键技术发现：Tailwind 3.4 对 var() 颜色的透明度修饰符失效

**现象**：颜色 var() 化后，`text-ink-muted/60`、`bg-primary/10`、`placeholder:text-ink-muted/60` 等透明度修饰符被静默丢弃（编译成不带 alpha 的 `var(--x)`），占位符回到浏览器默认灰。

**根因**：Tailwind 3.4 的 `withAlphaVariable` 对裸 `var(--x)` 颜色调用 `parseColor` 返回 null，null 路径直接返回 `{ color: var(--x) }`，丢弃 alpha；3.4 不产出 `color-mix()`。

**修复**：idiomatic 方案 `rgb(var(--x-rgb) / <alpha-value>)`。config 颜色改为 `rgb(var(--page-bg-rgb) / <alpha-value>)` 等，并在 globals.css 两套主题补 `--x-rgb` 三元组。

**二次坑（关键）**：三元组必须是**空格分隔**（`245 244 242`），不能用逗号。逗号分隔会产出 `rgb(245, 244, 242 / 0.6)` —— 混用旧版逗号语法与现代斜杠 alpha，浏览器判定为非法声明并丢弃。空格分隔 → `rgb(245 244 242 / 0.6)` 合法。已在浏览器实测验证（空格分隔后占位符正确渲染为 `rgba(142,142,147,0.6)`）。

1. **无 Git 历史**：服务器代码仍无 `.git`，依赖 rsync；且本轮首次同步了根目录 `tailwind.config.ts`，后续若改动根目录配置文件（tailwind/next/postcss），rsync 必须显式包含，否则部署遗漏。
