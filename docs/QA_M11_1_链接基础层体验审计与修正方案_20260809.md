# QA：M11.1 链接基础层体验审计与修正方案

日期：2026-08-09

## 一、结论

M11.1 当前实现从技术上完成了外部 URL 解析、内部 noteId 链接、单条便签 GET、桌面壳外部打开能力；但产品交互不达标。

主要问题不是解析能力，而是把链接能力藏进了「阅读模式」，导致链接不像链接、内部便签链接像代码、跳转路径没有返回栈。这会让普通用户觉得功能割裂。

建议 M11.1 做一次体验修正，不改底层存储模型：

- 保留 `[[note:id|title]]` 作为底层存储格式。
- 前端编辑器不要直接暴露这串语法给用户。
- 外部 URL 与内部便签链接应在正文中自然呈现为蓝色链接/链接芯片。
- 内部链接跳转必须支持“返回上一条便签”。
- 插入内部链接应支持输入 `[[` 唤起搜索，而不是只靠更多菜单按钮。

## 二、当前实现问题

### P0-1：阅读模式作为链接入口不符合用户预期

当前交付报告明确写：URL 只在「阅读模式」下渲染为蓝色可点击链接。

代码上也是 `preview` 为 true 时才渲染 `LinkedText`，否则继续显示纯 textarea。

问题：

- 用户输入网址后，正常预期是它自然变蓝可点，而不是需要进入一个额外模式。
- 「阅读模式」像 Markdown 预览，不像便签链接能力。
- 链接是高频基础能力，不应藏在更多菜单里。

修正方向：

- M11.1.1 不再把“能不能点链接”绑定到阅读模式。
- 正文区域在常态下就应能识别链接。
- 若 textarea 技术限制导致不能直接在输入中渲染链接，至少要做“非聚焦时自动显示链接层，聚焦时进入编辑”的无感切换，而不是让用户主动找阅读模式。

### P0-2：内部便签链接暴露为代码，体验不合格

当前插入内部链接后，编辑态直接显示：

```text
[[note:NOTE_ID|显示标题]]
```

这对开发者合理，对用户不合理。

问题：

- 用户想插入的是“客户反馈记录”这个便签链接，不是代码片段。
- 日常编辑时看到一长串 ID 会破坏笔记可读性。
- 标题越短、ID 越长，越显得突兀。

修正方向：

- 底层仍保存 `[[note:id|title]]`。
- 编辑器展示层应显示为链接芯片或蓝色链接：`客户反馈记录`。
- 用户复制纯文本时可以保留底层语法，或者复制显示文本，二者后续再定；第一版先保证视觉不暴露 ID。

建议视觉：

- 外部 URL：蓝色下划线链接。
- 内部便签：蓝色/主色“便签链接芯片”，可以带一个小文档图标。
- 失效内部链接：灰色、删除线或弱化文案。

### P0-3：插入便签链接不应只靠菜单按钮

当前只有「更多」菜单里的「插入便签链接」入口。

问题：

- 插链接是写作过程中的原地动作，不应每次去菜单里找。
- 用户更自然的方式是输入 `[[` 后出现便签搜索小窗。
- 这也是内部链接区别于普通附件/图片的核心交互。

修正方向：

- 保留更多菜单入口作为备选。
- P0 新增 `[[` 触发器：
  - 用户在正文中输入 `[[`。
  - 光标下方或附近弹出便签搜索浮层。
  - 输入关键词过滤便签。
  - Enter/点击选择后，插入底层语法 `[[note:id|title]]`。
  - 编辑器展示为链接芯片/蓝色链接。

验收：

- 输入 `[[客` 后出现搜索结果。
- 选择“客户反馈记录”后正文中显示可读链接，而不是裸 ID。
- Esc 关闭搜索，不污染正文。

### P0-4：内部链接跳转缺少返回上一层

当前点击内部链接后，直接切换 `selectedNoteId`，没有记录来源。

问题：

- 从 A 点到 B 后，用户想回 A，只能去左侧列表重新找。
- 如果是多层跳转 A → B → C，没有路径感。
- 这会让内部链接变成“跳走”，而不是“查看引用”。

修正方向：

- 增加内部链接导航栈 `noteNavigationStack`。
- 点击内部链接前，把当前 noteId 压栈。
- 打开目标便签后，在编辑器顶部显示轻量返回入口：
  - `返回上一条`
  - 或 `← 客户反馈记录` / `← 上一条便签`
- 点击返回后回到来源便签，并恢复编辑器状态。

第一版不要求复杂面包屑，只需要一层/多层栈均可返回：

```text
A -> B -> C
返回：C -> B
返回：B -> A
```

注意：

- 返回动作也必须沿用切换便签前的保存/flush 保护。
- 如果来源便签被删除，返回按钮消失或提示“来源便签已失效”。

## 三、推荐的新交互方案

### 方案：无感链接层 + `[[` 搜索 + 返回栈

保持当前纯文本存储，但编辑器表面做一层链接体验。

#### 1. 正文显示规则

普通文本便签正文有两种状态：

- 聚焦编辑中：用户可以正常输入。
- 非聚焦/光标不在该行时：链接被渲染成可点击链接或芯片。

如果实现行内混排成本太高，第一版可采用折中：

- textarea 失焦后，正文区域自动切到渲染层。
- 点击非链接区域进入编辑。
- 点击链接直接打开链接。
- 不再需要用户手动点「阅读模式」。

这比“更多菜单阅读模式”自然很多。

#### 2. 外部 URL

- `https://...`、`http://...`、`www...` 在渲染层直接蓝色可点。
- 网页端新标签打开。
- 桌面壳系统浏览器打开。
- 不支持 `javascript:` 等危险 scheme。

#### 3. 内部便签链接

底层：

```text
[[note:NOTE_ID|显示标题]]
```

表面：

```text
显示标题
```

点击：

- 打开对应便签。
- 当前便签进入返回栈。
- 顶部出现“返回上一条”。

#### 4. 插入方式

优先：

- 输入 `[[` 唤起便签搜索。

保留：

- 更多菜单「插入便签链接」作为辅助入口。

不建议：

- 只靠菜单插入。
- 让用户手写 `[[note:id|title]]`。

## 四、技术修正建议

### 4.1 NoteEditor

当前：

- `preview` 控制阅读模式。
- 更多菜单切换「阅读模式/返回编辑」。
- `LinkedText` 只在 preview 下出现。

建议：

- 移除“阅读模式”作为主要入口，或降级为开发/高级入口。
- 改为 `isEditingContent` / `contentFocused` 控制渲染层：
  - textarea focus：编辑。
  - textarea blur：渲染链接层。
  - 渲染层点击普通文本：进入编辑。
  - 渲染层点击链接：不进入编辑，执行打开。
- 新增 `[[` trigger 监听与搜索浮层。
- 点击内部链接时调用 `onOpenNote(noteId, { pushHistory: true })`。

### 4.2 LinkedText

当前 `LinkedText` 可复用，解析和安全渲染方向正确。

建议增强：

- 支持内部链接芯片样式。
- 点击内部链接时阻止外层进入编辑。
- 支持失效链接稳定渲染。
- 可接收 `variant="body" | "card" | "compact"`，后续列表卡片也能复用。

### 4.3 page.tsx

当前 `openNoteById(noteId)` 只切换目标。

建议改为：

```ts
openNoteById(noteId, options?: { pushHistory?: boolean })
goBackLinkedNote()
```

状态：

```ts
const [noteNavStack, setNoteNavStack] = useState<string[]>([]);
```

行为：

- 内部链接点击：把当前 `selectedNoteId` 入栈，再打开目标。
- 返回上一条：pop 栈，打开来源。
- 手动点左侧列表：清空或保留栈需产品定；建议清空，避免路径混乱。

### 4.4 InsertNoteLinkDialog

当前可保留，但从主入口变成辅助入口。

新增：

- `InlineNoteLinkSuggest` 或复用 dialog 的搜索逻辑。
- 由 `[[` 触发，贴近光标显示。

## 五、验收标准

### 外部链接

1. 普通正文中输入 `https://example.com`，光标离开正文后自动显示为蓝色链接。
2. 不需要进入「阅读模式」即可点击。
3. 点击非链接区域可继续编辑。
4. 桌面壳外部链接仍走系统浏览器。

### 内部链接显示

1. 插入 B 便签链接后，正文表面显示 `B标题`，不直接显示 `[[note:id|B标题]]`。
2. 刷新页面后仍显示为链接。
3. B 改标题后仍能打开 B；显示名是否同步可后续定，但不能断链。
4. B 删除后显示失效状态。

### `[[` 唤起

1. 在正文输入 `[[`，出现便签搜索浮层。
2. 输入关键词能过滤便签。
3. Enter/点击选择后插入链接。
4. Esc 关闭浮层，不破坏正文。
5. 更多菜单「插入便签链接」仍可用。

### 返回上一条

1. A 点击内部链接进入 B 后，编辑器顶部出现“返回上一条”。
2. 点击返回后回到 A。
3. A → B → C 连续跳转后，可逐级返回。
4. 返回前当前便签未保存内容不丢失。

### 回归

1. 自动保存 debounce 不受影响。
2. M10.12 手动刷新不受影响。
3. M10.13 工具栏布局不被新入口挤乱。
4. 320px 下链接显示、`[[` 搜索、返回上一条不溢出。

## 六、优先级

### 必须修（P0）

1. 不再要求用户进入「阅读模式」才能点击链接。
2. 内部链接表面不暴露 `[[note:id|title]]` 裸语法。
3. 点击内部链接后提供返回上一条。

### 应该做（P1）

1. 输入 `[[` 唤起便签搜索。
2. 列表卡片/悬浮窗也复用链接渲染。
3. 失效链接预校验或坏链扫描。

### 暂不做

1. 完整 Markdown。
2. 富文本编辑器。
3. 反向链接页。
4. 日历事件挂载。

## 七、给技术部的结论

当前 M11.1 不建议直接作为最终体验验收通过。可以承认底层能力已打通，但需要做一次 M11.1.1 体验修正：

- 链接应像链接一样自然显示，而不是藏在阅读模式。
- 内部链接应像便签引用，而不是代码。
- 插入应支持 `[[` 原地唤起。
- 跳转必须有返回上一条。

这次修正仍不需要改数据库，也不需要上完整 Markdown/富文本。重点是把现有解析能力从“工程可用”改成“用户可用”。
