## 本轮验收重点（第 1 批）

### 1. P0-01：壳内置顶 / 极小模式真正可用

验证点：

1. Windows App 内点「窗口置顶」→ 不再弹"请确认在桌面壳中运行"，置顶开关能实际生效。
2. 点「极小模式」→ 能打开悬浮窗（不再是"打开悬浮窗失败"）。
3. 若仍失败：弹窗现在会显示**原始错误文本**，请把弹窗文字 + Windows DevTools 控制台报错贴回反馈。
4. 悬浮窗默认置顶，Alt+Tab 切走后仍不被遮挡；取消置顶后可被遮挡，再置顶恢复。

证据要求：

- 录屏：置顶开→关→开、Alt+Tab 切换后仍置顶。
- 截图：主编辑页「窗口置顶」「极小模式」按钮可见。
- 置顶 command 成功调用证据（DevTools 网络面板 / 控制台无 `toggle_always_on_top failed` 报错）。

### 2. P0-02：小窗口文字不再提前裁切

验证点：

1. 主窗口缩到约 320px 宽：长文本便签正文随内容生长，不再在离边缘明显留白处被裁切。
2. 纵向空间足够时，正文不会提前在底部被截掉（正文区随内容增高，超出后整页滚动）。
3. 悬浮窗缩到约 260px 宽：同样通过。
4. 内容超出可视区时滚动正常。

证据要求：

- 截图：320px 主窗口、260px 悬浮窗各一张（长文本便签）。
- 修复前后对比说明（M7 旧包是固定高度 textarea，内容在内部滚动像被截断；本轮自动增高）。

### 3. P0-03：换行连续，不再固定档位

验证点：

1. 拖动窗口从 520px 到 260px，正文行宽连续变化（padding 随窗口宽度线性缩放）。
2. 长句靠近边界时自然换行。
3. 悬浮窗窗口大于 320px 时正文填满整个宽度（不再右侧留"假边界"空白）。
4. 工具栏不把正文挤到不可用。

证据要求：

- 录屏：窗口从 520px 一路缩到 260px，正文随宽度连续换行。
- 截图：悬浮窗在约 400px 宽时正文填满窗口（对比旧版 max-w-[320px] 右侧留白）。

### 4. P0-04：右键不再出现浏览器菜单

验证点：

1. Windows App 内右键任意位置 → 不出现"返回/刷新/另存为/打印/共享"浏览器默认菜单。
2. 文本输入区域右键 → 出现产品内菜单：复制、粘贴、剪切、全选、删除所选。
3. 复制/粘贴在文本区域可用（至少不劣于浏览器自带行为）。

证据要求：

- 录屏：文本区域右键出现产品菜单、浏览器菜单未出现。
- 若复制/粘贴异常：请说明具体操作步骤（WebView 环境下粘贴依赖剪贴板权限，实机为准）。
