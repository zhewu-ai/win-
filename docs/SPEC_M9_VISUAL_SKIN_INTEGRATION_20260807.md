# PinNote M9 视觉换皮集成说明

日期：2026-08-07

## 1. 背景

产品侧基于参考图和当前 PinNote 体验，单独做了一版视觉原型：

```text
visual-prototypes/pinnote-skin-v1/
```

这是一个独立静态原型，不是生产代码，也不是要求技术部逐像素复制的最终布局。它的目的只有一个：确定 PinNote 下一阶段的主视觉气质。

本轮集成应理解为“视觉换皮”，不是功能重构，也不是新增业务能力。

## 2. 核心原则

### 2.1 主视觉方向不要再改

技术部集成时可以根据现有产品结构调整按钮位置、间距、断点和组件落位，但整体视觉方向不要偏离原型。

必须保留的视觉气质：

1. 亮色优先：干净、轻、白但不刺眼。
2. 左侧像便签卡片，不像普通列表。
3. 右侧编辑区低干扰、强留白。
4. 选中态使用蓝色作为明确视觉锚点。
5. 图标统一为细线 SVG，不要出现临时拼接、比例奇怪的图标。
6. 暗色模式要干净、有层次，不要纯黑、脏灰、死暗。

### 2.2 不要求机械照搬原型位置

原型和当前生产产品并不是完全一一对应。技术部需要按现有项目实际情况重新归位。

允许调整：

1. 工具栏按钮顺序。
2. 某些低频按钮是否放入更多菜单。
3. 色球在不同宽度下的展示方式。
4. 同步状态的位置与宽度。
5. 侧边栏宽度、卡片高度、列表密度。
6. 断点数值和动画时长。

但调整后必须满足：

1. 不破坏主视觉。
2. 不破坏现有功能。
3. 不引入新的信息架构。
4. 不为了贴合原型而增加不必要功能。

### 2.3 不借换皮加功能

本轮只做皮肤和视觉体验集成。

明确不做：

1. 不新增富文本。
2. 不新增账号系统。
3. 不新增复杂离线能力。
4. 不重做数据结构。
5. 不重写保存逻辑。
6. 不重做附件系统。
7. 不改变 API。
8. 不改变服务名、域名、数据库表名。

如果集成过程中发现必须改逻辑，先单独提出，不要混进换皮任务。

## 4. 必须继承的视觉元素

### 4.1 颜色方向

亮色模式：

```text
窗口背景：浅灰白
侧边栏：轻灰、有层次
编辑区：接近白色
卡片：白色/浅灰边框/轻阴影
选中卡片：蓝色渐变或稳定蓝色面
文字：高对比黑，不要发灰
hover：浅色轻提示，不要暗块
```

暗色模式：

```text
窗口背景：深灰蓝/深中性灰
侧边栏：比编辑区略有层次
卡片：半透明浅叠层
边框：低对比
选中卡片：蓝色保持清晰
文字：清楚但不刺眼
```

技术部可以重新命名 token，但需要把这些语义拆出来，而不是继续散落硬编码颜色。

建议 token：

```text
--window-bg
--sidebar-bg
--editor-bg
--line
--line-strong
--ink
--ink-soft
--ink-muted
--hover
--selected
--card-bg
--card-bg-hover
--card-border
--active-card-text
--active-card-subtext
--blue
--blue-deep
--sync-dot
--drag-dot
```

### 4.2 侧边栏卡片

左侧不要再像纯列表。需要有更明确的“便签卡片”感：

1. 未选中卡片：白/浅灰底、轻边框、轻阴影。
2. hover：轻微浮起或浅背景变化，不能变成暗色块。
3. selected：蓝色强锚点，文字要清晰。
4. 卡片圆角可以按生产系统收敛，但不要变回完全普通列表。
5. 卡片内容密度要兼顾现有便签长标题和待办预览。

### 4.3 编辑区

右侧编辑区重点是阅读和输入，不要做复杂装饰。

要求：

1. 标题强，但不能大到窄窗裁切。
2. 正文和待办行留白更舒展。
3. 工具栏视觉降低干扰。
4. 底部时间/元信息弱化。
5. 不要把编辑区包成大卡片。

### 4.4 图标系统

本轮已把原型里的临时 CSS 图标改掉。技术部集成时也要遵守：

1. 使用主项目已有的线性 SVG 风格，线宽约 1.5px。
2. 更多按钮使用竖向三点。
3. 置顶按钮沿用当前 `NoteEditor.tsx` 的窗口置顶图标。
4. 待办拖拽手柄使用 2 列 6 点。
5. 不要使用 CSS 伪元素拼复杂图标。
6. 不要引入和当前产品气质不一致的卡通/拟物/重描边图标。

## 5. 允许技术部重新归位的内容

以下内容不要求照抄原型：

1. 工具栏具体按钮位置。
2. “便签/待办”文字是否保留。
3. 色球是全部展开、只展示当前色，还是收进更多菜单。
4. 保存状态是文字、点，还是固定槽位组合。
5. 侧边栏自动隐藏阈值。
6. 侧边栏手动折叠入口位置。
7. 左下角新建和账号入口的精确排列。
8. 卡片高度和预览行数。

判断标准不是“和原型像素一样”，而是：

```text
当前产品功能完整 + 主视觉气质一致 + 窄窗稳定 + 不产生新的跳变
```

## 6. 与 M8.9 的关系

M8.9 仍然需要处理之前用户实测发现的细节问题：

1. 亮色 hover 不应过暗。
2. 侧边栏自动收起要有动画。
3. 工具栏响应式不要反复展开/收起。
4. 临界宽度不要出现图标颤动。

M9 视觉换皮可以吸收这些要求，但不要混淆优先级：

```text
先保证当前功能稳定和防丢不退化，再换视觉。
```

如果 M9 集成会影响 M8.8 断网防丢保护，必须优先保护防丢逻辑。

## 7. 推荐实施顺序

### 阶段 1：只接 token 和主题底色

目标：

1. 建立 M9 亮/暗 token。
2. 替换页面背景、侧边栏、编辑区、边框、文字、hover。
3. 不改组件结构。

验收：

1. 亮色不脏。
2. 暗色不闷。
3. 原功能全部正常。

### 阶段 2：改侧边栏卡片视觉

目标：

1. NoteList 从列表感升级为卡片感。
2. selected 使用蓝色视觉锚点。
3. hover 轻量化。

验收：

1. 亮色 hover 清楚但不暗。
2. selected 和 hover 层级清楚。
3. 长标题、待办预览、时间、进度不互相挤压。

### 阶段 3：改编辑工具栏和图标系统

目标：

1. 工具栏统一线性 SVG。
2. 固定关键按钮槽位。
3. 减少文字显隐造成的跳变。
4. 置顶、更多、图片、模式、拖拽手柄视觉统一。

验收：

1. 宽屏、820px、390px、320px 工具栏不换行。
2. 临界宽度无明显颤动。
3. 图标不奇怪、不变形、不跑位。

### 阶段 4：微调编辑区和待办行

目标：

1. 标题、正文、待办行对齐到新视觉。
2. 拖拽手柄、勾选圆点、完成态保持轻量。
3. 底部时间弱化。

验收：

1. 阅读优先。
2. 编辑区不花。
3. 待办行可读、可点、可拖。

### 阶段 5：全状态 QA

至少覆盖：

1. 亮色宽屏。
2. 暗色宽屏。
3. 亮色 390px。
4. 暗色 390px。
5. 320px 窄窗。
6. 侧边栏手动收起/展开。
7. 侧边栏自动收起。
8. 新建普通便签。
9. 新建待办便签。
10. 编辑保存。
11. 断网继续编辑防丢。
12. 图片按钮、更多菜单、置顶按钮。
13. 回收站/归档页是否仍可读。

## 8. 不通过标准

出现以下任一情况，本轮不能算通过：

1. 视觉明显偏离原型，重新变回“普通后台列表感”。
2. 亮色 hover 仍是暗块。
3. 图标出现比例怪、风格混乱、临时 CSS 拼接感。
4. 侧边栏卡片选中态文字不清楚。
5. 工具栏在缩放时反复展开/收起。
6. 320px/390px 下按钮重叠、文字竖排、内容裁切。
7. 换皮导致新建、编辑、保存、待办、图片、置顶任一核心功能坏掉。
8. 换皮导致断网后继续编辑的防丢保护退化。

## 9. 交付物要求

技术部交付时请提供：

1. 改动文件清单。
2. token 对照说明。
3. 亮色/暗色截图。
4. 390px/320px 截图。
5. 侧边栏 hover/selected 截图。
6. 工具栏缩放录屏或截图序列。
7. 防丢保护复测结果。
8. 已知未对齐原型的地方，以及为什么需要按生产结构调整。

## 10. 产品侧确认口径

本轮产品侧确认的是：

```text
主视觉方向确认：按 visual-prototypes/pinnote-skin-v1/ 的气质集成。
```

不是确认：

```text
逐像素复制原型。
```

也不是确认：

```text
借这次换皮重做功能或扩范围。
```

技术部可以随机应变，但边界是：

```text
视觉气质不能变，功能范围不能扩，已有稳定体验不能退。
```
