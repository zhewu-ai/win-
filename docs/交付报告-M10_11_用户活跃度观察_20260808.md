# M10.11 交付报告：用户活跃度观察（最近活跃时间 + 操作统计）

日期：2026-08-08
规格：`docs/SPEC_M10_11_USER_ACTIVITY_OBSERVABILITY_20260808.md`

## 一、本期变更

PinNote 已进入真实内测，管理员此前看不到「用户有没有在用、最近什么时候用、做了什么操作」。本期新增轻量用户活跃度观察，**不做心跳、不做实时在线**，只在用户发起业务请求成功时顺手记录活跃。

三件事：
1. `User` 记录最近活跃时间 + 最近操作类型（`lastActiveAt` / `lastActiveAction`）。
2. 新增 `UserActivityLog` 表，统计今日 / 近 7 天操作次数。
3. 管理员用户列表弱化展示这 4 项信息。

### 边界（本期严格遵守）
- 不记录便签标题/正文/待办文字/反馈正文/附件原始文件名（`metadata` 仅允许 `{count}`、`{type}` 等非内容字段）。
- 埋点失败绝不抛错、绝不影响主业务成功率（`recordUserActivity` 整体 try/catch + 事务吞错）。
- 管理员只看动作类型与时间，不看内容。
- 90 天日志清理本轮不做（SPEC 预留，代码未实现）。

## 二、实现说明

### Schema（`prisma/schema.prisma`）
- `User` 追加 `lastActiveAt DateTime?`、`lastActiveAction String?`、`userActivityLogs UserActivityLog[]`。
- 新增模型 `UserActivityLog { id, userId, action, metadata?, createdAt }`，索引 `[userId, createdAt]`、`[createdAt]`、`[action]`。
- 纯增量，`prisma db push` 即可；本地与生产均已验证建表成功。

### 埋点 `src/lib/activity.ts`（新增）
- `UserActivityAction` 联合类型：`login / create_note / edit_note / check_todo / delete_note / restore_note / archive_note / unarchive_note / permanent_delete_note / upload_attachment / delete_attachment / submit_feedback / read_announcement / change_avatar / change_password`。
- `cstDayStartUTC()`：固定 UTC+8 上海自然日零点，与服务器进程 TZ 解耦，用于「今日」边界。
- `recordUserActivity(userId, action, metadata?)`：`prisma.$transaction([user.update(lastActiveAt/lastActiveAction), log.create])`，整体 try/catch + `console.error`，绝不抛出。

### 埋点清单（15 类动作，均在业务成功后、return 前调用）
- 登录：`auth/login` → `login`。
- 便签：`POST /api/notes` → `create_note`；`PATCH /api/notes/:id` → 区分 `archive_note` / `unarchive_note` / `check_todo` / `edit_note`；`DELETE` → `delete_note`；`restore` → `restore_note`；`permanent` → `permanent_delete_note`（`{count}`）。
- 附件：上传 → `upload_attachment`；删除 → `delete_attachment`。
- 反馈：`POST /api/feedback` → `submit_feedback`（`{type}`）。
- 公告：`POST /api/announcements/:id/read` → `read_announcement`。
- 账号：换/删头像 → `change_avatar`；改密 → `change_password`。
- 批量（4 个）：`bulk-delete` → `delete_note`、`bulk-restore` → `restore_note`、`bulk-unarchive` → `unarchive_note`、`bulk-permanent-delete` → `permanent_delete_note`，均带 `{count}`，仅在确有处理时才记录。

### PATCH 动作区分逻辑（`src/app/api/notes/[id]/route.ts`）
- 已过 M10.8 无变化检测（noop 直接 return），此处必有真实变化。
- `updateData.isArchived !== undefined && isArchived !== 旧值` → `archive_note` / `unarchive_note`（与旧值比较，避免前端顺带传 `isArchived` 误报）。
- 否则 `updateData.checklistItems !== undefined` → `check_todo`（mode 切换误归类为 SPEC 允许）。
- 否则 → `edit_note`。

### 管理员列表
- `src/lib/admin.ts`：`ADMIN_USER_SELECT_WITH_COUNTS` 追加 `lastActiveAt`、`lastActiveAction`。
- `GET /api/admin/users`：与用户列表并行 `Promise.all` 两次 `userActivityLog.groupBy`（`by:[userId]`，`createdAt >= cstDayStartUTC()` / `createdAt >= now-7d`），Map 拼到每个 user → `activityCounts: { today, last7Days }`。

### 管理员 UI（`AdminUsersClient.tsx`）
- `AdminUser` 接口加 `lastActiveAt/lastActiveAction/activityCounts`。
- 新增 `ACTION_TEXT` 中文映射（15 类动作）。
- `src/lib/format-time.ts` 新增 `formatLastActiveAt(iso|null)`：null→"暂无"；今天 `今天 HH:mm`；昨天 `昨天 HH:mm`；更早 `YYYY-MM-DD HH:mm`。
- 卡片「创建于」行改写为合并弱化行（`text-[11px] text-ink-muted/70 break-words`，避免截断统计数字）：
  `创建于 {createdAt} · 活跃 {lastActiveAt} · {最近操作} · 今日 {today} 次 · 近7天 {last7Days} 次`
- **顺带修复**：禁用/启用/调整额度后，状态与额度接口返回的对象不含 `activityCounts/_count`，状态更新时改为 `{ ...data.user, lastActiveAt, lastActiveAction, activityCounts, _count }` 全部保留，避免渲染崩坏。
