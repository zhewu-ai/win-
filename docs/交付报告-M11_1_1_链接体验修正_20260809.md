# M11.1.1 交付报告：链接体验修正（无感链接层 + `[[` 搜索 + 返回栈）

日期：2026-08-09

## 一、交付内容

依据 QA 审计（`docs/QA_M11_1_链接基础层体验审计与修正方案_20260809.md`）实施四项 P0 体验修正。**不改存储模型**（保留 `[[note:id|title]]` 底层语法），**不引入 Markdown/富文本**，仅把 M11.1 的链接能力从「工程可用」改成「用户可用」。

- **P0-1 无感链接层**：移除「阅读模式」菜单门槛。正文 textarea 失焦后自动切到渲染层（`showRenderLayer` 派生：`mode==="text" && content 非空 && !contentFocused && !linkSuggest`）。点击非链接区域回编辑态并按 `lastCaretRef` 恢复光标；点击链接直接打开，不触发编辑态。
- **P0-2 链接芯片**：内部便签链接在渲染层显示为芯片（标题 + 文档图标），不再暴露 `[[note:id|title]]` 裸语法；目标失效时芯片变灰 `标题（已失效）` 并禁用。
- **P0-3 `[[` 唤起搜索**：输入 `[[query` 在光标附近弹出便签搜索浮层（`InlineNoteLinkSuggest`，`createPortal` + `useLayoutEffect` 定位 clamp），可键盘操作（↑/↓ 选择、Enter 插入、Esc 关闭不污染正文）；菜单「插入便签链接」保留为辅助入口（仅 text 模式）。
- **P0-4 返回栈**：内部链接跳转带返回栈，编辑器顶部显示「← 来源标题」可逐级返回；沿用切换便签的 flush 保护；长标题截断（`min-w-0` + `truncate`）。

## 四、说明与已知限制
- **320px 单栏整页布局未在预览环境复测**：headless preview 的 `resize` 事件不触发 `useLayoutMode`，app 停留在双栏布局（既有环境问题，与本次改动无关，本次未触碰布局代码）。改为直接在 `innerWidth=320` 下验证浮层 clamp 与返回条截断，均通过。
- **生产浏览器实机未复测**：部署完成后 Chrome 自动化连接不可用，未做生产页面的浏览器内渲染复验。生产 bundle 与 dev 验证的源码逐字节一致，且 API/存储路径已用 curl 确认，风险低。桌面壳渲染属后续 Tauri 壳构建范畴，本轮无 Rust 改动。
- **`[[` 浮层与 ContextMenu 共用 portal 体系**：320px 下已按 QA 第 5 条回归 clamp。
- 服务器历史 hydration mismatch（`useLayoutMode` 窗口宽度差异）为既有问题，与本次改动无关。

## 五、风险与后续
- 渲染层/textarea 挂载切换的焦点往返：已用 `lastCaretRef` 恢复光标，dev 下稳定；若后续引入其他「点击即聚焦」行为需回归。
- 返回栈与删除/归档/刷新 interplay：清栈时机已覆盖 handleSelect/handleArchive/删除事件/删除事件 effect，避免栈内残留已删除 id。
- 后续方向（M11.2+）：反向链接、坏链扫描、`NoteLink` 关系表。
