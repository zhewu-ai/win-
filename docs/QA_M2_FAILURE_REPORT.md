## 2. 阻塞问题

### 2.1 QA-M2-008：空便签切待办后刷新，没有显示可编辑空待办项

问题描述：

空便签切换到待办模式后，刷新页面，没有显示至少一条可编辑空待办项。

影响：

- 用户进入空待办状态后无法自然继续输入。
- 不符合 M2 规格中“至少保留一条可编辑空项，避免用户进入空白死状态”的要求。

期望结果：

- 空便签切换到待办模式后，应显示一条可编辑空待办项。
- 刷新页面后仍应显示一条可编辑空待办项。
- 页面不得出现空白死状态、undefined、null 或无法输入的状态。

修复方向：

- 待办模式下，如果 `checklistItems` 为空数组，前端渲染层需要兜底显示一条临时可编辑空项。
- 如果用户输入内容，该空项需要正常进入 `checklistItems` 并自动保存。
- 如后端保存空待办模式，也应保证接口返回后前端仍能进入可编辑状态。

复验标准：

1. 新建空便签。
2. 切换为待办模式。
3. 不输入任何内容。
4. 刷新页面。
5. 页面仍显示一条可编辑空待办项。

### 2.2 QA-M2-016：普通删除确认文案未说明“可在回收站恢复”

问题描述：

普通删除时有确认弹窗，但文案未明确说明“删除后可在回收站恢复”。

影响：

- 用户无法判断删除是永久删除还是进入回收站。
- 与 M2 规格中普通删除的确认文案要求不一致。

期望结果：

- 普通删除确认文案需要明确表达：删除后可在回收站恢复。
- 永久删除文案需要明确表达：永久删除后无法恢复。

建议文案：

```text
确定删除此便签？删除后可在回收站恢复。
```

复验标准：

1. 在主页删除普通便签。
2. 弹窗文案明确包含“回收站”或“可恢复”含义。
3. 确认后便签进入回收站。

### 2.3 QA-M2-025：390px 移动端返回列表后，列表和编辑内容同时残留，状态不干净

问题描述：

在 390px 移动端宽度下，从编辑页返回列表后，列表和编辑内容同时残留，移动端状态没有干净切回列表。

影响：

- 移动端主流程体验异常。
- 用户无法明确判断当前处于列表还是编辑视图。
- 可能造成内容遮挡、误操作或返回路径混乱。

期望结果：

- 390px 移动端默认列表优先。
- 点击便签后进入编辑视图。
- 点击返回后，只显示列表，不应残留编辑内容。
- 再次点击便签后，应只显示编辑视图。
- 顶部栏状态需要和当前视图一致。

修复方向：

- 移动端返回列表时，需要清理或隐藏编辑视图状态。
- 检查 `showEditor`、`selectedNoteId` 和响应式 class 的组合逻辑。
- 桌面端可以列表 + 编辑并排；移动端不应同时显示两者。

复验标准：

1. 浏览器宽度设为 390px。
2. 进入主页。
3. 点击任意便签进入编辑。
4. 点击返回列表。
5. 页面只显示列表，不显示编辑内容残留。
6. 再次点击便签，页面只显示编辑视图。
