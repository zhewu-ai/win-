# PinNote M10.2 账号入口、基础身份与图片入口降级

日期：2026-08-07

## 1. 背景

M10.1 已完成账号地基审计：

1. 历史数据全部归属默认用户 `admin`。
2. `Note` / `Attachment` 已按 `userId` 隔离。
3. 隔离测试通过。
4. 本轮零代码改动，无数据迁移。

M10.2 开始把“已有账号地基”收口成用户能感知的账号体验，但仍然控制范围，不开放注册，不做复杂账号系统。

本轮可以一次做两件相关的小事：

```text
1. 登录入口 + 登录态收口
2. 基础身份展示：昵称 + 文字头像
```

同时顺手做一个低风险 UI 调整：

```text
图片入口从主工具栏降级到更多菜单，窗口置顶留在主工具栏。
```

## 2. 本轮目标

### 2.1 登录入口收口

目标：

1. 未登录访问 PinNote 时进入登录页。
2. 登录成功后进入便签主页。
3. 已登录访问登录页时自动回到便签主页。
4. 刷新页面保持登录态。
5. session 未过期时关闭浏览器/桌面壳后再打开仍保持登录。
6. 退出登录可用。
7. 退出后不能继续访问便签页面和便签 API。

本轮继续使用现有账号体系：

```text
username + password
```

不改成邮箱注册，不接微信登录。

### 2.2 基础身份展示

目标：

1. 左下角账号区域显示当前用户身份。
2. 支持修改昵称。
3. 使用文字头像，不做头像上传。
4. `GET /api/auth/me` 返回当前用户基础资料。

建议字段：

```text
User.displayName String?
User.avatarColor String?
```

显示规则：

1. 有 `displayName` 时显示昵称。
2. 没有 `displayName` 时显示 `username`。
3. 文字头像取 `displayName` 首字；没有昵称时取 `username` 首字。
4. `avatarColor` 从预设色中选择或首次自动分配。

头像示例：

```text
圆形头像：D
旁边文字：dian 或 displayName
```

### 2.3 图片入口降级

当前产品判断：

```text
图片功能保留，但不是核心能力，不应占据主工具栏显眼位置。
```

要求：

1. 顶部主工具栏移除“添加图片”独立按钮。
2. “窗口置顶”按钮保留在顶部主工具栏。
3. “添加图片”移动到三个点更多菜单。
4. 已有图片展示、上传、删除能力不能退化。
5. 窄屏下工具栏不应因为图片按钮显隐再次抖动。

推荐工具栏主区：

```text
保存状态 / 窗口置顶 / 更多
```

推荐更多菜单：

```text
便签置顶
归档
添加图片
删除
```

注意区分：

```text
窗口置顶：Tauri / 桌面窗口 always-on-top，留在主工具栏。
便签置顶：列表排序置顶，放在更多菜单。
```

如果当前生产只在 Tauri 环境显示窗口置顶按钮，保持这个逻辑。

## 3. 本轮不做

M10.2 明确不做：

1. 不开放注册。
2. 不做邮箱验证码。
3. 不做找回密码。
4. 不做微信登录。
5. 不做头像上传。
6. 不做存储额度。
7. 不做管理员后台。
8. 不做内容审核。
9. 不改便签数据归属规则。
10. 不改附件存储结构。

存储额度单独放到 M10.4，因为它会影响保存、图片上传、历史统计和超额策略，不适合混进本轮。

## 4. 推荐实现

### 4.1 数据模型

在 `User` 上增加可选字段：

```prisma
model User {
  id           String   @id @default(cuid())
  username     String   @unique
  passwordHash String
  displayName  String?
  avatarColor  String?
  createdAt    DateTime @default(now())
  updatedAt    DateTime @updatedAt
  notes        Note[]
  attachments  Attachment[]
}
```

要求：

1. 字段可选，避免影响现有 `admin` 用户。
2. 老用户没有昵称时前端 fallback 到 `username`。
3. `avatarColor` 必须来自安全预设值，不接收任意 CSS 字符串。

### 4.2 Auth API

扩展当前用户接口：

```text
GET /api/auth/me
```

返回建议：

```json
{
  "ok": true,
  "user": {
    "id": "xxx",
    "username": "admin",
    "displayName": "当前用户",
    "avatarColor": "blue"
  }
}
```

新增或扩展账号资料接口：

```text
PATCH /api/auth/me
```

只允许修改：

```text
displayName
avatarColor
```

校验要求：

1. 未登录返回 401。
2. `displayName` 去除首尾空格。
3. `displayName` 最长建议 20 个中文字符或 40 个英文字符以内。
4. 空昵称允许，前端 fallback 到 username。
5. `avatarColor` 必须在预设枚举内。
6. 不能通过该接口修改 `username`、`passwordHash`、`userId`。

### 4.3 页面访问保护

要求：

1. 未登录访问主页，进入登录页。
2. 未登录访问归档/回收站/浮窗页面，也不能看到数据。
3. 已登录访问登录页，自动进入主页。
4. 401 状态要有明确处理，不要停在空白页。

桌面壳注意：

1. 如果 session 过期，桌面壳打开应显示登录页，而不是空数据列表。
2. 登录成功后回到主页面。
3. 浮窗路由若未登录，应给出登录态失效提示或跳登录，不应报错。

### 4.4 左下角账号菜单

左下角账号区域需要显示：

```text
文字头像 + 昵称/username
```

账号菜单至少包含：

1. 当前用户信息。
2. 修改昵称入口。
3. 外观切换入口继续保留。
4. 退出登录。

修改昵称可以是弹窗或菜单内轻量表单，不需要单独页面。

视觉要求：

1. 不破坏 M9 左侧视觉。
2. 头像保持文字圆形头像。
3. 不做头像上传按钮。
4. 菜单不要过重，不要做成管理员后台。

### 4.5 图片入口移动

需要调整：

1. `ImageUploadButton` 从 `NoteEditor` 主工具栏移出。
2. 在更多菜单中增加“添加图片”菜单项。
3. 点击“添加图片”触发原有上传逻辑。
4. 原有上传校验、附件列表刷新、失败提示保持不变。

如果当前 `ImageUploadButton` 封装较重，可以保留组件，但以菜单项形式触发隐藏 input。

验收重点：

1. 主工具栏更简洁。
2. 窗口置顶位置更显眼。
3. 图片能力仍可用。
4. 窄屏没有新增跳变。

## 5. 数据安全要求

本轮虽然有 schema 小变更，但不能影响历史数据。

执行前：

1. 备份生产数据库。
2. `PRAGMA integrity_check = ok`。
3. 记录 User / Note / Attachment 数量。

执行后：

1. User 数量不异常减少。
2. Note 数量不变。
3. Attachment 数量不变。
4. `admin` 用户仍存在。
5. `admin` 下历史便签仍可见。
6. `displayName` / `avatarColor` 字段缺省不影响登录。

## 6. 验收标准

### 6.1 登录验收

必须通过：

1. 未登录访问首页进入登录页。
2. 错误密码提示清楚，但不暴露用户是否存在。
3. 正确账号密码登录成功。
4. 登录后看到历史便签。
5. 刷新后仍保持登录。
6. 退出登录成功。
7. 退出后访问 `/api/notes` 返回 401。
8. 退出后不能看到便签列表。
9. 已登录访问登录页自动回主页。

### 6.2 身份验收

必须通过：

1. 左下角显示当前用户。
2. 默认无昵称时显示 username。
3. 修改昵称后立即显示新昵称。
4. 刷新后昵称仍保留。
5. 文字头像随昵称/username 正常显示。
6. 修改 `avatarColor` 后刷新仍保留。
7. 空昵称不会导致页面空白或报错。

### 6.3 图片入口验收

必须通过：

1. 主工具栏不再直接显示图片按钮。
2. 窗口置顶按钮仍在主工具栏。
3. 更多菜单中有“添加图片”。
4. 通过更多菜单可以上传图片。
5. 旧图片仍能查看。
6. 图片删除仍可用。
7. 上传失败提示不退化。

### 6.4 回归验收

必须复测：

1. 新建普通便签。
2. 新建待办便签。
3. 编辑保存。
4. 搜索。
5. 归档/恢复。
6. 删除/回收站/永久删除。
7. 浮窗打开。
8. 亮色/暗色切换。
9. 390px/320px 窄窗工具栏不抖动。
10. 断网防丢保护实机复查。

## 7. 不通过标准

出现以下任一情况不能通过：

1. 登录后历史便签看不见。
2. 退出后仍能访问便签 API。
3. 昵称保存导致 `username` 或 `passwordHash` 被改坏。
4. 空昵称导致 UI 空白或报错。
5. 图片入口移动后无法上传图片。
6. 旧附件无法查看。
7. 工具栏重新出现明显跳变。
8. 为了账号菜单破坏 M9 左侧视觉。
9. 本轮混入注册、验证码、额度、管理员后台等非本轮范围。

## 8. 交付物要求

技术部交付时必须提供：

1. 改动文件清单。
2. schema 变更说明。
3. 数据库备份路径。
4. 迁移/`db push` 命令与结果。
5. User / Note / Attachment 数量前后对比。
6. 登录验收结果。
7. 身份展示验收结果。
8. 图片入口验收结果。
9. 390px/320px 截图或录屏。
10. 断网防丢复查结果。
11. 回退方案。

## 9. 回退方案

若出现历史数据不可见、登录阻塞、附件不可用等问题：

```text
停服务
恢复 M10.2 前数据库备份
回退 M10.2 代码
重新 build
重启服务
复查历史便签和附件
```

回退后必须确认：

1. `admin` 用户仍可登录。
2. 历史 Note 数量恢复。
3. 历史 Attachment 数量恢复。
4. 旧图片可打开。


M10.2 不确认：
