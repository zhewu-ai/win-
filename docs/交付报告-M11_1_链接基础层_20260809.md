# M11.1 交付报告：链接基础层（外部 URL 与内部便签链接）

日期：2026-08-09

## 一、交付内容

### P0 外部 URL 自动识别
- 正文输入 `https://…` / `http://…` / `www.…` 后，在**阅读模式**下渲染为蓝色可点击链接。
- `www.` 自动补 `https://` 前缀。
- URL 尾部的 ASCII/全角标点（`。，,．.；;：:！!？?、）)】」』"'”’`）不吞进链接，作为链接后的普通文本。
- 网页端点击新标签打开（`target="_blank" rel="noopener noreferrer"`）。
- 桌面壳点击转交系统默认浏览器（新增 `open_external` 命令，见下）。
- 不改变 `note.content` 原始文本存储格式，不破坏编辑/自动保存/离线/跨设备刷新。

### P0 内部便签链接
- 语法 `[[note:NOTE_ID|显示标题]]`，底层绑定 noteId，标题修改不影响打开。
- 编辑器「更多」菜单新增 **「插入便签链接」**（仅普通文本模式）：弹窗搜索当前用户未归档便签，选中后在正文**光标处**插入语法并更新光标；无光标信息（如处于阅读模式）则追加到末尾。
- **「阅读模式」**（仅普通文本模式）：正文切换为只读渲染视图，外部 URL 与内部链接均可点击；点击正文任意位置或再次点菜单项「返回编辑」回到编辑态。
- 点击内部链接在应用内打开目标便签：
  - 列表已有目标 → 直接选中。
  - 列表没有目标 → 调新增 `GET /api/notes/:id` 拉取，非归档便签 upsert 进列表并选中（搜索态下也会插入当前过滤列表，v1 接受）。
  - 目标已删除/无权限/不存在 → 链接变灰显示 `标题（已失效）`、禁用，不报错不跳空白页。
  - 目标已归档 → 不跳转，toast 提示「该便签已归档，可前往归档页查看」。

### 安全
- 全程无 `dangerouslySetInnerHTML`，链接解析输出结构化片段供组件安全渲染。
- 外部链接仅 http/https 落地为链接；`javascript:` 等按普通文本输出。
- noteId 格式校验（`[A-Za-z0-9_-]+`），禁止把任意 JS/HTML 当链接执行。
- `GET /api/notes/:id` 只允许当前用户自己的未删除便签（未登录 401，他人/已删除/不存在 404）。

## 四、说明与已知限制
- **光标落到链接后偶有回落**：插入时用 `requestAnimationFrame` 设置光标到链接后；若插入后立即有其他渲染/焦点变化（如对话框关闭抢焦），光标可能停在末尾。核心验收「在光标位置插入」满足；SPEC 允许无光标时插入末尾。
- **搜索态 fallback 插入**：搜索过滤下点击不在列表的链接，目标便签会被 upsert 进当前（过滤后的）列表，即使与搜索词不符——v1 接受，已报告。
- **失效链接不预校验**：不预先对每条链接发请求，点击失败才变灰（无多余网络开销）。
- **阅读模式仅主编辑器**：列表卡片、悬浮窗、归档页不渲染链接（v1 边界）。
- **桌面壳外部打开**：本机/生产未实机验证（无壳运行环境），依赖 CI 壳构建后验收；rust 代码已通过编译。
- 服务器存在历史 hydration mismatch（`useLayoutMode` 服务端/客户端窗口宽度差异导致，位于基础布局 div），与本次改动无关，为既有问题。
