# PinNote M10.9 复验反馈：下载页去 demo 化 + 左栏三点按钮视觉修正

日期：2026-08-07

## 1. 结论

M10.9 暂不通过，先不要进入 M10.10。

本轮复验发现两个需要先修的问题：

1. 左侧列表栏的横向三点选择按钮视觉太小，几乎像 1px 点，用户难以识别和点击。
2. 桌面版下载页 demo 感过强，暴露技术构建信息和旧品牌/旧版本口径，不适合作为真实内测用户看到的下载页面。

技术部先完成本反馈单，再提交 M10.9 复验报告。

## 2. 问题一：左侧三点选择按钮太小

### 2.1 当前问题

左侧列表栏顶部的横向三点入口已经替代了“选择”文字按钮，但当前三点视觉尺寸过小。

用户感受：

```text
每个点像只占 1px，视觉占比太小，不像一个可点击的操作入口。
```

这会导致：

1. 用户不知道这里能点。
2. 多选删除入口发现成本高。
3. 点击热区虽然可能够大，但视觉反馈不够。

### 2.2 目标效果

横向三点图标应参考编辑器右上角“更多操作”的视觉大小。

区别只是方向：

```text
编辑器更多操作：竖向三个点
左栏选择入口：横向三个点
```

两者视觉权重应接近，不能差太多。

### 2.3 修正要求

技术部需要调整：

1. 三个点本身要明显可见，不能像 1px 小点。
2. 图标整体视觉尺寸参考现有编辑器右上角更多操作按钮。
3. 按钮点击热区不小于 32 x 32。
4. hover/focus 状态要清楚。
5. `title` 或 tooltip 保持“选择便签”。
6. 与第一张便签卡片的间距仍保持收紧，不要恢复大空白。
7. 320px 宽度下不横向溢出。

建议实现：

1. 优先复用现有图标库的 `MoreHorizontal`。
2. 如果手写 SVG，圆点半径和间距要与现有 `MoreVertical` 风格一致。
3. 不要只靠 CSS `font-size` 渲染一个过小的省略号字符。

### 2.4 验收标准

1. 横向三点肉眼明显可见。
2. 与编辑器右上角“更多操作”按钮视觉大小接近。
3. 点击横向三点进入多选模式。
4. 多选删除功能不退化。
5. 左栏顶部空白仍比旧版“选择”按钮小。
6. 320px / 桌面宽度均无横向溢出。

## 3. 问题二：桌面版下载页 demo 感过强

### 3.1 当前问题

点击“下载桌面版”后进入的页面不像正式下载页，更像内部 demo / 构建说明页。

复验看到的问题包括：

1. 页面仍出现旧品牌口径，例如“全平台便签 V0.1.1”。
2. 页面赤裸裸展示“Windows 桌面可自动构建加载某网址”等技术说明。
3. 页面有过多修复记录、构建记录、内部工程信息。
4. 用户看不出这是一个正式的桌面客户端下载页。
5. 当前产品已经更新很多轮，但下载页没有体现现在的产品价值。

这些内容对内测用户不合适：

1. 暴露内部实现细节。
2. 降低信任感。
3. demo 感强。
4. 与现在产品名和产品阶段不一致。

### 3.2 产品口径

下载页应该面向用户，而不是面向开发者。

用户进入后应立刻知道：

1. 这是什么产品。
2. 桌面版能做什么。
3. 应该下载哪个安装包。
4. 安装后用同一账号登录，数据与网页同步。

不应该看到：

1. 构建流水线说明。
2. “加载某某线上网址”的技术描述。
3. 大段修复记录。
4. 旧品牌名。
5. demo / test / internal 字样。

## 4. 下载页改版要求

### 4.1 页面标题

统一使用当前产品名：

```text
PinNote
```

或：

```text
PinNote 桌面版
```

不要再使用：

```text
全平台便签 V0.1.1
```

除非产品侧确认这个名字仍对外使用。

### 4.2 首屏内容

建议文案：

```text
PinNote 桌面版

把重要便签固定在电脑桌面，随时记录待办、备忘和临时想法。
网页端和桌面端使用同一账号，数据自动同步。
```

主按钮：

```text
下载 Windows 版
```

次要链接：

```text
查看所有版本
```

### 4.3 功能简介

下载页可以简短展示 4 个点：

1. 桌面置顶：重要便签可以保持在桌面前方。
2. 同步数据：网页端和桌面端使用同一账号。
3. 待办和备忘：支持普通便签和待办清单。
4. 离线保护：网络不稳定时尽量保护未保存内容。

文案要面向用户，不要写工程实现。

### 4.4 下载说明

推荐下载：

```text
StickyNotes_0.1.0_x64-setup.exe
```

但按钮文案不要暴露文件名，按钮可以写：

```text
下载 Windows 安装包
```

页面底部可保留小字：

```text
适用于 Windows 10/11。安装后使用你的 PinNote 账号登录。
```

### 4.5 内部信息处理

以下内容必须移除或移到管理员/开发文档，不在用户下载页展示：

1. GitHub Actions 构建细节。
2. “加载线上网页 URL”的描述。
3. 修复记录流水账。
4. 内部验收批次。
5. demo/test/internal 口径。
6. 旧版本技术说明。

如果确实要保留版本历史，放到页面底部“版本说明”折叠区，并使用用户能理解的短句。

### 4.6 版本说明建议

可以写少量产品化版本说明，例如：

```text
近期更新

- 支持邀请制注册和账号管理
- 支持存储额度和头像设置
- 支持多选删除和回收站
- 支持用户反馈
- 打开便签查看不会打乱排序
```

不要把所有技术 commit 都搬上页面。

## 5. 下载入口链接策略

如果当前“下载桌面版”直接链接 GitHub Release 页面，而 Release 页面本身无法改造成产品化页面，则建议：

1. 新增站内下载说明页，例如：

```text
/download
```

2. 网页端账号菜单“下载桌面版”先进入 `/download`。
3. `/download` 页面再提供 GitHub Release / 安装包按钮。

这样用户先看到正式产品说明，而不是直接看到工程化 Release 页面。

如果技术部选择继续直达 GitHub Release，则必须至少把 Release 标题、说明文案、旧品牌和内部技术描述全部清理。

## 6. 验收标准

### 6.1 左栏三点按钮

1. 三点按钮视觉大小接近编辑器右上角更多操作按钮。
2. 肉眼可识别为“更多/选择”入口。
3. 点击热区不小于 32 x 32。
4. hover/focus 清晰。
5. 点击后进入多选模式。
6. 左栏顶部空白不明显。
7. 320px 不横向溢出。

### 6.2 下载页

1. 页面标题使用 `PinNote` 或 `PinNote 桌面版`。
2. 不出现“全平台便签 V0.1.1”等旧品牌口径。
3. 不出现“加载某网址”“自动构建”等内部技术描述。
4. 页面首屏像正式下载页，不像 demo。
5. 有简短产品简介。
6. 有清晰下载按钮。
7. 用户知道 Windows 桌面版的用途。
8. 用户知道网页端和桌面端同账号同步。
9. 下载按钮可正常打开 Release 或安装包。
10. 手机端如果能访问下载页，也不能出现横向溢出；但网页端下载入口仍只在电脑端显示。

### 6.3 回归

1. 账号菜单正常。
2. “反馈问题”入口正常。
3. “下载桌面版”入口仍只在电脑网页端显示。
4. Tauri App 内不显示下载入口。
5. 多选删除功能不退化。
6. `npm run build` 通过。

## 7. 交付物要求

技术部交付时必须提供：

1. 改动文件清单。
2. 左栏三点按钮前后对比截图。
3. 下载页改版后截图。
4. 下载页文本清单，确认无旧品牌/内部技术口径。
5. 下载链接 200 验证。
6. 320px 验收结果。
7. build 结果。
8. commit hash。
