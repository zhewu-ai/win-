## 一、结论

本轮 R3 不扩展工作日历功能，也不要影响正在进行的 M13 AI 排期导入返修。只处理以下体验问题：

1. 侧边栏“更多”按钮位置改错了。
2. 侧边栏收起动画被去掉了，需要恢复平滑过渡。
3. 日历宽度和整体尺度需要与现有便签工作台统一。

## 二、必须返修的问题

### 2.1 侧边栏“更多”按钮位置被误解

用户原意：

- 不是把“横向三个点 / 选择便签”按钮放到列表内容区上方。
- 是希望把这个按钮上移到侧边栏顶部搜索栏这一行。
- 具体位置：搜索框右侧现在有“收起侧边栏”的方向按钮，三个点按钮应放在方向按钮左边。
- 目的：省掉列表上方单独一行的空间，让左侧有效信息更靠上。

当前问题：

- 技术部把按钮放到了 NoteList 内部，形成了搜索框下面的一条独立小行。
- 这反而占用了更多纵向空间。
- 用户直观看到的是“后半截改了，搜索框下面多/空了一块”，没有达到节省空间的目标。

要求：

- 侧边栏顶部行应为：

```text
[ 搜索便签...                         ] [横向三个点] [收起侧边栏]
```

- “横向三个点”菜单继续承载：
  - 选择便签
  - 刷新
  - 后续可放其它低频操作
- 不要在 NoteList 列表内容顶部再单独渲染“更多”按钮行。
- 多选状态下可以隐藏搜索框，但多选工具条也应接管同一块顶部区域，不要在列表和搜索之间留下奇怪空白。

验收：

- 普通状态下，搜索栏右侧能看到横向三个点按钮。
- 横向三个点按钮位于收起侧边栏按钮左侧。
- 点击横向三个点能打开“选择便签 / 刷新”等菜单。
- 列表内容区顶部不再多出一行仅放三个点按钮的空白。
- 320px/390px 下顶部不拥挤、不横向溢出。

### 2.2 恢复侧边栏收起/展开动画

当前问题：

- 上一轮把侧边栏宽度/透明度过渡去掉了。
- 用户体验上从原来的平缓过渡变成直接“咔”一下消失。
- 这是反向修改，降低了质感。

要求：

- 恢复侧边栏收起/展开的平滑动画。
- 动画目标是“自然、轻、不会卡顿”，不是夸张动效。
- 如果之前存在双栏/单栏宽度切换冻结 bug，应修 bug，而不是直接取消所有过渡。
- 可以采用更稳的技术方案，例如：
  - 外层固定布局槽位，内层做 `transform` / `opacity`。
  - 双栏只动画 `width: 350px -> 0`，单栏切换避免跨断点同帧过渡。
  - 使用独立状态区分“正在收起动画”和“布局已隐藏”。

验收：

- 双栏模式点击收起侧边栏，侧边栏平滑收起，不是瞬间消失。
- 点击展开条，侧边栏平滑展开。
- 单栏模式进入便签/日历时不出现 350px 卡住、闪烁或白屏。
- 动画期间右侧内容不明显抖动。

### 2.3 日历宽度和便签工作台尺度统一

当前问题：

- 日历内部设置了固定的最小宽度，但视觉上和便签/待办的整体尺度不够统一。
- 用户希望日历的宽度大小与其他内容保持一致，不要显得像另一个尺度系统。

要求：

- 在不破坏日历可读性的前提下，统一工作日历与便签/待办的空间尺度。
- 日历的左右 padding、主体最大/最小宽度、卡片/格子间距应与现有工作台风格一致。
- 日历内部最小列宽只允许作用在日历网格内部，不得撑坏全局布局。
- 320px/390px 下可以让日历网格内部横向滚动，但外层页面不能横向溢出。

验收：

- 切换便签、待办、工作日历时，右侧主工作区的视觉宽度和留白节奏一致。
- 月视图日期格仍可读。
- 320px/390px 下没有全局横向滚动。
- 720px/1440px 下日历不显得过宽、过挤或与便签编辑器尺度割裂。

### 2.4 便签/待办最小宽度下顶部工具栏隐藏

用户原意：

- 窗口缩到最小时，用户主要目的是看清标题和待办事项。
- 顶部工具栏在最小宽度下一直显示，会占用空间并增加心智干扰。
- 希望在便签/待办最小化程度下，也能像日历窄宽专注模式一样，把顶部收起来。

当前状态判断：

- 这不是完全做不了。
- 现有 NoteEditor 已经有按编辑区宽度切换 `spacious / compact / minimal` 的工具栏分档。
- 但目前只是把部分按钮收进更多菜单，没有把整条顶部工具栏收起成极简栏。

要求：

- 技术部先评估并尽量实现“便签/待办窄宽专注模式”。
- 只在编辑区宽度低于阈值时触发，例如 380px 或 420px，具体阈值由实测决定。
- 默认隐藏或压缩顶部工具栏，只保留最必要入口：
  - 返回列表（单栏需要）
  - 标题/状态的必要提示
  - 一个展开按钮
- 用户 hover、点击展开按钮或触碰顶部区域时，再显示完整工具栏。
- 不要影响正常宽度下的便签/待办编辑体验。

如果技术部认为暂不适合做，必须说明原因：

- 是因为会影响保存状态展示？
- 是因为会影响图片/颜色/置顶/删除入口？
- 是因为单栏返回路径有风险？
- 是因为当前工具栏状态机需要重构？

不能只回复“做不了”。

验收：

- 便签在最小宽度下，正文/标题区域获得更多可用高度。
- 待办在最小宽度下，列表内容更靠上，不被整条工具栏长期占用。
- 用户仍能通过展开按钮访问颜色、刷新、置顶、图片、归档、删除等操作。
- 保存中/保存失败状态仍可被用户感知。
- 正常宽度下原有工具栏不退化。

### 2.5 M13 AI 排期返修不得被本轮 M12 改动打断

### 2.5 左侧列表选中后不应自动跳回顶部

现象：

- 随着便签/文档越来越多，用户会滚动到左侧列表很底部去找某个文档。
- 点击底部文档后，右侧编辑区确实打开了对应文档。
- 但左侧列表会突然跳回最顶部。
- 结果是用户失去当前浏览位置，无法继续在底部附近看相邻文档。

用户预期：

- 选中某个文档后，右侧编辑区打开该文档。
- 左侧列表的滚动位置应该停在用户刚刚点击的位置附近。
- 被选中的文档仍应保持可见，列表不应自动回到顶部。

可能原因方向：

- 选中便签后 `NoteList` 或外层 `Sidebar` 被重新挂载，导致滚动容器重置。
- 选中态、日历态或分组数据重算导致列表 DOM 结构被整体替换。
- 搜索框/多选栏/日历分组显示状态变化，触发布局复位。
- 某处在选中后主动执行了 `scrollTo(0, 0)` 或类似逻辑。
- `key` 使用不稳定，导致 React 认为列表是新组件。

要求：

- 点击任意位置的便签/待办后，左侧列表滚动位置必须保持。
- 只允许在明确用户操作时回到顶部，例如：
  - 用户清空/改变搜索条件。
  - 用户切换列表大类。
  - 用户主动点击“回到顶部”。
- 普通选中、切换右侧编辑内容、从工作日历返回便签，不应重置左侧滚动位置。
- 如果必须重排列表，也应在重排后恢复到原 scrollTop 或让选中项仍可见。

验收：

- 准备足够多的便签，让左侧列表可以滚动到很底部。
- 滚到底部，点击底部某条便签。
- 右侧打开该便签后，左侧列表仍停留在底部附近。
- 连续点击底部附近多条便签，列表不跳到顶部。
- 点击工作日历再返回便签，列表也不无故跳回顶部。
- 320px/390px 单栏模式下同样不出现选中后滚动位置丢失。

### 5.2 逐条验收结果

**2.1 三个点按钮上移搜索行** ✅

- 顶部行为 `[搜索便签...] [⋮] [收起侧边栏]`，三点按钮位于搜索框右侧、收起按钮左侧（CDP 实测 class 归属搜索行，且全页仅 1 个 `aria-label="更多操作"`）。
- 点击打开「选择便签 / 刷新」菜单；多选态隐藏搜索框、多选工具条接管顶部区域，取消后搜索框恢复。
- NoteList 列表内容区顶部不再有多余独立行。
- 320/390 下无横向溢出（`document.documentElement.scrollWidth <= innerWidth`）。

**2.2 恢复侧边栏收起/展开动画** ✅

- 双栏模式点击收起，侧边栏宽度平滑过渡：CDP 采样 `350 → 305 → 175 → 81 → 5 → 0`（约 240ms，与 `width 200ms ease-in-out` 一致），非瞬间消失，无冻结。
- 单栏模式进入便签/日历不出现 350px 卡住/白屏（此前 R1 §9.6 冻结 bug 通过「双栏才启用过渡 + 模式切换首帧禁用」规避）。

**2.3 日历宽度与便签工作台统一** ✅

- 月/周/今日视图统一 `max-w-[1000px] mx-auto`，1440 双栏下日历主体 1000px（编辑区约 1090px，按预期封顶），留白节奏与便签编辑器一致。
- 月视图网格 `min-w-[560px]` 仅在日历内部 `overflow-x-auto` 滚动；320/390 下全局无横向滚动（`scrollWidth === innerWidth`），日历内部可横向滚动。
- 日历主体 padding 用 `clamp(10px,3vw,36px)`，与工作台尺度衔接。

**2.4 便签/待办窄宽专注模式** ✅

- 编辑区宽度 <420px 时触发（实测阈值），整条工具栏收起为极简条：返回（单栏）/ 标题 / 保存状态（无文字图标态）/ 展开按钮。
- 390px 与 320px 单栏打开便签：极简条显示（`展开工具栏` 存在、`刷新便签` 隐藏）；点展开 → 完整工具栏 + 收起按钮；保存中/失败状态仍可感知。
- 1440px 双栏：完整工具栏（刷新/颜色/置顶等）不变。
- 720px 为双栏边界（`innerWidth < 720` 才算单栏），编辑区约 370px，按编辑区宽度判定进入极简条，符合「按编辑区宽度」触发原则。

**2.5 左侧列表选中不跳顶** ✅

- 防御性实现：点击便签前记录列表滚动容器 `scrollTop`，选中后若容器被意外重置为 0 则恢复；仅在确实重置且有滚动时生效，不与用户主动滚动到顶部冲突。
- CDP 实测（44 条便签使列表可滚动到底部）：
  - 1440 双栏：滚到底点底部便签，`scrollTop` 保持 6693（= 最大滚动值）。
  - 1440 双栏：连续点击底部 4 条便签，`scrollTop` 稳定 6693。
  - 1440 双栏：打开工作日历再返回便签，`scrollTop` 6693→6691（渲染差异 2px，无跳顶）。
  - 390 单栏：滚到底点底部 3 条便签，`scrollTop` 稳定 7144（= 最大滚动值）。
  - 390 单栏：打开工作日历后关闭，`scrollTop` 7370→6795（= 最大滚动值，保持底部）。
