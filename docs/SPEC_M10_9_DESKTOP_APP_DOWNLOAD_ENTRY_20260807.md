# PinNote M10.9 桌面应用下载入口 + 左栏选择按钮微调

日期：2026-08-07

## 1. 背景

当前 Windows 桌面应用安装包已经发布在 GitHub Release，但入口分散在历史聊天和验收文档里。内测用户如果不知道下载地址，就很难自行安装桌面端。

本轮增加两个很轻的网页端体验修正：

1. 增加桌面应用下载入口，只在电脑网页端显示。
2. 优化左侧列表栏“选择”入口，减少按钮下方空白，改为更轻的横向三点图标。

## 2. 当前下载信息

现有文档记录：

```text
Release 页：
https://github.com/zhewu-ai/win-/releases/tag/v0.1.0

推荐安装包：
StickyNotes_0.1.0_x64-setup.exe

备选：
StickyNotes_0.1.0_x64_en-US.msi
```

如果技术部后续更新 Release 版本，应同步更新本入口配置和交付报告。

## 3. 本轮目标

M10.9 做五件事：

1. 在电脑网页端增加一个“小的下载桌面版”入口。
2. 手机网页端隐藏该入口。
3. 下载链接指向当前 Windows 安装包 Release 页或推荐安装包。
4. 将左侧列表栏“选择”按钮改为横向三点图标入口。
5. 收紧选择入口与下方便签卡片之间的垂直间距。

## 4. 本轮不做

明确不做：

1. 不做手机 App 下载入口。
2. 不做 Mac App 下载入口，除非已有真实安装包。
3. 不做自动检测系统后直接下载不同安装包。
4. 不做应用内自动更新。
5. 不重新打包 Windows 安装包。
6. 不做大横幅、弹窗、营销页。
7. 不影响登录、注册、便签编辑、反馈工单。
8. 不重做左侧列表整体布局。
9. 不改变多选删除功能逻辑。
10. 不改变便签卡片视觉样式。

## 5. 功能一：桌面应用下载入口

### 5.1 展示位置

推荐位置：账号菜单底部，靠近“反馈问题 / 退出登录”附近。

显示文案：

```text
下载桌面版
```

也可以显示更明确：

```text
下载 Windows 版
```

入口样式：

1. 小号文本按钮或菜单项。
2. 可带下载图标。
3. 不使用醒目主按钮。
4. 不使用弹窗强推。

### 5.2 设备显示规则

只在电脑网页端显示。

建议条件：

1. CSS 层：`hidden sm:flex` 或更保守 `hidden md:flex`。
2. JS 层：如需要，判断 `window.innerWidth >= 768`。
3. Tauri 桌面壳内不显示，避免已在 App 内还提示下载 App。

Tauri 判断可复用现有：

```ts
isTauri()
```

规则：

| 环境 | 是否显示 |
|---|---|
| 桌面浏览器 Web | 显示 |
| 手机浏览器 Web | 不显示 |
| Windows Tauri App | 不显示 |
| 窄窗口桌面浏览器 | 可隐藏，避免挤占空间 |

### 5.3 链接策略

优先使用 Release 页：

```text
https://github.com/zhewu-ai/win-/releases/tag/v0.1.0
```

原因：

1. Release 页能看到所有安装包。
2. 如果资产名变化，用户仍可找到最新文件。
3. 比硬编码 exe 资产链接更不容易失效。

如果技术部选择直连推荐安装包，交付报告必须写明具体 URL，并验证 200。

### 5.4 可维护配置

不要把下载 URL 散落在多个组件里。

建议新增常量：

```ts
export const DESKTOP_APP_DOWNLOAD_URL =
  "https://github.com/zhewu-ai/win-/releases/tag/v0.1.0";
```

可放在：

```text
src/lib/downloads.ts
```

或同等的配置文件。

## 6. 功能二：左栏选择按钮微调

### 6.1 当前问题

M10.8 增加左侧列表多选删除后，列表栏顶部的“选择”按钮下方留白偏大，和第一张便签卡片之间形成明显空隙。

这个入口本身是低频操作，不应该占太多垂直空间。

### 6.2 调整目标

将“选择”文字按钮简化为横向三个点图标按钮：

```text
…
```

或使用 lucide/现有图标库里的横向更多图标：

```text
MoreHorizontal
```

要求：

1. 图标按钮尺寸控制在 28-32px。
2. 放在左侧列表顶部右侧，和搜索/标题区域对齐。
3. 不再单独占一整行大按钮。
4. 与下方第一张便签卡片的间距收紧到 8px 左右。
5. hover/focus 时有轻微背景反馈。
6. tooltip 或 `title` 写“选择便签”。

### 6.3 交互

点击横向三点图标后：

1. 进入多选模式。
2. 每条便签显示 checkbox。
3. 顶部显示已选择数量和删除/取消操作。

退出多选模式后：

1. 回到横向三点图标入口。
2. 不保留选中状态。

### 6.4 响应式

桌面和手机网页都可以显示该图标，因为多选删除是网页功能，不是桌面 App 下载入口。

要求：

1. 320px 宽度下图标不能挤压搜索框或标题。
2. 不产生横向滚动。
3. 点击热区不能小于 28px。

## 7. 验收标准

### 7.1 下载入口验收

1. 桌面浏览器登录后可看到“下载桌面版”或“下载 Windows 版”入口。
2. 入口尺寸较小，不抢占主操作。
3. 点击后新标签打开 Release 页。
4. 手机 320px/390px 宽度下不显示该入口。
5. Windows Tauri App 内不显示该入口。
6. 入口不遮挡账号菜单、反馈、退出登录。

### 7.2 链接验收

1. Release 页返回 200。
2. 页面包含 `StickyNotes_0.1.0_x64-setup.exe` 或当前推荐安装包。
3. 如果使用直连下载，直连 URL 返回 200，文件名正确。

### 7.3 左栏选择按钮验收

1. 左侧列表顶部不再显示占整行的“选择”大按钮。
2. 显示横向三点图标入口。
3. 图标 `title` 或 tooltip 为“选择便签”。
4. 点击图标进入多选模式。
5. 多选删除功能不退化。
6. 图标与第一张便签卡片之间的间距明显小于旧版，目标约 8px。
7. 320px 宽度下不横向溢出。

### 7.4 回归验收

1. 登录页正常。
2. 首页便签列表正常。
3. 账号菜单正常。
4. 反馈入口正常。
5. 管理员入口正常。
6. 手机网页无横向溢出。
7. `npm run build` 通过。

## 8. 交付物要求

技术部交付时必须提供：

1. 改动文件清单。
2. 下载 URL。
3. 桌面显示验收截图或 DOM 结果。
4. 手机隐藏验收结果。
5. Tauri App 内隐藏验收结果，若本地无法跑 Tauri，需要写明未验证并列入 Windows 实机验收。
6. Release 链接 200 验证。
7. 左栏三点图标入口截图或 DOM 验收结果。
8. 三点图标进入多选模式验收结果。
9. 320px 左栏无横向溢出验收结果。
10. build 结果。
11. commit hash。

```

```
