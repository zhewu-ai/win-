# 全平台便签 M8.5 稳定感打磨规格与验收标准

日期：2026-08-06

## 1. 背景

当前全平台便签的核心功能已经基本满足用户真实工作流：

- 普通便签可用。
- 待办清单可用。
- Windows 壳可置顶。
- 小窗口可缩放。
- 右键菜单、回收站、图片、复制一份等基础能力已经逐步补齐。

但深度使用后，横向缩放和局部响应式细节仍显得“不稳”：

- 窗口横向缩放时，侧边栏会突然收起，右侧内容瞬间变宽。
- 工具栏按钮会分多次变化：文字竖排、色球折叠、保存状态变点、更多按钮横移。
- 滚动条出现/消失时，列表卡片宽度会跳一下。
- 滚动条视觉像浏览器默认样式，削弱桌面 App 质感。

M8.5 的目标不是增加新功能，而是让软件在横向缩放、滚动、工具栏收纳时更稳定、更像成熟桌面应用。

## 2. 本轮目标

M8.5 只做“稳定感打磨”：

1. 横向缩放过程中界面不突然跳变。
2. 工具栏始终稳定，不出现文字竖排、按钮掉行、图标横跳。
3. 侧边栏不自动突然收起，改为用户可控。
4. 滚动条出现/消失不影响内容宽度。
5. 滚动条视觉更像桌面 App，不像浏览器默认控件。
6. 暗色模式先打磨到稳定版本。

## 3. 本轮不做

1. 不做邮箱注册/账号系统。
2. 不做多用户权限。
3. 不做亮色模式实现。
4. 不做复杂富文本。
5. 不做 Mac 壳。
6. 不做离线同步。
7. 不做新的图片大功能。

亮色模式只保留现有评估，不进入本轮实现。账号系统放到 M9。

## 4. 当前主要问题

### 4.1 横向缩放时侧边栏突然自动收起

用户现象：

- 从宽窗口往窄窗口拖动。
- 到某个宽度时，左侧侧边栏突然自动收起。
- 右侧详情区瞬间变宽，画面“蹭一下”变化。

产品判断：

这是最明显的不稳定来源之一。成熟桌面 App 通常不会在用户拖动过程中突然自动重排大结构，除非进入明确的移动端模式。

产品要求：

- 宽屏/桌面壳环境下，侧边栏不要因窗口宽度变化突然自动收起。
- 侧边栏折叠应由用户主动点击按钮触发。
- 如果确实需要在极窄宽度进入单栏模式，也要有明确阈值，并避免拖动中反复来回切换。

建议规则：

1. 桌面壳和桌面 Web 下：
   - 默认显示侧边栏。
   - 提供手动折叠按钮。
   - 折叠状态本地持久化。
2. 极窄窗口下：
   - 可以进入单栏模式，但阈值必须少且稳定。
   - 不要在多个相近宽度间反复切换。
3. 侧边栏宽度变化使用平滑 transition，但不要影响正文输入光标和滚动位置。

验收标准：

1. 从 1200px 缩到 700px，侧边栏不突然自动消失。
2. 点击折叠按钮后，侧边栏收起；再次点击恢复。
3. 折叠/展开后刷新或重开 App，状态按设计保持。
4. 收起侧边栏时，当前便签不丢失选择状态。

### 4.2 工具栏响应式断点太多，横向缩放时多次跳动

用户现象：

横向收窄时会出现多次顿挫：

1. “便签/待办”两个字从横排变竖排。
2. 色球突然折叠成一个按钮。
3. “已保存”突然变成一个点。
4. 更多按钮横移。
5. 继续收窄时，色球/图标又颤动。

产品判断：

这不是功能问题，而是响应式规则过碎。每个控件各自用断点切换，导致拖动窗口时多处独立变化，整体显得轻飘、不稳定。

产品要求：

- 工具栏必须像一整块稳定控件，而不是多个控件各自乱跳。
- 不允许“便签/待办”文字竖排。
- 不允许删除/归档等按钮掉到第二行。
- 不允许保存状态、颜色、更多按钮在拖动中频繁横移。

推荐工具栏分级：

### A. 宽布局

宽度充足时显示：

```text
返回 | 便签/待办 | 颜色 | 保存状态 | 图片 | 窗口置顶 | 更多
```

低频动作放进“更多”：

- 删除
- 归档
- 便签置顶
- 颜色更多选项，如果颜色已折叠

### B. 中布局

不要让各控件分散切换。到达一个明确阈值后，整体进入中布局：

```text
返回 | 模式图标 | 颜色按钮 | 保存状态短文案/固定区 | 图片 | 置顶 | 更多
```

### C. 窄布局

窄布局从一开始就图标化，不要等文字被挤成竖排：

```text
返回 | 模式图标 | 颜色按钮 | 保存点位 | 图片 | 置顶 | 更多
```

要求：

- 三种布局最多 2 个切换点。
- 每个切换点要整体切换，不要控件一个个跳。
- 颜色区域要么完整色球，要么一个颜色按钮，不要在接近阈值时来回颤动。
- 保存状态区域预留固定宽度，避免“已保存”变点导致右侧按钮横移。

验收标准：

1. 从 900px 缩到 260px，工具栏最多发生 2 次明显布局切换。
2. “便签/待办”文字不会竖排。
3. 工具栏始终单行。
4. 删除、归档、便签置顶等低频动作在窄宽度进入“更多”菜单。
5. 保存状态变化不会推动右侧图标横移。
6. 连续拖动窗口时，颜色按钮/色球不颤动。

### 4.3 滚动条出现/消失导致内容宽度跳动

用户现象：

- 竖向拉伸到某个高度后，右侧滚动条突然消失。
- 滚动条消失后，左侧选中卡片的彩色背景/宽度会跳一下。

产品判断：

这是典型的滚动条 gutter 问题。滚动条占用宽度时，内容区域宽度发生变化；滚动条消失后，内容变宽，所以选中卡片会跳。

产品要求：

- 滚动条出现或消失时，内容宽度不要变化。
- 列表卡片、编辑内容、选中背景不能因为滚动条状态跳动。

技术建议：

1. 使用 `scrollbar-gutter: stable;` 或等价方案。
2. 对主要滚动容器统一设置稳定 gutter：
   - 便签列表
   - 编辑器正文
   - 回收站列表
   - 归档列表
3. 如果 WebView/浏览器支持不一致，使用固定内边距或 overlay scrollbar 策略兜底。

验收标准：

1. 便签列表滚动条出现/消失时，选中卡片宽度不跳。
2. 编辑器滚动条出现/消失时，正文行宽不跳。
3. Windows 壳内实机验证通过。

### 4.4 滚动条视觉太像浏览器默认控件

用户现象：

- 当前滚动条像 Windows 浏览器默认滚动条。
- 桌面 App 感不足。

产品要求：

- 滚动条要弱化、现代、简洁。
- 不要高对比、不要厚重、不要像浏览器默认控件。
- 暗色模式下使用低对比灰色。

建议样式：

- 宽度：6px 或 8px。
- track：透明。
- thumb：
  - 默认 `rgba(255,255,255,0.12)` 或接近当前设计 token 的低对比灰。
  - hover 时略亮。
  - 圆角。
- 非滚动时可弱显示，但不要导致布局宽度变化。

验收标准：

1. Windows 壳内滚动条不再像浏览器默认厚重控件。
2. 列表、编辑器、回收站、归档页面滚动条风格一致。
3. 滚动条 hover/拖动反馈清楚。
4. 不影响滚动性能。

### 4.5 侧边栏折叠与移动端/窄窗口逻辑需要统一

用户需求：

- 侧边栏可以像其他桌面 App 一样手动收起。
- 默认展开，但可以一键收起，给编辑区更多空间。

产品要求：

- 侧边栏折叠是用户主动行为，不是横向拖动时突然发生。
- 折叠后仍有明确入口恢复。
- 当前选择的便签状态不丢。
- 不影响移动端/窄窗口已有返回列表逻辑。

建议：

- 在侧边栏顶部或编辑器左上角提供“侧边栏”图标按钮。
- 宽屏时：按钮控制侧边栏折叠/展开。
- 窄屏时：仍沿用列表/详情单页切换，不强行显示双栏。
- 折叠状态保存在 localStorage。

验收标准：

1. 宽屏下可手动收起/展开侧边栏。
2. 收起时编辑区扩展，当前便签保持。
3. 展开后列表仍选中当前便签。
4. 重开 App 后折叠状态符合设计。

## 5. 设计原则

### 5.1 少断点，少跳变

禁止每个控件各自定义一套断点，导致缩放时连续跳动。

建议：

- 用 2 个核心断点控制整体布局。
- 控件内部只做必要微调。

### 5.2 稳定占位

会发生内容变化的区域必须预留稳定空间：

- 保存状态。
- 更多菜单按钮。
- 颜色入口。
- 置顶按钮。

不要让“文字变图标”时推动其他按钮。

### 5.3 工具栏单行

工具栏不能自动变两行。空间不足时：

- 低频项进更多菜单。
- 文案变图标。
- 不重要状态弱化。

但整体高度必须稳定。

### 5.4 桌面壳优先

M8.5 的最终验收以 Windows 壳为准。浏览器端通过只能算初步验证。

## 6. 推荐实施批次

### 第 1 批：布局稳定

1. 侧边栏取消横向缩放自动收起。
2. 增加手动折叠/展开。
3. 工具栏断点合并，最多 2 个整体切换点。
4. 工具栏单行化，更多菜单收纳低频项。

### 第 2 批：滚动稳定

1. 主要滚动容器增加稳定 gutter。
2. 选中卡片不因滚动条出现/消失跳动。
3. 统一滚动条视觉。

### 第 3 批：Windows 实机验收

1. Windows 壳横向缩放录屏。
2. 滚动条出现/消失录屏。
3. 侧边栏折叠/展开录屏。
4. 工具栏窄宽度录屏。

## 7. 验收标准

### 7.1 横向缩放验收

验收人录屏：

1. 从 1200px 宽慢慢拖到 260px。
2. 再从 260px 慢慢拖回 1200px。

必须满足：

- 侧边栏不突然自动消失。
- 编辑区不突然蹭一下变宽。
- 工具栏不出现按钮掉行。
- “便签/待办”文字不竖排。
- 色球/颜色入口不颤动。
- 保存状态变化不推动按钮横移。
- 更多按钮位置稳定。

### 7.2 侧边栏验收

1. 宽屏下点击折叠按钮，侧边栏收起。
2. 再点击，侧边栏展开。
3. 当前便签仍然选中。
4. 重开 App 后状态按设计恢复。

### 7.3 工具栏验收

1. 900px、520px、360px、260px 四个宽度截图。
2. 每个宽度下工具栏都是一行。
3. 低频操作在窄宽度进入更多菜单。
4. 删除、归档等操作仍可执行。

### 7.4 滚动条验收

1. 便签列表内容少到多，触发滚动条出现。
2. 再调整高度，让滚动条消失。
3. 选中卡片宽度不跳。
4. 编辑器滚动条出现/消失，正文不跳。
5. 滚动条视觉统一、轻量。

### 7.5 Windows 壳验收

必须在 Windows App 内录屏，不接受只用 Mac 浏览器证明：

1. 横向缩放全过程。
2. 工具栏窄宽度表现。
3. 侧边栏折叠/展开。
4. 滚动条出现/消失。
5. 置顶能力回归，确认未被本轮改坏。

## 8. 技术部交付证据

1. `npm run build` 通过。
2. Windows 壳构建通过。
3. Windows 实机录屏：
   - 横向缩放 1200px -> 260px -> 1200px。
   - 侧边栏折叠/展开。
   - 滚动条出现/消失。
4. 四档截图：
   - 900px
   - 520px
   - 360px
   - 260px
5. 说明本轮减少了哪些断点、哪些控件进入更多菜单、哪些滚动容器加了稳定 gutter。

## 9. 通过标准

M8.5 通过标准：

> 横向拖动窗口时，界面像成熟桌面 App 一样稳定：侧边栏不突然消失，工具栏不跳、不掉行、不竖排，滚动条不导致内容宽度变化，整体没有轻飘飘的网页感。

如果缩放过程中仍出现多次明显顿挫、按钮颤动、滚动条导致宽度跳动，本轮不通过。

## 10. 后续路线

M8.5 通过后，再进入：

1. M9：账号系统。
2. M10：亮色模式或主题能力。

不要在 M8.5 中混入账号系统或亮色模式实现。
