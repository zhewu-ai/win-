# PinNote M10.10 内测运营与新手引导：归档/回收站批量操作、手动公告、删除废用户、示例便签

日期：2026-08-07

## 1. 背景

M10.8/M10.9 后，PinNote 已经进入真实内测阶段。当前重点不应只是继续加编辑器功能，而是补齐内测运营能力：

1. 用户在归档和回收站里也需要批量处理便签。
2. 更新公告不能由 AI 自动生成和发布，必须由管理员手动编辑后发布。
3. 管理员需要删除明显无效的废账号，而不是只能禁用。
4. 新用户第一次进入应用时，需要有少量示例便签帮助理解产品价值。

本轮是内测运营补强，不做大规模权限系统或复杂 CMS。

## 2. 本轮目标

M10.10 做四件事：

1. **归档/回收站批量操作**：归档页、回收站页也支持多选；入口统一使用横向三点图标。
2. **管理员手动公告栏**：管理员手写更新公告并发布；用户首次看到新公告时弹窗；管理员能看到阅读人数。
3. **管理员删除废用户**：管理员可删除无效/废弃用户，但必须有严格保护条件和二次确认。
4. **新用户示例便签**：新注册用户首次进入时自动获得少量示例便签，教用户怎么用备忘录和待办。

## 3. 本轮不做

明确不做：

1. 不让 AI 自动生成或自动发布公告。
2. 不做富文本公告编辑器。
3. 不做公告评论。
4. 不做复杂用户行为分析平台。
5. 不做批量永久删除所有用户数据的危险后台。
6. 不做导入外部模板市场。
7. 不做手机 App 引导。
8. 不改变 M10.9 的横向三点图标要求。

## 4. 功能一：归档/回收站批量操作

### 4.1 统一入口

M10.9 已要求首页左侧列表“选择”入口改为横向三点图标。

M10.10 要求归档页和回收站页也采用同样入口：

```text
MoreHorizontal / 横向三个点
```

要求：

1. 图标按钮尺寸 28-32px。
2. `title` 或 tooltip 为“选择便签”。
3. 不再使用占整行的“选择”按钮。
4. 与第一张卡片间距约 8px。
5. 320px 宽度下不横向溢出。

### 4.2 归档页批量操作

归档页支持：

1. 多选归档便签。
2. 批量取消归档。
3. 批量删除到回收站。

删除仍然是软删除：

```text
deletedAt = now
```

确认文案：

```text
确定将选中的 X 条归档便签移入回收站？
```

取消归档确认文案：

```text
确定将选中的 X 条便签移回列表？
```

### 4.3 回收站页批量操作

回收站页支持：

1. 多选回收站便签。
2. 批量恢复。
3. 批量永久删除。

永久删除是危险操作，必须二次确认。

第一层确认：

```text
确定永久删除选中的 X 条便签？此操作不可恢复。
```

第二层确认：

```text
请输入 DELETE 确认永久删除。
```

只有输入 `DELETE` 才允许执行。

### 4.4 API

建议新增：

```text
POST /api/notes/bulk-archive
POST /api/notes/bulk-restore
POST /api/notes/bulk-permanent-delete
```

或按现有风格拆成：

```text
POST /api/notes/archive/bulk
POST /api/notes/trash/bulk-restore
POST /api/notes/trash/bulk-permanent
```

技术部可按现有路由风格选择，但交付报告必须写明最终路径。

所有批量 API 要求：

1. 必须按当前 `session.userId` 限定。
2. 单次最多 100 条。
3. 重复 id 去重。
4. 不属于当前用户的 id 返回 `notFoundIds`，不能泄露他人数据。
5. 部分成功允许返回 `processedIds` + `notFoundIds`。

### 4.5 回收站永久删除的数据释放

批量永久删除必须复用单条永久删除的安全逻辑：

1. 删除 Note。
2. 删除 Attachment 数据。
3. 删除附件文件。
4. 释放 `storageUsedBytes`。
5. 不留下孤儿文件。
6. 不影响其它用户附件。

## 5. 功能二：管理员手动公告栏

### 5.1 产品原则

更新公告不能由 AI 自动发布。

原因：

1. AI 可能误解改动。
2. AI 可能写出不准确或引发误会的描述。
3. 更新公告是面向真实用户的产品沟通，必须由管理员确认。

本轮公告必须是：

```text
管理员手写 -> 管理员点击发布 -> 用户看到
```

### 5.2 管理员入口

新增后台页面：

```text
/admin/announcements
```

管理员菜单中新增：

```text
更新公告
```

### 5.3 数据模型

建议新增：

```prisma
model Announcement {
  id          String   @id @default(cuid())
  title       String
  content     String
  version     String?
  status      String   @default("draft")
  publishedAt DateTime?
  createdById String
  createdAt   DateTime @default(now())
  updatedAt   DateTime @updatedAt

  createdBy User @relation(fields: [createdById], references: [id])
  reads     AnnouncementRead[]

  @@index([status])
  @@index([publishedAt])
}

model AnnouncementRead {
  id             String   @id @default(cuid())
  announcementId String
  userId         String
  readAt         DateTime @default(now())

  announcement Announcement @relation(fields: [announcementId], references: [id])
  user         User         @relation(fields: [userId], references: [id])

  @@unique([announcementId, userId])
  @@index([userId])
}
```

允许状态：

```text
draft
published
archived
```

### 5.4 管理员功能

管理员可以：

1. 新建公告草稿。
2. 编辑草稿标题和正文。
3. 填写版本号，例如 `M10.10`。
4. 发布公告。
5. 归档旧公告。
6. 查看阅读统计。

阅读统计至少包含：

1. 应看到人数：当前 active 用户数。
2. 已读人数：`AnnouncementRead` 去重用户数。
3. 未读人数。
4. 阅读率。
5. 可展开查看已读用户列表。

### 5.5 用户侧弹窗

用户登录后检查最新 `published` 公告。

如果当前用户没有对应 `AnnouncementRead`：

1. 弹出公告弹窗。
2. 用户点关闭 / 知道了 / 叉号时，记录为已读。
3. 之后不再弹同一条公告。

弹窗规则：

1. 不强制用户停留。
2. 不阻塞继续使用。
3. 320px 不横向溢出。
4. 公告内容只显示管理员写入文本，不做 AI 改写。

### 5.6 API

建议：

```text
GET /api/announcements/latest
POST /api/announcements/:id/read
GET /api/admin/announcements
POST /api/admin/announcements
PATCH /api/admin/announcements/:id
POST /api/admin/announcements/:id/publish
POST /api/admin/announcements/:id/archive
```

管理员 API 必须 `requireAdmin()`。

## 6. 功能三：管理员删除废用户

### 6.1 使用场景

内测阶段可能出现用户用废邮箱、随便注册、重复注册。管理员需要清理这些无效账号，避免用户列表长期堆积。

### 6.2 删除原则

用户删除是高风险操作，必须严格限制。

默认允许删除的用户：

1. 非 admin。
2. 当前不是登录管理员本人。
3. 用户已经 disabled。
4. 用户没有便签、附件、反馈、公告已读等业务数据。

如果用户已有业务数据，本轮默认不允许硬删除，建议只禁用。

错误文案：

```text
该用户已有数据，不能直接删除。请先禁用保留数据。
```

### 6.3 可选清理策略

如果技术部确实要支持“连带删除空数据用户”，只能删除这些对象：

1. 该用户未使用的邀请码关系。
2. 该用户未使用的 password reset token。
3. 该用户的空反馈草稿如果存在。

不允许在本轮删除真实便签数据。

### 6.4 API

新增：

```text
DELETE /api/admin/users/:id
```

要求：

1. `requireAdmin()`。
2. 不能删除自己。
3. 不能删除 admin 用户。
4. 只能删除 disabled 用户。
5. 删除前统计用户数据：
   - Note
   - Attachment
   - FeedbackTicket
   - InviteCode usedBy/createdBy
   - AnnouncementRead
6. 如存在关键业务数据，返回 409。

成功：

```json
{
  "ok": true
}
```

数据存在：

```json
{
  "ok": false,
  "error": "USER_HAS_DATA",
  "counts": {
    "notes": 3,
    "attachments": 1
  }
}
```

### 6.5 UI

管理员用户列表中，对 eligible 用户显示：

```text
删除用户
```

删除按钮必须弱化，不与禁用/启用同级醒目。

确认流程：

1. 第一层弹窗：说明只用于删除废账号。
2. 第二层要求输入该用户邮箱或 `DELETE`。

确认文案：

```text
删除用户后不可恢复。仅当这是废弃账号且无有效数据时使用。
```

## 7. 功能四：新用户示例便签

### 7.1 目标

新用户第一次进入应用时，应看到几个示例，快速理解：

1. 这是备忘录。
2. 这是待办。
3. 可以置顶、归档、删除、上传图片。
4. 可以用作工作、生活、灵感记录。

### 7.2 生成时机

推荐在邀请注册成功创建用户时生成示例便签。

要求：

1. 只给新用户生成一次。
2. 老用户不补发，避免污染真实数据。
3. 如果用户创建第一条真实便签前删掉示例，不再自动重建。

### 7.3 数据标记

建议在 Note 增加：

```prisma
isSample Boolean @default(false)
```

或者不改 schema，使用标题前缀内部识别。但推荐 schema 字段，便于后续统计和清理。

### 7.4 示例内容建议

示例 1：欢迎备忘录

```text
欢迎使用 PinNote

这里可以记录临时想法、会议摘要、灵感和备忘。
左侧是便签列表，点击新建可以继续添加。
```

示例 2：今日待办

```text
今日待办
- 写下今天最重要的 3 件事
- 完成后勾选
- 不重要的事情可以归档或删除
```

示例 3：使用技巧

```text
使用技巧

你可以：
- 给便签换颜色
- 把重要便签置顶
- 删除后在回收站恢复
- 在电脑网页端下载桌面版
```

### 7.5 UI 要求

示例便签看起来应像普通便签，但可以在标题或内容里自然说明它是示例。

不需要做新手引导遮罩，不要强制用户一步步点击。

### 7.6 验收

1. 新注册用户首次进入有 3 条示例便签。
2. 示例包含普通文本和待办。
3. 示例归属当前用户。
4. 其它用户看不到这些示例。
5. 删除示例后进入回收站。
6. 老用户登录不会被追加示例。
7. 数据隔离不退化。

## 8. 内测用户保护

本轮必须继续保护真实内测用户：

1. 生产验收使用临时测试用户。
2. 不删除真实内测用户。
3. 删除用户功能只用临时废账号验收。
4. 公告弹窗验收可以用临时用户，避免打扰真实用户。
5. 归档/回收站批量操作只操作临时测试便签。

## 9. 验收标准

### 9.1 归档/回收站批量操作

1. 归档页有横向三点选择入口。
2. 归档页可多选取消归档。
3. 归档页可多选删除到回收站。
4. 回收站页有横向三点选择入口。
5. 回收站页可多选恢复。
6. 回收站页可多选永久删除。
7. 永久删除需要输入 `DELETE`。
8. 批量操作只影响当前用户。
9. 320px 不横向溢出。

### 9.2 公告栏

1. 管理员可新建公告草稿。
2. 管理员可编辑标题/正文/版本。
3. 管理员发布后，普通用户首次登录弹窗看到公告。
4. 用户关闭弹窗后记录已读。
5. 同一公告不重复弹。
6. 管理员能看到已读人数、未读人数、阅读率。
7. 公告内容完全来自管理员输入，不由 AI 改写。
8. 非管理员不能访问公告管理页/API。

### 9.3 删除废用户

1. 管理员不能删除自己。
2. 管理员不能删除 admin 用户。
3. active 用户不能直接删除，需先 disabled。
4. 有 Note/Attachment 的用户不能删除。
5. 无数据 disabled 废账号可删除。
6. 删除前有二次确认。
7. 删除后用户列表不再显示该废账号。
8. 真实用户数据不变。

### 9.4 新用户示例便签

1. 新注册用户获得示例便签。
2. 示例便签数量和内容符合规格。
3. 示例归属当前用户。
4. 老用户不被追加示例。
5. 示例可正常编辑、删除、恢复。

M10.10 完成后，对内测用户说明：

```text
归档和回收站支持批量操作；更新公告由管理员手动发布，首次打开会显示；新用户首次进入会看到示例便签；管理员可以清理无效废账号。
```

对技术部说明：

```text
本轮是内测运营补强。公告必须管理员手动发布，禁止 AI 自动发布。删除用户是高风险能力，只允许删除 disabled 且无业务数据的废账号。归档/回收站批量操作必须沿用 M10.9 横向三点入口，并严格按 userId 隔离。
```
