# 全平台便签 M8.7：标题字号收敛与亮色模式

日期：2026-08-06

## 1. 背景

M8.6 继续优化了横向缩放稳定性，但整体体感仍不是完全理想。产品侧决定：响应式稳定感先到此为止，不继续在这一轮追求极致。下一步先做两个明确、可感知、范围可控的体验优化：

1. 编辑区标题字号过大，小窗口下长标题容易被裁切或压迫正文。
2. 当前只有暗色模式，需要增加一个亮色模式，并提供黑/白切换入口。

本轮目标是做“清晰可交付的小优化”，不要扩大成账号系统、复杂主题市场或大规模视觉重构。

## 2. 本轮目标

M8.7 目标：

1. 降低便签详情页标题字号，让它比正文略大，但不要大很多。
2. 标题在小窗口下不裁切、不压迫正文。
3. 增加暗色/亮色模式切换。
4. 主题切换入口放在全局账号/个人便签菜单中。
5. 主题选择本地持久化。
6. 亮色模式使用 token/变量方案实现，避免散改颜色导致 bug。

## 3. 本轮不做

1. 不做账号系统。
2. 不做多用户。
3. 不做多套皮肤市场。
4. 不做自定义主题颜色。
5. 不做富文本编辑器。
6. 不继续深挖 M8.6 响应式稳定感。

## 4. P0：编辑区标题字号收敛

### 4.1 当前问题

用户现象：

- 进入便签详情后，标题字号太大。
- 标题长一点时，在最小窗口/窄窗口下容易被裁切。
- 标题过大也会显得视觉重，不符合当前“桌面便签工具”的定位。

当前代码线索：

- `tailwind.config.ts`
- `edit-title` 当前约为：

```text
30px / line-height 1.22 / font-weight 750
```

- 使用位置包括：
  - `src/components/NoteEditor.tsx`
  - `src/app/notes/[id]/floating/FloatingNoteClient.tsx`
  - archive 详情页标题
  - login 标题可能也复用该 token，需要注意不要误伤登录页视觉。

### 4.2 产品要求

标题应该是“编辑标题”，不是文章页大标题。

建议：

```text
正文：17px
标题：20-22px
```

不要再使用 30px 这种大展示标题。

推荐值：

```text
桌面/宽屏标题：22px
窄窗口标题：20px
行高：1.28-1.35
字重：650-700
```

如果用 CSS clamp：

```css
font-size: clamp(20px, 2.2vw, 22px);
```

注意：不要用过强 viewport 缩放导致宽屏标题又变大。标题最大值应控制在 22px 左右。

### 4.3 换行与裁切要求

标题输入框必须：

1. 支持长标题自然展示。
2. 不在小窗口下被横向裁切。
3. 不出现单词/中文长串撑破容器。
4. 不挤压工具栏。

如果当前标题是 `input`，天然单行，长标题只能横向滚动或裁切。建议评估改为：

- autosize textarea；或
- 保持 input，但在小窗口下降低字号并确保可横向滚动体验可接受。

产品建议：

优先将标题改为 autosize textarea，最多 2-3 行；超过后内部滚动或继续撑开内容区。

### 4.4 验收标准

1. 宽屏下标题不超过 22px。
2. 260-320px 小窗口下标题不超过 20px 或视觉等效。
3. 长标题在小窗口下不被明显裁切。
4. 标题与正文层级清楚：标题略大于正文，但不夸张。
5. 普通便签、待办便签、归档详情、悬浮页均一致。
6. 登录页如不适合使用降级后的 `edit-title`，应拆出独立登录标题样式。

## 5. P0：亮色模式

### 5.1 产品范围

第一版只做两个模式：

```text
暗色
亮色
```

不做：

- 多套皮肤
- 自定义颜色
- 自动壁纸/背景
- 复杂主题编辑器

### 5.2 默认主题

建议默认：

```text
跟随系统
```

但为了实现简单可控，可以采用：

1. 首次进入：读取 `prefers-color-scheme`。
2. 用户手动切换后：以用户选择为准，写入 localStorage。

如果技术部认为“跟随系统 + 手动覆盖”略复杂，本轮可接受更简单版本：

```text
默认暗色，用户可手动切换亮色，并持久化。
```

优先级：

1. 手动切换必须稳定。
2. 跟随系统可作为 P1。

### 5.3 切换入口

用户建议：

- 放在左下角“我的/个人便签”菜单中。

产品要求：

- 在账号/个人便签菜单中增加：

```text
外观：暗色 / 亮色
```

或一个清晰按钮：

```text
切换为亮色模式
切换为暗色模式
```

要求：

1. 入口不占用主编辑工具栏。
2. 不增加顶部空间。
3. Windows 壳和 Web 端一致。
4. 切换后无需刷新即可生效。

### 5.4 实现方式

必须基于现有主题评估文档：

```text
SPEC_M8_LIGHT_MODE_ASSESSMENT_20260806.md
```

推荐采用“CSS 变量覆盖”方案。

要求：

1. 不要在组件里大面积硬编码亮色 class。
2. 不要复制一套组件。
3. 将暗色/亮色都收敛到 token 或 CSS variables。
4. 白/黑透明叠层要抽象成语义 utility，避免亮色下 hover 看不清。

建议结构：

```css
:root,
[data-theme="dark"] {
  --page-bg: ...;
}

[data-theme="light"] {
  --page-bg: ...;
}
```

应用启动：

```text
读取 localStorage.theme
设置 document.documentElement.dataset.theme
```

### 5.5 亮色模式视觉方向

亮色模式不要做成纯白刺眼网页。

建议：

```text
页面背景：#F5F5F7 或接近
侧边栏：#F2F2F4
编辑区：#FFFFFF 或 #FBFBFC
工具栏：#F7F7F8
边框：#DADADD
主文字：#1C1C1E
次文字：#6E6E73
弱文字：#8E8E93
主强调色：保留当前便签黄，但亮色下可略加深
```

注意：

- 亮色模式也要保留 Apple Notes/iCloud Notes 风格倾向。
- 不要做成普通后台管理系统白底。
- 列表选中态、便签颜色、待办勾选、危险删除按钮都要重新验证对比度。

### 5.6 需要覆盖的页面/组件

必须适配：

1. 首页主界面。
2. 侧边栏。
3. 便签列表卡片。
4. 编辑器工具栏。
5. 普通便签正文。
6. 待办清单、小标题、已完成区。
7. 颜色选择器。
8. 图片附件和图片预览。
9. 右键菜单。
10. 删除确认弹窗。
11. 回收站。
12. 归档页。
13. 登录页。
14. Windows 壳背景。

### 5.7 验收标准

功能验收：

1. 账号/个人便签菜单中可以切换暗色/亮色。
2. 切换后立即生效，无需刷新。
3. 刷新页面后保持用户选择。
4. 关闭 Windows App 再打开后保持用户选择。
5. Web 和 Windows 壳表现一致。

视觉验收：

1. 亮色模式不刺眼。
2. 文本对比度足够。
3. 按钮 hover/active 可见。
4. 列表选中态清晰。
5. 待办勾选状态清晰。
6. 删除/危险按钮清晰但不过度刺眼。
7. 图片预览遮罩仍合理。
8. 右键菜单不突兀。

回归验收：

1. 暗色模式不能被改坏。
2. 暗色/亮色下都能新建、编辑、保存、删除、恢复。
3. 待办拖拽、右键菜单、复制一份、回收站剩余时间都正常。
4. `npm run build` 通过。
5. Windows 壳实机截图：暗色一张、亮色一张。

## 6. 优先级

P0：

1. 标题字号收敛。
2. 手动暗色/亮色切换。
3. 主题选择 localStorage 持久化。
4. 暗色模式回归不破坏。

P1：

1. 首次跟随系统。
2. 亮色模式细节 polish。
3. 亮色下勾选色/选中态对比度微调。

P2：

1. 多主题。
2. 自定义主题色。
3. 账号同步主题设置。

## 8. 通过标准

M8.7 通过标准：

> 标题不再像大文章标题一样压迫小窗口；用户可以在个人便签菜单中稳定切换暗色/亮色，两套主题都保持当前便签工具的质感和可读性。

如果亮色模式只是把背景改白、但 hover/边框/选中态/弹窗大量失衡，本轮不通过。
