# PinNote M10.4 管理员最小用户管理

日期：2026-08-07

## 1. 背景

M10.1 已完成账号地基审计：历史数据归属默认用户，API 按 `userId` 隔离。

M10.2 已完成账号入口与基础身份：登录态、昵称、文字头像、图片入口降级。

M10.3 已完成存储额度：每用户默认 10 MB、账号菜单显示用量、超额上传拦截、后端维护 `storageUsedBytes`。

下一步需要补上最小管理员能力。否则后续一旦有第二个用户，就会出现几个基础问题：

1. 谁能用？
2. 用户能不能被禁用？
3. 空间不够时谁能调额度？
4. 忘记密码时怎么处理？

M10.4 目标不是做完整后台，而是做“能管住用户”的最小闭环。

## 2. 本轮目标

M10.4 只做四件事：

1. 管理员用户列表。
2. 禁用 / 启用用户。
3. 调整用户存储额度。
4. 管理员重置用户密码。

## 3. 本轮不做

明确不做：

1. 不做开放注册。
2. 不做邀请制注册。
3. 不做邮件找回密码。
4. 不做邮箱验证码。
5. 不做微信登录。
6. 不做头像上传。
7. 不做内容审核后台。
8. 不做查看用户便签内容。
9. 不做删除用户。
10. 不做复杂角色权限系统。
11. 不做计费套餐。
12. 不做审计日志大系统。

后续路线：

```text
M10.5 邀请制注册
M10.6 忘记密码 / 邮件重置
```

## 4. 产品原则

### 4.1 管理用户，不管理内容

M10.4 管理员可以管理账号状态和额度，但不进入用户便签内容。

原因：

1. PinNote 是私人便签工具。
2. 本轮先解决账号可控，不做内容审核。
3. 管理员能禁用账号即可处理明显滥用。

### 4.2 不删除用户

本轮不做删除用户。

原因：

1. 删除用户会牵涉便签、附件、回收站、文件清理、备份与合规。
2. 容易造成不可逆数据丢失。
3. 禁用用户已经能解决“不能继续使用”的问题。

### 4.3 先做管理员重置密码，不做邮件找回

忘记密码先由管理员手动重置。

原因：

1. 邮件找回需要 SMTP、邮件模板、reset token、防刷、过期和一次性使用。
2. 对当前私有小产品来说，管理员重置更简单可靠。

## 5. 数据模型

在 `User` 上增加：

```prisma
model User {
  role   String @default("user")
  status String @default("active")
}
```

字段约束建议：

```text
role: "admin" | "user"
status: "active" | "disabled"
```

说明：

1. 现有 `admin` 用户必须设置为 `role="admin"`、`status="active"`。
2. 普通用户默认 `role="user"`、`status="active"`。
3. 不建议本轮使用复杂权限表。
4. 如果技术部愿意，可以在代码层做常量枚举，避免魔法字符串散落。

## 6. 权限规则

### 6.1 管理员判断

新增服务端工具：

```text
requireAdmin()
```

要求：

1. 未登录返回 401。
2. 已登录但不是 admin 返回 403。
3. disabled 用户返回 403 或强制退出。

所有 `/api/admin/*` 接口必须使用 `requireAdmin()`。

### 6.2 禁用用户后的行为

当用户 `status="disabled"`：

1. 不能登录。
2. 已登录 session 后续访问 API 时应返回 403 或强制 logout。
3. 不能继续新建、编辑、上传、删除。
4. 不能访问附件文件。

建议：

```text
getCurrentUser / requireUser 层统一检查 status。
```

这样不需要每个业务 API 单独判断。

### 6.3 防止管理员把自己锁死

必须禁止：

1. 管理员禁用自己。
2. 管理员把自己降级为普通用户。
3. 管理员把自己额度调到低于已用空间。

如果未来有多个管理员，再扩展更细规则。本轮简单处理即可。

## 7. 管理页面

### 7.1 入口

入口建议放在：

```text
左下角账号菜单 -> 管理用户
```

仅管理员可见。

普通用户不显示该入口。

页面路径建议：

```text
/admin/users
```

### 7.2 用户列表

列表字段：

```text
头像 / 昵称
username
role
status
已用空间 / 总额度
创建时间
更新时间
操作
```

如果未来引入 email，再补 email 列。本轮没有 email 字段，不强行做。

操作：

```text
启用 / 禁用
调整额度
重置密码
```

视觉要求：

1. 不要做复杂后台大屏。
2. 风格跟 M9/M10 账号菜单一致，干净轻量。
3. 单页即可，不需要多层管理系统。
4. 390px/320px 可以降级为纵向卡片，不要求表格硬塞。

## 8. API 设计

### 8.1 获取用户列表

```text
GET /api/admin/users
```

仅 admin。

返回字段建议：

```json
{
  "ok": true,
  "users": [
    {
      "id": "xxx",
      "username": "admin",
      "displayName": null,
      "avatarColor": null,
      "role": "admin",
      "status": "active",
      "storageQuotaBytes": 10485760,
      "storageUsedBytes": 2579562,
      "createdAt": "...",
      "updatedAt": "..."
    }
  ]
}
```

不要返回：

```text
passwordHash
```

### 8.2 修改用户状态

```text
PATCH /api/admin/users/:id/status
```

请求：

```json
{
  "status": "disabled"
}
```

要求：

1. 仅 admin。
2. `status` 必须为 `active` 或 `disabled`。
3. 不能禁用自己。
4. 被禁用用户不能再登录。
5. 被禁用用户已有 session 后续请求应失效或返回 403。

### 8.3 调整用户额度

```text
PATCH /api/admin/users/:id/quota
```

请求：

```json
{
  "storageQuotaBytes": 52428800
}
```

要求：

1. 仅 admin。
2. 额度必须为正整数。
3. 建议最小 1 MB。
4. 建议最大先限制为 500 MB，避免误填超大值。
5. 允许把额度调低，但不能低于该用户 `storageUsedBytes`，否则会让用户瞬间进入已满不可用状态。
6. 返回更新后的用户。

常用额度选项：

```text
10 MB
50 MB
100 MB
500 MB
```

### 8.4 重置用户密码

```text
PATCH /api/admin/users/:id/password
```

请求：

```json
{
  "newPassword": "new-password"
}
```

要求：

1. 仅 admin。
2. 密码必须重新 bcrypt hash。
3. 不允许返回明文密码。
4. 密码最少 8 位。
5. 建议要求包含字母和数字，但本轮可以先只做长度校验。
6. 不允许空密码。
7. 管理员可以重置自己的密码，但重置后当前 session 是否保留由技术部决定，必须写清楚。

安全提示：

```text
重置密码成功后，只显示“密码已重置”，不要在日志或响应里输出明文密码。
```

## 9. 登录与 API 行为调整

### 9.1 登录接口

`POST /api/auth/login` 需要检查：

```text
user.status === "active"
```

如果 disabled：

```json
{
  "ok": false,
  "error": "ACCOUNT_DISABLED",
  "message": "账号已被禁用，请联系管理员"
}
```

状态码建议：

```text
403
```

### 9.2 当前用户接口

`GET /api/auth/me` 返回：

```text
role
status
```

用于前端判断是否显示“管理用户”入口。

### 9.3 业务 API

`requireUser()` 应统一排除 disabled 用户。

建议：

```text
disabled 用户访问业务 API -> 403 ACCOUNT_DISABLED
```

不要让 disabled 用户继续用旧 session 操作数据。

## 10. UI 交互细节

### 10.1 禁用确认

禁用用户前必须二次确认。

文案：

```text
禁用后，该用户将无法登录和访问便签。确认禁用？
```

### 10.2 调整额度

UI 可以使用：

1. 预设按钮：10 MB / 50 MB / 100 MB / 500 MB。
2. 自定义输入框。

显示：

```text
当前已用：2.5 MB
当前额度：10 MB
新额度：50 MB
```

如果新额度低于已用空间，应禁止提交并提示：

```text
新额度不能低于当前已用空间
```

### 10.3 重置密码

UI 要求：

1. 输入新密码。
2. 再次确认新密码。
3. 两次不一致不能提交。
4. 成功后提示“密码已重置”。
5. 不显示密码明文。

## 11. 数据安全执行顺序

生产执行顺序：

1. 备份生产数据库。
2. 记录 User / Note / Attachment 数量。
3. `PRAGMA integrity_check = ok`。
4. 部署 schema。
5. `prisma db push`。
6. 把现有 `admin` 用户设置为 `role=admin`、`status=active`。
7. build。
8. 重启服务。
9. 健康检查。
10. 管理员页面和 API 回归。

## 12. 验收标准

### 12.1 数据验收

必须提供：

```text
User: 前 -> 后
Note: 前 -> 后
Attachment: 前 -> 后
admin.role
admin.status
```

通过标准：

1. User / Note / Attachment 数量不异常减少。
2. `admin.role = admin`。
3. `admin.status = active`。
4. 历史便签和附件仍可见。

### 12.2 管理员权限验收

必须通过：

1. admin 能打开 `/admin/users`。
2. 普通用户不能打开 `/admin/users`。
3. 未登录访问 `/admin/users` 跳登录或返回 401。
4. 普通用户访问 `/api/admin/users` 返回 403。
5. API 不返回 `passwordHash`。

### 12.3 用户列表验收

必须通过：

1. 用户列表显示 admin。
2. 显示昵称/username。
3. 显示 role/status。
4. 显示已用空间/总额度。
5. 显示创建时间。
6. 390px/320px 不横向溢出。

### 12.4 禁用/启用验收

建议临时创建测试用户：

```text
username: admin-m10-test
```

必须通过：

1. admin 能禁用测试用户。
2. disabled 用户不能登录。
3. disabled 用户已有 session 访问 `/api/notes` 返回 403。
4. admin 能重新启用测试用户。
5. 启用后测试用户可重新登录。
6. admin 不能禁用自己。

测试后清理测试用户和测试数据。

### 12.5 调额度验收

必须通过：

1. admin 能把测试用户额度从 10 MB 调到 50 MB。
2. 调整后 `/api/auth/me` 返回新额度。
3. 用户账号菜单显示新额度。
4. 不能把额度调为 0。
5. 不能把额度调低到低于已用空间。

### 12.6 重置密码验收

必须通过：

1. admin 能重置测试用户密码。
2. 旧密码登录失败。
3. 新密码登录成功。
4. 响应和日志不输出明文密码。
5. 空密码/过短密码被拒绝。

## 13. 回归验收

必须复测：

1. admin 登录。
2. 普通便签新建/编辑/保存。
3. 待办便签新建/编辑/保存。
4. 搜索。
5. 归档/恢复。
6. 删除/回收站/永久删除。
7. 图片上传额度仍生效。
8. 账号菜单存储进度仍显示。
9. 昵称修改仍可用。
10. 断网防丢保护不退化。

## 14. 不通过标准

出现以下任一情况不能通过：

1. admin 被锁死无法登录。
2. 普通用户能访问管理员 API。
3. disabled 用户仍能操作便签。
4. API 返回 `passwordHash`。
5. 重置密码泄露明文。
6. 调额度导致 `storageQuotaBytes` 小于 `storageUsedBytes`。
7. 历史便签或附件不可见。
8. 本轮混入注册、邀请码、邮件找回、内容审核等非本轮范围。

11. 重置密码测试结果。
12. 回归测试结果。
13. 回退方案。

## 16. 回退方案

若出现 admin 无法登录、管理员 API 权限错误、历史数据不可见：

```text
停服务
恢复 M10.4 前数据库备份
回退 M10.4 代码
重新 build
重启服务
复查 admin 登录和历史便签
```

回退后确认：

1. admin 可登录。
2. Note 数量恢复。
3. Attachment 数量恢复。
4. 账号菜单恢复 M10.3 状态。
5. 存储额度仍可用。
