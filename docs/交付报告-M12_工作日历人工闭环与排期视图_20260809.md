# M12 交付报告：工作日历人工闭环与排期视图

日期：2026-08-09

## 一、交付内容

按 `docs/SPEC_M12_工作日历人工闭环与排期视图_20260809.md` 实现工作日历的人工闭环与排期视图，在 M12 基础层（R2 嵌入右面板）之上，将日历从「个人事件」升级为「项目管理 + 排期」，管理员灰度上线：

- **结构化数据模型**：
  - `WorkProject`（工作项目）：`name/colorKey(blue|red|green|purple|gray)/status(active|archived)/startDate/endDate/description/source=manual`，含软删 `deletedAt`。`source=manual` 为 M13 AI 导入预留。
  - `WorkScheduleItem`（排期条目）：`projectId/title/type(range 连续阶段|node 单日节点)/startDate/endDate/status(todo|done|postponed)/noteId(便签关联)/source=manual`，含软删 `deletedAt`。
- **管理员专用 CRUD API**（全部 `requireAdmin()`：未登录 401、普通用户 403）：
  - `/api/work-projects` GET（默认 active、`?status=all` 含归档）/ POST
  - `/api/work-projects/[id]` PATCH（改名/换色/调状态/改时间/改描述/归档）/ DELETE（软删）
  - `/api/work-schedule-items` GET（`?from&to` 范围）/ POST
  - `/api/work-schedule-items/[id]` PATCH（改标题/类型/日期/状态/换项目/关联便签）/ DELETE（软删）
  - `/api/work-schedule-items/quick-week` POST：快速录入一周 → 服务端智能解析（连续多天相同内容合并为 range、含「call/提交/反馈/交付」等词判定 node）→ 返回可编辑预览行
- **三视图**（复用 R2 嵌入右面板的 `CalendarPageClient`，周视图为默认）：
  - **周视图**：周一到周日 7 列，range 显示紧凑小卡（左色条 + 标题 + 日期）、node 单日圆点卡；今天高亮。窄窗口纵向 7 天列表。
  - **月视图**：range 按起止日期渲染跨列色条（gantt 语义）、node 渲染单日标记；今天高亮。
  - **今日视图**：待完成 / 已完成 / 已延期 三段，勾选完成、点击打开、快速新建。
- **快速录入一周**：选项目 + 周首日 + 7 天速记 + 可选交付/收付节点 → 服务端解析生成预览（可改类型/日期）→ 确认批量写入正式排期。
- **项目侧栏**：项目增/改/归档、显示归档开关、项目筛选（点击项目名只看该项目）、便签链接层开关（切换显示已关联便签的排期）。
- **入口选中态**：工作日历入口卡片打开时呈**蓝色衬底**（`card-selected card-selected-blue`），与便签选中态一致（R1 的灰色衬底改为蓝色）。
- **左侧日历卡数据源改排期**：`CalendarCard` 从 `calendar-events` 改为拉取 `work-schedule-items` 今日范围，显示「今天 / 今日未完成 N 项 / 最多 2 条排期」，底部按钮改「添加排期」。
- **普通用户灰度**：无「日历」分组入口；直接访问 `/calendar` 重定向回首页 + toast「无权限访问日历」；全部 work-calendar API 返回 403。
- **旧日历组件清理**：删除 `EventChip/EventEditorDialog/MonthView/TodayList/WeekView/useCalendarEvents` 等 CalendarEvent 时代的死组件与 hook，`CalendarEvent` 模型保留在库中不迁移（无数据）。

## 二、架构与实现要点

1. **双实体模型**：项目（WorkProject）与排期条目（WorkScheduleItem）各自独立 CRUD；条目挂在项目下，删除项目软删（条目保留但项目不可见）。日期一律 `YYYY-MM-DD` 字符串，避免时区错位。
2. **软删统一**：项目/条目删除均置 `deletedAt`（与便签习惯一致），查询默认过滤 `deletedAt: null`；归档用 `archivedAt`（项目）/ `status=archived`（项目）。入口默认只列 active 项目，「显示归档」开关才列出归档项目。
3. **`useWorkCalendar` 数据 hook**：范围拉取 + 增删改，带乐观更新与失败回滚（`projectsRef/itemsRef` 快照）。`quickWeekPreview` 调 quick-week 接口取预览行。
4. **快速录入一周解析**：服务端把 7 天速记文本按「相邻同文本合并为 range、含 call/提交/反馈/交付 等词判 node」生成 preview 行；前端预览阶段仍可逐行改类型与日期后批量写入。
5. **三视图只依赖周首日**：`weekStart` 为单一状态，月/今日视图由 `weekStart` 推导，`rangeFor` 计算拉取范围；切换视图不重新拉取。
6. **项目配色**：`globals.css` 新增 `.wp-*` 项目色系（5 色 × 亮/暗两套），同一项目用 `--wp-base` 主色 + `--wp-soft` 浅底 + `--wp-soft-border` 描边，chip/bar/dot 共用变量。
7. **R2 嵌入态延续**：`CalendarPageClient` 保持 props 驱动（`embedded/onBack/openNewEvent/initialAction`），工作日历视图作为其内部实现替换旧三视图；独立页 `/calendar` 保留。

## 六、风险与后续建议

- **AI 排期导入（M13）**：模型已预留 `source`、`description`、`noteId`、批量创建扩展空间；M13 在 M12 数据结构上做 AI 解析 + 确认页 + 批量写入。
- **CalendarEvent 数据不迁移**：旧 `CalendarEvent` 表与模型保留在库中，无数据（基础层阶段即空），工作日历切换到新模型；后续可从 schema 移除。
- **暗/亮色截图验收受限**：本环境截图工具不可用，暗/亮色通过 `getComputedStyle` 计算值 + 无控制台报错验证（.wp-* 暗色变体与 CSS 定义逐值匹配）。
- 拖拽排期、冲突检测、提醒通知：M12 明确不做，`startDate/endDate` 仅展示与排序。
- 便签删除后排期关联显示「便签已失效」：沿基础层行为（`note.isTrashed` 判定），复杂交互留后续。
