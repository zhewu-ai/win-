## 四、附带修复（既有问题，非 M12 引入）

1. **`useSyncStatus.ts` SSR 水合错位**（历史遗留）：Next.js 在 SSR 渲染 client 组件时会 polyfill `navigator`，使 `navigator.onLine` 在服务端返回 false，与浏览器端不一致 → 首页 `OfflineBar` 水合错位（SSR 渲染「当前离线」、客户端渲染 null → hydration error）。改为 `typeof window !== "undefined"` 判断后，SSR 默认按「在线」渲染，修复首页水合。
2. **`EventNotePicker` 两个 bug**（本轮验收发现并修复）：
   - 搜索永远空结果：接口返回 `{ notes: [...] }`（无 `ok` 字段），原判断 `!data.ok` 恒真 → 下拉永远「没有匹配的便签」。改为 `!Array.isArray(data.notes)`。
   - 选中便签显示「未命名便签」：`handlePick` 清空 results 后 `[value]` effect 重跑，用空 results 把选中项覆盖成 `{ title: "" }` 占位。改为函数式 `setSelected`（`prev.id === value` 保留），并用新 prop `noteTitle` 回填编辑已有事件的标题。

### 10.2 架构调整

1. **`CalendarPageClient` 改为可嵌入组件**：去掉 `useSearchParams`（需 Suspense 边界、且嵌入态拿不到 URL 深链），改为 props 驱动：
   - `onBack`：单栏嵌入态点击返回关闭面板；不传则嵌入双栏不显示返回区。
   - `embedded`：true → 根节点 `flex-1 h-full` 填充右面板；false → `h-screen` 独立页。
   - `openNewEvent: { date, n }`：嵌入态由父级「+ 添加今日事件」触发，`n` 递增可重复弹出。
   - `initialAction: { date, newEvent, eventId }`：独立页从 URL 深链读到的初始动作，挂载时生效一次。
2. **`/calendar` 独立页保留但不再作入口**：`searchParams` 改为 `await`（Next 16 为 Promise）转 `initialAction`，删除 `<Suspense>`。管理员直接访问仍可用（月视图 + 深链 `?date=…&new=1` / `?event=…`）；普通用户仍 `requireAdmin()` 失败 → `redirect("/?notice=calendar_forbidden")` + toast + API 403。
3. **入口移入 `NoteList`**：列表滚动区顶部渲染「日历」分组（`SectionHeader` + `CalendarCard`），随后才是置顶/日期分组；空态重构——管理员空列表在滚动区内「日历分组 + 行内空提示」，普通用户空列表仍居中空态。

### 10.5 顺手修复：侧边栏宽度过渡卡死（既有 bug，R2 触碰同段代码）

R2 要求「单栏点入口 → 侧栏收起、日历占满」，实测发现 R1 §9.6 记录的既有 bug 会直接破坏该体验：侧边栏包裹 div 的 `transition-[width,opacity]` 在「双栏 350px ↔ 单栏 100%」以及「transition-property 与宽度同帧变化」时被浏览器冻结在起始值（`getAnimations()` 显示 width/opacity 动画 currentTime=0、永久 running），侧栏既不收起也不展开，日历被挤到 151px。

**修复**：移除该 div 的 width/opacity 过渡（侧栏收起改为即时）。150ms 动画收益远低于反复卡死的代价，且即时收起对移动端更干脆。修复后验证：单栏 390px 侧栏精确 390→0 收敛、1440px 350→0 收敛、双向缩窗无卡死、`getAnimations()` 为空。普通便签编辑/返回流程同步回归通过。
