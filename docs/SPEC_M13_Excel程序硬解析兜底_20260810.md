# SPEC M13：Excel 程序硬解析兜底

日期：2026-08-10

状态：已完成并上线（2026-08-10 生产验证通过）

## 一、实现结论

Excel 程序硬解析兜底已实现并接入 AI 排期导入流程：

```text
AI 识别成功 → 使用 AI 草稿
AI 识别超时 / 失败 / 返回不可用 → 启用程序硬解析 → 生成可编辑草稿
```

程序兜底使用确定性解析器 `parseExcelSchedule`（SheetJS 读取 + 日期行/合并单元格/连续重复文本规则），解析结果与 AI 草稿同构，进入现有「草稿预览 → 用户确认 → 入库」流程。前端在兜底启用时显示横幅「AI 识别未及时返回，已使用 Excel 程序解析生成草稿，请确认。」

## 三、样本共性

### 3.1 周历横排结构

多数样本都是：

```text
一行星期 / 日期横向排列
下一行或相邻多行填写任务
```

常见结构：

- 7 列日期横排。
- 日期行下方是任务行。
- 一周接一周纵向排列。

### 3.2 日期行可识别

日期格式包括：

- `July 13`
- `August 01`
- `10/13/25`
- `11/30/25`
- `December 01`
- `January 09`
- `8.10日交付`

程序可以通过日期模式识别日期行，并建立：

```text
列号 → 日期
```

### 3.3 合并单元格表达跨天

很多任务通过合并单元格表达跨多天，例如：

```text
C11:E11 = 某阶段任务
```

程序可根据合并区域推断：

```text
startDate = 合并区域起始列对应日期
endDate = 合并区域结束列对应日期
```

### 3.4 连续重复文本表达跨天

有些表不一定合并单元格，而是在连续日期列里重复同一任务，例如：

```text
B12=layout制作
C12=layout制作
D12=layout制作
```

程序可合并连续相同文本，生成一条跨天排期。

### 3.5 项目名可从多处推断

项目名可按优先级提取：

1. 表格标题，例如 `Production Schedule HUAWEI Laputa MG视频`
2. Sheet 名，例如 `MG视频` / `APK视频`
3. 文件名，例如 `HUAWEI Laputa_MG&APK时间表_0622.xlsx`
4. 左侧项目列，例如 `Lindy CMF` / `APK视频`

## 四、触发时机

程序硬解析不是第一优先级，而是兜底。

建议触发条件：

1. AI 识别超过超时阈值，例如 60s / 90s。
2. AI 返回空草稿。
3. AI 返回 JSON 解析失败。
4. AI 返回项目数或条目数为 0。
5. AI 调用失败但 Excel 本地解析成功。

前端提示建议：

```text
AI 识别未及时返回，已使用 Excel 程序解析生成草稿。请确认日期和任务是否正确。
```

## 五、程序解析规则

### 5.1 读取基础结构

使用 SheetJS 或现有 Excel 解析库读取：

- workbook
- sheet 名
- 非空单元格
- 单元格显示值
- 合并单元格区域
- 行列坐标

### 5.2 找日期行

对每个 sheet 扫描行，判定日期行：

- 一行中有 5 个以上日期型单元格，基本可判定为周日期行。
- 一行中有 7 个星期文本，下一行有 7 个日期，也可判定。
- 日期行附近如果左侧有 `Project/ Date`，优先作为日期行。

识别后建立：

```ts
type DateColumnMap = {
  rowIndex: number;
  columns: Array<{
    colIndex: number;
    date: string; // YYYY-MM-DD
  }>;
};
```

### 5.3 年份处理

如果日期缺年份：

- 优先从文件内完整日期推断年份。
- 其次从交付日期推断年份。
- 再其次使用当前业务年份。

当前业务年份必须由后端传入，例如：

```text
当前日期：2026-08-10
当前年份：2026
```

如果文件明确写了 2025，则使用 2025，不强行改成 2026。

### 5.4 找任务单元格

从日期行下方扫描任务行，直到遇到下一条日期行。

忽略：

- 空单元格。
- 星期文本。
- 纯日期文本。
- `Project/ Date`。
- 说明性备注，例如“此时间表为初步计划时间”。
- 明显元信息字段，例如 `Client`、`Agency`、`Director`、`Duration`、`Specification`。

保留：

- 阶段名。
- 任务名。
- 提交/反馈/确认/修改/制作/测试等排期节点。

### 5.5 推断日期范围

优先级：

1. 如果任务单元格在合并区域内，用合并区域起止列推断日期范围。
2. 如果连续相邻单元格文本相同，合并为一个日期范围。
3. 如果单个单元格有任务文本，生成单日排期。

### 5.6 项目分组

左侧列常出现项目/子项目名，例如：

- `Lindy CMF`
- `MG澜盾`
- `MG红枫/开合`
- `APK视频`
- `产品制作`

规则：

- 如果任务行左侧同一行或上方近邻有项目名，作为该条排期的项目或分组。
- 如果没有明确项目名，使用 sheet/title/file 推断的项目名。
- 不确定时放入 `warnings`，不要丢弃任务。

### 5.7 输出草稿

输出结构应与 AI 草稿一致，继续进入现有预览/编辑/确认流程。

建议 warnings：

- `PROGRAM_FALLBACK_USED`
- `YEAR_INFERRED`
- `PROJECT_NAME_INFERRED`
- `MERGED_CELL_RANGE_INFERRED`
- `LOW_CONFIDENCE_ROW`

## 六、成功边界

### 6.1 适合程序硬解析的情况

- 日期横向排列。
- 一周 7 列。
- 日期下方是任务。
- 合并单元格表示跨天。
- 连续重复文本表示跨天。
- 项目名在标题、sheet、文件名或左侧列中。

### 6.2 不适合程序硬解析的情况

- 日期和任务完全混在自然语言里。
- 单元格里写大量说明，任务边界不清。
- 没有明确日期行。
- 任务需要复杂语义判断才能知道是否是排期。
- 一个单元格里包含多个不同日期范围。

这些情况仍应优先交给 AI，或由程序生成低置信草稿并要求用户确认。

## 七、预期收益

对本轮 4 类样本，程序硬解析预计能生成可用草稿：

- 日期列识别：高成功率。
- 单日任务提取：高成功率。
- 合并单元格跨天任务：高成功率。
- 连续重复任务合并：中高成功率。
- 项目名推断：中高成功率。
- 复杂语义合并：中等，需要用户预览修正。

作为 AI 失败兜底，价值很高：

- 不会 60-90 秒后直接空失败。
- Excel 导入稳定性提升。
- 成本下降。
- 用户至少能拿到一版可编辑草稿。

### 8.3 不直接入库

程序硬解析结果和 AI 结果一样，必须先进入草稿预览。

禁止：

- 程序解析后直接创建项目/排期。
- 用户未确认就入库。

### 8.4 性能

Excel 程序硬解析应在本地/后端快速完成。

目标：

- 单个 Excel 解析时间 < 2s。
- 大文件也应有明确错误提示，不阻塞页面。

### 10.2 兜底触发条件（已实现）

1. AI 抛 `AiParseError`（超时 / JSON 解析失败 / 调用失败）且文件为 Excel → 启用程序硬解析。
2. AI 正常返回但 `items` 与 `projects` 均为 0（空草稿）→ 启用程序硬解析。
3. 程序解析产出为空 → 仍抛 AI 错误，前端展示原错误。

图片文件不参与程序兜底（`kind !== "excel"` 时原样走 AI），符合「程序兜底只覆盖周历横排 Excel」的边界。

### 10.3 4 个样本程序解析结果

本地对 4 个真实排期 Excel 执行 `parseExcelSchedule` 的实测：

| 样本 | sheet 处理 | 项目数 | 条目数 | 跨天条数 | 是否识别日期行 | 是否使用合并单元格 | 耗时 |
|---|---|---|---|---|---|---|---|
| HW V+ ID视频-时间表0802.xlsx | 1 | 1（HW V+ ID视频） | 30 | 12 | 是 | 是 | 13ms |
| Aoiiena-制作时间表.xlsx | 1 | 1（Anoval） | 27 | 15 | 是 | 是 | 3ms |
| HONOR LINDY CMF时间表.xlsx | 1 | 1（Lindy CMF） | 17 | 4 | 是 | 是 | 6ms |
| HUAWEI Laputa_MG&APK时间表_0622.xlsx | 多 sheet | 5（产品制作 / MG澜盾 / MG红枫/开合 / MG红枫/开合/澜盾 / APK视频） | 57 | 29 | 是 | 是 | 4ms |

样本共性覆盖验证：

- 日期行识别：4/4 全部命中（≥5 连续日期单元格规则）。
- 项目名推断：标题 / sheet 名 / 文件名 / 左侧项目列均生效；Laputa 多 sheet 文件正确按左侧项目列拆出 5 个项目分组。
- 合并单元格跨天：4/4 命中，跨天条数 4-29 条不等；Laputa 中存在「合并 span 内有独立值」的复杂情况，解析器按「值优先，合并 span 只到值前一列」处理，避免吞掉信息。
- 连续重复文本：任务在同文本连续列出现时合并为一条跨天排期。
- warnings：每文件 1 条兜底标识（`PROGRAM_FALLBACK_USED: AI 识别未及时返回，已使用 Excel 程序解析生成草稿，请确认。`）。
