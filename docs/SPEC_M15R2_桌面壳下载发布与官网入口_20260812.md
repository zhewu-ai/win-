# SPEC M15 R2：桌面壳下载发布与官网入口

日期：2026-08-12

状态：新增需求，待技术部处理

## 一、背景

用户在 Mac 上测试 Tauri 桌面壳后确认：Mac 壳已经可以使用，体验不错。

但当前出现新的产品化问题：

1. 关掉 Mac 壳后，不知道从哪里重新下载。
2. 官网 `/download` 下载页没有 Mac 版本入口。
3. 下载页的 Windows 直链仍绑定旧版本 `v0.1.0`，没有跟随 GitHub 最新 Release 更新。
4. 壳内没有明显入口告诉用户网页版 / 官网地址。
5. 技术部把 Mac 壳做出来了，但发布、下载、版本说明没有同步。

这说明桌面壳已经从“内部测试工具”进入“可用产品能力”，需要补齐发布和入口闭环。

## 二、当前检查结果

### 2.1 下载页仍是旧 Windows 单入口

当前：

- `src/lib/downloads.ts` 中 `DESKTOP_WINDOWS_INSTALLER_URL` 写死：

```text
https://github.com/zhewu-ai/win-/releases/download/v0.1.0/StickyNotes_0.1.0_x64-setup.exe
```

- `src/app/download/page.tsx` 页面标题和按钮只面向 Windows：

```text
PinNote 桌面版
Windows 桌面应用
下载 Windows 安装包
适用于 Windows 10/11
```

问题：

- 用户访问下载页，只能下载旧 Windows 版本。
- 页面没有 Mac 入口。
- 页面没有说明最新版、更新时间、当前壳能力。

### 2.2 GitHub Release 最新可见版本仍偏旧

GitHub Release 页面当前可见：

- 最新 Release：`全平台便签 v0.1.1`
- 发布时间：2026-08-06
- Release 内容仍是 Windows 桌面壳自动构建说明。

这和当前代码里的 M15 拖拽上传、Mac 壳可用状态不一致。

需要技术部确认：

- M15 桌面壳构建是否已经生成正式 Release。
- Mac 构建产物是否只是本地 `tauri dev / tauri build`，还没有上传 GitHub Release。
- Windows workflow 是否因为 `src-tauri/tauri.conf.json` 版本仍是 `0.1.1`，导致重复 tag / draft release / 没有新可见发布。

### 2.3 版本号不一致

当前存在多个版本源：

- `package.json`：`1.0.0`
- `src-tauri/tauri.conf.json`：`0.1.1`
- `src-tauri/Cargo.toml`：`0.1.0`
- 下载页直链：`v0.1.0`
- GitHub 最新可见 Release：`app-v0.1.1`

这会直接导致：

- 用户不知道哪个是最新版。
- GitHub Actions tag 不一定能正确生成新版本。
- 下载页容易长期指向旧包。
- 技术部口径不一致。

## 三、目标

本轮目标不是继续扩功能，而是补齐桌面壳产品化闭环：

1. 下载页同时支持 Windows 和 Mac。
2. 下载入口不再写死旧版本。
3. GitHub Release 有明确最新版。
4. Mac 壳产物可下载。
5. 壳内提供“打开网页版 / 官网”入口。
6. 版本号统一。

## 四、需求 1：下载页改版

### 4.1 页面内容

`/download` 页面改为“桌面版下载中心”。

应显示：

```text
PinNote 桌面版
Windows / Mac
```

下载按钮：

```text
下载 Windows 版
下载 Mac 版
查看所有版本
```

如果 Mac 包暂未正式发布，则不要隐藏问题，应显示：

```text
Mac 版内测中，暂未开放下载
```

或：

```text
Mac 版待发布
```

不要让用户以为没有 Mac 壳。

### 4.2 下载链接策略

短期建议：

- 主要按钮不要直连旧具体资产。
- 优先链接 GitHub 最新 Release 页面：

```text
https://github.com/zhewu-ai/win-/releases/latest
```

或者分别配置：

```ts
DESKTOP_WINDOWS_DOWNLOAD_URL
DESKTOP_MAC_DOWNLOAD_URL
DESKTOP_RELEASES_URL
```

如果要直连资产，必须每次发版同步更新，不允许继续停留在 `v0.1.0`。

### 4.3 页面验收

1. `/download` 页面有 Windows 和 Mac 两个区域。
2. Windows 不再指向旧 `v0.1.0` 安装包，除非明确说明“旧版”。
3. Mac 若已发布，有可点击下载入口。
4. Mac 若未发布，显示“内测中 / 待发布”，而不是完全没有。
5. “查看所有版本”进入 GitHub Releases。
6. 390px / 320px 下不横向溢出。

## 五、需求 2：Mac 壳发布

### 5.1 产物要求

Mac 至少提供一个用户可理解的下载产物：

- `.dmg`，优先推荐。
- 或 `.app.tar.gz`，仅作为备用。

下载页文案需要说明：

```text
适用于 macOS。首次打开如提示安全限制，请在系统设置中允许打开。
```

如果未签名 / 未公证，需要明确标注“内测包”。

### 5.2 GitHub Actions

当前只有：

```text
.github/workflows/build-windows.yml
```

建议新增：

```text
.github/workflows/build-mac.yml
```

或改成矩阵构建：

```text
windows-latest
macos-latest
```

要求：

- Windows 和 Mac 都上传 artifact。
- 正式 release 里能看到对应平台资产。
- Mac 构建失败不应静默。
- Release 文案区分平台。

### 5.3 验收

1. GitHub Actions 产出 Mac 包。
2. GitHub Release 能看到 Mac 资产。
3. 下载页 Mac 按钮可打开或下载。
4. 用户从下载页下载 Mac 包后能重新打开壳。
5. Mac 壳加载生产站点。
6. Mac 壳内拖拽上传仍可用。

## 六、需求 3：版本号统一与发版规则

### 6.1 统一版本源

技术部需要明确桌面壳版本号来源。

建议：

- `src-tauri/tauri.conf.json` 作为桌面壳版本源。
- `src-tauri/Cargo.toml` 同步为相同版本。
- Release tag 使用：

```text
app-v0.1.2
```

下一次包含 M15 拖拽 + Mac 壳可下载的正式包，建议发：

```text
0.1.2
```

### 6.2 发版规则

每次桌面壳能力变化，必须：

1. bump `src-tauri/tauri.conf.json` version。
2. bump `src-tauri/Cargo.toml` version。
3. GitHub Actions 生成新 tag。
4. Release 标题写清平台和能力。
5. `/download` 页面同步。

### 6.3 验收

1. 代码版本、Release tag、下载页展示版本一致。
2. 不再出现页面直链旧版本的问题。
3. 用户能判断哪个是最新版。

## 七、需求 4：壳内显示官网 / 网页版入口

### 7.1 当前问题

用户进入桌面壳后，有时想找网页版地址，但不知道官网在哪里，需要翻聊天记录。

壳内应该提供一个稳定入口：

```text
打开网页版
```

或：

```text
官网 / 网页版
```

点击后用系统浏览器打开：

```text
https://notes.hello-mylife.online
```

### 7.2 入口位置

建议放在账户菜单里，靠近“反馈问题 / 下载桌面版 / 外观”区域。

Web 浏览器中：

- 可以显示“下载桌面版”。

Tauri 壳中：

- 不显示“下载桌面版”。
- 显示“打开网页版”。

### 7.3 技术实现

当前已有：

- `src/lib/tauri.ts`
- `openExternal(url)`
- Tauri command：`open_external`
- 权限：`allow-open-external`

所以壳内入口可以复用现有能力，不需要新增 Rust command。

建议新增常量：

```ts
export const WEB_APP_URL = "https://notes.hello-mylife.online";
```

不要把官网 URL 散落在多个组件里。

### 7.4 验收

1. Mac 壳账户菜单能看到“打开网页版”。
2. 点击后用系统默认浏览器打开 `https://notes.hello-mylife.online`。
3. Windows 壳同样可用。
4. 普通浏览器中不显示“打开网页版”，避免重复。
5. 普通浏览器中仍显示“下载桌面版”。
6. 该入口不影响退出登录、反馈、外观切换。

## 八、当前产品口径

在本轮补齐前，建议口径：

```text
Mac 壳已具备可用性，但暂未完成正式下载发布。

```

补齐后口径：

```text
桌面版支持 Windows / Mac。可从 /download 下载，壳内可一键打开网页版。
```
