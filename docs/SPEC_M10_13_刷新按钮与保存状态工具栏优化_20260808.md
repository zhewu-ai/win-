# M10.13 方案：刷新按钮与保存状态工具栏优化

日期：2026-08-08

## 一、背景

M10.12 已补了跨设备手动刷新入口，但当前编辑区工具栏在窄宽度/桌面壳缩小时出现视觉问题：

- 刷新按钮被「已保存」状态占位挤到偏中间位置，右侧工具区不够稳定。
- 「已保存」属于低价值常态信息，长期显示会占用工具栏空间。
- 用户真正需要的是明确可点的刷新按钮，以及异常时能看到保存/同步状态。

本轮只做 UI 信息层级调整，不改 M10.12 的刷新逻辑、不改数据库、不改账号体系。

## 二、产品决策

常态隐藏「已保存」，把稳定位置让给刷新按钮。

保留保存状态组件，但改变展示策略：

- 正常状态：不显示「已保存」文字，也不占固定宽度。
- 异常/过程状态：才显示保存/同步提示。
- 刷新按钮：常驻显示，作为明确的手动拉取入口。

理由：

- 「已保存」只能说明本机内容已保存，不能说明多端最新；常驻展示价值低。
- 刷新是用户主动解决跨设备可见性的核心动作，应占据稳定且容易找到的位置。
- 窄窗口下工具栏应优先保证高频操作按钮稳定排列，不被状态文案推挤。

## 三、目标效果

编辑区工具栏右侧建议排序：

1. 刷新按钮
2. 置顶便签
3. 窗口置顶（仅桌面壳）
4. 更多操作

保存状态的展示规则：

| 状态 | 是否显示 | 文案/形态 |
|---|---|---|
| saved + synced/无 pending | 不显示 | 不占位 |
| saving | 显示 | 小点 +「保存中」或仅脉冲点 |
| error/localError | 显示 | 红点 +「保存失败」+ 重试 |
| pendingCreate/pendingUpdate/pendingDelete | 显示 |「等待同步」或离线提示 |
| syncError | 显示 |「同步失败，内容已保存在本地」 |

刷新按钮展示规则：

- 网页端和桌面壳都显示。
- 使用圆形箭头图标。
- tooltip/aria-label：`刷新便签`。
- 刷新中：图标旋转、按钮禁用。
- 刷新失败：走 M10.12 已有 toast，不在工具栏挤出长文案。

## 四、改动范围

预计涉及：

- `src/components/SaveStatus.tsx`
  - 增加常态隐藏逻辑：当 `status === "saved"` 且无 pending、无 syncError、在线正常、非 syncing 时返回 `null`。
  - 只在保存中、失败、离线 pending、等待同步、同步失败时渲染。

- `src/components/NoteEditor.tsx`
  - 移除或缩小保存状态的固定宽度容器。
  - 将刷新按钮放到右侧主按钮组的稳定位置。
  - 不要让隐藏的保存状态继续占 `w-14` 一类固定空间。
  - 在 `toolbarMode === "minimal"` 时也优先保留刷新按钮。

- `src/components/Sidebar.tsx`
  - 保留 M10.12 搜索区刷新按钮。
  - 确认搜索输入、清空按钮、刷新按钮、折叠按钮在 320px 下不重叠。

可选：

- 若仍想给用户“保存完成”的反馈，可在保存完成时短暂 toast 或弱提示 0.8-1 秒，但不得常驻占工具栏空间。
- 不建议把刷新动作绑定到「已保存」文字上；保存状态和远端刷新是两个不同语义。

## 五、交互细节

### 正常状态

用户编辑完成并保存成功后：

- 工具栏不显示「已保存」。
- 刷新按钮保持在右侧稳定位置。
- 底部「最后编辑于」仍保留，不受影响。

### 保存中

用户正在输入或 debounce 保存中：

- 可以显示小型「保存中」状态。
- 状态提示不得推动刷新按钮明显横移。
- 建议状态区域使用 `absolute`、固定小宽度、或放在刷新按钮左侧但只在有状态时出现。

### 保存失败

保存失败时：

- 必须显示明显错误状态。
- 保留重试入口。
- 不允许因为隐藏常态保存状态而让保存失败不可见。

### 离线/等待同步

本机有 pending 队列时：

- 必须显示等待同步/离线提示。
- 同时保留刷新按钮，但刷新点击应沿用 M10.12 的刷新前保护逻辑。

## 六、验收标准

### 视觉布局

1. 桌面双栏宽窗口：刷新按钮在编辑区工具栏右侧，和置顶/更多按钮成组排列。
2. 桌面壳缩小窗口：刷新按钮不被「已保存」挤到中间。
3. 320px 宽度：刷新、置顶、更多按钮不重叠，不溢出，不遮挡返回按钮/颜色按钮。
4. 常态保存成功时，工具栏不显示「已保存」文字。
5. 按钮 hover/disabled/刷新中旋转状态正常。

### 功能回归

1. 点击刷新仍能拉到其他设备新建的便签。
2. 点击刷新仍能拉到同一便签远端新内容。
3. 刷新前仍会保护本机未保存输入。
4. 保存失败时仍能看到错误提示和重试入口。
5. 离线 pending 时仍能看到等待同步提示。

### 抽搐观察

1. 常态保存成功后静置 5 分钟，工具栏不因「已保存/同步中」文字出现消失而横跳。
2. 若仍抽搐，继续按 M10.12 的 ResizeObserver / sync 状态方向排查。

## 七、不做事项

- 不做自动低频拉取。
- 不做 WebSocket/SSE。
- 不做冲突合并。
- 不改 M10.12 刷新前保存保护逻辑。
- 不改生产数据和 schema。

## 八、上线注意

- 本轮是前端 UI 调整，仍需 `npx tsc --noEmit` 和 `npm run build -- --webpack`。
- 生产共享 VM 构建继续使用 webpack，不使用 Next 16 默认 Turbopack。
- 上线后请在网页端和桌面壳各验一遍 320px/窄窗口布局。
