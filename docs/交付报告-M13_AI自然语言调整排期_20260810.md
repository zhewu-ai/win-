# M13 交付报告：AI 自然语言调整排期

日期：2026-08-10

## 一、交付内容

按 `docs/SPEC_M13_AI自然语言调整排期_20260810.md` 实现 AI 自然语言调整排期最小闭环。管理员在工作日历右侧面板选项目 + 输入一句话（如「DCO 确认提前一天，A 修改顺延一天」），AI 生成结构化变更草稿，用户逐条勾选 / 跳过 / 手动改标题与起止日期后确认，才写入排期。

- **入口**：工作日历右侧面板「导入排期」次级区下方新增「AI 调整排期」入口（独立于文件导入，默认折叠）。选项目（默认当前选中项目）+ 一句话描述 + 范围天数（7-60，默认 30）→ 生成草稿。
- **只读 AI，绝不写库**：`POST /api/calendar-adjustments/preview` 只生成草稿；`POST /api/calendar-adjustments/apply` 在用户确认后才事务写入。两条链路独立，AI 结果必须经用户确认。
- **草稿形态**：`summary`（一句话说明）+ `confidence`（high/medium/low）+ `warnings`（提示）+ `changes`（新增 / 修改 / 不变）。每条变更带原→新值、AI 理由、真实 itemId，可直接校验。
- **低置信度保护**：置信度低且无可用变更时返回「需要补充信息」，引导用户补充目标节点 / 提前或推迟 / 目标日期，不强行生成。
- **AI 上下文裁剪**：只传项目名、当前日期、用户指令、该项目未来 14-30 天 + 近 7 天排期，不暴露全量数据；不改历史排期（除非用户明确要求）。
- **权限**：两个 API 均 `requireAdmin()`；入口仅在管理员可见的工作日历中。

## 二、关键设计

1. **双端点拆分**：preview 纯读 AI（生成草稿，调一次模型）；apply 纯写库（不调 AI，逐条重新校验后事务写入）。避免「AI 直接写库」风险，与 M13 导入同款「预览 → 确认」安全模式。
2. **模型回退链**：`SILICONFLOW_SCHEDULE_ADJUST_MODEL` → `SILICONFLOW_EXCEL_MODEL` → `SILICONFLOW_MODEL`（文字模型，非 VL）。`resolveTextModel("adjust")` 实现，新增环境变量可独立路由。
3. **apply 全量预校验**：事务前先 `findMany` 拉取所有 update 目标 itemId，校验存在且属于当前项目且未删除（软删走 `deletedAt`），任一不满足即 `ITEM_NOT_FOUND` 整体拒绝；日期倒置、超长标题 / 理由逐条过滤。
4. **noop 变更**：AI 可返回「不变」项说明哪些排期不需要动，前端折叠展示为弱化卡片，不计入可应用变更。
5. **脱敏日志**：不打印指令原文、草稿内容、模型 key；只记请求 id、项目 id、变更条数。

## 三、架构与实现要点

- **`src/lib/schedule-adjust.ts`**：`generateAdjustmentDraft(input)` 组装 system/user prompt（日期上下文、原则：只改当前项目、不改历史、低置信度给空变更 + 提示、不做删除）；`normalizeAdjustDraft(raw, projectId)` 强制 create 归属请求项目、`normalizeDate` 宽松日期归一、非法项转 warnings。
- **preview 路由**：校验项目归属（`isProjectOwnedBy`，含 `deletedAt`）→ 取该项目 future（`startDate ≤ 今天+range && endDate ≥ 今天`）与 recent（`startDate ∈ 近7天`）排期 → `generateAdjustmentDraft`。
- **apply 路由**：校验项目归属 → changes 非空 ≤100 → 逐条类型 / 标题 ≤120 / 日期合法 / `endDate ≥ startDate` / 理由 ≤200 / update 需 itemId → 预校验 itemId 全量存在归属 → 事务：create 项 `type = startDate===endDate ? "node" : "range"`、`status:"todo"`、`source:"ai_adjust"`；update 项改标题 / 起止日期。
- **前端 `AdjustPreviewPanel`**：置信度徽标（高绿 / 中黄 / 低红）+ usage（模型 · 耗时）+ summary + 提示块 + 变更卡（新增绿 / 修改蓝 / 不变灰；勾选框应用 / 跳过；标题与起止日期可编辑；修改项展示原→新；AI 理由）+ 底部「确认更新排期（N）」/ 取消。`skipped` Set 与 `edits` Record 驱动 `appliedChanges` 派生。
- **`WorkRightPanel`**：新增「AI 调整排期」折叠区（选项目 + 文本域 + 生成草稿 / 收起）；`adjustDraft` 时切换到 AdjustPreviewPanel；apply 成功后清除草稿、刷新项目与排期。
- **`CalendarPageClient`**：`adjustState {busy, error, draft, usage}`；`handleAdjustPreview` / `handleApplyAdjustment` / `handleCancelAdjust` 回调透传给右栏。

## 六、风险与后续建议

- **AI 返回不可靠变更的兜底**：apply 端逐条校验 + 事务，越界 / 无效条目整体拒绝；AI 不直接写库，风险可控。
- **模型偶尔改历史**：prompt 明确「默认不动历史排期」，但非强约束；如出现误改历史，可进一步在 prompt 输出约束里加「startDate < 今天 的变更需单独提示」。
- **多项目联调**：当前只允许选单个项目调整（SPEC §十一 明确不做跨项目）。未来可扩展「本次调整涉及多项目」时拆成多次预览 / 应用。
- 无 schema 变更，复用 `WorkScheduleItem.source` 预留字段；不涉及数据迁移。
