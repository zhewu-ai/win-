## 本轮验收重点

### 1. 布局断点（双栏固定 350 / <720 单栏）

验证点：

1. 打开 App，窗口拖到 **≥720px** 宽（如 1000 / 800）：侧边栏**固定约 350px**，窗口缩放侧栏宽度不变；编辑器够宽时工具栏显示完整文字（便签/待办）+ 5 色球 + 保存文案。
2. 在 **≥720px** 区间（900↔720）来回拖动：侧边栏**不再自动变宽/变窄**，彩色球不会因侧栏变化而跳动。
3. 点侧边栏顶部「收起侧边栏」→ 收起；点右侧展开条 → 恢复，状态被记住。
4. 拖到 **<720px**：切换为**单栏**——列表全宽；点开一条便签，列表隐藏、编辑器全宽、顶部出现返回箭头；点返回回列表。
5. 在 720 断点来回拖动：只切换一次，无来回横跳。

证据要求：≥720 区间拖动一段录屏（确认侧栏恒定 350、彩色球不跳）+ 单栏截图一张。

### 2. 工具栏三态（按编辑器宽度）

验证点：

1. 打开任意便签编辑，把编辑器（窗口）宽度在 **520px 以上 / 360–519px / 360px 以下** 三档之间拖动。
2. spacious（≥520）：工具栏整行显示「便签 / 待办」文字、5 个色球、保存文字、分割线。
3. compact（360–519）：文字和色球收起——只留**一个色板按钮**（点击弹出 5 色弹层），保存状态变**圆点**，无文字。
4. minimal（<360）：只剩纯图标；点「⋯」更多菜单，里面应有 **5 色颜色行** + 置顶便签 / 归档 / 删除；从菜单里改色应生效并自动关闭菜单。
5. 在 520 / 360 断点附近微调窗口：工具栏形态**只切换一次**，不来回横跳（已加 20px 迟滞：520 进入、500 退出；360 进入、340 退出）。
6. 全程工具栏始终**一行**、**不竖排**、**不横向溢出**。

证据要求：三档宽度各截图一张 + 断点附近微调的录屏一段。

### 3. 窄窗口不横向裁切（260px 重点）

验证点：

1. 把窗口一路缩到最小（约 260px）。
2. 新建/打开一条**待办（checklist）**便签：编辑区应整宽显示，**右侧不被裁掉**，无横向滚动条。
3. 普通文本便签同复测。
4. 列表侧栏 / 编辑器之间无元素跑出窗口右缘。

证据要求：260px 下待办便签截图一张，确认无裁切、无横向滚动。

### 4. 过渡动画（顺带确认不突兀）

验证点：

1. 宽度在断点附近来回拖动：工具栏文字/图标切换时**淡入**，不是硬切闪跳。
2. 打开「⋯」更多菜单 / 色板弹层：轻微上浮 + 缩放弹出。
3. 收起/展开侧边栏：宽度平滑过渡（约 150ms），不是瞬变。

证据要求：拖动断点的录屏一段（3–5 秒即可）。

## 常见问题

**Q：以前缩到 520px 才进单栏，现在 <720px 就单栏了？**
A：对。M8.5 的 520/580 迟滞已升级为更明确的 720 断点——720px 以下按单栏布局是更符合移动/窄窗习惯的稳定方案，且断点处只切换一次、不横跳。

**Q：为什么工具栏要按"编辑器宽度"而不是"窗口宽度"？**
A：编辑器实际可用宽度受侧栏是否收起、窗口宽度共同影响。按编辑器宽度判断，收起侧栏后工具栏能提前回到更宽的状态，更稳定可预测。

**Q：以前窗口缩小时侧栏会自动变窄/消失，现在为什么不动？**
A：双栏区间（≥720px）侧栏宽度固定 350px，只由手动折叠按钮控制并记住状态。窗口缩放不再自动改变侧栏，避免编辑器宽度骤变引起工具栏彩色球跳动；<720px 窄窗因放不下双栏，仍自动进单栏。

**Q：在 520px 附近微调，工具栏怎么有时候不变、有时候变？**
A：加了 20px 迟滞——进入舒展态要 ≥520px、退出到 <500px；进入紧凑态 ≥360px、退出到 <340px。在迟滞区间内（500–519 / 340–359）保持当前形态，不会在断点边缘来回横跳。

**Q：macOS 上缩到 260px 不裁切，Windows 上也会吗？**
A：裁切根因是 Web 通用问题（textarea 固有最小宽），已从样式层修复，两个平台同样生效。但建议在 Windows WebView2 实机复核一次。
