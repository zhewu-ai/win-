## 二、下一轮必须处理的问题

### 2.1 左侧列表卡片尺寸统一

现象：

- 左侧便签/待办列表里，不同卡片因为文本长度不同，宽度或高度看起来不统一。
- 长文本撑开视觉节奏，列表显得不整齐。

要求：

- 普通便签/待办卡片宽度、高度、圆角保持一致。
- 长文本超出后截断，不撑开卡片。
- 标题、摘要最多显示固定行数。
- 日历入口卡片可以例外，但普通列表卡片必须统一。

验收：

- 同一列表中所有普通卡片视觉尺寸一致。
- 长标题/长摘要不会撑宽或撑高卡片。
- 320px/390px 下不横向溢出。

### 2.2 选中态必须互斥

现象：

- 选中某条便签/待办后，再点击“工作日历”，工作日历高亮了，但之前的便签/待办仍保持高亮。
- 用户会误以为两个对象同时处于选中状态。

要求：

- 右侧工作区同一时间只能有一个主对象选中：
  - 便签
  - 待办
  - 工作日历
- 选中工作日历时，清除左侧便签/待办选中态。
- 再选中便签/待办时，工作日历选中态取消。

验收：

- 点击便签 A，只有便签 A 高亮。
- 点击便签 B，高亮从 A 移到 B。
- 点击工作日历，便签 B 高亮消失，只有工作日历高亮。
- 再点击便签，工作日历高亮消失。

### 2.3 日历右侧操作栏默认不常驻占空间

现象：

- 工作日历右侧一直显示“添加排期”“新增项目”等操作区，占据空间。
- 用户只是查看日历时，这些操作会造成干扰。

要求：

- 右侧操作区默认弱化或收起。
- 仅在以下场景展开：
  - 用户点击“添加排期”。
  - 用户点击某个项目。
  - 用户点击某条排期。
- 没有选中对象时，右侧不要长期占用大块空间。

可选方案：

- 桌面端：右侧详情面板可折叠。
- 窄屏：改为抽屉。
- 默认只保留一个小按钮或轻量入口。

验收：

- 进入工作日历默认查看时，主要空间留给日历。
- 点击项目/排期后，详情面板出现。
- 关闭详情后，日历主体恢复空间。

### 2.4 顶部布局压缩

现象：

- “今日 / 月 / 周”“今天/昨天”“日期”“左右切换”等控件横向挤在一起。
- 窗口缩小时顶部过密，影响阅读。

要求：

- 顶部控件重新分层或压缩。
- 视图切换不一定必须横向长排，可以用更紧凑的 segmented control 或下拉。
- 日期导航建议压缩为：

```text
‹ 8月10日 ›    日 / 周 / 月
```

- “今天”只作为辅助按钮，不占主层级。
- 不要把所有操作按钮都堆在同一行。

验收：

- 1440px 下顶部清爽。
- 720px 以下不拥挤。
- 390px/320px 下不会出现一排按钮挤压正文。

### 2.5 月视图改为连续月份滚动

现象：

- 当前月视图更像单月切换。
- 用户预期是上下连续滚动不同月份，更符合时间线和排期回看。

要求：

- 月视图可考虑改为连续月份流。
- 上下滚动能看到前后月份。
- 当前月/今天要有明确定位。
- 不要求一次加载无限月份，可先加载当前月前后若干个月。

验收：

- 在月视图中向下滚动可以看到下个月。
- 向上滚动可以看到上个月。
- 今天定位清楚。

### 2.6 月视图加入便签链接层

现象：

- 月视图只显示排期时，不能体现“工作日历把便签串起来”的目标。

要求：

- 月视图除了排期，也应显示当天创建/更新的便签链接。
- 点击某一天可进入该日视图，看到当天排期和便签。
- 便签链接层必须可关闭。

验收：

- 某天创建/更新便签后，月视图当天有便签链接提示。
- 点击当天进入日视图。
- 日视图能看到该天排期和便签。
- 关闭便签链接层后，月/周/日都隐藏便签链接。

### 2.7 “今日”命名改为“日”

现象：

- 点击历史日期后，页面仍叫“今日”，语义不对。

要求：

- 顶部视图 tab 改为：
  - 日
  - 周
  - 月
- 只有日期等于今天时，页面内部才显示“今天”。
- 历史日期显示具体日期，例如：

```text
8月9日 · 周五
```

验收：

- 今天进入日视图，可显示“今天”。
- 点击历史日期进入日视图，不再显示“今日”，而是具体日期。

### 2.8 日历最小尺寸只作用于日历内部

现象：

- 月历横向缩小时日期格变得很扁。
- 但如果粗暴给全局设置最小宽度，可能影响便签/待办的最小可用尺度。

要求：

- 日历最小列宽、最小格高只作用于 `CalendarPageClient` 内部。
- 不得影响：
  - `NoteEditor`
  - `ChecklistEditor`
  - 左侧便签列表
- 切回便签/待办时，不保留日历尺寸限制。

验收：

- 日历月视图缩小时，日期格仍可读。
- 切回便签/待办后，窗口仍能缩到当前可接受的最小尺度。
- 日历内部可以滚动，但不能把全局布局撑坏。

### 2.9 窄宽专注模式

产品判断：

- 窗口缩到很小时，用户主要是看标题、待办和当天内容。
- 顶部大块工具区会增加心智干扰。

要求：

- 当日历工作区宽度低于某个阈值，例如 520px 或 480px，进入窄宽专注模式。
- 默认收起：
  - 大标题。
  - 解释性文案。
  - 项目筛选。
  - 次要操作按钮。
- 只保留极简栏：

```text
‹ 8月10日 ›    日 / 周 / 月
```

- 用户 hover、点击展开按钮或触碰顶部区域时，再展开完整工具栏。

范围限制：

- 先只给工作日历做。
- 不强制改便签/待办现有体验。

验收：

- 窄宽下顶部明显更精简。
- 用户仍能切换日/周/月。
- 用户仍能展开操作区。
- 便签/待办不受影响。

### 2.10 侧边栏顶部空间优化

现象：

- 当前侧边栏顶部存在刷新按钮，占用横向和纵向空间。
- 下方已有“横向三个点 / 选择便签”按钮，点击后会出现“全选”“删除”等批量操作选项，可以承载次要操作。
- 工作日历作为有效信息入口时，顶部空间越紧凑越好。

要求：

- 评估移除侧边栏顶部独立刷新按钮。
- 将刷新能力放入“横向三个点 / 选择便签”菜单或等价批量操作菜单中。
- 顶部只保留搜索和必要主入口，减少占位。
- 不得删除刷新功能本身，只是降低常驻视觉优先级。

验收：

- 侧边栏顶部空间更紧凑。
- 刷新仍可通过“横向三个点 / 选择便签”菜单触发。
- 320px/390px 下日历入口上方不出现多余挤压。

### 2.11 多选状态隐藏搜索框

现象：

- 进入多选状态后，顶部仍保留“搜索便签”区域。
- 多选时用户主要进行删除/取消等批量操作，搜索框暂时没有必要。
- 搜索框保留会在日历/列表有效信息上方形成一个奇怪空格。

要求：

- 进入多选状态时，暂时隐藏“搜索便签”。
- 多选工具条接管顶部区域，例如显示：

```text
已选 3 条    删除    取消
```

- 完成删除或退出多选后，搜索框恢复。
- 不影响普通浏览状态的搜索功能。

验收：

- 进入多选后，搜索框消失。
- 多选操作区不留奇怪空白。
- 删除完成后，搜索框恢复。
- 取消多选后，搜索框恢复。
