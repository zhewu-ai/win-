## 二、程序是怎么封装的（讲人话版）

**整体架构 = 一个网页 + 一个壳**

- **网页版**：全平台便签的全部功能（登录、便签、待办清单、图片、回收站、搜索）都在线上网页：
  https://notes.hello-mylife.online
- **Windows 桌面壳**：用 **Tauri**（Rust 编写的一个轻量桌面封装技术）把一个浏览器内核包进 Windows 程序。桌面壳打开后加载的就是上面的线上网页。

由此带来的三个特点：

1. **手机 / 网页 / Windows 桌面用的是同一套账号和数据** —— 没有独立的桌面端数据库。
2. **改线上 = 桌面打开就是最新版** —— 桌面程序本身不含业务逻辑，只是一层"壳"（但需要联网）。
3. **桌面壳专门补齐了网页做不到的能力** —— 比如把窗口贴在其它软件上方（置顶）、打开很小的一块悬浮窗常驻桌面。

**两种窗口**

| 窗口 | 用途 | 大小 |
|------|------|------|
| 主窗口 | 完整管理（列表、搜索、回收站、归档） | 默认 1100×760，最小可缩到 320×480 |
| 悬浮窗（极小模式） | 单条便签贴在桌面上 | 默认 360×520，最小可缩到 260×340 |

- 主窗口里点「极小模式」→ 弹出悬浮窗（只显示当前这一条便签，可置顶）。
- 安装包由 GitHub 自动构建（CI）生成，发布在 Release 页面，当前版本 v0.1.0。

## 三、这两轮干了什么

### 第一轮：QA 复验问题单的 3 个 P0

| 问题 | 现象 | 修复内容 |
|------|------|----------|
| 置顶不生效 | App 能打开，但窗口无法保持在其他软件前方 | 主编辑页新增「窗口置顶」按钮；操作失败不再静默吞掉（会提示） |
| 缺少极小模式 | 打开后更像完整网页，没有适合挂在桌面上的小窗口 | 「极小模式」按钮在网页端和桌面壳都可见，点击打开单条便签的悬浮窗 |
| 图片无法单独删除 | 删除入口不可见 / 不可用 | 删除按钮改为始终可见（不再悬停才出现）；预览大图里也加了删除入口；失败提示带错误码 |

### 第二轮：针对实机反馈（"窗口缩不下去 + 置顶还是不行"）

| 问题 | 根因 | 修复内容 |
|------|------|----------|
| 窗口缩不下去 | 桌面程序写死了最小尺寸（主窗口 900×600），而网页端缩放浏览器没有这个限制 | 主窗口最小尺寸放宽到 **320×480**，悬浮窗放宽到 **260×340**，与网页端缩放行为一致 |
| 置顶还是无效 | Windows 的 WebView2 初始化时会把"置顶"标志丢掉（这是一个已知的技术坑），导致窗口看着置顶了、实际没有 | 悬浮窗创建后强制再设置一次置顶并延迟重试；首次打开**默认置顶**，只有用户手动取消后才记录为关闭状态 |

## 五、需要产品部配合做什么

1. **下载新安装包实机验收**（先卸载旧版再安装，避免缓存残留）。
2. 重点验证三条：
   - 悬浮窗能否在其它软件（浏览器 / AE / C4D / 资源管理器）前方置顶，含 Alt+Tab 切换后仍不遮挡；
   - 主窗口能否直接缩到很小（约 320px 宽）、悬浮窗能否缩到很小（约 260px 宽）；
   - 便签里多张图片能否单独删除、刷新后仍然删除。
3. 完整验收步骤和证据要求见《M7_WINDOWS_ACCEPTANCE_GUIDE_20260803.md》。

## 六、需要知道的边界

- **桌面壳必须联网**：它加载的是线上网页，没有离线功能。
- **Windows 置顶效果以实机为准**：本地只能保证代码和构建正确，最终行为要实机确认。
- **如果实机还有问题**：现在报错不会静默，请把弹出的提示文字 / 控制台报错贴回给我们，能大幅加快定位。
- 本轮不做、也不在本轮范围：邮箱注册登录、多用户权限、图片排序/标注、Mac 壳、离线同步。
