## 1. 结论摘要

本轮按更新后的 SPEC_M10_7（人工邮箱验证找回密码 + 用户修改密码）完成两项交付：

**A. 人工邮箱验证找回密码**（上轮已完成并上线）：

**B. 已登录用户修改密码**（本轮新增，人工找回闭环的关键收尾）：

## 5. 用户流程与管理员操作规范

### 5.1 用户忘记密码流程

1. 登录页点「忘记密码？」→ `/forgot-password`。
2. 阅读说明 → 复制管理员邮箱与邮件模板。
3. 用**账号绑定邮箱**发送邮件至 `yan251@foxmail.com`（标题 `PinNote 密码重置申请`，正文写明账号邮箱并确认需要重置密码）。
4. 等待管理员核验后回复临时密码。
5. 用临时密码登录，登录后从账号菜单「修改密码」改成自己的新密码。

### 5.2 管理员操作规范（SPEC §5.3/§6）

1. 登录 `/admin/users`，用搜索框按邮箱定位用户。
2. **必须校验发件邮箱与账号绑定邮箱完全一致**，才允许重置：
   - 不接受：发件邮箱不是绑定邮箱但正文自称本人、只提供昵称/用户名/截图、他人代发、未绑定邮箱的老账号。
3. 确认用户状态：
   - `active`：可以重置。
   - `disabled`：默认不重置，除非先明确启用（SPEC §6.4）。
4. 用「重置密码」设置**临时密码**，要求：
   - 至少 12 位；含大小写字母和数字；不用简单词、生日、手机号；不复用历史临时密码。
   - 示例格式：`Pn-202608-7KQm29xA`（**不要**在文档或交付报告记录真实临时密码）。
5. 回复用户邮件告知临时密码，提醒登录后尽快改密。

### 5.3 用户修改密码流程

1. 登录后点击账号头像 → 账户菜单 → 「修改密码」。
2. 弹窗填写：当前密码、新密码、确认新密码。
3. 前端校验：新密码至少 8 位；两次新密码一致（不满足则前端拦截，不发请求）。
4. 后端校验当前密码正确后，bcrypt 重哈希保存新密码。
5. 成功展示「密码已修改」，点击「完成」关闭弹窗，**当前登录状态保持**。
6. 之后旧密码登录失败，新密码登录成功；现有便签、附件、额度、角色、状态不变。

### 5.4 老 admin 账号

若老 `admin` 无绑定邮箱，不走人工找回流程，其找回仍由服务器/数据库管理员线下处理（SPEC §6.3）；老 admin 登录后同样可在账号菜单修改密码。

## 6. 用户修改密码（新增功能）

### 6.1 API 定义

```text
POST /api/auth/change-password
```

请求：

```json
{
  "currentPassword": "old-password",
  "newPassword": "new-password"
}
```

成功响应：

```json
{
  "ok": true,
  "message": "密码已修改"
}
```

错误：

| 场景 | HTTP | error |
|---|---:|---|
| 未登录 | 401 | `UNAUTHORIZED` |
| disabled 用户 | 403 | `ACCOUNT_DISABLED` |
| 当前密码错误 | 400 | `INVALID_CURRENT_PASSWORD` |
| 新密码少于 8 位 | 400 | `PASSWORD_TOO_SHORT` |
| 请求体非法 | 400 | `INVALID_REQUEST` |

### 6.2 后端实现要点

1. 使用当前 session 获取用户（`authOrResponse()` → `getActiveSessionUser()`，未登录 401）。
2. **必须重新查数据库用户状态**（disabled 旧 session 也不能修改，403）。
3. 使用 `bcrypt.compare` 校验当前密码。
4. 使用 `bcrypt.hash` 保存新密码。
5. 响应不返回 passwordHash。
6. 服务端不写明文密码日志。
7. 修改成功后当前 session 保持有效（iron-session 只存 userId，不存 passwordHash）。

### 6.3 界面

- 入口：账号菜单新增「修改密码」按钮（锁形图标），位于管理用户入口之后、外观区之前，与退出登录同一菜单层级。
- 弹窗：`max-w-[360px]`，三字段「当前密码 / 新密码 / 确认新密码」，按钮「取消 / 保存」；Esc 关闭；保存成功后展示「密码已修改」+「完成」按钮。
- 错误文案：`当前密码不正确` / `密码至少 8 位` / `两次输入的密码不一致` / `账号已被禁用，请联系管理员` / `修改失败，请检查网络`。
- 前端拦截：新密码 <8 位、两次不一致时不发请求。
- 320px 宽度下弹窗不横向溢出（实测 scrollWidth=320，弹窗 x=16 宽 288）。

## 7. 安全规则落地说明

- 人工找回为纯前端说明页 + 复用 M10.4 管理员重置，**无新增攻击面**：用户侧无任何接口调用；管理员重置密码 API 有 `requireAdmin()` 鉴权 + 密码长度校验 + bcrypt 重哈希（明文不入日志）。
- `POST /api/auth/forgot-password` 与 `POST /api/auth/reset-password` 保留但**本轮用户侧无入口调用**（已实测页面无任何 `/api/` 请求）。生产 SMTP 为空，若未来误调用 forgot-password 会走既有优雅降级（不崩溃、token 落库、journal 记 SMTP_NOT_CONFIGURED，不泄露 token）。
- 修改密码 API 走 `getActiveSessionUser()`（DB 重查状态）+ bcrypt 校验/重哈希，满足 SPEC §6.5 全部安全规则；不返回 passwordHash、不写明文密码日志。
