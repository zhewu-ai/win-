## 一、结论

M12 下一步不继续做 AI 排期导入，也不继续把日历做成普通日历软件。当前优先级是把“工作日历”的**人工闭环**做扎实：

1. 用户能快速手动录入一个项目从周一到周五做什么，以及关键提交/交付/收付时间。
2. 用户能修改 AI 或人工生成的排期数据，但第一版先不做 AI，只做人工新增和修正。
3. 月视图、周视图、今日视图读取同一份结构化数据，任何修改都同步反映。
4. 项目结束后自动从顶部进行中列表隐藏或归档，不继续占据最显眼入口。
5. 视觉必须干净、统一、专业。功能可用但界面拥挤、丑、不想用，不算通过。

本 SPEC 替代此前偏“普通日历事件”的 M12 方案。此前的数据模型/API 可复用，但需要扩展到“项目 + 排期条目”语义。

## 二、产品定位

工作日历不是通用日历，也不是复杂项目管理软件。它在 PinNote 里承担三个作用：

1. 把工作排期串起来：项目、阶段、提交/反馈/交付节点。
2. 把便签串进时间：今天写了什么便签、哪些便签关联到项目/日期。
3. 为后续 AI 导入打基础：Excel、PDF、图片识别出来的内容，最终都进入同一套结构化排期数据。

第一版必须先支持手动流程。原因：

- 如果人工都无法快速输入和修正，AI 导入生成错数据后没有可靠兜底。
- 真实排期格式不固定，有 Excel、图片、PDF，AI 不可能一开始完全可靠。
- 人工基础层能先验证“月/周/今日三视图怎么组织信息”。

## 三、范围

### 3.1 本轮必须做

1. 管理员可见的工作日历入口。
2. 工作日历右侧主空间展示，不跳到一个割裂的奇怪页面。
3. 项目列表与项目详情。
4. 手动新增项目。
5. 手动新增排期条目。
6. 快速录入一周排期。
7. 修改、删除、归档项目和排期条目。
8. 月视图：项目色系 + 轻量甘特条 + 单日节点。
9. 周视图：默认进入，展示周一到周日，每天要做什么。
10. 今日视图：展示今天进行中的阶段、今天节点、今天编辑/关联便签。
11. 项目筛选、便签链接层开关。
12. 项目结束后从顶部进行中列表自动隐藏或进入归档。

### 3.2 本轮不做

1. AI 排期导入。
2. 图片识别排期。
3. PDF 自动识别排期。
4. Excel 自动解析排期。
5. 拖拽调整日期。
6. 多人协作、成员分配、权限流转。
7. 提醒通知。
8. 复杂甘特图依赖、资源负载、工时统计。
9. 把日历嵌进便签正文编辑器。

### 3.3 后续预留

后续 AI 导入只进入“待确认草稿”，不能直接写入正式排期。用户确认/修正后，才写入正式数据。

## 四、入口与布局

### 4.1 管理员灰度

第一版只给管理员账户展示：

- 普通用户左侧不显示“日历”入口。
- 普通用户直接访问相关页面/API 返回无权限。
- 不能只做前端隐藏，API 也必须校验管理员权限。

### 4.2 左侧入口位置

不要把工作日历放在整个侧边栏最顶上，也不要再改造首页顶部栏。

按用户确认后的结构：

1. 搜索/刷新等原有工具区保持原样。
2. 左侧列表区域第一个分组标题使用“日历”。
3. “工作日历”作为一张卡片或列表项放在“日历”分组下。
4. 原本“置顶”“收藏”等分组顺位下移。
5. 点击“工作日历”后，右侧主区域显示日历空间，行为类似点击一条便签后右侧显示便签详情。

禁止：

- 在首页顶部新增日历条。
- 在编辑器顶部再塞日历入口。
- 把日历做成普通一行导航文字。
- 把日历入口做得比便签列表还抢眼。

### 4.3 选中态

左侧“工作日历”被选中时，使用蓝色衬底，而不是灰色文字或禁用态样式。

要求：

- 选中态要明确、专业。
- 文字对比度足够。
- 与现有便签选中态一致或接近。

## 五、核心数据概念

### 5.1 WorkProject

项目是排期的容器。

建议字段：

```ts
type WorkProject = {
  id: string;
  userId: string;
  name: string;
  colorKey: "blue" | "red" | "green" | "purple" | "gray";
  status: "active" | "archived";
  startDate?: string; // YYYY-MM-DD
  endDate?: string;   // YYYY-MM-DD
  description?: string;
  source: "manual";
  createdAt: string;
  updatedAt: string;
  archivedAt?: string;
};
```

项目状态规则：

- `active`：还在进行或未来将开始。
- `archived`：已结束，不再显示在顶部进行中列表。
- 如果项目最后一个排期条目的 `endDate` 早于今天，可以提示归档或自动折叠到历史分组。
- 历史项目仍可在月历里显示，不能删除历史排期记录。

### 5.2 WorkScheduleItem

排期条目是月/周/今日视图共同读取的基本单元。

建议字段：

```ts
type WorkScheduleItem = {
  id: string;
  userId: string;
  projectId: string;
  title: string;
  type: "range" | "node";
  startDate: string; // YYYY-MM-DD
  endDate: string;   // YYYY-MM-DD；node 等于 startDate
  status: "todo" | "done" | "postponed";
  noteId?: string;
  source: "manual";
  createdAt: string;
  updatedAt: string;
  deletedAt?: string;
};
```

类型说明：

- `range`：连续阶段，例如“周一到周四修改”“8/24-8/27 动态打光渲染”。
- `node`：单日节点，例如“A call”“V1 提交&反馈”“交付”“收付时间”。

### 5.3 NoteActivity

第一版不一定需要新增表。今日视图可先从现有便签 `createdAt/updatedAt` 派生：

- 今天创建的便签。
- 今天更新的便签。
- 与当前项目关联的便签。

显示时作为“便签链接层”，不是正式排期条目。

## 六、手动输入流程

### 6.1 新增项目

日历空间必须有清晰的“新增项目”入口。

表单字段：

- 项目名称，必填。
- 项目颜色，必选，默认自动分配。
- 开始日期，可空。
- 预计结束日期，可空。
- 备注，可空。

保存后：

- 项目出现在项目筛选列表。
- 项目详情可查看。
- 可以继续添加排期条目。

### 6.2 新增排期条目

排期条目表单字段：

- 所属项目，必填。
- 标题，必填。
- 类型：连续阶段 / 单日节点。
- 开始日期，必填。
- 结束日期，连续阶段必填；单日节点自动等于开始日期。
- 关联便签，可选。

保存后：

- 月视图出现对应甘特条或节点。
- 周视图对应日期列出现任务。
- 今日视图如果命中今天，立即出现。

### 6.3 快速录入一周排期

这是第一版的重点，必须比逐条点表单更快。

建议提供“快速录入本周”面板：

```text
项目：A 项目
周一：修改 Layout
周二：修改 Layout
周三：修改 Layout
周四：修改 Layout
周五：内部检查
周六：A call
周日：
交付/收付节点：周五 18:00 输出检查
```

解析规则：

1. 连续日期内文字完全相同，自动合并为一条 `range`。
2. 只有一天出现的内容，默认为 `node` 或单日 `range`，由用户可切换。
3. 包含“修改、制作、优化、调整、渲染、合成”等词，默认倾向 `range`。
4. 包含“call、会议、提交、反馈、确认、交付、收付、输出、检查”等词，默认倾向 `node`。
5. 自动合并结果必须在保存前展示预览，允许用户改类型和日期。

示例：

```text
周一：A 修改
周二：A 修改
周三：A 修改
周四：A 修改
周五：
周六：A call
```

生成：

- `A 修改`：`range`，周一到周四。
- `A call`：`node`，周六。

### 6.4 修改与删除

用户点击任一视图中的条目后，右侧显示编辑面板：

- 修改标题。
- 修改项目。
- 修改类型。
- 修改开始/结束日期。
- 关联或取消关联便签。
- 删除条目。

保存后必须同步更新：

- 月视图。
- 周视图。
- 今日视图。
- 项目详情统计。
- 左侧日历卡片预览。

## 七、三视图设计

### 7.1 默认视图

点击左侧“工作日历”后，右侧默认进入**周视图**。

原因：

- 真实排期主要按周工作。
- 周一到周日纵向空间足够，能看清每天要做什么。
- 月视图更适合看趋势，不适合承载所有细节。

### 7.2 周视图

周视图是主工作区。

布局：

- 七列：周一到周日。
- 每列顶部显示日期。
- 每天下面显示命中当天的排期条目。
- 连续阶段在每天列中都可见，但标题不要重复得太吵，可以显示为同一色系的小卡。
- 单日节点显示为更紧凑的节点卡。
- 便签链接层可显示在当天底部或独立区域。

周视图必须回答：

- 今天要改哪个项目的什么内容？
- 当前处于哪个阶段？
- 哪天有 call / 提交 / 反馈 / 交付 / 收付？
- 哪些便签和这天有关？

### 7.3 今日视图

今日视图不能只是事件列表，必须像工作台。

至少分三块：

1. 今天要做：
   - 正在进行中的 `range`。
   - 示例：`A 修改：处于 8/10 - 8/13 阶段，今天继续推进。`
2. 今天节点：
   - 今天发生的 `node`。
   - 示例：`A call`、`V1 提交&反馈`、`交付`、`收付时间`。
3. 今天编辑的便签：
   - 今天创建/更新的便签链接。
   - 可点击打开便签。

今日视图不应显示过期无关项目。

### 7.4 月视图

月视图用于看总节奏和项目并行关系，不承担全部细节。

视觉规则：

- 按项目分色系，不按事件类型乱分颜色。
- A 项目使用同一色系，例如蓝色、浅蓝、淡蓝。
- B 项目使用另一色系，例如红色、粉红、淡红。
- 连续阶段显示为跨日期甘特条。
- 单日节点显示为当天小节点。
- 便签链接层用独立样式，可开关。
- 多项目并行时，同一周内上下分轨显示，不互相覆盖。

月视图必须支持：

- 项目筛选。
- 便签链接层开关。
- 点击项目条目进入编辑。
- 点击项目进入项目详情。

### 7.5 项目详情

点击某个项目后，右侧显示项目详情：

- 项目名称。
- 项目状态：进行中 / 已归档。
- 时间范围。
- 当前阶段。
- 下一节点。
- 所有关联排期条目。
- 关联便签。
- 归档按钮。

项目详情不是弹窗优先，建议使用右侧详情面板，保持和便签详情一致。

## 八、项目归档与过期显示

### 8.1 顶部列表规则

已经结束的项目不能继续占据顶部进行中列表。

定义：

- 如果项目 `status=archived`，不显示在进行中顶部列表。
- 如果项目所有排期条目的 `endDate < today`，在进行中列表中折叠或提示“可归档”。
- 已归档项目可在“历史/归档项目”入口查看。

### 8.2 月历历史保留

归档不是删除。

- 归档项目在对应月份的历史视图里仍可显示。
- 用户筛选“显示归档项目”后，可以看到历史项目。
- 默认当前工作区不展示过期项目，避免顶部被旧项目占用。

## 九、视觉设计硬性要求

用户是视觉/三维设计师，对视觉质量敏感。技术部不能只按功能完成判断通过。

### 9.1 整体气质

要求：

- 安静、专业、工具型。
- 信息密度高但不拥挤。
- 与 PinNote 现有卡片、侧边栏、编辑区一致。
- 圆角不超过现有系统习惯，默认 8px 以内。
- 不做营销式大标题、大色块、渐变装饰、夸张图标。

### 9.2 颜色

项目色系原则：

- 颜色第一层含义是“项目”，不是“事件类型”。
- 同一个项目使用同色系深浅变化。
- 不同项目使用明显可区分但克制的色系。
- 便签链接层使用独立但弱化的样式，不能抢排期主层级。

禁止：

- 每一种事件类型都用完全不同颜色，导致一眼很乱。
- 大面积高饱和色块。
- 选中态灰得像禁用。

### 9.3 筛选

项目筛选必须清楚：

- 勾选 A 项目，只显示 A 项目。
- 取消 A 项目，月/周/今日都不显示 A 项目。
- 取消便签链接，所有便签链接层都隐藏。
- 筛选状态必须影响统计数字和左侧卡片预览，不能只隐藏一部分。

### 9.4 空状态

空状态要干净：

- 没有项目：显示“暂无工作项目”，提供“新增项目”。
- 当前筛选无内容：显示“当前筛选下没有排期”。
- 今日无事项：显示“今天没有进行中的排期”，不能留一堆空框。

## 十、API 与存储建议

### 10.1 建议新增表

如果当前已有 `CalendarEvent`，可以迁移或扩展；否则建议新增：

- `WorkProject`
- `WorkScheduleItem`

不要把这些数据塞进便签正文或 checklist JSON。

### 10.2 API

建议接口：

- `GET /api/work-projects`
- `POST /api/work-projects`
- `PATCH /api/work-projects/[id]`
- `DELETE /api/work-projects/[id]` 或归档接口
- `GET /api/work-schedule-items?from=YYYY-MM-DD&to=YYYY-MM-DD&projectId=...`
- `POST /api/work-schedule-items`
- `PATCH /api/work-schedule-items/[id]`
- `DELETE /api/work-schedule-items/[id]`
- `POST /api/work-schedule-items/quick-week`

所有接口：

- 必须登录。
- 第一版必须管理员权限。
- 只能访问自己的数据。
- 删除优先软删。

### 10.3 quick-week 接口

`POST /api/work-schedule-items/quick-week`

Body 示例：

```json
{
  "projectId": "proj_1",
  "weekStart": "2026-08-10",
  "days": {
    "mon": "A 修改",
    "tue": "A 修改",
    "wed": "A 修改",
    "thu": "A 修改",
    "fri": "内部检查",
    "sat": "A call",
    "sun": ""
  },
  "nodes": [
    { "date": "2026-08-14", "title": "输出检查" }
  ]
}
```

返回必须包含生成预览，不建议直接保存：

```json
{
  "preview": [
    {
      "title": "A 修改",
      "type": "range",
      "startDate": "2026-08-10",
      "endDate": "2026-08-13"
    },
    {
      "title": "内部检查",
      "type": "node",
      "startDate": "2026-08-14",
      "endDate": "2026-08-14"
    },
    {
      "title": "A call",
      "type": "node",
      "startDate": "2026-08-15",
      "endDate": "2026-08-15"
    }
  ]
}
```

用户确认后再批量创建。

## 十二、验收标准

### 12.1 管理员与权限

- 管理员能看到左侧“日历”分组和工作日历卡片。
- 普通用户看不到日历入口。
- 普通用户直接访问 API 返回 403。
- 普通用户直接访问日历页面不展示半成品功能。

### 12.2 手动新增项目

- 点击“新增项目”能创建项目。
- 项目可设置名称、颜色、开始日期、结束日期。
- 创建后项目出现在筛选区和项目详情。
- 项目可归档。
- 归档后不出现在顶部进行中列表。

### 12.3 手动新增排期

- 能新增连续阶段：例如 2026-08-10 到 2026-08-13 “A 修改”。
- 能新增单日节点：例如 2026-08-15 “A call”。
- 能新增交付/收付节点：例如 2026-08-14 “输出检查”。
- 能关联便签。
- 保存后月/周/今日同步更新。

### 12.4 快速录入一周

- 输入周一到周四相同内容“修改”，预览合并为一条连续阶段。
- 输入周六“A call”，预览为单日节点。
- 预览阶段允许用户调整类型、标题、日期。
- 用户确认后才写入正式数据。
- 保存后所有视图同步。

### 12.5 修改闭环

- 在月视图点击甘特条，右侧出现编辑面板。
- 修改日期后，甘特条位置变化。
- 修改项目后，颜色和项目筛选归属变化。
- 修改类型后，连续条和单日节点展示相应变化。
- 删除后，三视图和统计都同步消失。

### 12.6 月视图

- 连续阶段跨日期连成一条，不每天重复散落。
- 同一项目使用同色系。
- 多项目并行时上下分轨，不重叠。
- 筛选 A 项目关闭后，A 项目的所有条目在月视图消失。
- 关闭便签链接后，月视图所有便签链接消失。
- 过期项目不占当前顶部列表，但历史月份仍可查看。

### 12.7 周视图

- 点击工作日历默认进入周视图。
- 周一到周日列清楚。
- 进行中阶段显示在命中的日期。
- 单日节点只显示在对应日期。
- 便签链接可显示/隐藏。
- 能看清“今天要做哪个项目的什么内容”。

### 12.8 今日视图

- 今日视图分为“今天要做”“今天节点”“今天编辑的便签”。
- 今天处于连续阶段内的任务显示在“今天要做”。
- 今天的 call/提交/反馈/交付/收付显示在“今天节点”。
- 今天创建或编辑的便签显示为可点击链接。
- 筛选项目后，今日视图同步过滤。

### 12.9 视觉验收

必须满足：

- 不挤压原有首页布局。
- 不出现额外顶部日历条。
- 左侧入口与便签卡片体系一致。
- 选中态使用蓝色衬底。
- 月视图不乱成彩虹色。
- 文字不溢出、不重叠。
- 320px 和 390px 下可用。
- 暗色/亮色主题都可读。

任一出现以下情况，验收不通过：

- 功能能用但明显丑、拥挤、不协调。
- 筛选关闭后仍有对应项目或便签显示。
- 修改后只有当前视图更新，其他视图没更新。
- 归档项目仍占据顶部进行中列表。
- 手动录入流程太慢，只能逐个字段复杂填写，无法快速录入一周。

## 十三、AI 导入后续方案

AI 导入放到下一阶段。

后续流程：

1. 用户上传 Excel/PDF/图片。
2. 系统解析为排期草稿。
3. 草稿进入确认页。
4. 用户逐条修正项目、标题、类型、日期。
5. 用户确认后写入正式 `WorkScheduleItem`。

AI 永远不直接覆盖正式排期。人工修正后的数据以用户保存结果为准。
