## 二、重要安全要求

### 2.1 密钥不要写进普通仓库或普通 Markdown

以下内容不得直接提交到 Git 仓库或普通 Markdown 文档：

- SSH 私钥。
- 服务器 root / ubuntu 密码。
- `.env` 真实内容。
- `SESSION_SECRET`。
- 数据库备份下载链接。
- AI API Key。
- GitHub Token。
- 邮件 SMTP 密码。
- 第三方服务密钥。

交付方式建议：

1. 普通文档只写“变量名、用途、配置位置、是否必须”。
2. 真实密钥必须交付，但通过单独安全渠道交付，例如密码管理器、加密压缩包、当面传输或一次性密钥分享。
3. 交接完成后，建议新技术部统一轮换关键密钥。

### 2.1.1 密钥交付包要求

为避免交接麻烦，现技术部需要额外准备一份“密钥交付包”，但不要把真实值写入本仓库文档。

密钥交付包应包含：

| 类型 | 必须交付 | 建议交付方式 |
|---|---|---|
| SSH 私钥 | 是 | 加密压缩包 / 密码管理器 / 当面传输 |
| 服务器登录密码，如存在 | 是 | 加密压缩包 / 密码管理器 / 当面传输 |
| 生产 `.env` 真实值 | 是 | 加密压缩包 / 密码管理器 |
| 云服务器控制台账号 | 是 | 转移账号权限 / 密码管理器 |
| 域名/DNS 账号 | 是 | 转移账号权限 / 密码管理器 |
| GitHub Token，如仍使用 | 是 | 新技术部重新生成，旧 token 交接后废弃 |
| AI API Key | 是 | 密码管理器 / 新技术部重新生成 |
| 邮件 SMTP 密码 | 如启用则是 | 密码管理器 / 服务商后台重置 |

建议做法：

1. 由现技术部把所有真实密钥放进一个加密压缩包，例如 `PinNote-secrets-20260822.zip`。
2. 压缩包本体通过文件发送。
3. 解压密码通过另一个渠道发送，例如电话、短信、当面口述或密码管理器共享。
4. 新技术部确认能登录和部署后，统一轮换 `SESSION_SECRET`、AI Key、SMTP 密码、GitHub Token 和服务器 SSH key。
5. 旧技术部在交接完成后撤销自身不再需要的服务器、GitHub、云厂商、域名后台权限。

### 2.2 必须区分“配置位置”和“真实值”

文档里可以写：

```text
SILICONFLOW_API_KEY：生产环境配置于 /home/ubuntu/projects/sticky-notes/.env
```

不要写：

```text
SILICONFLOW_API_KEY=真实 key
```
