# M13 交付报告：AI 排期导入（图片 / Excel → 草稿 → 确认 → 写入）

日期：2026-08-10

## 一、交付内容

按 `docs/SPEC_M13_AI排期导入完整执行方案_20260810.md` 与 `docs/SPEC_M13_AI排期导入测试接入_20260810.md` 实现 AI 排期导入最小闭环，管理员可用：

- **入口**：工作日历右侧面板底部「导入排期」次级区，`[上传图片] [上传 Excel]`。手动添加仍是主流程，入口弱化呈现。
- **识别**：图片（png/jpg/jpeg/webp，≤8MB）或 Excel（xlsx/xls，≤5MB）上传 → 后端构造 AI 输入（图片 base64 / Excel 结构化文本）→ 硅基流动 `Qwen/Qwen3.5-9B` 输出 JSON 草稿 → 后端校验归一化。
- **预览**：前端「导入预览」面板可编辑——改项目名、改标题、改起止日期、删除单条、删除项目草稿、低置信度（<0.7）弱提示「请确认」；AI 识别提示（warnings）以琥珀色块展示。
- **确认**：用户点「确认导入」→ 事务内再次全量校验 → 同名 active 项目复用，缺失项目新建 → 排期写入（`startDate===endDate` 存 `node`，跨天存 `range`），全部标记 `source=ai_import`。
- **权限**：两个 API 均 `requireAdmin()`，未登录 401、普通用户 403；入口仅在管理员可见的工作日历中。
- **明确拒绝**：PDF 在 parse 阶段直接 400「暂不支持 PDF，请上传图片或 Excel。」，不调 AI、不静默。

## 二、关键发现与修复：推理模型 enable_thinking

`Qwen/Qwen3.5-9B` 是**推理模型**：默认先输出 `reasoning_content`（思维链），可能耗尽 `max_tokens` 却从未产出最终 JSON 正文（实测 `content=""`、`finish_reason=length`，首次试跑即命中）。

修复：`src/lib/siliconflow.ts` 对 `Qwen3` 系模型传 `enable_thinking: false`，模型直接输出 JSON 正文。修复后两个 Excel 样本与图片样本均稳定出稿。

## 三、架构与实现要点

1. **链路**：上传 → `/api/calendar-imports/parse`（识别，不入库）→ 前端草稿预览 → `/api/calendar-imports/confirm`（事务写入）。AI 只做识别与结构化，绝不直接写正式数据。
2. **Excel 提取**：`src/lib/excel-text.ts` 用 SheetJS（`xlsx`）读工作簿 → 文件名 / sheet 名 / 非空单元格 `- 坐标 = 值` / 合并单元格范围（含左上角值）/ 日期格式化为 `YYYY-MM-DD`。不写死行列规则，识别交给 AI。
3. **归一化**：`src/lib/siliconflow.ts` `normalizeDraft` 宽松日期解析（`YYYY/M/D`、`YYYY.M.D`、`YYYY年M月D日`、`YYYYMMDD`、`M/D/YYYY` 美式）、非法项进 warnings 丢弃、倒置区间自动交换、未知 projectTempId 归入首个项目、`MAX_PROJECTS=50 / MAX_ITEMS=200`。
4. **事务写入**：`/confirm` 用 `prisma.$transaction` 交互式事务；项目按名复用 active 项目或新建（默认色 blue）；排期逐条校验标题/日期/项目引用，非法项计 skipped 不中断。
5. **数据模型**：复用 `WorkProject.source` / `WorkScheduleItem.source` 预留字段（M12 已加注释「M13 AI 导入阶段扩展」），**无 schema 变更**。
6. **脱敏日志**：parse 仅记 `model / prompt/completion tokens / ms / projects/items/warnings 数`；不打印 key、base64、文件内容、明文草稿。

## 九、已知问题与风险

1. **耗时**：`Qwen3.5-9B` 单次识别 10-55s，「识别中」期间无进度条，仅文案提示。后续可评估换用更快的非推理模型或做大模型蒸馏。
2. **年份推断**：样本中「7月14日」无年份时 AI 推断为 2024（图像样本），已在 warnings 提示；用户预览时需留意修正。
3. **多行单元格拆分**：Excel 中一个单元格含多行任务（如「layout制作\n材质测试」）会被拆成多条并提示合并，属预期弱提示。
4. **无自动去重**：同名项目复用（active），但排期条目不去重；重复导入会产生重复条目，由用户在预览中人工删除。
5. **手动添加仍是主流程**：导入是辅助；识别错误依赖预览人工修正后入库。

## 十、后续建议

- 评估模型替换：`enable_thinking:false` 已验证可行，若希望提速可测更小/非推理模型并对比准确率。
- 生产部署时把 `SILICONFLOW_API_KEY` 写入服务环境变量（本地 `.env` 不入库）。
- 可用真实排期图补齐图片样本的更多验收。
