# M11.1.2 交付报告：链接编辑态一致性（Tiptap 最小化链接编辑器）

日期：2026-08-09

## 一、交付内容

依据 QA 审计（`docs/QA_M11_1_2_链接编辑态一致性与待办覆盖审计_20260809.md`）修复两个 P0 缺口，使**外部 URL 与内部便签链接在查看与编辑时都保持链接外观（蓝色链接/芯片），普通便签与待办一致支持，不再出现「聚焦变代码」**：

- **P0-1 待办链接渲染**：`ChecklistEditor` 每行/每小标题从纯 textarea 换为 Tiptap 链接编辑器——URL 失焦即显蓝、`[[note:...]]` 渲染为芯片，可点击打开、`[[` 搜索、勾选/回车新增/删除/排序全部保留。
- **P0-2 普通便签编辑态链接保持**：正文 textarea⇄LinkedText 双态整体替换为 Tiptap 编辑器——聚焦编辑时 URL 始终蓝色、内链始终芯片，链接后继续输入不再「回退成代码」，外链点击直接打开不进入编辑。

实现方式（与用户确认的方向，未改变）：**成熟编辑器内核 Tiptap v2**，只开放最小能力——不扩展 Markdown、不存未清洗 HTML、**存储模型不大改**（普通便签仍为纯文本 `note.content` 内含 `[[note:id|title]]`；待办仍为 `checklistItems` JSON）。保存时序列化为纯文本、解析时还原为编辑器文档，**已存数据无损 round-trip（`serialize(parse(text)) === text`）**。

范围收窄：`FloatingNoteClient.tsx`（历史遗留/无主入口，不在主产品链路，详见八）与列表卡片弱渲染（P1）本轮不做。

## 二、架构与技术决策

1. **依赖**：Tiptap v2（`@tiptap/core` `@tiptap/react` `@tiptap/pm` + `document/text/hard-break/history/placeholder` 最小扩展）。SSR 用 `immediatelyRender: false`，`editor` 为 null 时渲染占位 div 防 hydration 错位。
2. **Schema**：单 `noteText` 块（`content: "inline*"`、`whitespace: "pre"`）+ 自定义 `noteLink` 原子节点（inline/atom/selectable，attrs `{id,title}`，ReactNodeViewRenderer 渲染芯片，`renderText` 复制输出 `[[note:id|title]]`）。换行用 `hardBreak` 节点，单个块节点从 schema 层面杜绝富文本。
3. **外链 = 装饰方案，不存 link mark**：`noteText` 加 ProseMirror 插件，事务后复用 `link-parser.ts` 的 `findUrlSpans` 扫描内联文本，命中区间加 `Decoration.inline(→ <a>)`。doc 里 URL 永远是纯文本 → 复制干净、编辑中 URL 变体自动重判、mark 零漂移、round-trip 恒等。
4. **`[[` 搜索**：探测 = `$pos.parent.textBetween(0, $pos.parentOffset)` 匹配 `/\[\[([^\]\n]*)$/`（跳过 `note:` 前缀）；浮层 anchor 用 `view.coordsAtPos`；键盘（↑/↓/Enter/Esc）在 `editorProps.handleKeyDown` 中优先接管；Enter → `insertContentAt` 插入 `noteLink` 原子。
5. **外部 value 同步**：仅当 `serializeNoteText(doc) !== value`（切便签/远端更新/reset）才 `replaceWith(0,size,doc)` 整体替换，`preventUpdate` + `addToHistory:false`，不丢光标、不污染撤销栈。

## 五、说明与已知限制
- **预览环境键盘测试的客观限制**：preview 标签页 `visibility:hidden` 导致 `requestAnimationFrame` 永不触发，`focusRow` 的 rAF 重试流程在自动化里无法完成（已用窗口级探针确认 `handleRowKeyDown` 正常执行、focus 失败属测试环境问题而非代码缺陷）；合成 KeyboardEvent 可触发 PM 的 `handleKeyDown`（Enter/ArrowDown 浮层导航已验证）但不触发 PM 默认 keymap（Backspace/Arrow 用 `execCommand` 替代验证）。生产/真实浏览器不受此影响。
- **最后一个编辑（resetKey 重建编辑器时清残留浮层）**：Chrome 自动化连接在最终验证前断连，未做浏览器内复测；该 effect 仅随 `editor` 引用变化触发（挂载 + resetKey 重建），正常输入不改 `editor` 引用，按构造分析不影响 `[[` 浮层流程，且 tsc + 生产构建均通过。
- **`contenteditable` React 警告**：Tiptap NodeViewWrapper 在 React 18 dev 下报一次 cosmetic 的 `Invalid DOM property contenteditable`，属性实际生效，非 bug。
- **execCommand 撤销/重做**：通过自动化不完全可靠（撤销已验证一次成功），History 为标准 Tiptap v2 扩展，留给真实浏览器回归。
- **桌面壳**：本轮无 Rust 改动，Tauri 壳渲染依赖下次 CI 壳构建后验收。

### P1-1 内部链接标题含 `]` 退回裸代码 —— 已修复（转义方案）

**问题**：旧解析正则 `([^\]]+)` 不允许标题含 `]`，存 `[[note:id|A]B]]` 会错位解析；标题含 `]` 的便签被引用后保存刷新即退回裸代码。

**修复（与用户确认方向：转义）**：
- `src/lib/link-parser.ts`：`NOTE_LINK_RE` 标题捕获改为 `((?:\\.|[^\]])+)`（允许 `\` 转义对）；新增 `escapeLinkTitle`（`\`→`\\`、`]`→`\]`）与 `unescapeLinkTitle`（`\\([\\\]])` → `$1`）。
- `src/lib/note-text-schema.ts`：`renderText` 与 `serializeNoteText` 序列化时对标题调 `escapeLinkTitle`。
- `src/components/NoteEditor.tsx:443`：对话框兜底 snippet 同样转义。

**恒等保证**：`serialize(parse(text)) === text` 对含 `\`/`]`/尾随标点/残缺 `[[...]]` 的全部输入成立；旧残缺数据不再部分匹配（整体退化为纯文本，聚焦不改 content）；新插入的 `]` 标题序列化为 `\[`，刷新后仍是芯片。

**验证**：新增 `scripts/roundtrip-check.ts`（25 条断言，`npm run test:roundtrip` 全绿）+ 浏览器实测——含 `M11Q-\]标题` 的便签解析为芯片、聚焦不还原、刷新仍芯片；`[[` 搜索插入 `]` 标题便签后序列化为 `[[note:id|M11Q-\]标题...]]`（普通正文与待办行均验证）；API 确认存储原样保留转义。

### P1-2 浮动窗口（FloatingNoteClient）仍是 textarea —— 历史遗留，不迁移

审计指出浮动窗口未迁移链接编辑器。**该能力已弃用**：`FloatingNoteClient` 是早期「极小模式/悬浮窗」的历史遗留，产品方向已调整为「主窗口缩小 + 窗口置顶」，主界面不再提供极小模式入口——该文件当前**无任何 UI 入口引用**（无组件调用 `openFloatingNote`，UI 无「悬浮」入口），不属于当前主产品链路。因此本轮**不迁移、不列入默认下一轮任务**。后续如需清理，应单独开一轮做废弃代码清理（连同 Rust 端 `open_floating_note` 命令一并评估），而不是继续功能化它。
