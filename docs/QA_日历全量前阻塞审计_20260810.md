## 二、阻塞项 P1：已删除项目排期仍从 API 返回

### 2.1 现象

项目被删除后：

- 项目本身是软删除：`WorkProject.deletedAt != null`。
- 排期条目保留：`WorkScheduleItem` 没有被物理删除。
- `/api/work-schedule-items` 目前只过滤 `WorkScheduleItem.deletedAt = null`。
- 没有过滤所属项目 `WorkProject.deletedAt = null`。

结果：

- 已删除项目下的排期仍会被 API 返回。
- 主日历页面有客户端二次过滤，通常不显示。
- 但左侧日历封面 `CalendarCard` 直接拉取未来 7 天排期，只按 `hiddenProjectIds` 过滤，不知道项目是否已删除。
- 所以封面可能显示已删除项目的关键节点。

### 2.2 风险

这是全量前的阻塞风险：

- 用户会以为排期数据重复或没删干净。
- 左侧封面和右侧日历主体可能不一致。
- AI 导入、删除项目、编辑项目后，封面可信度下降。
- 后续如果其它地方也直接调用 `/api/work-schedule-items`，同样会拿到脏数据。

### 2.3 涉及文件

主要检查：

- `src/app/api/work-schedule-items/route.ts`
- `src/lib/work-calendar.ts`
- `src/components/calendar/CalendarCard.tsx`
- `src/components/calendar/CalendarPageClient.tsx`

当前关键问题在：

```ts
// src/app/api/work-schedule-items/route.ts
where: {
  userId: admin.id,
  deletedAt: null,
  ...
}
```

这里需要同时过滤所属项目未删除。

### 2.4 修复要求

`/api/work-schedule-items` 服务端查询必须过滤所属项目：

```ts
project: {
  deletedAt: null
}
```

同时要确认 Prisma schema 中 `WorkScheduleItem -> WorkProject` 关系字段名称。如果当前 include/where 不方便，应按现有 schema 正确写法实现。

建议行为：

- 默认返回：仅未删除项目下的排期。
- `projectId` 查询：如果项目已删除，应返回空或 404/无效项目，不应返回排期。
- 归档项目：按当前产品策略处理。主日历当前支持“显示归档”，如果 API 需要区分 active/archived，应明确参数，不要和 deleted 混在一起。

### 2.5 验收

必须用以下场景验收：

1. 创建项目 A，添加未来 7 天内关键节点，例如 `3天后 DCO 确认`。
2. 左侧日历封面能显示该节点。
3. 删除项目 A。
4. 左侧日历封面立即不再显示项目 A 的节点。
5. 右侧月/周/日视图也不显示项目 A 的排期。
6. 刷新页面后仍不显示。
7. 直接请求 `/api/work-schedule-items?from=...&to=...`，返回结果不包含项目 A 的排期。

### 2.6 修复记录（2026-08-10，已部署验证）

技术部已按 §2.4 修复，最小改动（每处一行 where 条件）：

1. `src/app/api/work-schedule-items/route.ts`（GET）：`where` 增加 `project: { deletedAt: null }` —— 所属项目已删除的排期一律不返回。
2. `src/app/api/work-schedule-items/[id]/route.ts`（`findOwnedItem`）：同样增加 `project: { deletedAt: null }` —— 已删除项目下的条目单条 PATCH/DELETE 返回 404 NOT_FOUND。

归档项目 `deletedAt` 为空，不受影响（主日历「显示归档」能力保留）。

生产验证结果（2026-08-10，curl API + CDP 浏览器）：

| 场景 | 结果 |
|---|---|
| 创建项目 A + 未来 7 天节点（3天后 DCO 确认） | 封面显示该节点 |
| 软删项目 A 后 `GET /api/work-schedule-items?from&to` | 不含 A 的条目（0 条），projectId 不再出现 |
| `GET /api/work-schedule-items?projectId=A` | 返回 0 条 |
| 刷新页面后左侧封面 | 不再显示 A 的节点（显示「今天暂无排期」） |
| 已删除项目下条目 PATCH | 404 NOT_FOUND |
| 归档项目 B（archived） | 归档前/后其排期均正常返回，未受影响 |

## 三、关注项 P2：连续月历修法可接受，但仍不是最终形态

### 3.1 当前判断

当前代码已把月视图排期裁剪到真实所属月份：

- 补位日期不再显示排期。
- 同一条排期不会在 7 月补位区和 8 月真实月份重复显示。

这个方向可以接受，能解决用户真实遇到的重复排期问题。

### 3.2 仍需注意

当前实现仍是多个完整月网格上下拼接，不是真正的“连续周流”。

这不是本次全量阻塞项，但技术部需要知道：

- 如果后续继续强化连续滚动体验，最好改为按周连续渲染。
- 月份标题只是时间流中的分隔，而不是每个月都重新生成完整 42 格网格。

### 3.3 验收

全量前仍需复测：

- 7 月底 / 8 月初跨月边界。
- 同一条 `A call` / `交单帧` / `交美术` 不重复出现。
- 补位日期视觉弱化，不显示排期条。
- 320px/390px 下不重叠、不横向溢出。
