## 功能内容（对应 QA Round 5）

### F01 右键菜单分场景（P1）

- **编辑器区**：保留文本菜单（复制 / 粘贴 / 剪切 / 全选 / 删除所选）；无选区时「剪切」「删除所选」置灰禁用，有选区时可用
- **侧边栏便签卡**：显示「复制一份 / 删除便签」，删除走产品内确认弹窗（删除后进回收站可恢复）
- **空白区 / 普通非编辑区**：无菜单，同时禁用浏览器默认菜单
- **复制一份**：服务端新建便签（标题加「副本」），连带复制附件文件（路径边界校验）与附件记录

### F02 回收站 7 天自动清理（P1）

- 回收站列表显示「删除于 8月6日 · 6天后永久删除」，当天到期显示「今天将永久删除」
- `trash-cleanup` 模块：清理过期（>7 天）便签的附件文件（safeResolve 路径边界校验）+ 附件行 + 便签行 + 日志
- 触发：**每日定时**（systemd --user timer，04:07，Persistent=true）+ **打开回收站惰性触发**（1 小时节流）
- `/api/trash-cleanup` 仅接受回环来源，伪造 XFF 返回 403

### F03 亮色模式评估（P2，仅评估）

产出 `SPEC_M8_LIGHT_MODE_ASSESSMENT_20260806.md`：现有 CSS 变量层可支撑方案 A（变量覆盖），硬编码颜色 10 处任意值 hex + ~40 处白/黑透明度叠层 + 3 处功能色，预估 3 个工作日，待产品确认默认主题后再进入实现。

### 部署后修复（重要）

首轮部署后生产 `/api/trash-cleanup` 对本地请求返回 403。根因：服务监听 `*:9002`（双栈），Next.js 将 IPv4 回环连接合成为 `x-forwarded-for: ::ffff:127.0.0.1`，原判断只认 `127.0.0.1`/`::1`。已修复：归一化 `::ffff:` 前缀后判定回环，非回环来源仍 403。本地与生产验证均通过。

### 回收站 7 天自动清理端到端验证（生产实测）

1. 建测试便签 + 上传 1 个附件 → 软删除进入回收站（deletedAt 2026-08-05）
2. sqlite3 将 deletedAt 回拨为 8 天前（unix ms：`1785256794847`）
3. 调用 `/api/trash-cleanup` → **`purged: 1`**
4. 验证：Note 行 = 0、Attachment 行 = 0、`uploads/notes/<id>/` 目录已删除
5. 服务日志：`[trash-cleanup] purged expired note ...` / `done: 1/1 expired notes purged`

注：SQLite 中 Prisma 的 DateTime 以 **unix 毫秒整数** 存储；测试回拨必须写整数格式，ISO 文本不参与数值比较（第一轮测试因此返回 purged:0，已纠正）。

```bash
export XDG_RUNTIME_DIR="/run/user/$(id -u)"
systemctl --user stop sticky-notes.service
# 恢复备份 /home/ubuntu/backups/prod_M8R7_20260806_003508.db
# 代码回滚：恢复上一版本受影响的 9 个源文件并重新构建

systemctl --user start sticky-notes.service
# 定时任务移除（如需）
systemctl --user disable --now sticky-notes-trash-clean.timer
```

注意：本次无 schema 变更，回滚不涉及数据库结构；定时任务禁用即停止每日清理（已过期便签将保留在回收站，打开回收站时的惰性清理仍受 1 小时节流限制）。
