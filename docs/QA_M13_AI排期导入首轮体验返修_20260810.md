# QA M13：AI 排期导入首轮体验返修

日期：2026-08-10

状态：已完成首轮返修（2026-08-10），6 项全部落地并在 dev 环境端到端验收通过（真实 AI 识别 + 确认入库）；已部署生产并通过健康检查与产物校验；待 Windows 桌面端回归后闭环。

## 一、结论

当前 AI 排期导入已经偶发跑通，但体验不通过。问题不在于“是否能偶尔识别成功”，而在于流程缺少稳定反馈、识别结果不可修正、年份容易错、项目创建前置导致用户路径不自然。

本轮返修目标：

1. 等待过程必须有明确阶段反馈。
2. 识别失败必须知道失败在哪一步。
3. AI 识别年份必须受当前日期约束。
4. AI 识别结果必须可编辑。
5. 上传前不应强制先创建项目。
6. 项目名应优先从文件/图片内容中识别，识别不到再让用户补。

## 二、问题与返修要求

### 2.1 等待时间太长且缺乏反馈

现象：

- 上传后等待时间较长。
- 页面没有进度或阶段提示。
- 如果失败，用户不知道是上传失败、Excel 提取失败、AI 调用失败，还是 JSON 解析失败。

要求：

导入流程必须显示阶段状态。

建议阶段：

```text
1. 上传文件
2. 读取内容
3. AI 识别
4. 整理草稿
5. 等待确认
```

每一步至少有：

- 当前状态。
- 成功/失败标记。
- 简短错误说明。
- 可重试入口。

错误示例：

- `上传失败，请检查文件大小。`
- `Excel 读取失败，请确认文件未损坏。`
- `AI 识别超时，请重试。`
- `AI 返回格式错误，已保留原始识别文本供重试。`

验收：

- 上传后用户能看到当前正在进行哪一步。
- AI 调用超过 3 秒必须有持续反馈。
- 失败时明确显示失败阶段。
- 失败后可以重新上传或重试识别。

### 2.2 年份识别错误

现象：

- 成功识别的一次，年份被识别成 2024 年。
- 用户需要往前翻很久才能看到识别结果。
- 排期图片上通常有月份和日期，但年份容易缺失或被模型猜错。

原因判断：

- 模型可能根据训练语境或默认上下文猜了年份。
- 上传的排期表可能只写了“8月”“8/10”，没有完整年份。
- 如果 prompt 不明确当前年份，AI 会自行补年。

要求：

AI 识别时必须传入当前业务日期上下文。

当前日期：

```text
2026-08-10
```

提示词必须明确：

```text
当前年份是 2026 年。
如果排期表中只有月份和日期，没有年份，默认使用 2026 年。
不要使用 2024 年或其他年份，除非表格中明确写出该年份。
```

后端校验规则：

- 如果 AI 返回年份早于当前年份 1 年以上，标记为高风险。
- 如果所有日期都落在异常年份，例如 2024，必须进入“请确认年份”状态。
- 系统应允许用户一键调整年份，例如：

```text
检测到识别年份为 2024，是否改为 2026？
[全部改为 2026]
```

验收：

- 对只写月份/日期的排期图，默认识别为 2026 年。
- AI 返回 2024 年时，前端明确提示异常。
- 用户能批量把年份修正为 2026。

### 2.3 识别结果必须可修改

现象：

- 识别成功后，用户不能修改识别出的时间。
- 一旦时间错了，就无法补救。

要求：

AI 导入结果必须进入“草稿预览”，草稿可编辑后才能确认导入。

每条草稿至少可编辑：

- 项目名。
- 排期标题。
- 开始日期。
- 结束日期。
- 删除该条。

项目也必须可编辑：

- 修改项目名。
- 删除项目草稿。
- 如果项目名为空，允许用户补充。

验收：

- 用户能把错误年份从 2024 改成 2026。
- 用户能修改某条排期的开始/结束日期。
- 用户能删除识别错误的条目。
- 确认导入后，使用用户修改后的草稿入库，而不是 AI 原始结果。

### 2.4 上传前不应强制先创建项目

现状：

- 用户必须先创建项目，再上传图片或 Excel。

问题：

- 真实排期文件本身通常包含项目名。
- 用户上传文件时，不一定知道应该先创建哪个项目。
- 这会让 AI 导入流程像“依赖手动项目管理”，不自然。

要求：

AI 导入入口不要求预先创建项目。

正确流程：

```text
上传图片 / Excel
→ AI 识别项目名和排期
→ 进入草稿预览
→ 用户确认或补充项目名
→ 确认导入时创建项目和排期
```

如果 AI 没识别出项目名：

- 前端显示“请补充项目名”。
- 用户补充后才能确认导入。

如果 AI 识别出多个项目：

- 草稿中显示多个项目分组。
- 用户可以改名、合并或删除。

验收：

- 没有任何项目时，也能上传排期图片/Excel。
- AI 识别出项目名后，草稿自动带项目名。
- AI 未识别项目名时，用户可在预览中补充。
- 确认导入后自动创建项目。

### 2.5 项目命名体验

现象：

- 上传后仍要求用户补充项目名。
- 但项目名通常可以从文件名、sheet 名、图片标题中识别。

要求：

项目名识别优先级：

1. 图片/表格标题中的项目名。
2. Excel sheet 名。
3. 文件名。
4. 用户手动补充。

示例：

- 文件名：`HUAWEI Laputa_MG&APK时间表_0622.xlsx`
- sheet 名：`MG视频`
- 可推断项目名：`HUAWEI Laputa MG视频`

验收：

- 上传包含明确项目名的文件后，草稿项目名自动填充。
- 项目名可修改。
- 未识别项目名时才要求用户补充。

### 2.6 Excel / 图片入口命名

用户口述中可能出现 “ESR”，这里按实际产品语义统一为：

- 图片
- Excel

界面不使用 PDF，不使用 ESR。

上传入口：

```text
导入排期
[ 上传图片 ] [ 上传 Excel ]
```

## 三、提示词必须更新

系统提示词必须加入日期上下文：

```text
当前日期是 2026-08-10，当前年份是 2026 年。
如果排期表中只有月份和日期，没有年份，默认使用 2026 年。
不要猜测为 2024、2025 或其他年份，除非文件中明确写出该年份。
```

输出要求：

```text
只输出 JSON。
所有日期必须为 YYYY-MM-DD。
不确定年份时，使用 2026 年，并在 warnings 中说明“年份按当前年份补全”。
```

## 四、后端校验要求

AI 返回后，后端必须做校验：

1. 日期格式是否合法。
2. `startDate <= endDate`。
3. 是否出现异常年份。
4. 是否缺项目名。
5. 是否缺标题。
6. 是否无有效排期条目。

异常年份规则建议：

- 当前年份为 2026。
- 如果返回日期年份 < 2025 或 > 2027，标记 `YEAR_OUT_OF_RANGE`。
- 如果 80% 以上条目都落在异常年份，给前端返回批量修正建议。

## 五、前端草稿预览要求

识别完成后不要直接入库。

预览页必须显示：

- 项目分组。
- 每条排期标题。
- 开始日期。
- 结束日期。
- sourceRef 或简短来源提示。
- warnings。

必须可操作：

- 修改项目名。
- 修改标题。
- 修改开始日期。
- 修改结束日期。
- 删除条目。
- 批量改年份。
- 确认导入。
- 取消。

## 六、验收标准

### 6.1 进度反馈

- 上传后显示阶段进度。
- 超过 3 秒仍有可见反馈。
- 失败时显示失败阶段。
- 可重试。

### 6.2 年份

- 使用同一张排期图片，不再默认识别为 2024。
- 只写月份日期时默认 2026。
- 如 AI 返回 2024，前端提示异常并支持一键改为 2026。

### 6.3 草稿编辑

- 能修改项目名。
- 能修改标题。
- 能修改开始/结束日期。
- 能删除条目。
- 确认导入后使用修改后的结果。

### 6.4 无项目也能导入

- 清空/无项目状态下，可以上传图片或 Excel。
- AI 识别项目名后自动生成项目草稿。
- 未识别项目名时，可手动补充。
- 确认后自动创建项目和排期。

### 6.5 导入后显示

- 确认导入后，月/周/日视图可见。
- 刷新页面后仍存在。
- 年份正确，不需要用户手动翻到 2024。
