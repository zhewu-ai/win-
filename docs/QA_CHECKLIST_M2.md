# 全平台便签 M2 交互验收清单

## 1. 使用方式

本清单用于人工验收 M2 功能，不替代构建和接口测试。验收人员需要按真实用户操作逐项检查。

验收环境：

- 桌面浏览器：Chrome 或 Edge。
- 移动端宽度：浏览器开发者工具模拟 390px 宽度，或真实手机浏览器。
- 测试账号：使用研发提供的管理员账号。

通过规则：

- P0 项必须全部通过。
- P1 项如不通过，需要记录原因和截图。
- 任一数据丢失、页面崩溃、保存失败无提示，均视为阻塞。

记录格式：

```text
编号：
结果：通过 / 不通过 / 未测
复现步骤：
实际结果：
期望结果：
截图或录屏：
备注：
```

## 2. P0 核心回归

### QA-M2-001 登录和主页

步骤：

1. 打开 Web 端。
2. 未登录时访问主页。
3. 登录。
4. 刷新页面。

期望：

- 未登录访问主页会进入登录页。
- 登录成功后进入主页。
- 刷新后仍保持登录态。
- 页面无报错、无白屏。

### QA-M2-002 新建普通便签

步骤：

1. 点击“新建”。
2. 输入标题。
3. 输入正文。
4. 等待保存完成。
5. 刷新页面。

期望：

- 新建后自动选中新便签。
- 输入区域自动聚焦。
- 显示“保存中”后变为“已保存”。
- 刷新后标题和正文仍存在。

### QA-M2-003 普通便签自动保存

步骤：

1. 打开一条普通便签。
2. 快速连续修改标题和正文。
3. 等待保存完成。
4. 刷新页面。

期望：

- 标题和正文都被保存。
- 不出现只保存最后一个字段的问题。
- 不丢失输入内容。

## 3. P0 待办模式

### QA-M2-004 普通便签切换为待办

步骤：

1. 新建普通便签。
2. 正文输入三行内容。
3. 点击“待办”模式按钮。

期望：

- 三行内容变成三条待办项。
- 每条待办左侧有 checkbox。
- 待办文字与原正文一致。
- 自动保存成功。

### QA-M2-005 待办项新增

步骤：

1. 打开待办便签。
2. 在第一条待办末尾按 Enter。
3. 输入新待办文字。
4. 等待保存完成。
5. 刷新页面。

期望：

- Enter 后新增下一条待办。
- 焦点进入新待办。
- 刷新后新增待办仍存在。

### QA-M2-006 待办勾选和取消

步骤：

1. 打开待办便签。
2. 勾选第一条待办。
3. 等待保存完成。
4. 刷新页面。
5. 取消勾选同一条。
6. 再次刷新页面。

期望：

- 勾选后 checkbox 显示已完成。
- 已完成文字变浅并显示删除线。
- 刷新后勾选状态保持。
- 取消勾选后恢复未完成状态。

### QA-M2-007 待办项删除

步骤：

1. 打开待办便签。
2. 删除一条非最后一条待办。
3. 等待保存完成。
4. 刷新页面。

期望：

- 被删除待办不再显示。
- 其他待办内容和勾选状态不受影响。
- 至少保留一条可编辑空项。

### QA-M2-008 空待办状态

步骤：

1. 新建空便签。
2. 切换为待办模式。
3. 不输入任何文字。
4. 刷新页面。

期望：

- 页面不崩溃。
- 至少显示一条可编辑空待办。
- 列表显示合理，不出现 undefined/null。

### QA-M2-009 反复切换模式

步骤：

1. 新建便签，正文输入：

```text
买牛奶
[x] 已完成
[ ] 未完成
```

2. 点击“待办”。
3. 点击“便签”。
4. 重复步骤 2-3 至少 5 轮。

期望：

- 不出现 `[ ] [ ]`、`[x] [x]` 等前缀叠加。
- 已完成项状态不丢失。
- 文本内容不重复、不丢失。

### QA-M2-010 待办行视觉对齐

步骤：

1. 打开待办便签。
2. 查看未完成项。
3. 查看已完成项。
4. 添加一条较长文字待办。

期望：

- checkbox 与文字在同一视觉中心线。
- 勾选图标居中。
- 删除线穿过文字中部，不偏上或偏下。
- 长文字不遮挡 checkbox 和删除按钮。

## 4. P0 列表和搜索

### QA-M2-011 便签卡片视觉

步骤：

1. 创建不同颜色的普通便签和待办便签。
2. 回到主页列表。

期望：

- 卡片背景使用对应浅色。
- 选中态清楚。
- 置顶区和普通区分区清楚。
- 不是只有颜色点。

### QA-M2-012 自动标题

步骤：

1. 创建无标题普通便签，正文第一行为“正文标题”。
2. 创建无标题待办便签，第一条待办为“待办标题”。
3. 回到列表。

期望：

- 普通便签列表标题显示“正文标题”。
- 待办便签列表标题显示“待办标题”。
- 完全空便签显示“无标题便签”。

### QA-M2-013 待办完成进度

步骤：

1. 创建 3 条待办。
2. 勾选其中 1 条。
3. 回到列表。
4. 再勾选第 2 条。
5. 回到列表。

期望：

- 列表显示完成进度。
- 进度从 `1/3` 更新为 `2/3`。
- 刷新后进度仍正确。

### QA-M2-014 搜索普通便签

步骤：

1. 搜索普通便签标题关键词。
2. 搜索普通便签正文关键词。
3. 点击清空搜索。

期望：

- 标题命中可显示结果。
- 正文命中可显示结果。
- 命中文字高亮。
- 清空后恢复默认列表。

### QA-M2-015 搜索待办项

步骤：

1. 创建待办项“搜索专用待办”。
2. 在搜索框输入“搜索专用”。
3. 点击清空搜索。

期望：

- 搜索结果包含该待办便签。
- 待办项命中文字高亮。
- 搜索时仍保留置顶/普通分区。
- 清空后恢复默认列表。

## 5. P0 删除和回收站

### QA-M2-016 删除进入回收站

步骤：

1. 创建一条普通便签。
2. 点击删除。
3. 确认删除。
4. 进入回收站。

期望：

- 删除确认文案说明可在回收站恢复。
- 主页不再显示该便签。
- 回收站显示该便签。

### QA-M2-017 回收站恢复

步骤：

1. 在回收站选择一条便签。
2. 点击恢复。
3. 回到主页或归档页。

期望：

- 便签从回收站消失。
- 未归档便签恢复到主页。
- 已归档便签恢复到归档页。
- 内容、颜色、待办状态保持。

### QA-M2-018 永久删除

步骤：

1. 进入回收站。
2. 点击永久删除。
3. 确认。
4. 搜索该便签。

期望：

- 永久删除前有明确不可恢复提示。
- 删除后回收站不再显示。
- 不能恢复。

### QA-M2-019 回收站搜索

步骤：

1. 删除一条包含特殊关键词的便签。
2. 进入回收站搜索该关键词。
3. 清空搜索。

期望：

- 可以搜索标题、正文、待办项文字。
- 清空后恢复全部回收站列表。

## 6. P0 保存和错误状态

### QA-M2-020 保存失败提示

步骤：

1. 打开浏览器开发者工具。
2. 模拟离线或阻断 `/api/notes` 请求。
3. 修改便签内容。

期望：

- 显示“保存失败”。
- 当前输入不丢失。
- 有“重试”入口。

### QA-M2-021 保存失败重试

步骤：

1. 在保存失败状态下恢复网络。
2. 点击“重试”。
3. 刷新页面。

期望：

- 重试后显示“已保存”。
- 刷新后内容存在。

### QA-M2-022 保存中切换便签

步骤：

1. 修改便签内容。
2. 在“保存中”时立刻切换到另一条便签。
3. 再切回原便签。
4. 刷新页面。

期望：

- 原便签修改内容不丢失。
- 不出现旧内容覆盖新内容。

## 9. P1 Floating 页面

### QA-M2-028 Floating 权限

步骤：

1. 未登录状态访问 `/notes/:id/floating`。
2. 登录后访问自己的便签 floating 地址。

- 未登录跳转登录页。

1. 打开 `/notes/:id/floating`。

期望：

- 无侧边栏。
- 320px 宽度下可编辑。
- 操作按钮不换行挤压到不可用。

### QA-M2-030 Floating 与主编辑一致性

步骤：

1. 在主编辑页修改便签。
2. 打开 floating 页面查看。

期望：

- 两边数据一致。
- 待办/便签模式切换规则一致。
- 不出现前缀叠加。

## 10. API 补充验证

### QA-M2-031 checklistItems 非法结构

步骤：

1. 用 API 工具向 `POST /api/notes` 传入非数组 `checklistItems`。
2. 用 API 工具向 `PATCH /api/notes/:id` 传入非数组 `checklistItems`。
3. 传入缺少 `id/text/checked` 的 item。

期望：

- 均返回 400。
- 不污染已有数据。
- 后续列表接口返回的 `checklistItems` 始终是数组。

### QA-M2-032 桌面窗口字段

步骤：

1. PATCH 写入：

```json
{
  "windowX": 10,
  "windowY": 20,
  "windowWidth": 320,
  "windowHeight": 400,
  "alwaysOnTop": true
}
```

2. 重新 GET 便签列表。

期望：

- 字段保存成功。
- GET 返回值一致。
- 主界面不需要展示这些字段。
