# SPEC M13：AI 自然语言调整排期

日期：2026-08-10

状态：新增需求，待技术部评估排期

## 一、背景

当前 AI 排期导入主要解决“从 Excel / 图片识别整张排期表”的问题。但真实工作中，排期并不总是完全按表执行：

- 某个节点可能提前一天。
- 某个节点可能晚一天。
- 今天临时要先交一版。
- 某个项目需要整体顺延或局部提前。

如果每次都让用户打开排期表、找到对应条目、逐条改日期，操作成本偏高。用户希望能通过一句话告诉 AI：

```text
这个项目调整了，今天需要先提前交一版。
```

由 AI 帮忙生成可确认的排期变更。

## 二、结论建议

建议新增一个“AI 调整排期”入口，使用文字 AI 即可，不需要视觉模型。

原则：

- 不直接让 AI 自动改库。
- AI 只生成“变更草稿”。
- 用户确认后才写入日历。
- 所有变更必须能看见“改了什么、为什么改、影响哪些日期”。

这条链路应独立于“上传给 AI”文件识别链路，避免把临时改排期和文件导入混在一起。

## 三、入口设计

### 3.1 入口位置

可选两种位置，技术部按现有布局选择：

1. 右侧工作日历面板内新增轻量入口：

```text
AI 调整排期
```

2. 放在 AI 导入区域下方，作为第二个 AI 能力：

```text
上传给 AI
AI 调整排期
```

建议不要默认展开大输入框。默认只显示一个按钮，点击后打开小面板或抽屉。

### 3.2 面板内容

面板最少包含：

- 项目选择：必选，默认当前选中项目或最近项目。
- 调整说明：多行文本输入。
- 生成草稿按钮。

示例输入：

```text
今天需要先提前交一版给客户，后面的交单帧顺延一天。
```

```text
A call 提前到明天，B call 不变。
```

```text
这个项目整体晚一天，但今天的内部检查不动。
```

## 四、AI 能力边界

### 4.1 输入给 AI 的上下文

后端只给 AI 当前项目的必要排期上下文，不给全量数据库：

- 项目名。
- 当前日期。
- 用户输入的调整说明。
- 该项目未来 14-30 天排期。
- 必要时包含最近 7 天排期。

不要把无关项目、完整便签正文、密钥、base64、日志全文传给 AI。

### 4.2 输出结构

AI 必须返回结构化 JSON，不能只返回自然语言。

建议结构：

```ts
type ScheduleAdjustmentDraft = {
  summary: string;
  confidence: "high" | "medium" | "low";
  warnings: string[];
  changes: Array<
    | {
        type: "create";
        projectId: string;
        title: string;
        startDate: string;
        endDate: string;
        reason: string;
      }
    | {
        type: "update";
        itemId: string;
        before: {
          title: string;
          startDate: string;
          endDate: string;
        };
        after: {
          title: string;
          startDate: string;
          endDate: string;
        };
        reason: string;
      }
    | {
        type: "noop";
        itemId?: string;
        reason: string;
      }
  >;
};
```

### 4.3 低置信度处理

如果 AI 无法判断用户意图，不要硬改。

例如：

```text
这个项目有点变动，你帮我调一下。
```

这种输入太模糊，应返回：

```text
需要补充：要调整哪个节点？提前还是延期？调整到哪一天？
```

前端展示为“需要补充信息”，不生成入库草稿。

## 五、草稿预览与确认

AI 生成后，前端展示“变更预览”，至少包括：

- 新增了哪些排期。
- 修改了哪些排期。
- 原日期 → 新日期。
- 原标题 → 新标题。
- AI 判断理由。
- 低置信度或冲突提醒。

用户可逐条勾选：

- 应用。
- 不应用。
- 手动编辑后应用。

确认按钮文案建议：

```text
确认更新排期
```

不要使用“自动更新”“一键执行”这类会降低用户控制感的文案。

## 六、典型场景

### 6.1 今天提前交一版

用户输入：

```text
今天需要先提前交一版给客户。
```

期望：

- 如果项目今天没有交付节点，AI 建议新增一条今天的节点：

```text
今天交一版给客户
```

- 如果未来已有“交单帧 / 交美术 / A call”等节点，AI 不应擅自删除或覆盖，只能建议是否需要同步调整。

### 6.2 节点提前一天

用户输入：

```text
A call 提前一天。
```

期望：

- 找到未来最近的 `A call`。
- startDate / endDate 各提前一天。
- 预览中显示原日期和新日期。

### 6.3 整体顺延一天

用户输入：

```text
这个项目整体晚一天。
```

期望：

- 对未来未完成排期整体顺延一天。
- 今天之前的历史排期不改。
- 如果跨周或跨月，日期正常推进。
- 预览中列出受影响条目数量。

### 6.4 局部不动

用户输入：

```text
整体晚一天，但今天内部检查不动。
```

期望：

- 今天内部检查保持不变。
- 其它未来节点顺延一天。
- 预览中明确“不变”的条目。

## 七、后端接口建议

### 7.1 生成草稿

```http
POST /api/calendar-adjustments/preview
```

请求：

```json
{
  "projectId": "xxx",
  "instruction": "今天需要先提前交一版给客户",
  "rangeDays": 30
}
```

返回：

```json
{
  "ok": true,
  "draft": {
    "summary": "...",
    "confidence": "medium",
    "warnings": [],
    "changes": []
  }
}
```

### 7.2 确认应用

```http
POST /api/calendar-adjustments/apply
```

请求只提交用户确认后的变更，不直接提交原始 AI 全量输出。

后端必须重新校验：

- 当前用户是管理员。
- projectId 属于当前管理员。
- project 未删除。
- itemId 属于该 project。
- 日期格式合法。
- startDate <= endDate。
- 不能修改已删除排期。

## 八、模型建议

该能力使用文字模型即可。

建议优先复用现有 Excel 文本模型配置：

```text
SILICONFLOW_EXCEL_MODEL=Qwen/Qwen3-30B-A3B-Instruct-2507
```

或新增更语义化的环境变量：

```text
SILICONFLOW_SCHEDULE_ADJUST_MODEL
```

未配置时回退：

```text
SILICONFLOW_EXCEL_MODEL -> SILICONFLOW_MODEL
```

注意：

- 不需要 `Qwen3-VL`。
- 不需要上传图片。
- 仍需遵守模型参数兼容逻辑，不要给不支持的模型传不支持参数。

## 九、日志与安全

日志只记录：

- 请求 id。
- 项目 id。
- 变更条数。
- 耗时。
- 成功 / 失败阶段。

日志不得记录：

- SiliconFlow key。
- 完整用户输入。
- 完整排期正文。
- 完整 AI 输出。
- 任何 base64。

失败提示要能区分：

- AI 超时。
- AI 无法理解。
- 输出格式错误。
- 权限 / 项目不存在。
- 应用变更失败。

## 十、验收标准

### 10.1 功能验收

1. 选择某个项目，输入“今天需要先提前交一版”，能生成新增节点草稿。
2. 输入“A call 提前一天”，能找到正确节点并生成日期调整草稿。
3. 输入“整体晚一天”，能批量生成未来排期顺延草稿。
4. 用户可取消某一条 AI 建议，不影响其它建议。
5. 用户确认后，月 / 周 / 日视图和左侧日历封面同步更新。
6. 低置信度输入不会硬改，前端提示用户补充信息。

### 10.2 数据验收

1. 不修改已删除项目。
2. 不修改已删除排期。
3. 不修改其它项目排期。
4. 不修改历史排期，除非用户明确要求。
5. 确认前不写库。
6. 确认后写库结果可刷新保持。

### 10.3 体验验收

1. 入口不常驻展开，不占用日历主体空间。
2. 390px / 320px 下可选择项目、输入说明、查看预览、确认。
3. 生成中显示等待时间。
4. 失败后保留用户输入，可重试。
5. 草稿预览不需要用户滚到最底部才能确认。

### 10.4 构建验收

技术部完成后必须提供：

- `npx tsc --noEmit` 结果。
- `npm run build -- --webpack` 结果。
- 以上典型场景截图或录屏。
- 确认后左侧日历封面同步刷新的截图。

## 十一、暂不做

本轮不做：

- 自动实时监听用户聊天并改排期。
- 跨多个项目的复杂统筹优化。
- 根据聊天上下文自动猜项目。
- 语音输入。
- 图片识别。
- 无确认直接写库。

先把“选项目 + 输入一句话 + AI 生成变更草稿 + 用户确认”做稳。
