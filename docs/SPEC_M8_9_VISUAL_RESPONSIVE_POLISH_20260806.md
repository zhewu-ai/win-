# PinNote M8.9 细节打磨：亮色 Hover、侧边栏动画与工具栏稳定

日期：2026-08-06

## 1. 背景

M8.8 断网防丢保护实测结果基本可用：在线进入 App 后，中途断网继续输入，当前已经能保存，核心防丢体验通过。

本轮进入一轮细节体验优化。用户连续实测后发现，目前 PinNote 的核心功能已经能满足使用，但仍有几个明显影响“成熟 App 体感”的细节：

1. 亮色模式下，侧边栏列表项 hover 状态颜色过暗，文字识别性差。
2. 横向收窄时，侧边栏自动收起是硬切，没有动画；但手动收起有动画，体验不一致。
3. 工具栏在临界宽度会出现多次状态跳变：文字消失、色球收起、保存状态变点，然后侧边栏自动收起后空间又变大，文字和色球又出现，造成“不稳定”的感觉。
4. 在某些收窄临界点，顶部工具栏图标会轻微颤动或横向跳一下，用户感知明显。

本轮目标不是重构整体 UI，而是集中打磨这些会被日常用户持续感知的细节。

## 2. 产品判断

当前不建议继续做大规模响应式重构。M8.6/M8.7 已经解决了大部分可用性问题，本轮应控制范围，只处理高感知细节。

产品侧判断：

1. 亮色 hover 问题必须修，因为它是明确视觉错误。
2. 自动收起侧边栏应补动画，因为已有手动动画，技术上应尽量复用同一套过渡。
3. 工具栏不应在同一轮收窄中反复从“文字版”变“图标版”再变回“文字版”。
4. “便签/待办”文字可以考虑默认取消，只保留图标，降低临界宽度跳变。
5. 侧边栏是否默认隐藏，需要谨慎。用户当前提出“默认不出现、手动点才出现”的想法，技术部可评估，但本轮不强制改默认信息架构。

## 3. 本轮目标

M8.9 目标：

1. 修复亮色模式侧边栏 hover 对比度。
2. 自动收起侧边栏时增加与手动收起一致的过渡动画。
3. 减少横向缩放时工具栏多次跳变。
4. 消除临界宽度附近顶部工具栏图标颤动。
5. 保持当前已可用功能不回退：新建、编辑、待办、保存、防丢、亮/暗切换、窗口缩放。

## 4. 本轮不做

1. 不重做整体视觉设计。
2. 不重新设计侧边栏信息架构。
3. 不做账号系统。
4. 不做完整离线系统。
5. 不做富文本。
6. 不做移动端原生 App。

## 5. 问题与要求

### 5.1 F01：亮色模式侧边栏 hover 颜色过暗

当前体验：

- 亮色模式下，鼠标滑过左侧便签标题时，hover 背景仍像暗色模式的深色叠层。
- 未点击时 hover 状态比选中状态更怪，整体显得很暗。
- 黑色文字叠在偏暗背景上，识别性下降。

要求：

1. 亮色模式下，侧边栏列表项 hover 应使用浅色中性背景。
2. hover 背景不要接近暗色模式的深色块。
3. hover 状态文字仍保持清晰，不能变灰到难读。
4. selected 状态和 hover 状态要有层级区分：
   - hover：轻微提示。
   - selected：明确选中。
5. 暗色模式不能被修坏。

建议 token：

```css
[data-theme="light"] {
  --note-row-hover: rgba(0, 0, 0, 0.045);
  --note-row-active: rgba(0, 0, 0, 0.075);
}

[data-theme="dark"] {
  --note-row-hover: rgba(255, 255, 255, 0.055);
  --note-row-active: rgba(255, 255, 255, 0.095);
}
```

技术部不一定按这个值实现，但必须达到：

- 亮色 hover 看起来轻，不脏。
- 文字对比度足够。
- hover 和 selected 有清晰区别。

### 5.2 F02：侧边栏自动收起缺少动画

当前体验：

- 用户手动点击收起侧边栏时，有动画。
- 横向缩放到某个宽度后，侧边栏自动收起时是硬切。
- 因为右侧编辑区瞬间变宽，页面有突兀跳变。

要求：

1. 自动收起侧边栏时，也应使用与手动收起一致或接近的动画。
2. 动画时间建议 160-220ms。
3. 动画曲线建议 `ease-out` 或当前系统已使用曲线。
4. 收起过程中右侧编辑区宽度变化应平滑，不要瞬间撑开。
5. 不能为了动画导致内容裁切、卡顿或延迟响应明显。

验收重点：

```text
从宽屏逐渐缩窄 -> 到自动收起阈值 -> 侧边栏平滑收起 -> 右侧平滑扩展
```

不能出现：

```text
侧边栏瞬间消失 -> 右侧内容瞬间跳大
```

### 5.3 F03：工具栏响应式状态反复跳变

当前体验：

从宽屏逐渐收窄时，工具栏会出现类似顺序：

1. “便签/待办”文字消失，只剩图标。
2. “已同步”文字消失，变成状态点。
3. 多个颜色球收成一个颜色按钮。
4. 侧边栏自动收起后，右侧空间又变大。
5. “便签/待办”文字又出现。
6. 色球又展开。
7. “已同步”文字又出现。
8. 继续收窄后，这些元素再次收起。

这种来回变化会让用户感觉界面不稳定。

要求：

1. 工具栏状态应跟随“布局模式”而不是当前瞬时可用宽度反复切换。
2. 一旦进入 compact 模式，就保持 compact，直到超过明确的恢复阈值。
3. 使用迟滞区间，避免在临界点来回抖动。
4. 侧边栏自动收起导致右侧空间变大时，不应立刻把工具栏从 compact 切回 expanded。
5. 工具栏模式切换应少而明确，不能在一次连续收窄中出现“收起 -> 展开 -> 再收起”。

建议策略：

```text
窗口/编辑区从宽到窄：
expanded -> compact -> narrow

窗口/编辑区从窄到宽：
narrow -> compact -> expanded
```

并设置迟滞：

```text
进入 compact：编辑区 < 560px
退出 compact：编辑区 > 640px

进入 narrow：编辑区 < 380px
退出 narrow：编辑区 > 440px
```

具体数值可由技术部按当前实现调整，但必须有迟滞，不允许临界点反复跳。

### 5.4 F04：“便签/待办”文字是否保留

用户反馈：

- “便签/待办”两个字在工具栏里不一定必要。
- 图标也许已经足够表达模式。
- 当前文字显隐是造成工具栏跳变的一个来源。

产品建议：

本轮优先方案：

```text
模式切换按钮默认只保留图标，hover/tooltip 显示“便签 / 待办”
```

理由：

1. 减少工具栏宽度占用。
2. 降低横向缩放时文字消失/出现的跳变。
3. 更符合桌面工具栏图标化习惯。

如果技术部认为完全去掉文字会降低新用户理解，也可以采用：

```text
宽屏显示图标+文字；compact/narrow 只显示图标，并且切换阈值必须稳定
```

但本轮验收优先看稳定性，不强制要求文字必须存在。

### 5.5 F05：顶部工具栏图标临界点颤动

当前体验：

- 横向收窄到某个临界点后，侧边栏已收起，工具栏图标大体没变化。
- 但顶部图标会突然轻微横移或颤动一下。
- 用户能明显感觉到“画面抖了一下”。

可能原因：

1. 滚动条出现/消失导致容器宽度变化。
2. 工具栏某个元素宽度从 auto 变 fixed 或反过来。
3. 保存状态、颜色选择器、更多按钮槽位没有固定宽度。
4. 侧边栏收起后触发二次 layout reflow。
5. CSS transition 和条件渲染同时发生。

要求：

1. 工具栏关键按钮槽位应有稳定宽度。
2. 保存状态区域应固定槽位，不因文字/点切换造成横移。
3. 更多按钮位置应稳定。
4. 颜色入口在 compact/narrow 模式下应占固定宽度。
5. 自动侧边栏动画过程中，不应触发工具栏二次模式切换。

## 6. 推荐实现方向

### 6.1 用统一 layoutMode 管理，而不是每个组件自己判断

建议保留或扩展现有 narrow/compact 判断，形成统一模式：

```ts
type LayoutMode = "expanded" | "compact" | "narrow";
```

组件根据 `layoutMode` 渲染：

- NoteList/Sidebar：是否显示、是否动画。
- EditorToolbar：文字/图标、颜色入口、保存状态。
- SaveStatus：文字或点。
- ModeSwitch：图标或图标+文字。

不要每个组件各自监听 viewport，然后各自切换。

### 6.2 给自动模式切换加迟滞

迟滞目的：

```text
避免用户在临界宽度附近轻微拖动时，UI 来回变。
```

例如：

- 小于 560px 进入 compact。
- 大于 640px 才退出 compact。

这样中间 560-640px 不会反复跳。

### 6.3 尽量减少可见元素的“条件渲染”

如果元素只是从文字变图标，优先使用：

- 固定槽位。
- opacity/visibility。
- CSS class 切换。

谨慎使用会导致布局重算的直接 mount/unmount。

### 6.4 侧边栏自动收起和手动收起复用同一套动画

手动收起已有动画，自动收起不要另走硬切逻辑。

期望：

```text
manual collapse
auto collapse
```

两者使用同一套 CSS transition 或同一套组件状态。

## 7. 验收标准

### 7.1 亮色 hover 验收

步骤：

1. 切换到亮色模式。
2. 鼠标移动到左侧便签列表任意标题。
3. 不点击，只观察 hover 状态。
4. 再点击选中，观察 selected 状态。

通过标准：

1. hover 背景是轻浅色，不是暗色块。
2. hover 时文字清晰可读。
3. selected 状态比 hover 更明确。
4. 暗色模式下 hover/selected 仍正常。

### 7.2 自动侧边栏动画验收

步骤：

1. 从宽屏开始，保持侧边栏展开。
2. 慢慢横向收窄窗口。
3. 到自动收起阈值时观察侧边栏。

通过标准：

1. 侧边栏平滑收起，不是瞬间消失。
2. 右侧编辑区平滑扩展。
3. 没有明显闪烁、白屏、内容裁切。

### 7.3 工具栏稳定验收

步骤：

1. 从宽屏慢慢横向收窄到最窄。
2. 再从最窄慢慢横向拉宽。
3. 重点观察：
   - 模式切换按钮。
   - 颜色入口。
   - 保存状态。
   - 更多按钮。

通过标准：

1. 连续收窄过程中，工具栏不出现“文字消失 -> 又出现 -> 再消失”的来回切换。
2. 色球不出现“收起 -> 展开 -> 再收起”的来回切换。
3. 保存状态不因点/文字切换导致其它按钮横移。
4. 顶部图标没有明显颤动。

### 7.4 窄窗口验收

步骤：

1. 将 Windows App 缩到较窄宽度。
2. 在普通便签和待办便签之间切换。
3. 编辑标题、正文、待办。

通过标准：

1. 工具栏单行稳定。
2. 无文字竖排。
3. 无横向裁切。
4. 保存状态可理解。
5. 模式切换可用。

## 8. 不通过条件

出现以下任意情况，本轮不通过：

1. 亮色模式侧边栏 hover 仍是明显深色块。
2. 亮色 hover 后文字难以识别。
3. 自动侧边栏收起仍然硬切，无动画。
4. 横向连续收窄过程中，工具栏控件反复展开/收起。
5. 顶部工具栏在临界宽度出现明显颤动。
6. 修复后导致暗色模式 hover/selected 退化。
7. 修复后导致新建、编辑、待办、保存、防丢保护任一核心功能回退。

## 9. 交付物

技术部交付时需提供：

1. 实现说明：
   - 亮色 hover token 或样式调整说明。
   - 自动侧边栏动画实现方式。
   - 工具栏 layoutMode/迟滞策略说明。
   - “便签/待办”文字保留或图标化的取舍说明。
2. Windows 实机录屏：
   - 亮色模式侧边栏 hover/selected。
   - 从宽屏连续收窄到窄屏。
   - 从窄屏连续拉宽到宽屏。
   - 自动侧边栏收起动画。
3. 构建：
   - `npm run build` 通过。
   - 生产部署前备份。

## 10. 产品结论

本轮重点不是增加新功能，而是减少“网页感”和“临界点抖动感”。

目标体感：

```text
亮色模式干净、hover 清楚；
侧边栏收起自然；
工具栏稳定，不来回变；
窗口怎么缩都像成熟桌面 App。
```
