# M10.10 补丁交付报告：放宽管理员删除废用户规则（级联清理）

日期：2026-08-08
规格：`QA_M10_10_DELETE_USER_RULE_FEEDBACK_20260808.md`

## 一、本期变更

将删除废用户规则从「仅允许删除 disabled 且**无业务数据**的用户」放宽为「仅允许删除 disabled 的普通用户，**删除时级联清理该用户个人数据**」。

### 保留的安全边界（未改动）
- 不能删除当前登录管理员自己（`CANNOT_DELETE_SELF`）。
- 不能删除任何 admin 角色用户（`CANNOT_DELETE_ADMIN`）。
- 不能直接删除 active 用户，必须先禁用（`MUST_DISABLE_FIRST`）。
- 双层确认（弹窗 + 输入邮箱或 `DELETE`）。
- 只作用于目标用户自己的数据，不影响其他用户。

### 移除的阻塞
- 移除 `409 USER_HAS_DATA`：用户存在 Note / Attachment / FeedbackTicket / AnnouncementRead 等不再阻止删除。

## 二、实现说明

### 后端 `DELETE /api/admin/users/:id`
- 校验链不变：非本人 → 存在 → 非 admin → 必须 disabled。
- 删除行前先收集附件文件路径与便签目录（供事务成功后清理）。
- **防御**：普通用户不应创建公告（公告仅 admin 接口可建）；若存在 `Announcement.createdById = userId` 则拒绝并返回 `USER_CREATED_ANNOUNCEMENTS`，避免外键残留。
- 事务内级联清理（先子后父，最后删 User）：
  1. `attachment.deleteMany`
  2. `note.deleteMany`（含正常/归档/回收站全部便签）
  3. `feedbackTicket.deleteMany`
  4. `announcementRead.deleteMany`
  5. `passwordResetToken.deleteMany`
  6. 删除其创建的邀请码（`createdById`）
  7. 其使用过的邀请码 `usedById` 置空
  8. `user.delete`
- 事务成功后**尽力清理文件**（失败不阻塞接口）：附件文件 + `uploads/notes/<noteId>` 目录 + 头像文件。
- 不维护 `storageUsedBytes`（User 已删除）。
- 成功返回：`{ ok, deletedUserId, counts: { notes, attachments, feedbackTickets, announcementReads, passwordResetTokens, createdInvites } }`。

### 列表接口
- `src/lib/admin.ts` 新增 `ADMIN_USER_SELECT_WITH_COUNTS`（在 `ADMIN_USER_SELECT` 上叠加 `_count`），仅列表路由使用，不污染额度/状态路由。

### 前端 `AdminUsersClient.tsx`
- 「删除用户」按钮条件不变：`disabled + role=user + 非本人`。
- 第一层确认文案：改为「此操作会同时清理该用户的便签、附件、反馈记录和公告已读记录」。
- 第二层弹窗展示影响范围计数：X 条便签、Y 个附件、Z 条反馈记录、N 条公告已读记录。
- **修复 bug**：禁用/启用用户后，状态接口返回的对象不含 `_count`，导致第二层计数显示为 0。改为 `{ ...data.user, _count: u._count }` 保留原计数。
