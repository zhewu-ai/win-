# SPEC M16R3：便签收纳与知识关系基础

日期：2026-08-14

状态：待技术部评估与排期

关联路线图：`docs/ROADMAP_M16_便签知识化升级路线图_20260812.md`

## 一、本阶段目标

M16R1/R2 已把便签从“纯文本/待办二选一”推进到统一文档和轻富文本基础。下一阶段不建议继续堆编辑器按钮，而是先解决内容增长后的组织问题。

M16R3 目标：

```text
让便签变多以后仍然可收纳、可筛选、可关联。
```

本阶段做三件事：

1. 单层文件夹/分组：解决“工作、生活、客户项目”等稳定收纳。
2. 标签基础：解决“#单针、#美术、#客户A、#待交付”等灵活归类。
3. 反向链接：把现有内部便签链接升级为可回看的关系基础。

本阶段不是完整知识库，也不是 Obsidian 关系图。

## 二、为什么现在做

当前产品已经具备：

- 统一文档编辑器。
- checklist block。
- 轻量格式工具栏。
- 内部便签链接。
- 工作日历。
- AI 排期导入。

继续加图片、表格、AI 问答之前，左侧内容会先变乱。用户最先遇到的问题不是“还能不能排版”，而是：

- 便签多了怎么归类。
- 某个客户/项目相关内容怎么集中查看。
- 一条资料被哪些便签引用了。
- 工作日历、便签、待办之间如何形成可理解的资料关系。

所以 M16R3 先做“收纳与关系”的基础层。

## 三、本轮范围

### P0：单层文件夹/分组

新增轻量文件夹概念：

```text
全部
未分组
工作
生活
客户项目
临时
```

要求：

1. 每条便签最多属于一个文件夹。
2. 固定存在“全部”和“未分组”两个视图。
3. 用户可以新建、重命名、删除文件夹。
4. 删除文件夹不删除便签，文件夹内便签回到“未分组”。
5. 左侧列表可以按文件夹筛选。
6. 当前筛选状态要清晰，不要让用户误以为便签被删除。

建议数据模型：

```prisma
model NoteFolder {
  id        String   @id @default(cuid())
  userId    String
  name      String
  sortOrder Int      @default(0)
  createdAt DateTime @default(now())
  updatedAt DateTime @updatedAt
  deletedAt DateTime?
}

model Note {
  ...
  folderId String?
}
```

要求：

- `NoteFolder.userId + name` 建议做软唯一或接口层防重名。
- 先做单层，不做多级目录。
- `folderId` 只指向同用户未删除文件夹。

验收：

1. 新建“工作”文件夹后，左侧出现该分组。
2. 把便签 A 移入“工作”，切到“工作”只看到 A。
3. 切回“全部”，仍能看到 A。
4. 切到“未分组”，A 不出现。
5. 删除“工作”后，A 不被删除，并回到“未分组”。
6. 320px/390px 下文件夹入口不挤压搜索、日历入口和便签列表。

### P0：便签归属编辑

每条便签需要有明确归属入口。

建议交互：

- 便签顶部或更多菜单里提供“移动到文件夹”。
- 左侧卡片更多菜单也可提供“移动到文件夹”。
- 新建便签默认进入当前筛选文件夹；如果当前在“全部”或“未分组”，则默认未分组。

验收：

1. 在“工作”筛选下新建便签，自动属于“工作”。
2. 在“全部”下新建便签，默认未分组。
3. 在便签详情里可以把便签移动到另一个文件夹。
4. 移动后左侧列表立即刷新，不需要手动刷新。
5. 离线/弱网时不丢归属变更，沿用现有 pending 同步机制。

### P1：标签基础

标签用于灵活归类，不替代文件夹。

支持两种来源：

1. 正文中输入 `#标签` 自动识别。
2. 便签信息区或更多菜单中手动添加标签。

建议第一版标签规则：

- 标签以 `#` 开头。
- 支持中文、英文、数字、下划线、短横线。
- 不支持空格。
- 单条便签最多 20 个标签。
- 单个标签最多 30 个字符。
- 标签归一化：去首尾空格，连续重复不重复保存。

建议数据模型：

```prisma
model NoteTag {
  id        String   @id @default(cuid())
  userId    String
  name      String
  color     String?
  createdAt DateTime @default(now())
  updatedAt DateTime @updatedAt
  deletedAt DateTime?
}

model NoteTagBinding {
  id     String @id @default(cuid())
  noteId String
  tagId  String
}
```

也可以先用 `Note.tagsJson` 做轻量实现，但如果后续要做关系图和 AI 范围筛选，建议一开始就用关系表。

验收：

1. 正文输入 `#客户A` 后，保存后便签拥有“客户A”标签。
2. 同一便签多次出现 `#客户A`，标签只保存一次。
3. 点击标签筛选，只显示含该标签的便签。
4. 修改正文删掉最后一个 `#客户A` 后，自动标签同步删除，手动标签不被误删。
5. 标签筛选和文件夹筛选可以组合：例如“工作 + #客户A”。
6. 标签文字不破坏普通段落排版；不要求第一版做彩色标签芯片。

### P1：标签列表与筛选入口

左侧需要有可发现的标签入口，但不要挤压主列表。

建议：

- 文件夹分组在上，标签分组在下。
- 标签默认折叠，只显示最近/常用标签。
- 提供“全部标签”入口。
- 标签筛选状态以 chip 或顶部小标题显示，可一键清除。

验收：

1. 有标签的便签保存后，标签出现在左侧标签入口。
2. 点击标签后列表筛选正确。
3. 清除标签筛选后恢复当前文件夹列表。
4. 390px/320px 下标签区域可折叠，不把便签列表挤没。

### P1：反向链接

现有内部链接已经支持 `[[note:id|title]]`。本轮在此基础上做反向链接。

目标：

```text
当前便签被哪些便签引用了，用户能看见并跳转。
```

建议能力：

1. 便签底部或信息区显示“被引用 N 次”。
2. 展开后显示引用来源列表：标题、摘要、更新时间。
3. 点击来源便签可跳转。
4. 删除来源便签或取消链接后，反向链接自动更新。

建议技术方案：

- 保存便签时解析 `documentJson` 或 `content` 投影里的 `[[note:id|title]]`。
- 写入 `NoteLinkEdge` 关系表。
- 反向链接查询走关系表，不每次全文扫描。

建议数据模型：

```prisma
model NoteLinkEdge {
  id        String   @id @default(cuid())
  userId    String
  fromNoteId String
  toNoteId   String
  createdAt DateTime @default(now())
  updatedAt DateTime @updatedAt
}
```

验收：

1. A 链接 B 后，打开 B 能看到“被 A 引用”。
2. 从 B 的反向链接点击 A，可以跳转到 A。
3. A 删除链接后，B 的反向链接消失。
4. A 被删除/归档后，B 的反向链接显示规则明确：
   - 删除：不显示或显示已删除占位，二选一并写清楚。
   - 归档：默认显示但带“已归档”标记，或默认隐藏可切换。
5. 同一来源 A 多次链接 B，反向列表只显示一条来源。
6. 旧便签已有内链，首次打开/保存或后台重建关系后能进入反向链接列表。

## 五、API 行为要求

### 文件夹

文件夹删除为软删除。

删除文件夹时：

- 不删除便签。
- 将该文件夹下便签的 `folderId` 置空。
- 返回更新后的文件夹列表和受影响便签数量。

重命名文件夹时：

- 名称不能为空。
- 长度建议不超过 40。
- 同用户下不允许同名未删除文件夹。

### 标签

标签可由正文自动生成，也可手动创建。

建议区分来源：

- `source = "auto"`：正文 `#标签` 自动识别。
- `source = "manual"`：用户手动添加。

如果第一版不建 `source`，也要避免一个问题：

```text
用户手动加的标签，不应因为正文没有 #标签 就被自动删除。
```

### 反向链接

`NoteLinkEdge` 必须按用户隔离：

- A 用户不能通过反向链接看到 B 用户便签。
- 目标便签不存在或无权限时，不显示来源。
- 删除便签后关系要清理或查询时过滤。

## 六、搜索与排序

### 搜索

现有搜索保留。

新增筛选组合：

```text
搜索词 q + folderId + tag
```

要求：

- `q` 搜标题、`content` 投影、`checklistItems`。
- `folderId` 限定文件夹。
- `tag` 限定标签。
- 多条件取交集。

### 排序

第一版沿用当前列表排序：

- 置顶优先。
- 更新时间倒序。

文件夹和标签筛选不改变排序规则。

## 七、离线与桌面壳

### 离线

需要扩展现有离线层：

- `folderId` 同步。
- 标签绑定同步。
- 反向链接关系可在线重建，离线不必强保证实时。

要求：

1. 离线时移动文件夹不丢。
2. 恢复网络后归属同步。
3. 标签自动识别可以本地先算，也可以保存成功后由服务端返回。

### 桌面壳

本轮不改 Rust/Tauri。

但必须验收：

- macOS 壳内文件夹筛选。
- macOS 壳内移动便签。
- macOS 壳内标签筛选。
- macOS 壳内反向链接跳转。
- Windows 壳待实机。

## 八、视觉与交互原则

1. 文件夹是稳定收纳，标签是灵活筛选，二者不要混成一个概念。
2. 左侧列表不能变成复杂后台系统，入口要轻。
3. 390px/320px 下优先保证便签列表可读，文件夹/标签可折叠。
4. 颜色仍作为便签视觉标记，不作为唯一分类方式。
5. 反向链接默认低调展示，不要抢正文编辑空间。

## 九、不做范围

M16R3 不做：

- 多级文件夹。
- 团队空间。
- 多人协作。
- 权限矩阵。
- Obsidian 关系图。
- AI 资料库问答。
- 图片正文混排。
- 表格编辑器。
- 网页剪藏。
- 分享链接。

这些进入后续阶段，不混入本轮。

## 十、验收清单

### 文件夹

1. 新建文件夹成功。
2. 重命名文件夹成功。
3. 删除文件夹不删除便签。
4. 移动便签到文件夹成功。
5. 当前文件夹下新建便签自动归属。
6. 全部/未分组/指定文件夹筛选正确。

### 标签

1. 正文 `#标签` 自动识别。
2. 手动标签可添加。
3. 自动标签和手动标签不互相误删。
4. 标签筛选正确。
5. 文件夹 + 标签组合筛选正确。

### 反向链接

1. A 链接 B，B 显示 A。
2. A 取消链接，B 不再显示 A。
3. A 多次链接 B，B 只显示一条 A。
4. 归档/删除来源便签时显示规则正确。
5. 点击反向链接能跳转。

### 兼容

1. 旧便签打开正常。
2. 旧 checklist 打开正常。
3. 旧内部链接正常。
4. M16 轻富文本格式不丢。
5. 工作日历关联便签不受影响。
6. AI 排期导入不受影响。
7. `?m16=legacy` 回滚路径仍可用。

## 十一、生产部署要求

本轮涉及新增表和字段，生产部署必须执行数据库步骤。

注意：如果服务器存在根目录 `schema.prisma` 遮蔽 `prisma/schema.prisma` 的历史问题，必须两个位置都同步或清理根目录旧文件。

部署清单：

1. 备份生产 DB。
2. 同步代码和 Prisma schema。
3. 执行 `npx prisma generate`。
4. 执行 `npx prisma db push` 或项目确认的迁移命令。
5. 验证新表/字段存在。
6. 构建生产包。
7. 重启服务。
8. 健康检查。
9. 生产浏览器冒烟。
10. macOS 壳冒烟。

不得只做 `rsync + build + restart`。
