# 全平台便签 M3 产品规格：图片附件

## 1. 本轮目标

M3 目标是在现有 Web 便签和待办能力上，增加轻量图片附件能力，让用户可以把截图、照片、票据、备忘图片附加到便签中。

本轮仍然只做 Web 端和服务端能力，不做原生 App，不做 Windows/Mac 壳。

## 2. 范围

### 2.1 P0 必须完成

1. 每条便签支持上传图片。
2. 支持图片缩略图展示。
3. 支持点击图片预览。
4. 支持删除图片附件。
5. 支持普通便签和待办便签都添加图片。
6. 限制单张图片大小。
7. 限制每条便签图片数量。
8. 删除便签进入回收站时，图片仍可恢复。
9. 永久删除便签时，清理对应图片文件。
10. 构建和部署说明更新。

### 2.2 P1 尽量完成

1. 上传前前端压缩图片。
2. 支持拖拽上传。
3. 支持粘贴图片上传。
4. 移动端选择相册图片。
5. 图片加载失败状态。

### 2.3 本轮不做

1. 图片 OCR。
2. 图片文字搜索。
3. 图片编辑、裁剪、标注。
4. 多图拖拽排序。
5. 对象存储迁移。
6. 附件共享链接。
7. 视频、音频、PDF、文档附件。

## 3. 数据模型

新增 `Attachment` 模型。

字段：

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `id` | string | 是 | 附件 ID |
| `userId` | string | 是 | 所属用户 |
| `noteId` | string | 是 | 所属便签 |
| `type` | string | 是 | 固定为 `image` |
| `url` | string | 是 | 前端可访问路径 |
| `storagePath` | string | 是 | 服务端本地文件路径 |
| `filename` | string | 是 | 原始文件名或生成文件名 |
| `mimeType` | string | 是 | MIME 类型 |
| `size` | number | 是 | 文件大小，单位 byte |
| `width` | number/null | 否 | 图片宽度 |
| `height` | number/null | 否 | 图片高度 |
| `createdAt` | string | 是 | 创建时间 |

关系：

- 一个 `Note` 可以有多个 `Attachment`。
- 一个 `Attachment` 只能属于一个 `Note`。
- 用户只能访问自己的附件。

## 4. 存储策略

第一版使用服务器本地磁盘。

建议路径：

```text
uploads/notes/{noteId}/{attachmentId}.{ext}
```

访问 URL：

```text
/uploads/notes/{noteId}/{attachmentId}.{ext}
```

要求：

- 上传目录必须可配置。
- 生产环境部署说明必须写清楚上传目录如何持久化和备份。
- 不允许把图片存进数据库。
- 不允许直接使用用户原始文件名作为最终存储文件名。

环境变量建议：

```text
UPLOAD_DIR="./uploads"
MAX_IMAGE_SIZE_MB=5
MAX_IMAGES_PER_NOTE=12
```

## 5. 文件限制

P0 限制：

- 单张图片最大 5MB。
- 每条便签最多 12 张图片。
- 只允许图片 MIME：
  - `image/jpeg`
  - `image/png`
  - `image/webp`
  - `image/gif`

非法情况：

- 文件过大返回 400。
- 非图片返回 400。
- 超过数量限制返回 400。
- 未登录返回 401。
- 上传到不存在或不属于当前用户的便签返回 404。

## 6. API 规格

### 6.1 获取便签时返回附件

所有返回 `Note` 的接口需要包含：

```json
{
  "attachments": []
}
```

附件结构：

```json
{
  "id": "attachment_id",
  "noteId": "note_id",
  "type": "image",
  "url": "/uploads/notes/note_id/attachment_id.jpg",
  "filename": "image.jpg",
  "mimeType": "image/jpeg",
  "size": 123456,
  "width": 1200,
  "height": 800,
  "createdAt": "2026-07-24T00:00:00.000Z"
}
```

不应返回：

- `storagePath`
- 服务器绝对路径

### 6.2 上传图片

`POST /api/notes/:id/attachments`

请求：

- `multipart/form-data`
- 字段名：`file`

成功返回：

```json
{
  "attachment": {}
}
```

规则：

- 只能上传到当前用户自己的未永久删除便签。
- 归档便签允许上传。
- 回收站便签不允许上传，返回 400。
- 上传成功后返回附件信息。

### 6.3 删除附件

`DELETE /api/notes/:id/attachments/:attachmentId`

规则：

- 只能删除当前用户自己的附件。
- 删除数据库记录。
- 删除本地文件。
- 如果本地文件已不存在，接口仍应清理数据库记录并返回成功。

### 6.4 获取图片文件

可以使用 Next.js 静态文件或自定义文件路由。

要求：

- 不允许通过路径遍历访问上传目录外文件。
- 附件 URL 不应暴露服务器绝对路径。

如果使用公开静态目录，需接受“知道 URL 即可访问图片”的私有自用风险；如果技术部实现鉴权文件读取更好，但不是 P0。

## 7. 页面规格

### 7.1 编辑区图片入口

普通便签和待办便签编辑区都需要显示图片入口。

入口位置建议：

- 编辑区工具行，靠近颜色选择。

入口文案：

```text
图片
```

行为：

- 点击后打开文件选择器。
- 支持选择一张或多张图片。
- 上传中显示进度或 loading。
- 上传失败显示错误。

### 7.2 图片展示

图片展示位置：

- 建议显示在正文/待办内容下方。

展示要求：

- 使用缩略图网格。
- 每张图片有删除入口。
- 图片加载失败显示占位。
- 移动端缩略图不应溢出屏幕。

### 7.3 图片预览

点击缩略图后打开预览层。

预览要求：

- 大图居中显示。
- 支持关闭。
- 支持查看文件名。
- 移动端可正常关闭。

不要求：

- 放大缩小。
- 左右切换。
- 下载按钮。

### 7.4 删除图片

删除图片前需要确认。

建议文案：

```text
确定删除这张图片？此操作不会删除便签内容。
```

期望：

- 删除后缩略图立即消失。
- 刷新后图片不再出现。
- 服务端文件被清理。

## 8. 回收站和永久删除

### 8.1 普通删除便签

删除便签进入回收站时：

- 不删除附件。
- 回收站中可以看到便签存在图片的提示。
- 恢复便签后图片仍存在。

### 8.2 永久删除便签

永久删除便签时：

- 删除便签。
- 删除附件数据库记录。
- 删除本地图片文件。

如果文件删除失败：

- 接口应返回错误，或记录错误并提供清理方式。
- 技术部需要固定策略并写入说明。

## 9. 列表展示

便签列表卡片需要显示图片提示。

P0 要求：

- 有图片的便签显示图片数量，例如 `3 图`。

P1 可选：

- 显示第一张图片的小缩略图。

注意：

- 列表不应加载过多大图。
- 缩略图展示不能明显拖慢列表。

## 10. 搜索

本轮不要求搜索图片内容。

搜索规则：

- 图片文件名不作为 P0 搜索范围。
- 便签标题、正文、待办项搜索保持现有行为。

## 11. 移动端

移动端必须支持：

- 选择图片上传。
- 查看缩略图。
- 点击预览。
- 删除图片。

要求：

- 390px 宽度下图片网格不横向溢出。
- 预览层关闭按钮可点击。
- 上传失败提示可见。

## 12. 安全和稳定性

最低要求：

- 校验 MIME 类型。
- 校验文件大小。
- 校验附件归属。
- 防止路径遍历。
- 不记录敏感路径到前端。
- 上传失败不能影响便签正文保存。

建议：

- 同时检查文件扩展名和 MIME。
- 生成随机文件名。
- 对上传目录做定期备份。

## 13. 测试清单

研发交付前至少验证：

1. 普通便签可以上传图片。
2. 待办便签可以上传图片。
3. 上传后刷新页面图片仍显示。
4. 点击缩略图可以预览。
5. 预览层可以关闭。
6. 删除图片后刷新不再显示。
7. 非图片上传返回错误。
8. 超过大小限制返回错误。
9. 超过每条便签数量限制返回错误。
10. 未登录不能上传。
11. 不能给别人的便签上传图片。
12. 归档便签图片仍显示。
13. 回收站恢复后图片仍显示。
14. 永久删除便签后附件记录被清理。
15. 永久删除便签后本地文件被清理。
16. 移动端 390px 下上传、预览、删除可用。
17. 有图片的便签列表显示图片数量。
18. 原有普通便签、待办、搜索、回收站功能不回退。
19. `npm run build` 通过。

## 14. 完成定义

M3 视为完成，当且仅当：

- P0 项全部完成。
- 测试清单全部通过。
- 技术部提供数据库迁移说明。
- 技术部提供上传目录配置和备份说明。
- 技术部说明永久删除时附件文件清理策略。
- 现有 M2 验收清单核心项不回退。
