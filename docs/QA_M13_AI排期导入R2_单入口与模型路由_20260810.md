# QA M13：AI 排期导入 R2 单入口与模型路由

日期：2026-08-10

状态：技术部已返修（2026-08-10）

## 一、结论

AI 排期导入下一轮应同时处理两个问题：

1. 上传入口合并：不要再分“上传图片 / 上传 Excel”两个按钮，用户只需要一个“上传给 AI”入口。
2. 模型按文件类型拆分：Excel 和图片分别调用更合适的模型，不要全部走同一个默认模型。

这不是增加复杂度，而是把复杂度放到后端路由里，减少用户心智负担，同时提升速度和稳定性。

## 二、入口合并

### 2.1 当前问题

当前界面把入口拆成：

```text
[ 上传图片 ] [ 上传 Excel ]
```

用户需要先判断文件类型再点按钮。这个选择没有必要，因为系统完全可以自动判断。

### 2.2 产品要求

前端只保留一个入口：

```text
[ 上传给 AI ]
```

或：

```text
[ 上传排期文件 ]
```

上传后由后端按文件类型自动路由。

### 2.3 后端路由规则

后端同时检查文件扩展名和 MIME：

- `.xlsx` / `.xls` / `.csv` 或 Excel MIME：走 Excel 解析链路。
- `.png` / `.jpg` / `.jpeg` / `.webp` 或 image MIME：走图片识别链路。
- `.pdf`、未知扩展名、未知 MIME：直接拒绝。

拒绝提示：

```text
当前仅支持图片和 Excel。
```

### 2.4 验收

- 前端不再并列显示“上传图片 / 上传 Excel”两个按钮。
- 上传 `.xlsx` 自动进入 Excel 导入。
- 上传 `.png/.jpg/.jpeg/.webp` 自动进入图片导入。
- 上传 PDF 被拒绝，提示清晰。
- 识别草稿、编辑、确认入库流程不受入口合并影响。

## 三、模型拆分

### 3.1 测试结论

根据 `报告-M13_AI识别模型拆分选型_20260810.md`：

Excel 链路：

- 本地读取约 1ms。
- Excel 转结构化文本约 15ms。
- 主要耗时在远端模型生成。
- 当前 `Qwen/Qwen3.5-9B` 处理 Excel 约 61.9s 到 66.4s，容易触发 60s 超时。
- `Qwen/Qwen3-30B-A3B-Instruct-2507` 约 27.5s，输出 1 项目 / 27 条，速度和结果更适合作为 Excel 默认模型。

图片链路：

- 图片需要 OCR、表格理解、日期任务对应关系识别。
- `Qwen/Qwen3-VL-32B-Instruct` 约 36.5s，输出 1 项目 / 23 条，质量更稳。
- `Qwen/Qwen3-VL-30B-A3B-Instruct` 虽然约 16.7s，但漏识别明显，不适合作默认。

### 3.2 模型配置要求

新增或支持：

```env
SILICONFLOW_EXCEL_MODEL="Qwen/Qwen3-30B-A3B-Instruct-2507"
SILICONFLOW_IMAGE_MODEL="Qwen/Qwen3-VL-32B-Instruct"
```

保留兜底：

```env
SILICONFLOW_MODEL="Qwen/Qwen3.5-9B"
```

选择逻辑：

- `kind === "excel"`：优先使用 `SILICONFLOW_EXCEL_MODEL`。
- `kind === "image"`：优先使用 `SILICONFLOW_IMAGE_MODEL`。
- 未配置专用模型时，才回退到 `SILICONFLOW_MODEL`。

### 3.3 重要兼容要求

不能对所有 Qwen3 模型一刀切传：

```ts
enable_thinking: false
```

原因：

- `Qwen3-VL-*-Instruct` 在硅基流动接口上不支持该参数。
- 只改模型名、不改参数能力判断，会导致图片模型调用失败。

要求：

- 按模型能力配置请求参数。
- `Qwen/Qwen3.5-9B` 可传 `enable_thinking: false`。
- `Qwen3-VL-*-Instruct` 不传 `enable_thinking`。
- 明确带 Thinking 的模型默认不要用于该导入功能。

## 四、接口返回

`POST /api/calendar-imports/parse` 保持一个接口即可。

请求：

```http
POST /api/calendar-imports/parse
Content-Type: multipart/form-data

file=<用户上传文件>
```

返回必须包含自动识别结果和实际模型：

```json
{
  "kind": "excel",
  "model": "Qwen/Qwen3-30B-A3B-Instruct-2507",
  "draft": {},
  "usage": {}
}
```

前端进度阶段可显示：

```text
已识别为 Excel，正在读取内容
```

或：

```text
已识别为图片，正在 AI 识别
```

## 五、验收标准

### 5.1 单入口

- 只有一个上传入口。
- 不要求用户选择图片或 Excel。
- 错误文件类型提示清楚。

### 5.2 路由正确

- 上传 Excel 后，usage 显示 `kind=excel`，模型为 Excel 模型。
- 上传图片后，usage 显示 `kind=image`，模型为图片模型。
- PDF 不进入 AI 调用。

### 5.3 速度

- Excel 样本 `HW V+ ID视频-时间表0802.xlsx`：AI 阶段目标稳定低于 45s，不再卡 60s 超时线。
- 图片样本：能输出可编辑草稿，不返回空 JSON，不打满 token。

### 5.4 安全日志

- 日志只记录模型、耗时、token、项目数、条目数、warnings 数。
- 不打印 `SILICONFLOW_API_KEY`。
- 不打印 base64。
- 不打印文件全文。
- 不打印完整草稿明文。
