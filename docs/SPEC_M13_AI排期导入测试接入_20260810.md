# SPEC M13：AI 排期导入测试接入

日期：2026-08-10

## 一、目标

在 M12 工作日历基础闭环稳定后，接入硅基流动模型，先跑通“图片 / Excel 排期导入 → AI 生成草稿 → 用户确认 → 写入工作日历”的最小流程。

本轮是测试接入，不追求复杂自动化，不直接写正式数据。

## 二、模型与密钥

### 2.1 模型

第一版使用：

```text
Qwen/Qwen3.5-9B
```

原因：

- 用户已用真实排期图片测试，转写准确率可接受。
- 体量和成本比大模型更适合第一版试跑。
- 任务复杂度不高，主要是排期识别、字段整理、JSON 草稿生成。

### 2.2 API Key 管理

禁止把真实 API Key 写入代码、文档、交付报告、commit、日志或截图。

使用环境变量：

```env
SILICONFLOW_API_KEY=由部署环境配置
SILICONFLOW_MODEL=Qwen/Qwen3.5-9B
```

技术部本地测试可写入 `.env.local`；生产/测试服务器写入服务环境变量。

交付报告只能写：

```text
SILICONFLOW_API_KEY 已配置，调用成功。
```

不能展示真实 key。

## 三、本轮支持范围

### 3.1 支持

1. 图片排期导入：
   - `png`
   - `jpg/jpeg`
   - `webp` 可选
2. Excel 排期导入：
   - `xlsx`
   - `xls` 可选，若解析成本高可先只做 `xlsx`
3. AI 生成排期草稿。
4. 用户在前端确认/修改草稿。
5. 用户点击确认后写入 `WorkProject` / `WorkScheduleItem`。

### 3.2 不支持

1. PDF。
2. Word。
3. 多文件批量导入。
4. AI 直接写入正式日历。
5. AI 自动覆盖已有排期。
6. 后台自动识别或定时导入。

## 四、核心原则

AI 不是“操作页面”的工具。AI 只做识别和结构化输出。

正确链路：

```text
上传图片 / Excel
→ 后端构造 AI 输入
→ Qwen/Qwen3.5-9B 输出 JSON 草稿
→ 后端校验和规范化
→ 前端展示导入预览
→ 用户修改确认
→ 写入正式工作日历
```

禁止链路：

```text
上传文件
→ AI 直接创建项目和排期
```

## 五、Excel 处理策略

Excel 不做复杂规则识别，不写死“第几行是日期、第几列是任务”。

程序只负责把 Excel 转成 AI 易读材料：

- 文件名。
- sheet 名。
- 有内容的单元格。
- 单元格坐标。
- 合并单元格范围。
- 日期格式值。
- 颜色/合并格可作为辅助信息。

AI 负责判断：

- 哪些是项目。
- 哪些是阶段。
- 哪些是 call / 提交 / 反馈 / 交付 / 收付节点。
- 每条排期的开始日期和结束日期。

## 六、图片处理策略

图片直接给多模态模型识别。

提示词要求 AI：

- 先读取图片里的排期表。
- 识别日期、项目、阶段、节点。
- 不确定的内容标记 `confidence` 较低。
- 输出严格 JSON。
- 不要输出解释性长文。

## 七、统一草稿格式

AI 返回后，后端必须转成统一草稿格式。

```ts
type CalendarImportDraft = {
  projects: Array<{
    tempId: string;
    name: string;
    colorKey?: "blue" | "red" | "green" | "purple" | "gray";
  }>;
  items: Array<{
    tempId: string;
    projectTempId: string;
    title: string;
    startDate: string; // YYYY-MM-DD
    endDate: string;   // YYYY-MM-DD
    note?: string;
    confidence?: number;
    sourceRef?: string; // 图片区域、sheet/cell 等
  }>;
  warnings: string[];
};
```

注意：

- 前端不显示“连续阶段 / 单日节点”类型选择。
- `startDate === endDate` 时，确认写入时内部保存为 `type=node`。
- `startDate < endDate` 时，确认写入时内部保存为 `type=range`。

## 八、API 设计

### 8.1 解析上传文件

```text
POST /api/calendar-imports/parse
```

请求：

- `multipart/form-data`
- `file`: 图片或 Excel
- `kind`: `image | excel`

限制：

- 仅管理员。
- 文件大小第一版建议：
  - 图片：≤ 8 MB。
  - Excel：≤ 5 MB。
- 不允许 PDF。

返回：

```json
{
  "ok": true,
  "draft": {
    "projects": [],
    "items": [],
    "warnings": []
  },
  "rawModel": {
    "model": "Qwen/Qwen3.5-9B",
    "usage": {
      "promptTokens": 0,
      "completionTokens": 0
    }
  }
}
```

失败：

```json
{
  "ok": false,
  "error": "AI_PARSE_FAILED",
  "message": "识别失败，请换一张更清晰的图片或手动添加。"
}
```

### 8.2 确认导入

```text
POST /api/calendar-imports/confirm
```

请求：

```json
{
  "draft": {
    "projects": [],
    "items": []
  }
}
```

行为：

1. 后端再次校验所有日期、标题、项目引用。
2. 创建缺失项目。
3. 创建排期条目。
4. 写入 `source=ai_import`。
5. 返回创建结果。

返回：

```json
{
  "ok": true,
  "created": {
    "projects": 1,
    "items": 8
  }
}
```

## 九、前端上传体验

入口建议放在工作日历右侧面板或顶部次级操作区：

```text
导入排期
[ 上传图片 ] [ 上传 Excel ]
```

不要把入口做得比“手动添加”更抢眼。第一版手动添加仍是主流程。

### 9.1 上传后状态

1. 上传中：
   - 显示“识别中”。
   - 禁用重复上传。
2. 识别成功：
   - 进入“导入预览”。
3. 识别失败：
   - 显示失败原因。
   - 保留重新上传入口。

### 9.2 导入预览

导入预览必须可编辑。

至少支持：

- 修改项目名。
- 修改排期标题。
- 修改开始日期。
- 修改结束日期。
- 删除某条草稿。
- 删除某个项目草稿。
- 确认导入。

草稿里置信度低的项要弱提示，例如：

```text
识别不确定，请确认日期
```

不要用大段 AI 解释文字。

## 十、提示词要求

系统提示词核心要求：

```text
你是排期表识别助手。请从用户提供的图片或表格文本中提取项目排期。
只输出 JSON，不输出解释。
日期必须输出 YYYY-MM-DD。
如果某个任务跨多天，输出 startDate 和 endDate。
如果只发生一天，startDate 和 endDate 相同。
不要编造日期；不确定时写入 warnings，并降低 confidence。
```

输出 JSON 必须符合 `CalendarImportDraft`。

## 十一、安全与日志

禁止：

- 日志打印 API Key。
- 日志打印完整原图 base64。
- 交付报告展示 API Key。
- AI 返回后不校验直接入库。

允许：

- 记录模型名称。
- 记录调用耗时。
- 记录 token usage。
- 记录识别成功/失败。
- 记录草稿条数。

## 十二、验收标准

### 12.1 图片导入

使用用户提供的真实排期图片测试：

- 上传成功。
- AI 返回草稿。
- 草稿中至少识别出项目名。
- 草稿中至少识别出 3 条排期。
- 日期格式正确。
- 用户能编辑草稿。
- 确认后写入工作日历。
- 月/周/今日能看到导入结果。

### 12.2 Excel 导入

使用真实 Excel：

- `/Users/dian/Desktop/HUAWEI Laputa_MG&APK时间表_0622.xlsx`
- `/Users/dian/Desktop/HW V+ ID视频-时间表0802.xlsx`

验收：

- 上传成功。
- 能识别 sheet 中的项目/阶段/节点。
- 能生成可编辑草稿。
- 用户确认后写入工作日历。
- 刷新页面后数据仍存在。

### 12.3 不支持 PDF

- 上传 PDF 时明确提示“不支持 PDF，请上传图片或 Excel”。
- 不能静默失败。

### 12.4 密钥保护

- 代码仓库不包含真实 API Key。
- 交付报告不包含真实 API Key。
- 日志不包含真实 API Key。
- `.env.local` 不提交。

### 12.5 成本与速度

交付报告记录：

- 图片样本平均识别耗时。
- Excel 样本平均识别耗时。
- token usage。
- 单次估算成本。

不要求极致准确率。第一版目标是跑通流程和评估修正成本。
