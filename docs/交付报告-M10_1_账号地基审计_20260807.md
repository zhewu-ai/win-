## 5. API userId 隔离审计清单

| # | 接口 | 归属校验方式 | 结论 |
|---|---|---|---|
| 1 | `GET /api/notes` | `where: { userId: session.userId, deletedAt: null, isArchived }` | ✅ |
| 2 | `POST /api/notes` | `create({ data: { userId: session.userId } })` | ✅ |
| 3 | `GET /api/notes/trash` | `where: { userId: session.userId, deletedAt: { not: null } }` | ✅ |
| 4 | `PATCH /api/notes/:id` | `findFirst({ id, userId, deletedAt: null })` 确认归属后 update | ✅ |
| 5 | `DELETE /api/notes/:id` | `findFirst({ id, userId, deletedAt: null })` 确认归属后软删 | ✅ |
| 6 | `POST /api/notes/:id/restore` | `findFirst({ id, userId, deletedAt: { not: null } })` | ✅ |
| 7 | `DELETE /api/notes/:id/permanent` | `findFirst({ id, userId, deletedAt: { not: null } })` 确认归属后删附件+便签 | ✅ |
| 8 | `POST /api/notes/:id/duplicate` | `findFirst({ id, userId, deletedAt: null })` | ✅ |
| 9 | `POST /api/notes/:id/attachments` | `findFirst({ id, userId })` 确认 note 归属后写入 `userId: session.userId` | ✅ |
| 10 | `DELETE /api/notes/:id/attachments/:attachmentId` | `findFirst({ id: attachmentId, noteId, userId })` 三条件同查 | ✅ |
| 11 | `GET /api/files/*` | 校验附件 `{ noteId, userId, storagePath }`，非本人 403；含路径穿越防护 | ✅ |
| 12 | `POST /api/trash-cleanup` | 全站回收站清理（删除超保留期便签），属**系统任务安全边界**，仅 loopback 可调 | ✅ |

补充说明（SPEC §5.9）：`runTrashCleanup` 不按 userId 过滤，但它是一个**系统级维护任务**（每日定时 + loopback 白名单），语义是「按保留策略清理全站过期回收站」，非按用户误删，符合「确认系统任务安全边界」条款，保持现状。

无 session / 无效 session 时所有接口均返回 401（回归中已实测 `GET /api/notes` → 401）。
