# PinNote M10.5 邀请制注册：交付报告

日期：2026-08-07

## 1. 结论摘要

本轮完成 M10.5 邀请制注册四件事：

1. **邀请码生成与管理**：管理员在「管理用户」页可生成邀请码（默认 7 天有效、可设 1–30 天）、查看邀请列表（状态/使用者/有效期）、撤销未使用邀请码。数据库只存 `codeHash`（sha256），明文仅在生成瞬间返回一次，列表绝不下发明文。
2. **邮箱 + 邀请码注册**：`/register` 页输入邮箱、密码（≥8 位）、邀请码即可注册并**自动登录**。事务内完成「校验邀请码 → 创建用户 → 标记邀请已使用」，任何一步失败整体回滚。新用户 `username=email`、`displayName` 为邮箱 @ 前缀、`role=user`、`status=active`、额度 10 MB。
3. **登录兼容邮箱**：登录页输入框改为「邮箱或用户名」，后端 `findFirst OR username/email` 双路匹配，老用户名登录不受影响。
4. **安全加固**：注册接口忽略 role/status/额度注入字段（不能注册出管理员）；重复邮箱 409 `EMAIL_ALREADY_REGISTERED`；邀请码错误统一收敛为「邀请码无效或已过期」。

未做（SPEC 明确排除）：开放注册、邮箱验证、找回密码、微信/手机/OAuth 登录、内容审核、删除用户。注册邀请码入口保留，不改变既有管理员账号。

## 3. schema 变更说明

```prisma
model User {
  // …既有字段不变
  email             String?  @unique   // 新增：新用户注册邮箱（老账号为 null，仍用用户名登录）
  createdInvites    InviteCode[] @relation("InviteCreatedBy")
  usedInvites       InviteCode[] @relation("InviteUsedBy")
}

model InviteCode {
  id          String    @id @default(cuid())
  codeHash    String    @unique
  createdById String
  usedById    String?
  status      String    @default("active") // "active" | "revoked" | "used" | "expired"
  expiresAt   DateTime
  usedAt      DateTime?
  createdAt   DateTime  @default(now())
  updatedAt   DateTime  @updatedAt
  createdBy   User  @relation("InviteCreatedBy", fields: [createdById], references: [id])
  usedBy      User? @relation("InviteUsedBy", fields: [usedById], references: [id])
  @@index([createdById]) @@index([usedById]) @@index([status])
}
```

- 仅存 `codeHash`，明文不落库；「已过期」状态由服务端按 `expiresAt` 实时判定，不单独存列。
- `db push --accept-data-loss`：email 列全新且全为 null，唯一约束添加安全；InviteCode 为新表。

## 4. 注册事务与安全设计（关键决策）

**注册原子性**：`prisma.$transaction` 内依次「按 codeHash 查邀请 → 校验 active/未过期 → create user → 更新邀请 used」。任一步抛错整体回滚，杜绝「创建了用户但邀请没标已用」或相反。

**安全加固**：

- 注册请求只读取 `email/password/inviteCode`，`role/status/storageQuotaBytes` 等注入字段被忽略，永远按服务端默认建普通用户。
- 邮箱 `trim().toLowerCase()` + 正则 + 长度 ≤254 校验（`INVALID_EMAIL`）。
- 密码 bcrypt 哈希，最少 8 位（`PASSWORD_TOO_SHORT`）。
- 邀请错误码（`INVALID_INVITE_CODE` / `INVITE_REVOKED` / `INVITE_USED` / `INVITE_EXPIRED`）在前端收敛为一句友好提示，不泄露邀请码存在性细节。
- 自动登录：注册成功后 `session.userId = newUser.id; session.save()`，新用户直达主页。

## 14. 回退方案

若出现注册异常、老账号登录异常：

```bash
# 1) 停服务
export XDG_RUNTIME_DIR="/run/user/$(id -u)"
systemctl --user stop sticky-notes.service

# 2) 恢复 M10.5 前数据库备份
cp /home/ubuntu/backups/prod_M10_5_20260807_134854.db \
   /home/ubuntu/projects/sticky-notes/data/prod.db

# 3) 校验
sqlite3 /home/ubuntu/projects/sticky-notes/data/prod.db "PRAGMA integrity_check;"

# 4) 回退代码（git checkout 上轮 commit 后 rsync src/ --delete + prisma/schema.prisma）
# 5) 重新 build + 重启服务
npm run build
systemctl --user restart sticky-notes.service

# 6) 复查：admin 可登录 / Note 26 / Attachment 1
```

回退后 email 列与 InviteCode 表随 schema 回退被移除，注册相关路由与入口随代码回退，老账号登录（用户名）完全不受影响。
