# QA M12：工作日历视觉一比一返修要求

日期：2026-08-09

原型基准：

- `/Users/dian/.codex/visualizations/2026/08/06/019fd7e6-8a92-7780-80ce-ef4cfb9e710b/work-calendar-interactive-prototype.html`

## 一、结论

当前 M12 人工闭环的功能骨架基本有了，但视觉完成度不达标。问题不是后端模型或 API，而是前端 UI 没有按原型的信息层级和视觉气质落地，整体更像工程化表格小组件，弱于原型。

本轮返修目标很明确：

**不要再自由发挥。直接按原型做视觉，一比一复刻原型的信息层级、布局节奏、项目色系、月视图甘特表达、右侧详情与筛选交互。**

现有数据模型、API、quick-week 逻辑可以保留，不要求推倒重写。返修重点是视觉和交互完成度。

## 二、硬性原则

1. 以原型为视觉基准，不以当前实现为基准。
2. 不新增 AI 导入。
3. 不改动 M12 后端主模型，除非为项目详情全量查询必须补 API。
4. 不继续把日历做成普通日历软件。
5. 不把界面做成密集表格、灰色小字、工程后台风。
6. 功能能用但视觉明显比原型差，不算通过。

## 三、必须一比一对齐的地方

### 3.1 整体布局

工作日历右侧主空间应接近原型结构：

```text
┌ 左侧便签栏 ┬ 工作日历主区 ┬ 右侧项目/编辑详情 ┐
│ 日历分组   │ 顶部标题/视图 │ 项目详情          │
│ 工作日历卡 │ 项目筛选条    │ 手动添加/修正      │
│ 置顶       │ 月/周/今日区  │ 后续导入提示       │
└───────────┴──────────────┴──────────────────┘
```

要求：

- 主区顶部不要堆很多小按钮。
- 视图切换、项目筛选、新增入口要有清楚层级。
- 右侧详情面板要常驻或在选中项目/条目后清楚出现，不能藏得太深。
- 视觉上要像一个完整工作空间，不像临时拼出来的表格。

### 3.2 顶部区

参考原型顶部：

- 左侧：`2026年8月` 或当前周范围。
- 次级说明：月视图看项目并行和风险密度；周视图处理连续阶段；今日视图落到可执行事项。
- 右侧：`今日 / 月 / 周` segmented control。

现有“工作日历 + 周/月/今日 + 上下页 + 今天 + 新增排期 + 新增项目 + 快速录入”挤在一行，视觉太碎。需要重排：

- 第一行：标题 + 视图切换。
- 第二行或筛选行：项目筛选 + 便签链接开关 + 新增/快速录入按钮。
- 不要让 6-8 个控件全部挤在同一行。

### 3.3 项目筛选

必须按原型做成清楚的 filter chip：

```text
[✓ A 项目 / HW V+] [✓ B 项目 / Laputa MG] [✓ C 项目 / APK] [✓ 便签链接] [新增排期] [项目详情]
```

要求：

- 每个项目 chip 有色块或色点。
- 勾选/取消后，月视图、周视图、今日视图、统计数字、左侧预览全部同步。
- 取消某项目后，不能在任何视图残留该项目。
- 取消便签链接后，月/周/今日的便签链接层都隐藏。

当前实现只在今日视图显示便签链接开关，不通过。

### 3.4 月视图

月视图必须按原型做成“月历 + 轻量甘特层”，不是每周上方另贴一排小条。

要求：

- 连续阶段跨日期连成一条，视觉上落在月历日期格内部。
- 单日节点显示在当天。
- 多项目并行时上下分轨。
- 同一项目同色系。
- 便签链接层可显示/隐藏。
- 日历格高度要稳定，不能因为任务多少造成布局跳动。

不要：

- 不要把甘特条挤成 10px 小字。
- 不要把甘特条单独塞在日期行上方，造成“贴片感”。
- 不要让文字、日期、节点互相抢位置。

### 3.5 周视图

周视图是默认主工作区。

要求：

- 七列清晰。
- 每天下面显示今天命中的连续阶段、单日节点、便签链接。
- 连续阶段应能看出“同一个阶段跨多天”，不要只是每天复制一个孤立 chip。
- 今天高亮要克制清楚。
- 空列显示“无排期”即可，不要制造视觉噪音。

### 3.6 今日视图

今日视图必须是工作台，不是普通列表。

分区必须是：

1. 今天要做：今天处于进行中阶段的排期。
2. 今天节点：call、会议、提交、反馈、交付、收付。
3. 今天编辑的便签：今天创建/更新的便签链接。

每条信息要说清楚：

- 今天要修改哪个项目的什么内容。
- 处于什么阶段。
- 是否有关联便签。

### 3.7 右侧详情面板

右侧要参考原型做成稳定详情区。

点击项目时显示项目详情：

- 项目名称。
- 状态：进行中 / 已结束待归档 / 已归档。
- 时间范围。
- 当前阶段。
- 下一节点。
- 排期条目列表。
- 关联便签。
- 新增排期、编辑、归档。

点击条目时显示条目编辑：

- 标题。
- 项目。
- 类型：连续阶段 / 单日节点。
- 开始日期。
- 结束日期。
- 状态。
- 关联便签。
- 保存 / 删除。

不能只依赖弹窗。弹窗可以保留，但右侧详情区必须承担主要编辑/查看角色，视觉要接近原型。

### 3.8 过期项目处理

项目排期结束后，不应继续占据顶部进行中列表。

要求：

- 如果项目 `status=archived`，默认不显示。
- 如果项目所有排期都已结束，显示“已结束待归档”或自动折叠到历史区。
- 顶部项目 chip 默认只显示 active 且未结束的项目。
- 月历历史中仍可查看过期项目。

当前只按 `status=active` 判断，不足。

### 3.9 手动输入

手动输入是第一版主流程，必须比 AI 入口更显眼。

必须保留：

- 新增项目。
- 新增排期。
- 快速录入一周。
- 预览确认。
- 保存后三视图同步。

AI 导入只做后续提示，不做主入口。

## 四、视觉标准

### 4.1 颜色

- 项目决定色系。
- 同一项目用深浅变化表达阶段/节点。
- 不同项目色系区分，但不要高饱和乱跳。
- 便签链接层必须弱于排期主层级。

### 4.2 字体与密度

- 不要把核心信息压成过小的 10px 字。
- 标题、项目名、日期、任务名要有清楚层级。
- 月视图可以省略次要信息，但不能把所有文字压小硬塞。

### 4.3 卡片与圆角

- 圆角控制在 8px 内。
- 卡片边框、背景、hover、选中态要与 PinNote 现有风格一致。
- 不做大渐变、大阴影、大 banner。

### 4.4 响应式

- 320px / 390px 不横向溢出。
- 窄屏下可以从三栏变成单栏/抽屉，但信息层级不能丢。
- 右侧详情在窄屏可变成抽屉。

## 五、验收标准

### 5.1 原型对齐

验收时必须把实际页面和原型并排看。

原型路径：

`/Users/dian/.codex/visualizations/2026/08/06/019fd7e6-8a92-7780-80ce-ef4cfb9e710b/work-calendar-interactive-prototype.html`

通过标准：

- 第一眼信息层级接近原型。
- 月视图项目色系、甘特条、节点、便签链接层接近原型。
- 右侧详情/编辑区接近原型。
- 筛选 chip 与开关接近原型。

不通过标准：

- 看起来仍像工程表格。
- 比原型明显更挤、更碎、更灰。
- 需要解释才知道哪里能点、哪里是项目、哪里是今天任务。

### 5.2 筛选闭环

- 关闭 A 项目，月/周/今日均无 A 项目。
- 关闭便签链接，月/周/今日均无便签链接。
- 统计和左侧预览同步变化。

### 5.3 手动闭环

- 新增项目后出现在项目筛选和详情。
- 快速录入周一到周四相同内容，生成一条连续阶段。
- 新增周六 call，生成单日节点。
- 修改条目日期后，月/周/今日全部同步。
- 删除条目后，所有视图消失。

### 5.4 过期项目

- 已结束项目不占顶部 active chip。
- 可在归档/历史中查看。
- 月历历史仍保留记录。

### 5.5 今日视图

- 今天要做、今天节点、今天编辑的便签三分区清楚。
- 今天处于连续阶段内的任务显示为“今天要做”。
- 今天创建/更新便签显示为链接，并能打开。

### 5.6 视觉验收

- 亮色、暗色都可读。
- 320px / 390px 不溢出。
- 文本不重叠。
- 主要按钮不挤在一行。
- 选中态蓝色明确，不像禁用。
