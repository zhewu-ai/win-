# M8 第三轮视觉复验反馈：窄窗口头部空壳、小标题样式、底部时间戳

日期：2026-08-04

结论：部分通过，继续修复。

本轮技术部已经修复了待办密度和边缘空隙问题，这个方向是对的。但窄窗口下顶部区域、小标题视觉和底部时间戳仍然没有达到产品可用标准。这些属于用户每天都能看到的细节，必须继续打磨。

## 1. 已改善项

### M8-R3-PASS-01：待办边缘空隙和行间距已有改善

用户反馈：

- 待办模式下边缘和行距已经比上一版好。
- 信息密度问题有明显改善。

后续要求：

- 保持当前紧凑度。
- 不要为了调整标题/顶部栏又把待办行距拉大。

## 2. 仍未通过问题

### M8-R3-F01：窄窗口下“新建/账户”移到底部，但顶部空间没有省出来

严重级别：P0

用户现象：

- 技术部把“新建”和“我的/账户”图标移动到了左下角。
- 但窗口缩小时，顶部仍然留着一整块高度。
- 用户感受到的是：图标虽然挪走了，但顶部还是很厚、不轻薄，核心编辑空间没有真正释放。

产品判断：

这不是“图标位置”问题，而是“顶部栏空壳高度”问题。

当前疑似代码线索：

- `src/components/TopBar.tsx` 顶层仍有类似：

```tsx
min-h-[56px]
px-4 py-2
border-b
```

- 窄窗口时只是隐藏了新建/账户，但 `TopBar` 本身仍占 56px 高度。
- 如果编辑态 `showEditor` 时顶部仅剩空白 spacer，这个顶部栏就应该进一步压缩或隐藏。

产品要求：

窄窗口下，不能只是把按钮移到底部。必须真实释放顶部高度。

建议规则：

1. 当窗口宽度小于 420px，且处于编辑态：
   - 顶部全局栏应隐藏，或压缩到极薄高度。
   - 不能保留 56px 空白栏。
2. 如果需要返回/搜索：
   - 列表态可保留搜索栏。
   - 编辑态优先保留编辑器自己的工具栏，不保留全局空栏。
3. 新建/账户可以放到底部，但底部工具条不能导致顶部继续占空间。

验收标准：

1. 320px 宽编辑态下，顶部不再有一条明显空白厚栏。
2. “新建/账户”移到底部后，编辑区垂直空间明显增加。
3. 顶部视觉更轻薄，不能像网页导航栏硬塞在小窗里。
4. 列表态如需搜索栏，可以保留；编辑态不要保留无功能空栏。

### M8-R3-F02：小标题样式太单薄，文字和分隔线没有视觉居中

严重级别：P1

用户现象：

- 小标题功能存在，但视觉太单薄。
- 小标题文字和旁边的段落/线条没有对齐、没有居中。
- 看起来像临时插入的一行普通文本，不像设计过的段落标题。

产品要求：

小标题应该是“轻量段落标题”，不是复杂分组，但必须有清楚的视觉层级。

推荐视觉方案：

```text
──────── C4D ────────
○ 模型比例调整
○ 材质太亮

──────── AE ─────────
○ 字幕错位
○ 输出预览
```

具体要求：

1. 小标题文字垂直居中。
2. 小标题文字和左右分隔线在同一水平中心线。
3. 小标题行高度要适中，不能太高，也不能挤成普通文本。
4. 小标题没有勾选圆圈。
5. 小标题可以编辑、删除、拖拽排序。
6. 小窗口下仍然美观，不要因为线太长或文字太长溢出。

建议样式：

- 使用 flex 居中：

```text
line - title - line
```

- 标题文字：
  - 字号略小于正文
  - 字重 600
  - 颜色用 `text-ink-muted` 或略亮
  - 最大宽度限制，长标题省略或换行需有规则
- 左右线条：
  - `flex: 1`
  - 低透明度
  - 与文字中心线对齐

验收标准：

1. 插入“小标题：C4D”，视觉上能一眼看出是段落标题。
2. 文字和左右线条居中对齐。
3. 在 320px 宽窗口下仍然不歪、不挤、不溢出。
4. 删除、拖拽、小标题编辑仍可用。

### M8-R3-F03：时间戳已到底部附近，但没有真正靠近底部边栏

严重级别：P2

用户现象：

- 时间戳已经不在顶部。
- 但它会跟着文本内容走。
- 当文本较少时，时间戳仍然出现在偏上的位置，没有靠近底部边栏。

产品判断：

这取决于产品想表达什么：

- 如果时间戳是文档内容的一部分，跟着文本走可以接受。
- 但用户当前感受是它仍然太靠上，尤其在窗口较高、文本较少时显得悬在中间。

本产品建议：

- 时间戳应作为编辑区的底部元信息，不是正文的一部分。
- 它应该尽量贴近可视编辑区底部，但不能遮挡正文。

产品要求：

1. 编辑区域内容较少时，时间戳靠近底部边栏。
2. 编辑区域内容很多时，时间戳跟随内容自然出现在内容之后。
3. 小窗口下时间戳不能挤占顶部或正文主要空间。

建议实现：

- 编辑器主体使用 flex column：
  - 上部：标题 + 正文/待办 + 图片，`flex: 1`
  - 底部：时间戳 footer
- 当内容不足一屏时，footer 被推到底部。
- 当内容超过一屏时，footer 在内容之后，需要滚动到底部看到。

验收标准：

1. 空便签或短文本便签中，时间戳靠近编辑区底部。
2. 长文本便签中，时间戳位于内容结束之后。
3. 320px 小窗口下时间戳不占用顶部空间，不遮挡正文。

## 3. 本轮优先级

P1：

1. 小标题视觉重新设计：文字和线条居中，视觉层级清楚。

P2：

1. 时间戳作为底部 footer，而不是普通内容流里一行。
