## 二、实现说明

### 1. 登录频控（`src/app/api/auth/login/route.ts`）
- 复用 `src/lib/rateLimit.ts` 内存桶（`rateLimit(key, limit, windowMs)`）。
- 双桶：IP 维度 `login:ip:{ip}` 10 次/10 分钟；账号维度 `login:acct:{identifier}` 5 次/10 分钟。
- 两条失败路径（密码错误 → 401、账号禁用 → 403）均先计次，超限返回 429 `RATE_LIMITED`。
- IP 取自 `x-forwarded-for` 首段，无代理时回退 `"unknown"`（同桶合并）。

### 2. 注册频控 + 先校验邀请码再 bcrypt（`src/app/api/auth/register/route.ts`）
- 频控：IP 5 次/10 分钟；邀请码维度 `register:invite:{codeHash}` 5 次/10 分钟（用 sha256 哈希做 key，不落明文）。
- **调整校验顺序**：先查邀请码记录（不存在/已吊销/已用/已过期分别返回 `INVITE_INVALID / INVITE_REVOKED / INVITE_USED / INVITE_EXPIRED`），通过后才执行 `bcrypt.hash(password, 10)`。事务内原子领取邀请码仍是权威（防并发重复领取）。
- 收益：未通过邀请码校验的请求不再支付 bcrypt 成本，杜绝 CPU 型 DoS。

### 3. 重置密码频控 + 先校验 token 再 bcrypt（`src/app/api/auth/reset-password/route.ts`）
- 频控：IP 5 次/10 分钟（密码长度校验通过后计）。
- **调整校验顺序**：先查 token 哈希（`reset_token` 哈希后 findUnique：不存在/已用/已过期 → `RESET_TOKEN_INVALID / RESET_TOKEN_USED / RESET_TOKEN_EXPIRED`），通过后才 `bcrypt.hash(newPassword, 10)`。事务原子领取仍是权威。

### 4. 附件真实图片校验，伪装文件不落盘（`src/app/api/notes/[id]/attachments/route.ts`）
- 由「先落盘再 sharp 校验」改为「先 `sharp(buffer).metadata()` 校验，通过才写盘」。
- 无法解析为有效图片 → 400 `INVALID_IMAGE_FILE`；尺寸超 8192×8192 → 413 `IMAGE_TOO_LARGE`。
- 保留 prisma 建行失败时 `unlink` 孤儿文件的兜底清理。

### 5. PATCH /api/auth/me 改 active 校验（`src/app/api/auth/me/route.ts`）
- 与 change-password 同口径：PATCH 前重新查库 `status`，非 `active` → 403 `ACCOUNT_DISABLED`。禁用用户旧 session 也不能改资料。

### 6. 输入长度与数量上限（`src/lib/note-serializer.ts`、`src/app/api/notes/route.ts`、`src/app/api/notes/[id]/route.ts`）
- 新增常量与 `validateNoteTextFields()`：标题 ≤200、正文 ≤50000。
- `validateChecklistItems`：条目数 ≤500、单条文本 ≤1000。
- `validateChecklistGroups`：分组数 ≤100、分组标题 ≤200。
- 搜索词 `q` 截断到 100 字符。
- 仅服务端 API 路由校验，前端不受影响。

### 7. rateLimit 内存清理（`src/lib/rateLimit.ts`）
- 新增 `pruneRateLimits()`：每 128 次调用触发一次，清理已过期的桶，杜绝长期运行内存只增不清。

### 8. /api/trash-cleanup 维护密钥（`src/app/api/trash-cleanup/route.ts`、`.env.example`、systemd timer）
- 配置 `TRASH_CLEANUP_SECRET` 后，要求 `Authorization: Bearer <secret>`，否则 403。
- 未配置时退回回环来源判断（仅本地开发），并归一化 `::ffff:` IPv4 映射。
- 生产已生成随机密钥写入 `.env`，systemd user timer `sticky-notes-trash-clean.service` 的 curl 已带 `-H "Authorization: Bearer <secret>"`。

## 三、验证记录

### 本地验证（macOS + dev 实测）
- `npx tsc --noEmit` + `npm run build` 通过。
- **登录频控**：伪造 5 次错误密码后第 6 次（账号桶上限 5）→ 429；换 IP 继续撞到 IP 桶上限 10 → 429；正确密码在桶内仍可登录。
- **注册频控**：无效邀请码直接返回 `INVITE_INVALID`（不再消费 bcrypt）；对同一邀请码连续请求触发 429。
- **重置密码频控**：无效 token 直接返回 `RESET_TOKEN_INVALID`；超频 → 429。
- **附件真实图片**：上传非图片文件 → 400，磁盘无残留；超 8192px 图片 → 413。
- **PATCH /me**：禁用账号（dev 库）PATCH 昵称 → 403 `ACCOUNT_DISABLED`。
- **输入上限**：超长标题/正文/待办 → 400；`q` 超长截断。
- **trash-cleanup**：本地无密钥模式伪造 XFF → 403；真实回环 → 200。
