# PinNote M10.13：刷新按钮与保存状态工具栏优化

日期：2026-08-08

## 1. 结论摘要

针对 M10.12 之后编辑区工具栏「刷新按钮被「已保存」占位挤到偏中间、窄窗口工具区不稳定」的视觉问题，本轮实现 SPEC_M10_13（纯前端 UI 信息层级调整，不改刷新逻辑、不改数据库、不改账号体系）：

1. **常态隐藏「已保存」（P0）**：`SaveStatus` 在本机已保存且无 pending、无 syncError 时返回 `null`，不渲染、不占固定宽度，把稳定位置让给刷新按钮。
2. **刷新按钮稳定居首（P0）**：`NoteEditor` 移除 `w-14` 固定宽度容器，`SaveStatus` 改为内联放在刷新按钮左侧（仅过程/异常态出现），右侧主按钮组排序稳定为 `[刷新]→[置顶]→[窗口置顶(桌面壳)]→[更多]`。
3. **异常/过程态不受影响（P0）**：保存中、保存失败+重试、等待同步、离线、同步失败等状态仍显示在刷新按钮左侧，且不推动刷新按钮横移。
4. **320px 窄布局回归（P0）**：实测侧边栏搜索/刷新/折叠、编辑器刷新/置顶/更多在 320px 下均不重叠、不横向溢出。

M10.12 的手动刷新逻辑、刷新前未保存保护、同便签远端版本应用逻辑均未改动，本轮只做展示策略调整。

## 3. 关键实现

### 3.1 SaveStatus 常态隐藏

```tsx
const pending =
  syncStatus === "pendingCreate" ||
  syncStatus === "pendingUpdate" ||
  syncStatus === "pendingDelete";

// M10.13 常态隐藏：本机已保存且无待同步、无同步失败 → 不渲染、不占位
if (!pending && syncStatus !== "syncError") {
  return null;
}
```

- `status === "saving"`（保存中）、`error`/`localError`（保存失败）、pending 三态（等待同步/离线）、`syncError`（同步失败）分支保持不变，全部照常渲染。
- 与 M10.12 语义一致：本机已保存 ≠ 多端最新，「已保存」属低价值常态信息，常态化隐藏避免长期占用工具栏。

### 3.2 NoteEditor 工具栏结构调整

- 删除原 `w-14 flex items-center justify-end flex-shrink-0` 固定宽度容器（原位于刷新按钮右侧）。
- `SaveStatus` 改为在 `<div className="flex-1" />` 与刷新按钮之间内联渲染，出现时向左自然展开，不推动右侧 `[刷新][置顶][更多]` 按钮组横移。
- 右侧主按钮组稳定排序：`[刷新便签] → [置顶便签] → [窗口置顶(仅桌面壳 isTauri)] → [更多操作]`。
- `toolbarMode === "minimal"` 时仍省略状态区域，极简模式只保留主按钮。

## 4. 验收结果

### 4.1 本地（dev + 浏览器实测）

- **常态无「已保存」**：1280px 双栏下编辑器工具栏右侧组为 `[刷新][置顶][更多]`，无「已保存」/「同步中」文字，状态区不占固定宽度。通过。
- **保存中**：编辑触发 debounce 保存时，小型「保存中」状态瞬时出现在刷新按钮左侧，刷新按钮位置不动。通过。
- **等待同步**：构造 pendingUpdate（PATCH 500 降级路径）后，状态显示在刷新按钮左侧（实测 1084px），刷新按钮仍在 1148px，无重叠。通过。
- **保存失败 + 重试**：PATCH 拦 400 触发 `saveStatus="error"`，工具栏显示「保存失败 重试」（实测 1060–1142），刷新按钮在 1148–1184，错误态不遮挡不推挤刷新按钮。通过。恢复 fetch 后点「重试」成功清除错误态。
- **同步失败**：syncError 时 SaveStatus 显示「同步失败，内容已保存在本地」提示。通过。
- **320px 窄布局**：
  - 侧边栏：搜索输入(12–253)、刷新(259–295)、折叠(301–337) 无重叠。
  - 编辑器工具栏：切换到普通便签、刷新(188–224)、置顶(230–266)、更多(272–308) 无重叠、全部落在 320px 内，`document.scrollWidth == 320` 无横向溢出。
  - 「返回列表」与折叠侧边栏内刷新按钮的视觉重叠为误判：该刷新按钮位于 `w-0 opacity-0 pointer-events-none` 的隐藏侧边栏内，实际不可见不可点。
- **刷新回归**：点击编辑器刷新按钮触发 `GET /api/notes?archived=false → 200`，无「刷新失败」。通过。
- 测试便签「M10.13状态验证」验证后已删除清理。

## 7. 风险与后续建议

1. **状态提示瞬时出现位置**：`SaveStatus` 内联在刷新按钮左侧，保存中/等待同步等过程态出现时会在状态区出现/消失一次。由于不再占固定宽度，出现时会向左展开约 70–100px，不推动右侧按钮组；若用户对「状态出现导致左侧布局瞬时变化」敏感，可在后续版本将状态区改为 `absolute` 浮层或固定小宽度。
2. **「已保存」完全不可见**：常态下用户无法确认本机已保存，只能靠「最后编辑于」时间戳。按 SPEC §七 权衡接受；如需给「保存完成」反馈，可后续叠加 0.8–1s 弱 toast，但不常驻工具栏。
3. **刷新仍为手动触发**：P1 低频自动拉取继续推迟，与 M10.12 结论一致；「刚刚刷新 HH:mm」角标等增强未做，属后续可选。
4. **生产构建约束**：共享 VM 继续使用 `npm run build -- --webpack`（Turbopack OOM 教训），本轮构建正常；preview 独立预演环境仍为清理状态，未重建。
