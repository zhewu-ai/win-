## 本轮验收重点（第 3 批）

### 1. F01：极小模式按钮已移除，不再崩溃（P0）

验证点：

1. 打开便签编辑页，工具栏中**没有**「极小模式」按钮（保留窗口置顶按钮）。
2. 界面上不存在任何能触发悬浮窗的入口。
3. App 正常使用（新建/编辑/切换便签）**不再崩溃**。
4. 窗口置顶开关仍可正常开/关。

证据要求：

- 截图：编辑页工具栏（确认无极小模式按钮、有窗口置顶按钮）。

### 2. F02：待办行紧凑、小窗高密度（P1）

验证点：

1. 新建待办便签，输入 8–10 条短待办（单行内容）。
2. 主窗口缩到约 320px 宽。
3. 待办行紧凑：单行待办高度约 28–32px，一屏能完整看到 8–10 条以上短待办。
4. 勾选几条后，底部「已完成」区同样紧凑，不占太多空间。
5. 一条 80 字长待办仍自动换行、可完整阅读，无横向滚动。
6. 左侧勾选圆圈、拖拽手柄仍可正常点击/拖拽（未被挤压）。

证据要求：

- 截图：320px 主窗，一屏含 8–10 条以上短待办 + 已完成区。
- 说明文字确认长待办换行后无横向滚动。

### 3. F03：Pointer Events 拖拽排序（P1，需真机确认）

验证点：

1. 在待办列表上，按住某条待办左侧的**拖拽手柄**（6 格图标，命中区已放大到 24px）拖动。
2. 拖动过程中出现**黄色插入指示条**，指示目标插入位置。
3. 松手后该待办移动到指示位置，顺序保存（刷新后仍保持）。
4. 小标题（heading 行）同样可拖拽排序。

证据要求：

- 录屏：按住手柄拖动 → 指示条出现 → 松手排序生效 → 刷新保持。
- 如仍拖不动：DevTools 控制台贴完整报错文本，并说明操作系统版本（Win10/Win11）与 App 版本。

### 4. F04：小窗左下角迷你工具条（P1）

验证点：

1. 主窗口缩到 ≤420px 宽（约 320px）。
2. 顶部**不再显示**「新建」「账户」入口（搜索框独占顶部，空间不再被挤占）。
3. 左下角出现固定的迷你工具条：新建 + 账户。
4. 点账户 → 下拉菜单**向上**弹出，含 归档 / 回收站 / 退出登录。
5. 新建便签、归档、回收站、退出登录均可用。
6. 列表滚到最底部，最后一条便签**不被**工具条遮挡。

证据要求：

- 截图：320px 主窗顶部（无新建/账户）+ 左下角迷你工具条。
- 截图：账户下拉向上弹出。
