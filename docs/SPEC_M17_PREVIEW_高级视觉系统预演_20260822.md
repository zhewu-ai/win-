# SPEC M17 Preview：PinNote 高级视觉系统预演

日期：2026-08-22

状态：待技术部评估与排期

## 一、结论

M17 下一阶段先不做功能扩张，也不直接改线上 UI。

本轮目标是：

```text
先做 2-3 套高保真视觉设计稿，让产品侧确认 PinNote 未来的高级视觉气质。
```

本轮不要求上线，不要求接生产数据，不要求合并 `main`。当前线上版本已经可用且已有用户，必须保持稳定。

## 二、背景

当前 PinNote 功能已经基本可用，但整体视觉仍有明显“网页组件拼装感”：

- 壳和 Web 内容不够一体。
- 顶部区域不像完整原生桌面应用。
- 搜索框、按钮、卡片、输入框圆角体系不统一。
- 图标风格不够一致。
- 文字层级、留白、卡片边框和阴影显得不够精致。
- 空态和浮动助手视觉与“高级、简洁、成熟桌面工具”的方向不一致。

用户对比了 Codex/GPT、苹果官网、GPT 网页版、iOS 备忘录后，明确反馈：

```text
PinNote 现在能用，但还不够高级、不够简洁、不够精致。
```

因此 M17 先做视觉系统预演。

## 三、硬性隔离要求

### 3.1 不影响线上业务

本轮设计稿和预览必须与正式线上版本完全隔离。

硬性要求：

1. 不直接修改生产站点。
2. 不直接部署覆盖正式域名。
3. 不连接生产数据库做写入。
4. 不影响正式桌面壳。
5. 不改变当前线上用户使用体验。
6. 不合并到 `main`，除非产品侧确认视觉方向并通过验收。

### 3.2 Preview 只给内部确认

如果需要可交互预览，必须走以下任一方式：

方案 A：本地确认

```text
本地 dev / 本地静态原型 / 本地 Tauri 壳
```

方案 B：隔离 preview 域名

```text
preview.notes.hello-mylife.online
```

preview 环境要求：

- 使用独立分支。
- 使用测试库或生产库副本。
- 使用独立上传目录。
- 使用独立服务和端口。
- 不复用生产 systemd service。
- 不复用生产上传目录。
- 不向真实用户发送邮件或通知。

### 3.3 客户端也先内部打磨

后续如果基于该视觉方向做 macOS/Windows 客户端，也先作为内部 Preview。

要求：

1. macOS 客户端先内部使用，不直接作为正式下载入口推给用户。
2. Windows 客户端后续补，不因 Mac Preview 影响正式 Web。
3. 客户端视觉未确认前，不替换官网正式下载页。
4. 客户端本地化、本地数据库、大文件策略另开技术预研，不混入本轮视觉设计稿。

## 四、本轮交付目标

技术部或设计执行方需要产出 2-3 套高保真视觉方案。

每套方案至少覆盖：

1. 主工作台：左侧列表 + 右侧编辑区。
2. 选中便签状态。
3. 空态。
4. 搜索框。
5. 顶部栏/壳融合方案。
6. 工具栏和格式按钮。
7. 待办块。
8. 工作日历入口卡片。
9. 暗色模式。
10. 320px / 390px / 720px / 1440px 响应式状态。

本轮验收重点是视觉气质，不是功能完整度。

## 五、建议设计方向

### 方向 A：Apple Notes 原生感

关键词：

```text
原生、安静、轻、内容优先、壳与内容一体
```

重点：

- 更像 macOS/iOS 备忘录的成熟工具感。
- 弱化卡片边框和阴影。
- 侧栏更像原生列表。
- 编辑区大留白，文字是视觉中心。
- 图标、按钮、搜索框统一为系统感。

### 方向 B：Codex / GPT 式安静侧栏

关键词：

```text
专业、克制、密度合理、层级清楚
```

重点：

- 左侧侧栏更干净。
- 选中态低调但明确。
- 卡片减少“白盒子”堆叠感。
- 搜索、列表、工具栏的层级更统一。
- 更适合长期办公使用。

### 方向 C：PinNote 轻办公感

关键词：

```text
便签感、温和、轻办公、识别度
```

重点：

- 保留 PinNote 的便签属性。
- 颜色更克制，不做儿童化、玩具化。
- 卡片仍有轻微便签感，但不要像组件库卡片。
- 日历和待办与便签风格统一。

## 六、必须重点解决的问题

### 6.1 壳和 Web 一体化

当前 macOS 壳上方有系统标题栏，Web 内容从下方开始，视觉上像“壳里塞了网页”。

设计稿需要给出至少一种解决方案：

1. 透明标题栏 + Web 自绘顶部栏。
2. 隐藏默认标题栏 + 保留红黄绿按钮区域。
3. Web 顶部延伸到窗口顶部，定义可拖拽区域。

要求：

- 不破坏 macOS 基础窗口操作。
- 不遮挡红黄绿按钮。
- 不牺牲搜索和新建入口可用性。
- 看起来像一个完整桌面应用。

### 6.2 搜索框和圆角体系

需要统一：

- 搜索框圆角。
- 卡片圆角。
- 按钮圆角。
- 输入框圆角。
- 弹层圆角。
- 图片缩略图圆角。

设计稿需要给出 token，而不是每个组件随意设值。

建议输出：

```text
radius-sm
radius-md
radius-lg
radius-pill
```

注意：不是圆角越大越高级。目标是统一、自然、成熟。

### 6.3 图标系统

当前图标存在风格不统一的问题。

要求：

1. 统一图标库或统一线性图标风格。
2. 统一线宽、尺寸、留白。
3. 避免混用像素风、重描边、拟物、临时 SVG。
4. 低频操作收进更多菜单。
5. 右下角像素机器人需要重新评估，默认建议移除或替换成更克制的助手入口。

### 6.4 排版和密度

需要重新定义：

- 标题字号。
- 正文字号。
- 时间/状态/数量字号。
- 字重。
- 行高。
- 卡片内边距。
- 分组标题间距。
- 工具栏按钮间距。

目标：

```text
信息清楚，但不粗糙；有密度，但不拥挤。
```

### 6.5 卡片和列表

当前左侧卡片容易显得像“白色小盒子堆叠”。

设计稿需要探索：

1. 更原生的列表式方案。
2. 弱边框/弱阴影卡片方案。
3. 选中态更高级的方案。

要求：

- 不要过度依赖重阴影。
- 不要每条内容都像后台管理卡片。
- 长标题、待办摘要、时间、颜色点都要有统一层级。

### 6.6 空态

右侧空态需要重做。

要求：

- 不像页面未加载。
- 不依赖卡通像素机器人。
- 文字简洁。
- 图标克制。
- 在大屏和窄屏都成立。

## 七、必须预留的未来状态

虽然本轮不做本地优先和大文件同步，但视觉稿需要预留未来状态位置。

需要考虑：

1. 已同步。
2. 本地保存中。
3. 离线可用。
4. 仅本机。
5. 待上传。
6. 文件过大，不自动上传。
7. 同步冲突。
8. 手动同步。

这些状态不要求实现，但设计稿需要说明未来放在哪里，不要到本地化阶段再推翻布局。

## 八、本轮不做

M17 Preview 不做：

1. 不上线正式站。
2. 不改生产数据库。
3. 不做本地 SQLite。
4. 不做本地文件系统同步。
5. 不做大文件同步。
6. 不做图片正文混排。
7. 不做文件夹/标签。
8. 不做 AI 问答。
9. 不做知识图谱。
10. 不做 Windows 正式发布。
11. 不重写为 Swift 原生应用。
12. 不重写为纯原生 Windows 应用。

如果技术部认为某个视觉方案必须牵涉上述功能，必须先提出，不得混入设计稿任务。

## 九、建议执行方式

### 阶段 1：视觉审计

输出当前问题清单：

1. 顶部栏/壳融合问题。
2. 搜索框和圆角问题。
3. 图标体系问题。
4. 排版和密度问题。
5. 卡片/列表问题。
6. 空态问题。
7. 暗色模式问题。

每个问题附当前截图和改进方向。

### 阶段 2：高保真方案

输出 2-3 套方案。

推荐形式：

- Figma。
- 静态 HTML 原型。
- 本地 Next preview route。
- 截图集。

每套方案必须包含：

- 亮色 1440。
- 暗色 1440。
- 390。
- 320。
- macOS 壳顶部一体化示意。

### 阶段 3：产品侧选择方向

产品侧只做方向选择：

1. 选 A。
2. 选 B。
3. 选 C。
4. 或要求合并其中两套的部分原则。

技术部不得在未确认方向前开始大面积改生产 UI。

### 阶段 4：可交互 preview

确认方向后，再做真实页面 preview。

要求：

- 独立分支。
- 独立 preview 环境或本地演示。
- 不写生产库。
- 不影响正式用户。

### 阶段 5：上线决策

只有满足以下条件，才进入正式集成：

1. 产品侧确认视觉方向。
2. 1440/720/390/320 截图通过。
3. macOS 壳观感通过。
4. 暗色/亮色通过。
5. 核心功能不退化。
6. 有回滚方案。

## 十、验收标准

高保真设计稿通过标准：

1. 明显减少网页感和后台感。
2. 壳和 Web 内容更像一个整体。
3. 搜索框、按钮、卡片、弹层圆角体系统一。
4. 图标风格统一，不再杂乱。
5. 字重、字号、行高、间距更成熟。
6. 左侧列表不再像白色卡片堆叠。
7. 空态不再像未加载页面。
8. 亮色和暗色都成立。
9. 320px/390px 不拥挤、不溢出。
10. 预留本地优先状态。

不通过示例：

1. 只是把圆角调大。
2. 只是换颜色。
3. 只是加阴影。
4. 图标仍然混风格。
5. 右下角助手仍然显得玩具化。
6. 看起来仍像网页后台。
7. 影响现在线上功能或线上用户。

   - 颜色。
   - 圆角。
   - 字号。
   - 字重。
   - 间距。
   - 图标尺寸。
6. 未来本地优先状态预留说明。
7. 不影响线上业务的隔离说明。
