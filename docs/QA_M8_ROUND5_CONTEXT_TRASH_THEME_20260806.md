# M8 第五轮体验反馈：侧边栏右键菜单、回收站保留期、亮色模式评估

日期：2026-08-06

结论：继续做细节打磨。本轮不属于核心功能阻塞，但会明显影响桌面 App 的成熟度和长期使用成本。

## 1. M8-R5-F01：侧边栏右键菜单不应显示文本编辑菜单

严重级别：P1

用户现象：

- 在右侧便签正文/待办里右键，出现：
  - 复制
  - 粘贴
  - 剪切
  - 全选
  - 删除所选
- 这些在编辑区域是合理的。
- 但在左侧便签列表/侧边栏右键时，也出现同样菜单。
- 左侧列表不是文本编辑区，复制/粘贴/剪切/全选基本没意义。
- “删除所选”在左侧点了也没有反应，造成困惑。

当前代码线索：

- `src/components/ContextMenu.tsx`
- 当前是全局监听 `document.addEventListener("contextmenu", ..., true)`。
- 菜单不区分右键发生在：
  - 编辑区
  - 便签列表项
  - 侧边栏空白区域
  - 普通页面区域

产品要求：

右键菜单必须按上下文变化。

### 1.1 编辑区右键

发生在正文、标题、待办文本、可编辑输入框中时，保留当前文本编辑菜单：

```text
复制
粘贴
剪切
全选
删除所选
```

要求：

- 有选区时，复制/剪切/删除所选可用。
- 无选区时，剪切/删除所选应禁用或隐藏。
- 粘贴在可编辑区域可用。

### 1.2 侧边栏便签项右键

发生在左侧便签列表某一条便签卡片上时，显示便签级菜单：

```text
复制一份
删除便签
```

说明：

- 用户口中的“增量保存”，产品上建议命名为“复制一份”或“创建副本”，比“增量保存”更直观。
- “复制一份”含义：复制当前便签，生成一条新便签。
- “删除便签”含义：将该便签移入回收站，需要产品内确认弹窗。

建议菜单扩展项，非 P0：

```text
置顶/取消置顶
归档
```

但本轮先不要扩大，优先做“复制一份”和“删除便签”。

### 1.3 侧边栏空白区域右键

发生在侧边栏空白区域时，可以：

- 不显示菜单；或
- 只显示“新建便签”。

本轮建议：不显示菜单，避免干扰。

### 1.4 普通非编辑区域右键

发生在无明确语义区域时：

- 不显示菜单。
- 也不能出现浏览器默认菜单。

验收标准：

1. 右侧编辑区右键：显示文本编辑菜单。
2. 左侧便签卡片右键：只显示“复制一份 / 删除便签”。
3. 左侧空白处右键：不显示无意义菜单。
4. 点击“复制一份”后生成一条内容相同的新便签，标题可自动追加“副本”或保持原名并靠更新时间区分。
5. 点击“删除便签”后出现产品内确认弹窗，不出现浏览器 confirm。
6. 删除后便签进入回收站。

## 2. M8-R5-F02：回收站建议增加 7 天自动清理策略

严重级别：P1

用户问题：

- 回收站里的便签目前会保存多久？
- 如果永久保存，会占用服务器空间，尤其是含图片的便签。
- 用户倾向：回收站只保留 7 天，超过 7 天自动永久删除。

当前判断：

- 现有实现是软删除：删除时设置 `deletedAt`。
- 回收站支持恢复和手动永久删除。
- 当前没有看到明确的 7 天自动清理策略。

产品建议：

回收站默认保留 7 天。

规则：

1. 删除便签后进入回收站。
2. 回收站便签保留 7 天。
3. 超过 7 天后自动永久删除。
4. 永久删除时必须同时清理附件文件，避免只删数据库不删图片。
5. 回收站列表应显示剩余保留时间。

文案建议：

```text
删除于 8月6日 · 6天后永久删除
```

少于 1 天：

```text
今天将永久删除
```

永久删除确认：

```text
永久删除后无法恢复。
```

技术实现建议：

### 2.1 服务端清理任务

可以采用以下任一方案：

1. 系统 cron 定时调用内部清理脚本。
2. systemd timer 定时执行清理命令。
3. 服务启动时和每天首次请求时触发一次轻量清理。

推荐生产环境：systemd timer 或 cron。

### 2.2 清理逻辑

清理条件：

```text
deletedAt < now - 7 days
```

清理动作：

1. 找到过期便签。
2. 删除附件本地文件。
3. 删除附件数据库记录。
4. 永久删除便签数据库记录。
5. 记录清理日志。

### 2.3 安全要求

- 清理任务必须只处理当前应用上传目录内的文件。
- 文件删除继续使用路径边界检查，防止路径穿越。
- 清理失败不能影响主应用运行，但必须记录日志。

验收标准：

1. 删除一条便签后，回收站显示剩余保留时间。
2. 构造一条 `deletedAt` 超过 7 天的便签，运行清理任务后被永久删除。
3. 该便签附件文件也被删除。
4. 未超过 7 天的回收站便签不被删除。
5. 清理任务有日志。

## 3. M8-R5-F03：亮色模式/皮肤模式需要评估，不建议立刻全量上

严重级别：P2

用户想法：

- 当前是暗色模式。
- 希望未来能有亮色模式或皮肤模式。
- 但担心一做主题就引入很多 bug。

产品判断：

亮色模式有价值，但不是当前最高优先级。主题切换会影响所有页面、弹窗、卡片、输入框、图片预览、Windows 壳、回收站、归档页、右键菜单等。如果没有设计 token 约束，很容易产生大量视觉 bug。

建议路线：

### 3.1 先做主题能力评估

技术部先评估：

1. 当前颜色是否都走 Tailwind token / CSS variables。
2. 还有多少硬编码颜色，例如 `bg-[#...]`、`text-[#...]`。
3. 哪些组件需要适配亮色：
   - TopBar / Sidebar
   - NoteList
   - NoteEditor
   - ChecklistEditor
   - ContextMenu
   - ConfirmDialog
   - Trash / Archive
   - ImagePreview
   - Windows 壳背景

### 3.2 再做最小亮色模式

第一版只做两种：

```text
暗色
亮色
```

不要一开始做多套皮肤。

要求：

- 主题选择保存到本地。
- 后续账号体系上线后，再考虑跟账号同步。
- 亮色模式下对比度必须合格。
- 删除/危险/置顶/选中态颜色必须重新验证。

### 3.3 优先级

建议放在当前细节稳定之后：

1. 先修右键上下文。
2. 先做回收站 7 天清理。
3. 再评估亮色模式。

验收标准：

1. 技术部先提交主题适配评估清单。
2. 统计硬编码颜色数量和需要改造的组件。
3. 给出亮色模式工作量预估。
4. 产品确认后再进入实现。

## 4. 本轮建议优先级

P1：

1. 侧边栏右键菜单上下文化。
2. 回收站 7 天自动清理。

P2：

1. 亮色模式评估。

## 5. 明确不做

本轮不做：

1. 多套皮肤市场。
2. 复杂主题编辑器。
3. 多用户/邮箱登录。
4. 协作共享。
5. 图片 OCR/标注。

## 6. 技术部交付证据

1. 右键菜单录屏：
   - 编辑区右键显示文本菜单。
   - 侧边栏便签右键显示便签菜单。
   - 空白区域右键不显示无意义菜单。
2. 复制一份录屏：
   - 右键便签卡片 -> 复制一份 -> 新便签生成。
3. 删除便签录屏：
   - 右键便签卡片 -> 删除便签 -> 产品内确认 -> 进入回收站。
4. 回收站清理测试：
   - 超过 7 天便签被清理。
   - 附件文件同步清理。
5. 亮色模式评估文档：
   - 不要求本轮实现，但要给出工作量和风险。

## 7. 通过标准

本轮通过标准：

> 右键菜单符合所在区域语义，回收站不会无限占用服务器空间，亮色模式先完成风险评估而不是贸然开工。

如果侧边栏右键仍出现“复制/粘贴/剪切/全选”这类文本编辑菜单，本轮不通过。
