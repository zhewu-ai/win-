# M11.1 方案：链接基础层（外部 URL 与内部便签链接）

日期：2026-08-09

## 一、背景

PinNote 后续会往「三维项目排期 + 每日工作提醒 + 便签资料库」方向扩展。无论后面做日历、排期表 AI 识别，还是把修改/反馈挂到某一天，都需要一个稳定的链接基础层：

- 便签里出现外部网址时，自动变成可点击链接。
- 便签之间可以互相引用，底层绑定 noteId，不因标题修改而断链。
- 后续日历事件可以挂载 noteId，点击直接打开相关便签。

本轮只做链接基础层，不做日历、不做 AI 排期导入、不做完整 Markdown/富文本编辑器。

## 二、产品目标

### P0：外部 URL 自动识别

用户在普通便签正文中输入：

- `https://example.com`
- `http://example.com`
- `www.example.com`

展示时自动识别为蓝色可点击链接。

要求：

- 网页端：点击外部链接新标签打开。
- 桌面壳：点击外部链接用系统默认浏览器打开，不困在 WebView 里。
- 不影响原有纯文本编辑、自动保存、离线保存、跨设备刷新。
- 不改变 note.content 的原始文本存储格式。

### P0：内部便签链接

用户可以把另一条便签嵌入当前便签，形成可点击内部链接。

建议第一版语法：

```text
[[note:NOTE_ID|显示标题]]
```

示例：

```text
今天修改参考 [[note:cm4abc123|客户反馈记录]]
```

展示效果：

- 渲染为蓝色/主色内部链接：`客户反馈记录`
- 点击后在当前 PinNote 应用内打开对应便签。
- 若目标便签已删除、无权限或不存在，显示灰色失效链接：`客户反馈记录（已失效）`。

为什么不只用 `[[便签标题]]`：

- 标题会改，重名也常见。
- 底层必须绑定 noteId 才稳定。
- 可以后续再支持输入 `[[` 搜索标题，但存储仍应落成 `[[note:id|title]]`。

## 三、不做事项

本轮明确不做：

- 不做完整 Markdown 编辑器。
- 不做富文本编辑器。
- 不做双向反链页面。
- 不做日历事件。
- 不做 AI 识别排期表。
- 不做多人协同编辑/冲突合并。

这些可以作为 M11.2/M11.3 继续规划。

## 四、建议交互

### 4.1 外部链接

编辑态：

- 用户仍在普通文本框里编辑，不强制切换富文本。
- 输入 URL 后不必立刻变成富文本块，避免影响光标和输入体验。

展示/阅读态：

- 当正文失焦、非编辑阅读、或点击链接预览层时，URL 渲染为可点击链接。
- 如果当前编辑器仍是 textarea，第一版可以采用“按住 Cmd/Ctrl 点击链接打开”的方式，或在链接旁提供轻量点击层；具体由技术部根据现有 `AutoGrowTextarea` 实现选择。

推荐折中：

- 第一版先做“正文渲染层”：便签非聚焦时显示带链接的渲染视图；点击正文进入编辑。
- 如果改动太大，可以先只在便签卡片/预览/详情只读区域渲染链接，编辑区继续纯文本，作为过渡。

### 4.2 插入内部便签链接

第一版入口：

- 编辑器「更多」菜单新增：`插入便签链接`
- 点击后弹出搜索框，搜索当前用户自己的便签。
- 选择目标便签后，在当前光标位置插入：

```text
[[note:目标noteId|目标标题]]
```

如果当前技术上拿不到光标位置，可先插入到正文末尾，并在验收报告中说明。

后续增强：

- 输入 `[[` 时弹出便签搜索。
- 支持反向链接：某条便签下方显示“被哪些便签引用”。

### 4.3 打开内部链接

点击内部链接后：

- 如果在主页：选中并打开目标便签。
- 如果当前在单栏移动/窄窗口：切到编辑器视图。
- 如果当前便签有未保存内容：沿用现有切换便签前 flush 机制，不能丢输入。
- 如果目标便签在归档/回收站：
  - 第一版建议只打开未删除、当前列表可见便签。
  - 若目标在归档，提示“便签已归档，是否前往归档页查看”可作为后续增强。
  - 若目标在回收站，显示失效，不直接恢复。

## 五、技术设计建议

### 5.1 数据层

第一版不新增表。

内部链接直接保存在 `Note.content` 字符串中：

```text
[[note:NOTE_ID|显示标题]]
```

原因：

- 改动小，不需要 schema 迁移。
- 和纯文本/离线/同步机制兼容。
- 后续需要反链时，可以通过解析 content 建索引或新增关系表。

可选增强（后续）：

- 新增 `NoteLink` 表，存储 `sourceNoteId -> targetNoteId`，用于反链、坏链扫描、日历挂载统计。
- 但本轮不要引入，避免把基础链接做重。

### 5.2 渲染层

建议新增：

- `src/lib/link-parser.ts`
  - `parseNoteLinks(text)`：识别内部便签链接 token。
  - `parseExternalUrls(text)`：识别外部 URL token。
  - 输出结构化 segments，避免直接拼 HTML。

- `src/components/LinkedText.tsx`
  - 输入：`text`、`onOpenNote(id)`、`mode`
  - 输出：文本片段 + 外部链接 + 内部链接。
  - 必须做安全处理：不要使用未经清洗的 `dangerouslySetInnerHTML`。

外部 URL 识别边界：

- 支持 `https://`、`http://`、`www.`
- URL 尾部常见标点 `。 , ， . ) ）] 】` 不应被吞进链接。
- 显示文本可以保留原文，href 对 `www.` 自动补 `https://`。

内部链接识别边界：

- 格式：`[[note:<id>|<title>]]`
- title 只作为显示文本，不作为查找依据。
- noteId 必须格式校验，禁止把任意 JS/HTML 当链接执行。

### 5.3 桌面壳外部打开

网页端：

```text
target="_blank" rel="noopener noreferrer"
```

桌面壳：

- 如果已有 Tauri helper，优先走 `openExternal(url)` 或对应 shell open API。
- 不允许外部链接在壳内直接导航，避免用户离开 PinNote 主应用。
- URL scheme 第一版只允许 `http:` / `https:`。

### 5.4 内部打开

需要在 `HomePage` 或便签上下文中提供：

```ts
openNoteById(noteId: string): Promise<void> | void
```

行为：

- 若 notes 列表已有目标，直接 `setSelectedNoteId(noteId)` + `setShowEditor(true)`。
- 若列表没有目标，调用 `/api/notes/:id` 或扩展 API 查询单条便签。
- 如果 API 返回 404/403，渲染失效状态或 toast 提示。

注意：当前 API 是否已有单条 GET 需要技术部确认；没有则新增：

```text
GET /api/notes/:id
```

只允许访问当前用户自己的未删除便签。

## 七、验收标准

### 外部 URL

1. 正文输入 `https://example.com`，展示时变蓝且可点击。
2. 正文输入 `www.example.com`，展示时可点击，实际打开 `https://www.example.com`。
3. URL 后接中文句号/逗号时，标点不属于链接。
4. 网页端点击外部链接新标签打开。
5. 桌面壳点击外部链接使用系统默认浏览器打开。
6. 非 `http/https` scheme 不打开，例如 `javascript:alert(1)` 必须作为普通文本或被拦截。

### 内部便签链接

1. 在 A 便签插入 B 便签链接，正文保存后刷新仍保留链接语法。
2. 展示时 `[[note:B_ID|B标题]]` 渲染为可点击内部链接。
3. 点击后打开 B 便签。
4. B 改标题后，A 中链接仍能打开 B；显示标题可保持旧标题，后续再考虑自动刷新显示名。
5. B 被删除后，A 中链接显示失效，不报错、不跳空白页。
6. 普通文本里的 `[[不是note格式]]` 不应误跳转。

### 编辑与同步

1. 插入链接不破坏 autosave debounce。
2. 离线状态下插入内部链接可保存为 pending，联网后正常同步。
3. 跨设备刷新后，链接仍可识别和点击。
4. 链接渲染不影响 checklist 模式；第一版可以只支持普通文本便签正文。

### 安全

1. 不使用未清洗 HTML 直接渲染用户输入。
2. 外部链接只允许 `http/https`。
3. 内部 noteId 只能打开当前用户有权限访问的便签。
4. 失效/无权限链接不泄露目标便签内容。

## 八、后续路线

M11.1 做完后，后续可以顺序推进：

1. M11.2：日历基础页
   - 手动添加日历事件。
   - 事件关联 noteId。
   - 首页顶部“今日工作条”。

2. M11.3：排期表 AI 导入
   - 上传排期表截图/PDF/Excel。
   - AI 识别日期、交付、修改、反馈。
   - 用户确认后写入日历。

3. M11.4：轻 Markdown
   - 标题、列表、引用、链接渲染。
   - 仍保留纯文本存储，避免过早引入重富文本编辑器。

本轮先把链接能力打稳，后续日历和 AI 导入都复用 noteId 链接模型。
