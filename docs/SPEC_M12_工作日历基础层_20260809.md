# SPEC M12：工作日历基础层 + Windows 壳外链小排查

日期：2026-08-09

## 一、结论

M11.1.2 链接编辑态一致性的主链路先收口，不继续围绕边角扩大范围。当前下一条产品主线进入 **M12 工作日历基础层**。

同时保留一个小修排查项：Windows 桌面壳里点击外部 URL 无法唤醒系统浏览器。该问题只做小范围定位，能快速闭环就修；不能快速闭环则记录为桌面壳 P1，不阻塞 M12。

M12 不做 AI 排期导入。AI 导入依赖结构化事件模型，放到 M13。

## 二、M11 收口与小排查

### 2.1 不继续扩 M11.1.2

当前不继续投入以下方向：

- 不迁移 `FloatingNoteClient`。它是历史遗留“极小模式/悬浮窗”能力，主界面入口已删除，当前主产品链路不覆盖。
- 不继续扩链接功能，如反向链接、坏链扫描、关系表、列表卡片链接渲染。
- `]` 标题转义、待办行 `React.memo`、报告措辞等边角问题可记录，但不作为进入 M12 的阻塞项，除非后续真实使用中复现明显 bug。

### 2.2 Windows 壳外链打不开：小范围排查

现象：网页端点击外部 URL 可以打开新标签；Windows 桌面壳内点击外部 URL 无法唤醒系统默认浏览器。

现有代码线索：

- Web 侧：`src/lib/tauri.ts` 有 `openExternal(url)`，Tauri 环境调用 `invoke("open_external", { url })`。
- Tauri 侧：`src-tauri/src/lib.rs` 有 `open_external(url)` 和 `open_external_system(url)`。
- 权限：`src-tauri/permissions/default.toml` 与 `src-tauri/capabilities/default.json` 已出现 `allow-open-external`。

排查顺序：

1. 确认用户当前 Windows 安装包是否包含最新 `open_external` 命令与权限。若只是旧包，重打 Windows 包即可。
2. 在 Windows 壳内加最小日志或 toast：点击 URL 时确认是否进入 `openExternal()`，是否进入 Rust `open_external`。
3. 若命令进入 Rust 但浏览器不打开，重点查 Windows `cmd /C start "" url` 调用是否被 URL 特殊字符、转义、权限或 WebView 环境影响。
4. 若当前手写 `cmd /C start` 不稳定，优先考虑 Tauri 官方 opener/shell 能力；但不要为了此项引入过大改造。

验收：

- Windows 桌面壳中，正文 URL 与待办 URL 点击后能唤醒系统默认浏览器。
- 外部链接只允许 `http://` 与 `https://`。
- Web 端行为不回退。

时间盒：

- 建议不超过 0.5-1 天。
- 如果不能快速闭环，记录为“桌面壳 P1：外链唤醒浏览器”，先进入 M12。

## 三、M12 范围

M12 目标是把“工作日历”作为独立结构化模块做出来，让用户能手动创建、查看、管理按日期排列的工作事件，并能把事件关联到便签。

M12 先做管理员灰度：

- 日历入口只展示给管理员账户。
- 普通用户账户不显示日历入口、不显示首页今日条。
- 日历 API 也必须限制管理员访问，避免普通用户手输 URL 或直接调 API 看到半成品功能。

M12 只做基础层：

- 日历页：月视图、周视图、今日列表。
- 手动添加事件。
- 事件关联便签。
- 首页顶部“今日条”。

M12 不做：

- AI 排期导入。
- 图片识别排期。
- 自动识别聊天/表格里的排期。
- 复杂项目管理、甘特图、多人协作、提醒通知。
- 富文本日历事件正文。
- 把日历做成 Markdown 表格或便签正文里的表格。

## 四、产品原则

日历看起来像表格，但底层不应是富文本表格。它应是结构化时间视图：

- 日期是容器。
- 事件是结构化数据。
- 事件可以关联便签。
- 后续 AI 导入是把识别结果写入事件表，而不是写成一大段便签正文。

这能保证后续可以做今日条、筛选、延期、完成状态、按日期跳转、AI 批量导入。

## 五、数据模型

新增 Prisma model，建议命名 `CalendarEvent`。

```prisma
model CalendarEvent {
  id          String    @id @default(cuid())
  userId      String
  noteId      String?
  title       String
  description String    @default("")
  date        String    // YYYY-MM-DD，按用户本地日期存储，M12 默认 Asia/Shanghai 语义
  startTime   String?   // HH:mm，可空；全天事件为空
  endTime     String?   // HH:mm，可空
  allDay      Boolean   @default(true)
  status      String    @default("todo") // todo | done | postponed
  source      String    @default("manual") // manual；AI 导入阶段再扩展 ai_import/image_import
  createdAt   DateTime  @default(now())
  updatedAt   DateTime  @updatedAt
  deletedAt   DateTime?

  user User @relation(fields: [userId], references: [id])
  note Note? @relation(fields: [noteId], references: [id])

  @@index([userId, date, deletedAt])
  @@index([userId, status])
  @@index([noteId])
}
```

同步修改：

- `User` 增加 `calendarEvents CalendarEvent[]`。
- `Note` 增加 `calendarEvents CalendarEvent[]`。

字段说明：

- `date` 用字符串 `YYYY-MM-DD`，避免 M12 因时区转换导致“今天/明天”错位。
- `startTime/endTime` 第一版只做展示和排序，不做复杂冲突检测。
- `description` 第一版可以有，但 UI 上保持轻量。
- `source` 先固定 `manual`，为 M13 AI 导入预留来源字段。
- 删除用 `deletedAt` 软删，保持与便签数据习惯一致。

## 六、API 设计

所有接口必须登录，且只能访问自己的事件。

### 6.1 获取事件列表

`GET /api/calendar-events?from=YYYY-MM-DD&to=YYYY-MM-DD`

行为：

- 仅管理员可访问；非管理员返回 403。
- 返回 `[from, to]` 范围内未删除事件。
- 默认按 `date asc, allDay desc, startTime asc, createdAt asc` 排序。
- `from/to` 必填，避免一次拉全量。

### 6.2 创建事件

`POST /api/calendar-events`

Body：

```json
{
  "title": "完成角色绑定初版",
  "description": "",
  "date": "2026-08-10",
  "allDay": true,
  "startTime": null,
  "endTime": null,
  "noteId": "optional-note-id"
}
```

校验：

- 仅管理员可访问；非管理员返回 403。
- `title` 必填，trim 后 1-120 字。
- `description` 最多 1000 字。
- `date` 必须是合法 `YYYY-MM-DD`。
- `startTime/endTime` 如存在必须是 `HH:mm`。
- `noteId` 如存在，必须属于当前用户且未删除。

### 6.3 更新事件

`PATCH /api/calendar-events/[id]`

可更新字段：

- `title`
- `description`
- `date`
- `allDay`
- `startTime`
- `endTime`
- `status`
- `noteId`

状态值：

- `todo`
- `done`
- `postponed`

权限：

- 仅管理员可访问；非管理员返回 403。

### 6.4 删除事件

`DELETE /api/calendar-events/[id]`

行为：

- 仅管理员可访问；非管理员返回 403。
- 软删：设置 `deletedAt`。
- 不删除关联便签。

### 6.5 今日事件快捷接口

可选：

`GET /api/calendar-events/today`

如果实现成本低，可以给首页今日条单独使用；否则首页直接用范围接口请求当天。

### 7.3 月视图

能力：

- 显示当前月份的 7 列日历网格。
- 每天显示日期数字。
- 每天最多展示 2-3 条事件，超出显示“+N”。
- 点击日期进入当天列表或打开当天详情区域。
- 点击事件打开编辑弹窗。
- 今天有明显但克制的高亮。

窄窗口：

- 如果 320px 下完整月网格不可读，优先降级为“周/日列表”，不要硬塞 7 列。

### 7.4 周视图

- 显示本周 7 天。
- 每天按全天事件、带时间事件排序。
- 适合查看一周排期密度。

M12 不要求拖拽改日期；可留到后续。

### 7.5 今日列表

能力：

- 显示今天所有事件。
- 支持勾选完成。
- 支持点击关联便签。
- 支持新建今天事件。

### 7.6 事件编辑弹窗

字段：

- 标题
- 日期
- 全天开关
- 开始时间
- 结束时间
- 状态
- 关联便签
- 备注

交互：

- 新建事件默认日期为当前所选日期。
- 从今日条新建默认今天。
- 关联便签使用现有便签搜索体验，按标题和正文匹配。
- 事件保存后日历视图和今日条同步更新。

### 7.7 首页顶部“今日条”

在主便签首页顶部增加轻量今日条。

灰度：

- 只对管理员账户展示。
- 普通用户首页不显示今日条，避免半成品能力进入普通使用路径。

位置：

- 在编辑器/列表主区域顶部，但不要挤压工具栏。
- 窄窗口下可以折叠为一行摘要。

内容：

- 今天日期。
- 今日未完成事件数量。
- 前 3 条今日事件。
- “查看日历”入口。
- 快速新增今日事件入口。

交互：

- 点击事件：若有关联便签，打开便签；否则打开事件编辑弹窗。
- 点击“查看日历”：进入日历页并定位今天。

原则：

- 今日条是工作提示，不是营销卡片，不做大 hero。
- 保持低噪音，不要抢便签编辑主流程。

## 八、事件与便签关联

M12 采用单向轻关联：

- 一个事件最多关联一条便签：`CalendarEvent.noteId`。
- 一条便签可以被多个事件关联。

事件里展示：

- 关联便签标题。
- 点击后打开该便签。

便签里是否展示关联事件：

- M12 可选。
- 如果做，建议在编辑器底部或元信息区域轻量显示“关联日程 N 条”，点击打开日历筛选。
- 如果实现成本高，本轮不做，不影响 M12 验收。

删除/归档边界：

- 便签删除后，事件不删除，但关联便签显示为“便签已失效”。
- 便签归档后，事件仍显示关联标题，点击时提示“该便签已归档”或跳转归档页，保持与内部链接语义一致。

## 九、验收标准

### 9.1 构建与迁移

- `npx prisma generate` 通过。
- `npx prisma db push` 本地通过。
- `npm run build -- --webpack` 通过。
- 本地和生产部署前都备份 DB。

### 9.2 API

- 未登录访问全部日历 API 返回 401。
- 普通用户访问全部日历 API 返回 403。
- 管理员访问日历 API 正常。
- 用户 A 不能读取/修改/删除用户 B 的事件。
- 创建事件后 GET 范围接口能查到。
- PATCH 日期后事件从原日期移动到新日期。
- DELETE 后范围接口不再返回。
- 关联不存在或不属于当前用户的 `noteId` 返回 400/404。

### 9.3 UI

- 管理员侧边栏能进入日历页。
- 普通用户侧边栏不显示日历入口。
- 普通用户直接访问 `/calendar` 不展示日历功能。
- 月视图能切换月份。
- 周视图能切换周。
- 今日列表显示今天事件。
- 新建、编辑、删除事件可用。
- 事件可关联便签，并能从事件跳到便签。
- 管理员首页今日条显示今天事件，并能跳日历/跳便签。
- 普通用户首页不显示今日条。
- 320px 窄窗口无重叠、无横向溢出。

### 9.4 回归

- 便签列表、新建便签、编辑便签、待办、附件、刷新按钮不回退。
- M11 链接编辑态不回退。
- Windows 壳外链排查如已修，Web 端外链不回退。

## 十一、M13 预研：AI 排期导入

M13 不在本轮实现，但 M12 需要为它留好入口。

M13 目标：

- 用户粘贴一段排期文字，或上传/识别一张排期图。
- AI 解析出日期、任务标题、时间段、备注、可能的关联便签。
- 用户在确认页校对。
- 确认后批量写入 `CalendarEvent`。

M13 为什么不能先做：

- 没有 M12 的事件模型，AI 结果只能落成一段文本，后续无法稳定展示、筛选、修改、完成或延期。
- 先做手动日历，可以让真实数据结构跑起来，AI 导入只是新的创建方式。

M12 需要预留：

- `CalendarEvent.source` 字段。
- 批量创建 API 的可扩展空间，M12 可不实现。
- 事件备注字段。
- 事件与便签关联字段。
