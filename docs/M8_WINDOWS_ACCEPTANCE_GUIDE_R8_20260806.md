## 本轮验收重点

### 1. 侧边栏横向缩放不再自动收起（4.1）

验证点：

**a. 桌面窗口横向缩放**：
1. 打开 App，侧边栏可见。
2. 按住窗口左/右边框，把窗口宽度从 1280 一路缩到 **700px**。
3. **预期**：全程侧边栏保持显示（双栏布局），**不会**因为窗口小于 768px 而突然消失（旧行为）。
4. 继续缩到 **500px** 以下：切换为单栏，编辑器保持打开、侧边栏隐藏、顶部出现返回箭头。
5. 再拉宽到 **560px**：仍保持单栏（迟滞区间）。
6. 拉宽到 **600px** 以上：恢复双栏。

**b. 手动折叠仍然可用**：
1. 在宽屏（>600px）点侧边栏顶部「收起侧边栏」→ 侧边栏收起，右侧出现展开条。
2. 点展开条 → 侧边栏恢复。
3. 选中一条便签后收起/展开，**选中状态保持**。
4. 收起后**重开 App**：折叠状态被记住。

证据要求：横向缩放全过程的录屏一张（重点看 1280→700 段侧边栏不消失）。

### 2. 工具栏单行 + 文字不竖排（4.2）

验证点：

1. 打开任意便签编辑，把窗口宽度在 **900px / 520px / 360px / 260px** 四档之间拖动。
2. **预期**：工具栏始终是**一行**，不换行、不挤压溢出；按钮整组切换（>640px 显示「便签/待办」文字与色球，<640px 全部变图标）。
3. 「便签/待办」文字**始终横向**，绝不竖排。
4. 编辑正文时看工具栏右侧「保存中 / 已保存」文字变化：状态变化时**右侧图标位置不左右移动**（保存状态有固定槽位）。
5. 低频操作（删除 / 归档 / 置顶便签）在「⋯」更多菜单里，不在工具栏直接占位。

证据要求：四档宽度各截图一张，肉眼确认工具栏单行、无溢出。

### 3. 滚动条不改变内容宽度（4.3，Windows 重点）

验证点：

1. 侧边栏便签很多、出现滚动条时，观察一条便签的右侧边缘位置。
2. 缩小窗口高度让滚动条出现 / 拉大窗口高度让滚动条消失，**同一窗口宽度下便签卡右侧边缘位置不变**（内容不被滚动条挤动）。
3. 编辑器正文、归档、回收站同样复测。

证据要求：滚动条出现/消失前后各截图一张，宽度对齐。

### 4. 滚动条桌面化观感（4.4）

验证点：

1. 滚动条为**细条（约 6px）、低对比浅灰**，轨道透明，不与浏览器默认滚动条相同。
2. 悬停滚动条时颜色略微变亮。

证据要求：滚动条截图一张。

## 常见问题

**Q：为什么 700px 宽侧边栏还在，以前 700px 会消失？**
A：以前用 768px 断点，把小于 768px 的桌面窗口误判为移动端。现在单栏只在小窗（<520px）触发，桌面窗口缩放不再跳变。

**Q：缩到 520px 以下又拉回 550px，为什么还是单栏？**
A：迟滞设计：进入单栏 520px、退出 580px，中间区间（520–580）保持当前模式，避免在阈值边缘来回横跳。

**Q：滚动条在 macOS 上本来就不占宽度，这个改动对我有意义吗？**
A：Windows WebView2 是经典滚动条（占宽度），`scrollbar-gutter: stable` 正是为它预留宽度，避免内容随滚动条出现/消失抖动。macOS 覆盖式滚动条下无感，属正常。
