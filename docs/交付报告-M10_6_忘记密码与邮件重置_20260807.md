# PinNote M10.6 忘记密码与邮件重置：交付报告

日期：2026-08-07

## 1. 结论摘要

本轮完成 M10.6 忘记密码与邮件重置，为**有邮箱的用户**补上自助找回密码闭环：

1. **数据模型**：新增 `PasswordResetToken` 表，只存 `tokenHash`（sha256），明文只在邮件链接中出现、不落库；token 30 分钟过期、一次性。
2. **请求重置** `POST /api/auth/forgot-password`：无论邮箱是否存在统一返回「如果该邮箱已注册，我们会发送密码重置邮件。」（不泄露账号存在性）；仅 active 且绑定了邮箱的用户才生成 token 并发邮件；disabled 用户不发；同一邮箱 1 次/分钟、同一 IP 5 次/10 分钟最小频控。
3. **提交新密码** `POST /api/auth/reset-password`：token hash 后查库，一次性 + 30 分钟过期；bcrypt 重哈希后旧密码立即失效；成功后作废当前 token 并清理该用户其它未使用 token；**不自动登录**。
4. **SMTP 邮件**：新增 `SMTP_*` + `APP_BASE_URL` 环境变量；生产缺失 SMTP 时接口返回通用文案、服务端记错误日志、**不崩溃**；SMTP 密码不入 git。
5. **UI**：登录页加「忘记密码？」→ `/forgot-password`（邮箱 + 通用成功态）；`/reset-password?token=`（新密码 + 确认，前端拦截、token 缺失显示「链接无效」、成功后「去登录」）。

按用户决定「先实现，SMTP 后配」：**邮件发送链路已实现并通过本地端到端验收，生产完成优雅降级验证；真实发信待 SMTP 凭据配置后生效**（见 §15）。

未做（SPEC 明确排除）：邮箱验证注册、手机号找回、微信/OAuth、MFA、改邮箱、开放注册、短信。

## 3. schema 变更说明

```prisma
model PasswordResetToken {
  id        String   @id @default(cuid())
  userId    String
  tokenHash String   @unique
  expiresAt DateTime
  usedAt    DateTime?
  createdAt DateTime @default(now())

  user User @relation(fields: [userId], references: [id])

  @@index([userId])
  @@index([expiresAt])
}
```

- `User` 新增 `passwordResetTokens PasswordResetToken[]`。
- 纯新增表 + 反向关系，`db push` 无数据变更，不影响既有用户/便签/附件/邀请码。

## 4. 安全设计（关键决策）

- **不泄露账号存在性**：forgot-password 对「存在 active / 存在 disabled / 不存在 / 邮箱格式非法」四种情况返回完全一致的 200 + 通用文案；邮箱速率限制先于查库执行，也避免通过限流差异枚举。
- **token 只存 hash**：DB 仅存 sha256(token)，明文只进邮件链接；服务端日志只记录发送失败原因，**token 绝不出现在日志**（生产 journal 实测无 token 泄漏）。
- **一次性 + 过期**：`usedAt` 置位即不可再用；`expiresAt` 超过 30 分钟即 `RESET_TOKEN_EXPIRED`；每次重置成功或重新申请都作废该用户其它未用 token。
- **disabled 不可绕过**：forgot 不发邮件；reset 返回 403 `ACCOUNT_DISABLED`。
- **不自动登录**：reset-password 不写 session，成功即要求重新登录。
- **SMTP 缺失不崩溃**：`sendMail()` 未配置 SMTP 时返回失败而非抛错，路由记录 serverError 后仍返回通用 200。

## 17. 并发修复（2026-08-07 补充）

上线后复查发现 `reset-password` 存在 TOCTOU 竞态：原实现先 `findUnique` 读 `usedAt` 判断"未使用"，再在事务内无条件 `update({usedAt})`，两步之间非原子——两个并发请求可同时读到 `usedAt=null` 都进入事务，使一次性 token 理论上可被并发使用两次。

**修法**（commit `05cbf3f`）：改为在事务内用条件更新原子抢占：

```ts
await prisma.$transaction(async (tx) => {
  const claim = await tx.passwordResetToken.updateMany({
    where: { tokenHash, usedAt: null, expiresAt: { gt: now } },
    data: { usedAt: now },
  });
  if (claim.count !== 1) {
    // 按记录当前状态映射错误码
    // 不存在 → INVALID_RESET_TOKEN / 已使用 → RESET_TOKEN_USED / 已过期 → RESET_TOKEN_EXPIRED
  }
  // count===1 才允许：查 userId → 校验 active → 更新密码 → 清理该用户其它未用 token
});
```

- `usedAt:null` + `expiresAt:{gt:now}` 两个条件合并进单条 `updateMany`，SQLite 单连接串行化保证同一 token 只有一个请求能抢占成功，后到者 `count=0` 返回 `RESET_TOKEN_USED`。
- bcrypt 计算移到事务外，缩短持锁时间。
- 错误码语义不变：抢占失败按记录状态区分 `INVALID_RESET_TOKEN` / `RESET_TOKEN_USED` / `RESET_TOKEN_EXPIRED`；用户禁用抛 `ACCOUNT_DISABLED` 使事务回滚（token 不消耗，与旧行为一致）。
