# M8 第四轮体验打磨反馈：全局入口下沉、工具栏稳定、列表日期、侧边栏折叠与原生弹窗

日期：2026-08-05

结论：基本功能已经可用，当前进入细节打磨阶段。不要再扩大功能范围，优先把桌面 App 的稳定感、原生感和信息可读性做好。

用户已经深度使用 2-3 天，核心需求基本满足。本轮问题主要是产品质感和长期使用细节。

## 1. 总体判断

当前产品已经可以适配用户主工作流：

- 记录普通便签。
- 管理待办反馈。
- Windows 壳置顶。
- 小窗口缩放。
- 基础图片、排序、小标题等能力。

下一阶段不要急着做多用户/邮箱登录。先把“看起来像一个真正桌面 App，而不是网页套壳”的细节磨好。

## 2. P0 / P1 问题

### M8-R4-F01：全局新建/账号入口不应继续占用顶部栏，建议统一放到侧边栏底部

严重级别：P1

用户现象：

- 当前顶部栏存在“新建”和“账号/我的”入口。
- 在窄窗口时它们会隐藏或移动，但在较宽窗口时仍占据顶部区域。
- 用户感觉没有必要为了两个按钮在顶部保留一整条全局栏。

产品判断：

当前结构是：

```text
左侧：便签列表侧边栏
右侧：当前便签详情
顶部：全局栏，放新建/账号等入口
```

更合理的结构应改为：

```text
左侧侧边栏：
  上部：搜索/列表
  中部：便签列表
  底部：新建、账号/我的、归档、回收站等全局入口

右侧详情区：
  只服务当前便签编辑
```

产品要求：

- “新建”和“账号/我的”作为全局管理入口，放到侧边栏底部。
- 右侧编辑区顶部不要被全局操作占用。
- 整个画面的左下角可作为全局入口区。
- 宽屏和窄屏尽量使用同一套信息架构，不要只在最窄时才临时移动。

建议设计：

侧边栏底部固定一条轻量工具区：

```text
+ 新建       我
```

或：

```text
[新建]  [账号]
```

账号菜单中包含：

- 个人便签/账号占位
- 归档
- 回收站
- 退出登录

搜索可以继续在侧边栏顶部，而不是全局顶部。

验收标准：

1. 宽屏状态下，顶部不再为了“新建/账号”保留一整条全局栏。
2. 新建和账号入口位于侧边栏底部。
3. 窄窗口下入口仍可用，不遮挡列表最后一条。
4. 右侧编辑区顶部只保留当前便签相关工具。
5. 整体视觉比当前更轻薄，不像网页导航栏。

### M8-R4-F02：编辑器工具栏窄窗口下不应换成两行，删除等低频操作应进入“更多”

严重级别：P1

用户现象：

- 窗口缩到较小时，编辑器顶部工具栏里的删除按钮会自动换到下一行。
- 虽然响应式换行本身没坏，但视觉上“轻飘飘”，不像稳定的 App。

产品判断：

工具栏可以响应式，但不能通过“突然变两行”解决空间不足。桌面 App 的工具栏应保持稳定的一行布局。

产品要求：

- 编辑器工具栏始终保持单行。
- 当宽度不足时，低频操作进入“更多”菜单。
- 不允许删除按钮单独掉到第二行。

建议操作优先级：

始终可见：

1. 返回，移动/窄屏时
2. 便签/待办切换
3. 保存状态，允许缩短成图标
4. 图片，若空间足够
5. 窗口置顶，Windows 壳内

可进入“更多”：

1. 删除
2. 归档
3. 便签置顶
4. 颜色选择，窄窗口时可折叠

建议 UI：

- 使用省略号按钮 `...` 或 More 图标。
- 点击后弹出菜单：

```text
置顶便签
归档
删除
颜色
```

验收标准：

1. 260px-320px 宽度下，编辑器工具栏仍是一行。
2. 删除按钮不会另起一行。
3. 更多菜单可打开，并能执行删除/归档等操作。
4. 工具栏高度稳定，不随窗口宽度突然变成两行。

### M8-R4-F03：侧边栏便签卡片需要显示具体日期，不只显示“几天前”

严重级别：P1

用户现象：

- 右侧/左侧便签列表当前只显示“几分钟前 / 几天前”等相对时间。
- 时间久了之后，只看“几天前”不够明确。

产品要求：

- 便签列表卡片应显示更明确的日期信息。
- 相对时间可以保留，但需要补具体日期。

建议规则：

```text
1 小时内：刚刚 / xx 分钟前
今天：今天 14:30
昨天：昨天 18:20
7 天内：周二 14:30
超过 7 天：08-01 14:30
跨年：2025-12-28
```

或者更简单：

```text
3天前 · 08-02
```

产品倾向：

- 在空间足够时显示：

```text
3天前 · 8月2日
```

- 空间很窄时可只显示：

```text
8月2日
```

验收标准：

1. 便签列表中能看到具体日期。
2. 久远便签不会只显示模糊相对时间。
3. 窄窗口下日期不挤压标题和摘要。

### M8-R4-F04：侧边栏需要支持手动折叠/展开

严重级别：P2

用户需求：

- 现在默认是左侧列表 + 右侧详情。
- 希望侧边栏像很多桌面 App 一样，可以手动收起/展开。
- 默认可以展开，但用户可以点按钮收起，让编辑区更大。

产品要求：

- 增加侧边栏折叠按钮。
- 折叠后隐藏便签列表，编辑区占满。
- 再次点击恢复侧边栏。
- 折叠状态最好本地记住。

建议位置：

- 侧边栏顶部靠近搜索处。
- 或编辑器左上角提供侧栏按钮。

验收标准：

1. 宽屏状态下可以收起左侧侧边栏。
2. 收起后编辑区宽度增加。
3. 可以重新展开。
4. 不影响移动/窄窗口本来的列表-编辑切换逻辑。

### M8-R4-F05：删除确认仍使用浏览器原生 confirm，桌面壳穿帮

严重级别：P1

用户现象：

- 点击删除时，出现浏览器/网页风格的确认框。
- 文案类似“网址显示确认”。
- 这会暴露网页套壳感。

产品判断：

`window.confirm`、`window.alert` 这类浏览器原生弹窗应逐步替换成产品内 Modal。尤其删除属于高频可见操作，不能再用浏览器默认弹窗。

产品要求：

- 删除便签、永久删除、删除图片等确认都改成自定义 Modal。
- Modal 视觉符合当前 App 风格。
- 文案清楚说明：

```text
删除后可在回收站恢复。
```

按钮：

```text
取消
删除
```

危险按钮用红色，但不要过度夸张。

验收标准：

1. 删除便签不再出现浏览器原生 confirm。
2. 删除图片不再出现浏览器原生 confirm。
3. 永久删除使用更强确认文案。
4. Windows 壳内没有“网页显示确认”这种穿帮提示。

## 3. 优先级建议

第一批，优先做：

1. 全局新建/账号入口下沉到侧边栏底部。
2. 编辑器工具栏更多菜单，避免删除按钮换行。
3. 删除确认改自定义 Modal。

第二批，再做：

1. 列表显示具体日期。
2. 侧边栏折叠/展开。

## 4. 明确不做

本轮不做：

1. 邮箱注册/多用户账号体系。
2. Mac 壳。
3. 离线同步。
4. 新的图片大功能。
5. 完整富文本编辑器。

## 5. 技术部交付证据

1. 宽屏截图：
   - 新建/账号在侧边栏底部。
   - 顶部不再为两个全局按钮保留大空间。
2. 320px 小窗口截图：
   - 编辑器工具栏保持一行。
   - 删除/归档等在更多菜单中。
3. 删除确认录屏：
   - 点击删除出现自定义 Modal，不出现浏览器 confirm。
4. 便签列表截图：
   - 能看到具体日期。
5. 侧边栏折叠录屏：
   - 收起/展开都正常。

## 6. 通过标准

本轮通过标准：

> 这个 App 不再像网页顶部导航套壳，而是像一个桌面便签工具：全局入口在侧边栏底部，编辑工具栏稳定，列表时间清楚，删除确认是产品内弹窗，侧边栏可以按需收起。

如果删除仍然弹浏览器 confirm，或窄窗口工具栏仍会掉到两行，本轮不通过。
