# M6 复验问题单：待办输入流、顶部操作区与窄窗口适配

日期：2026-08-02

结论：不通过，需要继续修复。

本轮不要做大重构，也不要继续强化“分组待办”。优先修复用户日常输入流里的阻塞问题：新建入口要明显，待办模式里 Enter 和粘贴要自然可用，窄窗口下工具栏不能挤压变形。

## 1. 不通过问题

### QA-M6-F01：待办模式下 Enter 无法稳定新增下一条

现象：

- 用户进入待办模式后，在待办项中按 Enter，仍然不能像备忘录/清单工具一样自然新增下一条。
- 当前体验让用户误以为必须依赖“添加待办”按钮。

定位：

- `src/components/ChecklistEditor.tsx:171-180`
- 当前逻辑在“最后一个空待办项”时直接 `return`：

```ts
if (isEmpty && isLast) return;
```

这会导致用户按 Enter 后没有可见反馈。对于便签类清单，这个判断不符合预期。

期望：

- 待办模式下，输入框内按 Enter 应新增下一条未完成待办，并自动聚焦新行。
- 不要求用户点击“添加待办”。
- 如果当前行为空，也必须给用户明确反馈。可以选择：
  - 新增下一条空行，并保持焦点在新行；或
  - 保持单空行但不作为主要路径，需确保用户在有内容行按 Enter 一定新增。
- 从已完成项按 Enter 时，应在该分组/默认列表的未完成区新增一条，不要新增到已完成区。

验收标准：

1. 切到待办模式，输入“修改模型比例”，按 Enter，出现第二条空待办且焦点进入第二条。
2. 输入第二条内容后再按 Enter，出现第三条空待办。
3. 勾选第一条后，第一条进入“已完成”；此时在未完成项按 Enter 仍能新增。
4. 不需要点击“添加待办”也能完成连续录入。

### QA-M6-F02：待办模式下直接粘贴多行/编号文本仍不能稳定拆成多条

现象：

- 用户反馈：必须先在普通便签模式下粘贴，再切到待办模式，系统才会识别多行/编号。
- 如果已经处于待办模式，直接粘贴一大段反馈，仍不能稳定拆成多条待办。

定位：

- `src/components/ChecklistEditor.tsx:221-285`
- 当前 `handlePaste` 只绑定在单个 `<input>` 上，且只处理 `lines.length > 1` 的情况。
- 如果粘贴目标不是某一个待办输入框，或文本被浏览器作为单行输入处理，就可能不会进入拆分逻辑。
- `src/lib/note-serializer.ts:25` 的编号清理规则要求编号后必须有空格：

```ts
/^(?:\d+|[A-Za-z])[.、)]\s+|^[-*•○]\s+/
```

这会漏掉常见反馈格式，例如：

```text
1.修改模型比例
2、材质太亮
3)AE 字幕错位
A.C4D 场景灯光
```

期望：

- 在待办模式下，用户直接粘贴以下内容，应立即生成多条待办：

```text
1. 修改模型比例
2、材质太亮
3)AE 字幕错位
4 输出一版预览
```

- 应兼容无空格编号：

```text
1.修改模型比例
2、材质太亮
3)AE 字幕错位
A.C4D 场景灯光
```

- 应兼容普通多行：

```text
修改模型比例
材质太亮
AE 字幕错位
输出一版预览
```

建议方向：

- `parseTodoLine` 的编号/项目符号清理规则改为允许“有空格或无空格”。
- 待办容器增加粘贴兜底：当当前没有明确聚焦某条 input，但用户在待办区域粘贴时，也能插入到默认列表末尾。
- 粘贴解析应统一复用 `parseTodoLine`，避免“普通便签切待办”和“待办内直接粘贴”两套行为不一致。

验收标准：

1. 在待办模式空白清单中直接粘贴 4 行编号文本，生成 4 条待办。
2. 在已有待办第二条中间粘贴 3 行文本，插入位置正确，不覆盖无关行。
3. `1.内容`、`1、内容`、`1)内容`、`A.内容`、`- 内容`、`[x] 内容` 均被清理前缀。
4. `[x] 内容` 或 `☑ 内容` 粘贴后应进入已完成状态。

### QA-M6-F03：新建便签入口在编辑态不可见或过深

现象：

- 用户在编辑某条便签时找不到“新建便签”按钮。
- 当前顶部栏里删除、归档、回收站、退出等入口混在一起，新建入口不明显。

定位：

- `src/components/TopBar.tsx:45-92`
- 新建按钮位于 `!showEditor` 条件内，编辑器打开时不会显示。
- `src/components/TopBar.tsx:96-122`
- 回收站、归档、退出登录始终显示，占据顶部全局栏空间。

期望：

- “新建便签”是最高频主操作，必须在列表态和编辑态都可见。
- 建议顶部全局栏保留：
  - 搜索
  - 新建
  - 用户入口/账号占位
- 回收站、归档、退出登录可以进入用户菜单或更多菜单，避免与“新建”抢空间。
- 编辑器内当前便签的删除、归档、置顶仍保留在编辑器工具栏，不要和全局导航混在一起。

验收标准：

1. 打开任意便签编辑页，顶部仍能直接看到“新建”入口。
2. 390px 宽度下，仍能找到新建入口，且不会被归档/回收站/退出按钮挤掉。
3. 点击新建后创建空便签，并进入可编辑状态。

### QA-M6-F04：顶部“红绿灯”装饰不符合 Web 产品语义，且增加拥挤感

现象：

- 顶部有类似 macOS 红黄绿窗口按钮的装饰。
- 但当前是 Web 应用，不是真正桌面壳窗口；这些点没有可点击语义。
- 用户反馈顶部已经很挤，这一栏容易造成误解和干扰。

定位：

- `src/components/TopBar.tsx:27-31`

期望：

- Web 端默认不显示无功能的红绿灯装饰。
- 未来 Windows/Mac 壳如需要，可在桌面壳布局里单独提供窗口控制区域，不应影响 Web 版主操作。

验收标准：

1. Web 端顶部不再出现无功能红黄绿点。
2. 顶部空间让位给搜索、新建、账户入口等真实功能。

### QA-M6-F05：缺少用户入口/账号占位

现象：

- 现在没有头像、昵称、账户入口。
- 用户后续希望支持同事使用、邮箱登录、多用户区分，因此需要先留出产品位置。

期望：

- 顶部右上角或左上角增加用户入口占位。
- MVP 阶段可显示：
  - 圆形头像占位，例如“我”
  - 昵称占位，例如“个人便签”
  - 菜单中放“归档 / 回收站 / 退出登录”
- 先不要求实现完整邮箱登录，但 UI 和信息架构要为后续账号体系留位置。

验收标准：

1. 顶部有明确账户入口。
2. 回收站、归档、退出登录可以从账户/更多菜单进入。
3. 账户入口在 390px 宽度下仍可见。

### QA-M6-F06：窄窗口下工具栏文字挤压换行

现象：

- 窗口缩窄后，“便签 / 待办”切换按钮文字会竖向排列或挤压。
- “已保存 / 保存中”等状态也可能被压缩换行。
- 色球在窄窗口下占用空间，但此时用户并不需要立即看到完整色卡。

定位：

- `src/components/NoteEditor.tsx:320-347`
- `src/components/ColorPicker.tsx:20-36`

期望：

- 编辑器工具栏必须单行稳定，不允许按钮文字竖排。
- 窄窗口下：
  - 模式切换优先显示图标，文字可隐藏。
  - 保存状态可缩短为小圆点或短文案，不能换行。
  - 色球可隐藏到调色盘按钮/更多菜单里。
  - 图片、置顶、归档、删除保留图标按钮即可。

验收标准：

1. 390px 宽度下，编辑器顶部工具栏不换行、不竖排、不遮挡。
2. 320px 宽度下，核心操作仍可点：返回、新建、待办/便签切换、图片、置顶。
3. “已保存”不会被挤成竖排或多行。

### QA-M6-F07：内置色卡观感偏灰暗，且缺少自定义色入口

现象：

- 用户认为当前几个颜色灰暗、不够好看。
- 用户希望后续可以自定义颜色。

期望：

- 本轮至少优化内置色卡：颜色要更清爽，贴近便签应用，不要灰暗。
- 列表卡片的整体背景/选中态应跟随颜色，而不只是小色条变化。
- 自定义色建议作为下一轮独立需求处理，因为可能涉及数据模型、API 和旧数据兼容。

验收标准：

1. 选择不同颜色后，列表卡片的整体视觉能明显区分。
2. 色卡不应全部偏灰、偏脏。
3. 产品上预留“自定义”入口方案，但本轮可不落库。

## 2. 本轮优先级

P0 必须修：

1. QA-M6-F01：Enter 新增待办。
2. QA-M6-F02：待办模式直接粘贴拆分。
3. QA-M6-F03：编辑态也能明显新建便签。
4. QA-M6-F06：窄窗口工具栏不挤压变形。

P1 应修：

1. QA-M6-F04：移除 Web 顶部红绿灯装饰。
2. QA-M6-F05：增加账户入口占位。
3. QA-M6-F07：优化内置色卡与列表整体颜色反馈。

## 3. 不要做的事

1. 不要重新扩大分组功能。
2. 不要做 AI 自动分类。
3. 不要做完整多用户登录系统。
4. 不要为了自定义色强行改大范围 schema，除非单独出迁移方案。
5. 不要把当前便签操作、全局导航、账户动作全部堆在同一排。

## 4. 回归验证清单

技术部修完后，至少按以下流程自测：

1. 新建一条普通便签，确认编辑态仍有明显“新建”入口。
2. 切到待办模式，输入一条内容，连续按 Enter 新增 3 条。
3. 在待办模式直接粘贴编号列表，确认拆成多条。
4. 在待办模式直接粘贴无编号多行文本，确认拆成多条。
5. 粘贴 `[x] 已完成任务`，确认进入已完成状态。
6. 勾选未完成项，确认自动下沉到已完成区域。
7. 取消勾选已完成项，确认回到未完成区域。
8. 切回普通便签，确认不会出现 `[ ]`、`[x]` 中括号污染。
9. 将浏览器宽度调到 390px，确认顶部栏和编辑器工具栏不换行、不竖排。
10. 将浏览器宽度调到 320px，确认核心入口仍可点击。
11. 选择不同便签颜色，确认列表卡片整体视觉随颜色变化。
12. 执行 `npm run build`，必须通过。
