# 全平台便签 M5 产品规格：视觉质感与交互打磨

## 1. 本轮目标

M5 目标是在不改变核心数据模型和主要功能范围的前提下，提升全平台便签的视觉质感、日常输入舒适度和移动端完成度，让线上版本更像一个可长期使用的私人便签工具。

本轮不是营销页改版，也不是新增大功能。本轮重点是：

```text
更像便签
更安静
更顺手
更统一
移动端更干净
```

## 2. 产品气质

建议视觉方向：

```text
安静、轻量、私密、现代、像桌面便签但不幼稚
```

参考感受：

- Windows Sticky Notes 的直接和轻量。
- Apple Notes 的安静输入体验。
- Google Keep 的卡片识别度。

不追求：

- 大面积渐变。
- 营销式 hero。
- 复杂动效。
- 过度装饰。
- 花哨插画。

## 3. 范围

### 3.1 P0 必须完成

1. 全局视觉基调统一。
2. 便签列表卡片更像真实便签。
3. 置顶区和普通区视觉层级更清楚。
4. 编辑区输入体验更舒适。
5. 工具栏图标、按钮、状态统一。
6. 图片附件区域视觉优化。
7. 回收站、归档页与主页保持同一视觉语言。
8. 移动端 390px 宽度体验干净，无控件拥挤和重复返回按钮。
9. 所有已有 M2/M3 功能不回退。
10. 构建通过。

### 3.2 P1 尽量完成

1. 登录页视觉优化。
2. 空状态更精致。
3. hover、focus、active 状态更细腻。
4. 图片预览层更高级。
5. 暗色模式预留设计变量，但本轮不要求完整暗色模式。

### 3.3 本轮不做

1. 不做桌面壳。
2. 不做 PWA。
3. 不做多用户管理。
4. 不做 OCR。
5. 不做富文本编辑器。
6. 不做主题市场。
7. 不做大规模重构。

## 4. 设计原则

### 4.1 少即是多

便签工具应该让内容成为主角。视觉升级不能抢输入注意力。

要求：

- 背景要轻。
- 边框要弱。
- 阴影要克制。
- 图标要统一。
- 颜色只用于表达便签属性和操作状态。

### 4.2 便签感来自内容卡片，不来自装饰

便签感应来自：

- 柔和纸张色。
- 卡片间距。
- 轻微边界。
- 标题和摘要排版。
- 图片和待办信息的自然摘要。

不允许通过强烈阴影、旋转角度、贴纸装饰来制造便签感。

### 4.3 可重复使用优先

用户每天会反复打开、输入、搜索和切换。视觉不能只在截图里好看，必须适合长期使用。

## 5. 视觉系统

### 5.1 全局背景

建议：

```text
页面背景：#F6F5F2 或 #F7F7F4
主内容面板：#FFFFFF
弱边框：#E7E3DA
主文字：#222222
次文字：#6F6A61
弱文字：#9A948B
主操作色：#2563EB 或 #2F6FED
危险色：#D92D20
成功色：#16803C
```

要求：

- 不要让页面读起来像单一蓝灰后台。
- 不要使用大面积紫色、深蓝、棕色或高饱和渐变。
- 便签颜色应柔和，但不同颜色可明显区分。

### 5.2 便签颜色

建议便签色：

```text
yellow: #FFF4C2
blue:   #DDEBFF
green:  #DFF3E4
pink:   #FFE1EA
gray:   #ECEBE7
```

配套边框：

```text
yellow: #E7D98F
blue:   #B7D1F8
green:  #B7DDBF
pink:   #E8B9C8
gray:   #D7D3CC
```

要求：

- 卡片背景应显示便签颜色，而不是只显示颜色点。
- 当前选中便签可用更清楚的边框或内阴影，不要用过重蓝色 ring。
- 搜索高亮不能破坏便签颜色。

### 5.3 字号层级

建议：

```text
列表标题：14px / 600
列表摘要：12px-13px / 400
列表元信息：11px-12px / 400
编辑标题：24px-28px / 650
编辑正文：16px-17px / 400
工具栏：12px-13px / 500
```

要求：

- 不使用随视口宽度变化的字号。
- 字距保持默认，不使用负字距。
- 移动端标题不能撑破容器。

### 5.4 圆角和阴影

建议：

```text
便签卡片圆角：10px-12px
按钮圆角：8px
输入框圆角：10px
缩略图圆角：8px
弹层圆角：12px
```

阴影要求：

- 默认状态可以无阴影或极轻阴影。
- hover 状态允许轻微浮起。
- 不允许多层强阴影造成卡片漂浮感过重。

## 6. 页面规格

### 6.1 主页整体布局

桌面端：

- 左侧列表宽度建议 320px-360px。
- 右侧编辑区为主工作区。
- 左右区域边界应柔和，不要像管理后台表格分栏。
- 顶部栏保持高度稳定，不因搜索、保存状态、按钮变化跳动。

移动端：

- 列表页和编辑页必须保持互斥显示。
- 编辑页只保留一个返回列表按钮。
- 顶部操作不能挤压标题或正文。
- 图片缩略图不横向溢出。

### 6.2 顶部栏

P0 要求：

1. 搜索框视觉更轻，focus 状态清晰。
2. 新建按钮更像主要操作，但不要过大。
3. 回收站、归档、退出使用统一图标按钮。
4. 图标按钮 hover 区域一致，建议 32px-36px。
5. 移动端编辑态只出现一个返回按钮。

验收：

- 390px 下顶部栏无横向滚动。
- 图标按钮之间间距一致。
- 搜索框有清空按钮，且不会遮挡输入文字。

### 6.3 便签列表

P0 要求：

1. 便签卡片使用完整颜色背景。
2. 卡片应有自然纸张感，但不要强阴影。
3. 标题最多一行，正文摘要最多 2-3 行。
4. 空标题时仍使用正文首行或待办首项作为标题。
5. 图片数量、待办进度、更新时间排列清楚。
6. 置顶区和普通区有明显但克制的分隔。
7. 选中态清楚，但不要过度蓝色化。

建议卡片结构：

```text
[置顶图标] 标题
正文摘要 / 待办摘要
更新时间    N 图    2/5
```

置顶区建议：

- 区域标题可显示 `置顶`。
- 与普通区之间使用更明显的间距或分隔线。
- 置顶图标不应过亮。

空状态：

- 无便签时显示简短文案。
- 搜索无结果和真正空列表使用不同文案。
- 不需要插画，但可以使用一个轻量图标。

### 6.4 编辑区

P0 要求：

1. 标题输入区更像文档标题，字号更自然。
2. 正文输入区行高更舒适。
3. 正文最大阅读宽度建议控制在 720px-820px，避免超宽屏一行过长。
4. 工具栏分组清楚：模式、颜色、图片、保存状态、置顶、归档、删除。
5. 保存状态弱化显示，失败时仍明显可重试。
6. 输入区和附件区之间有自然间距。

建议布局：

```text
顶部工具栏
标题
正文 / 待办项
附件区域
```

要求：

- 不要把编辑区放进浮动大卡片。
- 页面应像一个干净工作区。
- 文本输入不能被工具栏或附件遮挡。

### 6.5 待办编辑

P0 要求：

1. checkbox 与文字垂直对齐。
2. 待办项之间间距一致。
3. 勾选后文字状态清楚，但不要过淡到不可读。
4. 空待办项仍可编辑。
5. 新增项按钮或交互位置自然。

必须回归：

- 反复切换普通便签/待办，不得再次出现 `[ ]` 或 `[x]` 前缀累积。
- 空便签切待办后刷新，必须仍显示可编辑空待办项。

### 6.6 图片附件区域

P0 要求：

1. 图片入口和颜色选择器在视觉上同属工具区。
2. 上传中状态清楚。
3. 错误提示不撑破工具栏。
4. 缩略图尺寸稳定，不因图片加载改变布局。
5. 删除按钮在桌面 hover 出现，移动端可点击，不应只依赖 hover。
6. 预览层背景、关闭按钮、文件名展示更统一。

建议：

- 附件区域可有轻量标题或图标，但不需要大标题。
- 缩略图网格在移动端保持 3 列或根据宽度自适应。
- 加载失败占位不能重复插入多个 DOM 占位。

### 6.7 回收站和归档页

P0 要求：

1. 回收站、归档页卡片视觉与主页一致。
2. 回收站必须显示图片数量提示。
3. 回收站恢复和永久删除按钮层级清楚。
4. 永久删除按钮必须保持危险色，但不要过度刺眼。
5. 归档页打开便签后仍保持编辑体验一致。

### 6.8 登录页

P1 要求：

1. 登录页应和便签产品气质一致。
2. 表单卡片不要过大。
3. 默认账号提示若仍保留，应弱化，生产环境不应突出默认密码。
4. 错误提示清楚。

## 7. 交互状态

所有按钮、输入框、卡片至少具备：

```text
default
hover
focus-visible
active
disabled
loading 或 saving
error
```

要求：

- focus-visible 必须键盘可见。
- hover 不应导致布局位移。
- loading 不应改变按钮宽度导致跳动。
- disabled 状态不应完全不可读。

## 8. 响应式验收

必须验收以下宽度：

```text
390 x 844
768 x 1024
1280 x 800
1440 x 900
```

每个宽度至少检查：

1. 首页列表。
2. 编辑普通便签。
3. 编辑待办便签。
4. 带 3 张图片的便签。
5. 图片预览层。
6. 回收站。
7. 归档页。

## 9. 回归验收清单

M5 不允许破坏 M2/M3 已通过能力。技术部完成后必须回归：

1. `npm run build` 通过。
2. 登录、退出正常。
3. 新建便签后自动聚焦。
4. 自动保存正常。
5. 保存失败后可重试。
6. 普通便签和待办切换正常。
7. 反复切换不出现前缀累积。
8. 空便签切待办刷新后仍有可编辑空项。
9. Cmd/Ctrl + Enter 新建下一条。
10. 搜索高亮正常。
11. 清空搜索正常。
12. 置顶区和普通区排序正常。
13. 删除进入回收站。
14. 回收站恢复正常。
15. 永久删除正常。
16. 图片上传正常。
17. 一次选择 3 张图片后立即显示 3 张。
18. 图片预览和关闭正常。
19. 删除单张图片正常。
20. 未登录访问图片返回 401。
21. 路径穿越请求不得返回 200。
22. 390px 移动端列表/编辑切换干净。
23. 390px 移动端无重复返回按钮。
24. 390px 移动端图片不溢出。

## 10. 技术实现建议

### 10.1 建议先整理设计 token

可在 `globals.css` 或 Tailwind 配置中统一：

```text
颜色
边框
阴影
圆角
字号
间距
focus ring
```

避免每个组件各自写一套颜色。

### 10.2 建议优先改组件

建议改动顺序：

1. 全局 token 和基础背景。
2. `TopBar`。
3. `NoteList`。
4. `NoteEditor`。
5. `ImageAttachments` / `ImagePreview`。
6. `trash/page` 和 `archive/page`。
7. `login/page`。

### 10.3 不建议本轮引入大型 UI 库

当前项目体量小，本轮不建议引入完整 UI 框架。可以继续用 Tailwind 和现有组件完成。

允许：

- 使用 `lucide-react` 替换手写 SVG，前提是统一且不显著增加复杂度。

不建议：

- 引入重型组件库。
- 引入动画库。
- 大规模重写布局。

## 11. 视觉验收方式

技术部交付时需要提供：

```text
1. 改动摘要
2. npm run build 结果
3. 桌面端首页截图
4. 桌面端编辑页截图
5. 移动端 390px 列表截图
6. 移动端 390px 编辑截图
7. 图片预览截图
8. 回收站截图
9. M2/M3 回归结果
10. 已知剩余问题
```

验收人检查时重点看：

- 是否真的更像便签。
- 是否降低后台感。
- 是否没有文字重叠。
- 是否没有横向滚动。
- 是否没有功能回退。
- 是否移动端控件干净。

## 12. 本轮完成标准

M5 通过标准：

1. 视觉比 M4 线上版明显更统一、更像便签。
2. 桌面端和移动端主要页面无明显粗糙、拥挤、错位。
3. 颜色、圆角、按钮、输入框、卡片风格统一。
4. 移动端无重复返回按钮。
5. 图片和待办相关视觉无回退。
6. M2/M3 核心功能回归通过。
7. 线上部署后不影响 Hermes 服务。

未满足以上任一关键项，M5 不通过。
