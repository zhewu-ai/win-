# PinNote Skin V1 视觉原型交付说明

日期：2026-08-07

## 定位

这是 PinNote 新视觉方向的独立静态原型，不是生产代码。

目录：

```text
visual-prototypes/pinnote-skin-v1/
```

当前目的：

1. 先把视觉气质跑出来。
2. 给产品侧确认“高级、干净、轻盈”的方向。
3. 后续再拆成 token、组件样式和交互规则，交给技术部集成到现有 Next/Tauri App。

## 参考方向

来自产品侧提供的视觉图：

- 左侧：轻灰侧边栏、白色便签卡、蓝色选中卡。
- 右侧：Apple Notes 风格编辑区，干净、低干扰、强留白。
- 图标：黄色便签拟物图标，后续可作为 App icon 方向。

## 已实现

1. 独立静态页面：`index.html`。
2. 样式文件：`styles.css`。
3. 简单交互：`script.js`。
4. 图标资源：`assets/pinnote-icon.png`。
5. 基础交互：
   - 点击左侧卡片切换编辑标题和内容。
   - 点击颜色球切换选中状态。
   - 点击待办圆点切换完成状态。
   - 点击侧边栏折叠按钮隐藏侧边栏。
   - 点击工具栏月亮/太阳图标切换亮色/暗色。
   - 工具栏、卡片操作、待办拖拽手柄已统一为线性 SVG，不再使用 CSS 临时拼接图标。
6. 响应式：
   - 1080px 以下收窄侧边栏和卡片密度。
   - 940px 以下工具栏进入 compact 状态。
   - 820px 以下隐藏侧边栏。
   - 560px 以下进一步压缩工具栏间距。
   - 360px 以下隐藏图片/置顶等次要按钮。
   - 工具栏文字和色球收敛。
   - 编辑区字号收敛。

## 视觉原则

### 1. 亮色优先

这版以亮色模式为主，不再把亮色做成暗色的简单反色。

目标：

```text
干净、轻、白但不刺眼、灰但不脏。
```

### 2. 侧边栏像便签，而不是普通列表

左侧卡片应保持：

- 明确卡片轮廓。
- 轻微阴影。
- 选中卡片有强视觉锚点。
- 未选中卡片保持白色和轻边框。

### 3. 右侧编辑区减少装饰

右侧不做卡片，不做复杂分割。

重点是：

- 标题强。
- 输入区域干净。
- 工具栏低干扰。
- 底部时间轻。

### 4. 工具栏图标化

模式、图片、置顶、更多等入口尽量图标化。

图标规则：

- 使用现有主项目的线性 SVG 语言，线宽约 1.5px。
- 置顶按钮沿用当前 `NoteEditor.tsx` 的窗口置顶图标，不使用拟物钉子。
- 更多按钮使用竖向三点。
- 待办拖拽手柄使用 2 列 6 点，尺寸固定为轻量辅助控件。
- 不要用 CSS 伪元素临时画复杂图标，容易出现比例奇怪、主题遮挡和窄屏变形。

文字只保留必要信息：

- 标题。
- 便签内容。
- 同步状态。
- 关键操作。

### 5. 暗色不是简单反色

暗色模式使用独立 token：

- 背景不是纯黑，而是深灰蓝。
- 边框降低对比度，避免脏线。
- 卡片使用半透明浅叠层。
- 蓝色选中态保持明亮，但阴影更克制。
- 搜索框、hover、selected 都单独适配。

目标：

```text
暗色安静、干净、有层次，但不脏、不闷。
```

### 6. 响应式以稳定为先

原型里不追求每个像素都塞满，而是优先保证：

- 工具栏单行。
- 不出现文字竖排。
- 色球和状态不要反复展开/收起。
- 小窗时低频按钮可以隐藏到更多菜单。
- 编辑内容优先保留可读空间。

## 后续集成建议

技术部集成时不要直接复制全部 CSS，应拆成：

1. Design tokens：
   - `--window-bg`
   - `--sidebar-bg`
   - `--editor-bg`
   - `--line`
   - `--ink`
   - `--hover`
   - `--selected`
   - `--blue`
   - `--teal`
   - `--mint`
   - `--yellow`
   - `--field-bg`
   - `--card-bg`
   - `--active-card-text`
   - `--sync-dot`
2. 组件：
   - Sidebar。
   - NoteList/Card。
   - EditorToolbar。
   - SaveStatus。
   - Checklist row。
   - Account footer。
3. 状态：
   - hover。
   - selected。
   - active。
   - synced/local draft/sync failed。
   - compact/narrow。
4. 主题：
   - `data-theme="light"`。
   - `data-theme="dark"`。
   - 用户选择写入 localStorage。
   - 后续生产版可接入现有 AccountMenu 外观入口。

## 不要直接做的事

1. 不要在技术部当前 M8.9 分支上直接混入这个原型。
2. 不要一次性替换所有生产样式。
3. 不要为了贴图完全照抄固定尺寸，生产代码仍需适配 320px/390px/Windows 小窗。
4. 不要破坏现有断网防丢保护。

## 验收建议

视觉方向确认时，至少看四个状态：

1. 亮色宽屏。
2. 暗色宽屏。
3. 820px 左右侧边栏隐藏状态。
4. 360px 左右极窄工具栏状态。

通过标准：

- 亮色不土、不灰脏。
- 暗色不闷、不死黑。
- 卡片 hover/selected 层级清楚。
- 工具栏小窗不换行、不颤动。
- 侧边栏折叠动画自然。
- 便签内容阅读优先级高于工具按钮展示。

## 建议下一步

1. 产品侧打开 `index.html` 确认视觉方向。
2. 如果方向通过，再写 M9 视觉升级 spec。
3. 技术部按 token + 组件逐步集成，而不是直接复制原型。
